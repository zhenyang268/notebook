## NET-05 传输层

### 408-NET-0501 服务与端口

传输层向上为应用进程提供端到端的逻辑通信，屏蔽底层网络细节。它的复用让不同应用进程能使用同一个传输层协议发送数据，分用则依据端口号把收到的数据交付给正确的进程。端口号 16 位，取值 $0\sim65535$，分为熟知端口（$0\sim1023$）、登记端口（$1024\sim49151$）和临时端口（$49152\sim65535$），TCP 与 UDP 各自拥有独立的端口号空间。通信端点的完整标识是套接字 $(IP,\ \text{端口})$，一条 TCP 连接由源 IP、源端口、目的 IP、目的端口四元组唯一定位。典型分配为 DNS 53、FTP 21 与 20、SMTP 25、HTTP 80、POP3 110、HTTPS 443、SNMP 161。易错点：传输层用端口号区分主机内的进程，网络层用 IP 地址区分主机；不同主机上相同的端口号互不相干。

### 408-NET-0502 UDP

UDP 是无连接、尽最大努力交付的传输协议，只在 IP 之上提供复用分用与差错检测，没有确认、重传和拥塞控制，因而时延小、首部开销小。UDP 面向报文，对应用层交下来的报文既不合并也不拆分，保留报文边界，所以报文长度受 IP 数据报最大长度的限制。首部固定 8 字节：源端口、目的端口、长度、检验和各 2 字节；长度字段是整个 UDP 数据报的长度，即首部加数据，最小值为 8。检验和计算时需临时加上 12 字节伪首部（源 IP、目的 IP、填充 0、协议号 17、UDP 长度），把首部与数据按 16 位反码求和后取反；检验和为 0 表示未使用检验和，但对 IP 分片的数据必须计算。易错点：UDP 检验和与 IP 首部检验和算法相同，覆盖范围却多了伪首部，并且校验了数据部分。

### 408-NET-0503 TCP 连接管理

TCP 是面向连接、全双工、提供可靠字节流服务的协议。连接建立采用三次握手：客户发送 $SYN=1,\ seq=x$；服务器回复 $SYN=1,\ ACK=1,\ seq=y,\ ack=x+1$；客户再发 $ACK=1,\ seq=x+1,\ ack=y+1$。前两次握手消耗序号，第三次可以携带数据。三次而不是两次，是为了防止已失效的连接请求报文突然送达服务器，使其建立无用连接而浪费资源。连接释放采用四次挥手：主动方发 FIN 进入 FIN-WAIT-1，收到 ACK 进入 FIN-WAIT-2；被动方发 FIN，主动方回 ACK 后进入 TIME-WAIT，等待 $2\text{MSL}$ 才真正关闭。等待 2MSL 一是保证最后一个 ACK 能到达（否则可重传 ACK），二是使本连接持续时间内产生的所有报文段从网络中消失，避免干扰新连接。

### 408-NET-0504 可靠传输与流量控制

TCP 用序号、确认和计时器重传保证可靠：接收方返回累积确认 $ack=n$，表示 $n-1$ 及之前的字节都已按序收到。超时重传时间由 $RTO=RTT_s+4RTT_d$ 给出，其中 $RTT_s=(1-\alpha)RTT_s+\alpha RTT_{sample}$，$\alpha=1/8$；$RTT_d=(1-\beta)RTT_d+\beta\,|RTT_s-RTT_{sample}|$，$\beta=1/4$。若收到三个重复 ACK，说明其后的报文段已丢失，立即快重传而不必等超时。流量控制靠接收方通告的接收窗口 $rwnd$ 实现，发送窗口取 $\min(rwnd,\ cwnd)$；窗口为 0 时发送方启动持续计时器，定期发零窗口探测。易错点：窗口字段只有 16 位，需用窗口扩大选项；零窗口探测报文只含 1 字节且需重传，故发送方即使无数据也要保持计时器运行。

### 408-NET-0505 拥塞控制

拥塞控制防止过多数据注入网络，与只求收发两端速率匹配的流量控制不同。它包含四个算法：慢开始使拥塞窗口 $cwnd$ 从 1 个 MSS 起，每收到一个 ACK 加 1，每轮加倍呈指数增长；$cwnd$ 达到门限 $ssthresh$ 后转入拥塞避免，每轮只加 1 MSS，呈线性增长。检测到丢失时：超时则置 $ssthresh=cwnd/2$、$cwnd=1$，重新慢开始；收到三个重复 ACK 则快重传并快恢复，置 $ssthresh=cwnd/2$、$cwnd=ssthresh$，直接进入拥塞避免。发送窗口等于 $\min(cwnd,\ rwnd)$。典型计算：$cwnd$ 由 1 增至 16 需 4 轮，路径为 $1\to2\to4\to8\to16$。易错点：快恢复后 $cwnd$ 不回到 1，也不重新执行慢开始。

## NET-06 应用层

### 408-NET-0601 模型

应用层协议的设计有两种典型模型。客户/服务器模型中，客户是服务请求方，主动向服务器发起连接；服务器被动等待并并发处理多个请求，客户之间不直接通信。服务器必须一直运行并固定端口，便于集中管理与安全控制，但请求集中时易成瓶颈。P2P 模型中各结点地位对等，既是客户又是服务器，可直接交换数据，可扩展性好、成本低，但管理困难、安全性差。判断某进程是客户还是服务器，看的是本次通信中谁主动发起，而不是主机硬件或性能的强弱，同一主机上也可同时充当两种角色。DNS、HTTP、SMTP、FTP 均采用客户/服务器模型；应用层并不只有客户/服务器这一种模型。易错点：把“服务器”理解为高性能主机，而忽略主动与被动的行为区别。

### 408-NET-0602 DNS

DNS 把域名映射为 IP 地址，是层次树状命名、分布式存储的数据库。域名服务器分为根、顶级、权限三级，再加上本地域名服务器。主机到本地域名服务器一般采用递归查询，由对方代为完成整个解析；本地域名服务器到根、顶级服务器一般采用迭代查询，自己逐级询问，根只告诉它下一个该问谁。高速缓存存放近期解析结果，可减少查询次数与网络流量。常用资源记录有：A 给 IPv4 地址，AAAA 给 IPv6 地址，CNAME 表示别名，MX 指向邮件服务器，NS 指向域名服务器。DNS 主要使用 UDP 的 53 端口，区域传送使用 TCP 的 53 端口。易错点：递归与迭代的区别在于谁承担后续查询工作，与查询次数的多少无关。

### 408-NET-0603 FTP 与电子邮件

FTP 使用两个并行的 TCP 连接：控制连接在 21 端口，贯穿整个会话，传送命令与应答，方式称为带外控制；数据连接在传输文件时建立、传完即关闭，主动方式下由服务器用 20 端口发起。电子邮件系统由用户代理、邮件服务器及相应协议组成。SMTP 在 25 端口把邮件从发送方推到服务器，或从一台服务器推到另一台服务器，只能传送 7 位 ASCII 文本，二进制内容需 MIME 扩展编码。收信时用户代理用 POP3（110 端口）拉取邮件，下载后通常删除；IMAP（143 端口）则在服务器上操作邮件，支持只下载部分内容。易错点：SMTP 是推送协议、POP3 是拉取协议；FTP 的控制连接长期保持，数据连接每次传输时新建。

### 408-NET-0604 WWW 与 HTTP

WWW 以 URL 定位资源，形如 协议://主机:端口/路径，用 HTTP 传输。HTTP 基于 TCP 的 80 端口，本身是无状态协议，服务器不记忆先前的请求，需要靠 Cookie 与缓存维持会话信息。请求报文含方法（GET、POST、HEAD、PUT、DELETE）与 URL，响应报文含状态码：200 成功、301 永久移动、304 未修改、400 请求错误、403 禁止、404 未找到、500 服务器错误。HTTP/1.0 默认非持续连接，每个对象都要新建 TCP 连接；HTTP/1.1 默认持续连接，可流水线发送请求。典型计算：页面含 1 个基本对象和 $N$ 个引用对象且忽略传输时间时，非持续连接需 $2(N+1)$ 个 RTT，持续非流水线需 $(N+1)$ 个 RTT，持续流水线只需 $2$ 个 RTT。
