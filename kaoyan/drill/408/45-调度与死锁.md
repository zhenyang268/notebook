## 二、L1 基础：先把模板默写出来

### L1-1 FCFS / SJF / RR 三种调度的周转时间表
**题干**：某单 CPU 系统有 3 个进程，到达时间与服务时间如下表（单位：ms，均为整数，忽略调度开销）：

| 进程 | 到达时间 | 服务时间 |
| P1 | 0 | 6 |
| P2 | 1 | 3 |
| P3 | 2 | 4 |

分别按下列三种算法调度：(1) FCFS；(2) SJF（非抢占，只在进程到达或运行结束时重新决策）；(3) RR（时间片 $q=2$，同一时刻新到达进程先入就绪队列，被抢占的进程后入队）。要求：对每种算法给出各进程的完成时间、周转时间、带权周转时间，并比较三种算法平均周转时间的大小关系。

**题眼**：看到「周转时间 / 带权周转时间」就要想到「先画时间轴定完成时间，再套『周转 = 完成 $-$ 到达』『带权周转 = 周转 $\div$ 服务』」；看到 RR 两个字就要想到「时间片到点必换人、被换下的排到队尾」。

**卡在哪**：算 SJF 时以为「把服务时间从小到大排一遍就是 SJF 的执行顺序」，于是直接按服务时间把三个进程排开，忘了非抢占 SJF 的每一次决策都只能在「此刻已经到达」的进程里挑，最开始只有 P1 在场，后面的进程还没来。算 RR 时又容易把就绪队列的入队次序弄反：同一时刻既有人到达、又有人时间片用完时，应先让新到达者入队、再让被抢占者入队，顺序一颠倒，后面所有进程的完成时间就全跟着错位，而阅卷是按完成时间逐格核对的。

**分步**：① 以时间为横轴分别画出三种算法的执行条，在每个调度点标明 CPU 交给了谁，据此读出三个进程的完成时间；FCFS 按到达先后排，SJF 每个调度点只在已到达者中取服务时间最短者，RR 每满一个时间片就把当前进程挂到队尾并让新到达者先入队。② 按定义「周转时间 $=$ 完成时间 $-$ 到达时间」逐个计算。③ 按定义「带权周转时间 $=$ 周转时间 $\div$ 服务时间」逐个计算，注意它是比值、无量纲。④ 分别对三种算法的周转时间求算术平均，按大小排序作答。

**拿分骨架**：①→3 分　②→2 分　③→1 分　④→1 分

**结果锚点**：FCFS：完成时间(P1,P2,P3)=(6,9,13) ms，周转时间=(6,8,11) ms，带权周转时间=(1,8/3≈2.67,11/4=2.75)，平均周转时间=25/3 ms≈8.33 ms；SJF：完成时间=(6,9,13) ms，周转时间=(6,8,11) ms，带权周转时间=(1,8/3≈2.67,11/4=2.75)，平均周转时间=25/3 ms≈8.33 ms；RR(q=2)：完成时间=(13,9,11) ms，周转时间=(13,8,9) ms，带权周转时间=(13/6≈2.17,8/3≈2.67,9/4=2.25)，平均周转时间=10 ms。大小关系：FCFS = SJF（≈8.33 ms） < RR（10 ms）。

**变式**：把 RR 的时间片改为 $q=1$，并增加一个与 P1 同时到达的进程，问三种算法中平均带权周转时间最小的那一种是否发生改变。

### L1-2 死锁四个必要条件与资源分配图判定
**题干**：某系统有资源 R1（2 个实例）和 R2（1 个实例），当前占用与申请情况如下表。规定：进程只能整份申请，运行期间不主动释放已占资源，同类资源的各实例完全等价。

| 进程 | 已占有 | 正在申请 |
| P1 | R1 一个 | R2 一个 |
| P2 | R2 一个 | R1 一个 |
| P3 | R1 一个 | 无 |

回答：(1) 写出死锁产生的四个必要条件，并逐条指出本题场景中哪一项事实体现了该条件；(2) 画出资源分配图，用化简资源分配图的方法判断系统当前是否处于死锁状态，若不是，说明系统按什么次序推进可以全部完成。

**题眼**：看到「资源分配图 + 问是否死锁」就要先数实例：单实例时环路与死锁等价，多实例时只能靠化简图下结论；看到「四个必要条件」就要一口气默出「互斥、占有并等待、不可剥夺、循环等待」。

**卡在哪**：一是把四个必要条件背成三条，或写成「请求与保持」「部分分配」这类非标准叫法，而这种题第一问就是按术语给分的，叫法不标准等于白丢分。二是把环路当成死锁的充分条件，一看到图里能连出环就判死锁，忽略了环上还挂着第三个进程，它手上握着的那份资源可以先还回来把环拆开——多实例情形下环路只是必要条件。三是化简时把申请边当成分配边去删，边的方向一颠倒，可化简的进程就永远找不出来。

**分步**：① 默写四个必要条件的标准名称，再回到题干表格里为每条条件找一句对应事实，做到一条条件对一句事实。② 按表画出资源分配图：资源画成方框、实例画成框内圆点，申请边由进程指向资源，分配边由资源指向进程，箭头方向不能反。③ 找出「申请边全部能被当前空闲实例满足」的进程，令其运行到底并释放全部占有，删去与它相连的所有边，重复这一过程直到再也找不到可化简的进程。④ 看最终图：边能全部消去则系统无死锁，此时把③中删点的先后次序整理成推进序列；若剩下既非孤立又化简不动的进程，它们构成的集合就是死锁进程集。

**拿分骨架**：①→3 分　②→1 分　③→2 分　④→1 分

**结果锚点**：(1) 互斥条件：R1的两个实例分别由P1、P3占用，R2的唯一实例由P2占用，同一实例同一时刻只归一个进程；请求和保持条件：P1占有R1又申请R2，P2占有R2又申请R1；不可剥夺条件：运行期间已占资源不主动释放、不能被强行抢占；循环等待条件：存在循环 P1→R2→P2→R1→P1。(2) 资源分配图分配边：{R1_a→P1, R1_b→P3, R2_a→P2}；申请边：{P1→R2, P2→R1}；化简后边集=∅；判定：非死锁，死锁进程集=∅；推进序列：P3→P2→P1。

**变式**：把 P3 改为「已占有 R1 一个，同时又申请 R1 一个」，问化简过程在哪一步卡住、死锁结论如何变化。

## 三、L2 提高：真题主干难度

### L2-1 多级反馈队列的时间线推演
**题干**：某系统采用三级反馈队列调度，规则如下：$Q_1$ 时间片为 2，$Q_2$ 时间片为 4，$Q_3$ 按先来先服务、进程一经投入便运行到结束；新进程到达一律进入 $Q_1$ 队尾；调度时总选非空队列中级别最高的队头运行；若某进程正在 $Q_2$ 或 $Q_3$ 运行，而此时有新进程到达 $Q_1$，则立即抢占，被抢占进程放回原队列**队头**、剩余时间不变；进程在本级时间片用完仍未结束则降入下一级队尾。现有四个进程：

| 进程 | 到达时刻 | 要求服务时间 |
| P1 | 0 | 7 |
| P2 | 1 | 4 |
| P3 | 3 | 2 |
| P4 | 8 | 3 |

求各进程的完成时刻、周转时间、平均周转时间，并统计整个过程中发生抢占的次数。

**题眼**：看到“多级反馈队列”与“带到达时刻的时间片”，就要想到这正是“每到一次到达时刻先做一次队列级别比较、再推进时间轴”的条件判断型时间线题。

**卡在哪**：多数人按“谁先到谁先连续跑”的习惯往下推，把第一个进程在 $Q_2$ 的那一段当成一次跑完的连续区间，脑子里根本没有“新进程落在 $Q_1$ 会把 $Q_2$ 上正在运行的进程顶下来”这个念头。这一步一错，被抢占进程的剩余时间没有保留，后面所有完成时刻整体错位，平均周转时间必然不对，而且还得不到抢占次数。

**分步**：① 把四个进程按到达时刻排成一列，画出时间轴，标出每个到达时刻，并把三级队列的时间片与降级规则写在旁边备用。② 从 $t=0$ 起一段一段推进：每进入一个新时刻，先判断“此刻有谁到达、它在哪一级队列、正在运行的进程在哪一级”，据此判定是否发生抢占，再决定这一段跑谁、跑多久。③ 每一段结束后按“用满时间片降一级入队尾、时间片内结束则撤离、被抢占则回原队列队头”三条分别处理，并在时间轴上记下该进程的剩余时间。④ 所有进程撤离后，逐个用“完成时刻减到达时刻”算周转时间。⑤ 把四个周转时间求和除以进程数得平均周转时间，同时把第②步中判定为抢占的时刻数出来。

**拿分骨架**：①→1 分　②→2 分　③→2 分　④→1 分　⑤→1 分

**结果锚点**：锚点不可唯一确定：被抢占进程再次运行时其本级时间片余量是否保留（Q2 中 P1 于 t=6～8 已运行 2，t=10 起是重新给 4 还是仅剩 2）。

**变式**：把 $Q_1$ 时间片改为 1，并把被抢占进程的归位规则改成“放回原队列队尾”，问四个进程中谁的完成时刻变化幅度最大。

### L2-2 银行家算法的安全性检查与安全序列
**题干**：某系统有 A、B 两类资源，总数分别为 5 个和 5 个。$T_0$ 时刻三个进程的最大需求与已分配情况如下（括号内依次为 A、B 的数量）：

| 进程 | Max | Allocation |
| P0 | (3, 2) | (1, 1) |
| P1 | (3, 3) | (2, 1) |
| P2 | (3, 3) | (1, 1) |

Need 按 $Max-Allocation$ 计算，Available 按“资源总数减去各进程已分配之和”计算。请回答：(1) 求出 $T_0$ 时刻的 Available，用银行家算法判断此时系统是否安全，若安全写出一个安全序列，并逐行写出每一步 Work 的取值与回收后的资源数；(2) 在 $T_0$ 时刻若 P0 又提出请求 $(1,0)$，按银行家算法判断能否立即满足；若不能，说明 P0 应处于什么状态。

**题眼**：看到“请求向量 + 已有 Max/Allocation 表”，就要想到银行家算法必须先试分配再对**新状态**做一次完整安全性检查，而不是只拿请求向量去和 Available 比大小。

**卡在哪**：第二问几乎人人会停在这里——看到请求的 $(1,0)$ 在 Need 之内、也在 Available 之内，两个不等式都成立，就顺手写下“可以立即分配”。漏掉的正是第三步：试分配之后 Available 变紧，必须拿新的 Available 重新跑一遍安全性检查，看还能不能找出一个安全序列；找不出就必须让请求者阻塞等待，而不是分配。

**分步**：① 由 Max 与 Allocation 逐行相减得到 Need 矩阵，再由资源总数减去已分配总量得到 Available，两者都列成表备用。② 按安全性检查算法初始化 Work 与 Finish，每一轮在未完成进程中找出“Need 的每一分量都不超过当前 Work”的进程，找不到即判不安全。③ 找到后令其完成，把它的 Allocation 加回 Work，记下它进入安全序列的位置，重复直到全部完成或卡住。④ 对 P0 的请求先做两道前置判断（不超过 Need、不超过 Available），通过后执行试分配，改写 Available、Allocation、Need 三张表。⑤ 用改写后的表重新执行第②③步，据能否化到全完成来判定这次请求是立即满足还是令 P0 阻塞。

**拿分骨架**：①→1 分　②→3 分　③→1 分　④→2 分

**结果锚点**：Available=(1,2)；Need：P0(2,1)、P1(1,2)、P2(2,2)；系统安全。安全序列不唯一：P1→P0→P2 与 P1→P2→P0。P1→P0→P2 的 Work/回收后：(P1,(1,2)→(3,3))、(P0,(3,3)→(4,4))、(P2,(4,4)→(5,5))；P1→P2→P0 的 Work/回收后：(P1,(1,2)→(3,3))、(P2,(3,3)→(4,4))、(P0,(4,4)→(5,5))。P0 请求(1,0)：前置判断通过；试分配后 Available=(0,2)，P0 Allocation=(2,1)、Need=(1,1)，P1 Need=(1,2)，P2 Need=(2,2)，无进程满足 Need≤Work，系统不安全；不能立即满足，P0 处于阻塞（等待）状态。

**变式**：把 P0 的 Max 由 $(3,2)$ 改为 $(4,2)$、其余不变，重新判断 $T_0$ 是否安全，并说明首次安全性检查中可选的第一个进程是否唯一。

### L2-3 资源分配图的化简
**题干**：某系统有资源类 $R_1$（2 个实例）和 $R_2$（2 个实例），当前分配状态为：$R_1$ 的 2 个实例中一个分配给 P1、一个分配给 P2；$R_2$ 的 2 个实例中一个分配给 P3，另一个空闲。请求情况为：P1 请求 $R_2$ 的一个实例，P2 请求 $R_2$ 的一个实例，P3 请求 $R_1$ 的一个实例。请回答：(1) 用资源分配图化简法判断该系统当前是否死锁，写出化简顺序，并说明每消去一个进程后 $R_1$、$R_2$ 各自空闲实例数的变化；(2) 若仅凭“图中存在环路”就判定系统死锁，会得出什么错误结论？结合本题说明环路与死锁之间的确切关系。

**题眼**：看到“资源分配图 + 多实例资源 + 有请求边”，就要想到用化简（消去可满足进程并回收资源）来判定，而不是数一数有没有环就下结论。

**卡在哪**：看到 P1 在等 P3 手里的 $R_2$、P3 又在等 P1 和 P2 手里的 $R_1$，脑子里立刻画出闭环，于是判“死锁”。停下来的那个错误念头是“有环就是死锁”——忘了这是在**多实例**资源上，P1 等的 $R_2$ 还有空闲实例，它的请求根本不需要等 P3 释放，环在化简过程中会自己消失。

**分步**：① 先把每类资源的实例总数、已分配数、空闲数三者对齐列成一张小表，这是后面每步回收的记账依据。② 逐个检查各进程的请求：请求量不超过该类资源当前空闲数的进程即为“可满足”，它一定能运行完并释放手中全部资源（依资源分配图的化简规则）。③ 消去该进程，把它的请求边与分配边一并去掉，并将其持有的各实例加回对应资源的空闲数，更新第①步的表。④ 用更新后的空闲数重复第②③步，直到没有进程可消去为止，按消去先后写下化简顺序。⑤ 比较最终结果：图能被完全化简则不存在死锁，仍有进程残留才判死锁；再把第②步中“P1 不需要等 P3”这一事实与图中的环路对照，说明环只是必要条件而非充分条件。

**拿分骨架**：①→2 分　②→3 分　③→1 分　④→1 分

**结果锚点**：初始空闲(R1,R2)=(0,1)；化简顺序不唯一，合法顺序及每步消去后空闲数：P1→P2→P3：(0,1)→P1后(1,1)→P2后(2,1)→P3后(2,2)；P1→P3→P2：(0,1)→P1后(1,1)→P3后(1,2)→P2后(2,2)；P2→P1→P3：(0,1)→P2后(1,1)→P1后(2,1)→P3后(2,2)；P2→P3→P1：(0,1)→P2后(1,1)→P3后(1,2)→P1后(2,2)。系统无死锁（可完全化简）。仅凭环路判定的错误结论：判为死锁；环路与死锁关系：环路是死锁的必要条件而非充分条件，本题存在环路（如 P1→R2→P3→R1→P1、P2→R2→P3→R1→P2）但无死锁。

**变式**：把 $R_2$ 的实例数改为 1、且该实例已分配给 P3，其余条件不变，重新用化简法判断系统是否死锁。

## 四、L3 拔高：条件一变就认不出来

### L3-1 调度与缺页耦合下的有效访问时间
**题干**：某单 CPU 系统采用时间片轮转调度，时间片 \(q=2\) ms，只对 CPU 服务计时。每个进程顺序执行 5 次访存，每次访存先占用 CPU 1 ms；若命中则继续下一次，若缺页则该进程立即阻塞并进入磁盘队列，磁盘按 FCFS 服务。缺页完成后，该进程剩余时间片作废，重新排到就绪队尾并获得完整 \(q\)。进程到达时若 CPU 忙则入就绪队尾；同一时刻先处理缺页完成，再处理新到达。三个进程的数据如下：

| 进程 | 到达时刻/ms | 访问次数 | 缺页的访问序号 | 每次缺页服务/ms |
|---|---|---|---|---|
| \(P_1\) | 0 | 5 | 第 2、4 次 | 6 |
| \(P_2\) | 1 | 5 | 第 2、4 次 | 6 |
| \(P_3\) | 2 | 5 | 第 2、4 次 | 6 |

定义 \(EAT_i=(F_i-A_i)/5\)，其中 \(F_i\) 为第 5 次访存完成的时刻，\(A_i\) 为到达时刻。问：(1) 给出 \(P_2\) 的 EAT 计算过程，需列出关键就绪队列变化；(2) 求 \([0,20]\) ms 内 CPU 空闲总时间；(3) 若只把 \(q\) 改为 1 ms，\(P_2\) 的 EAT 是否一定变小？给出判断依据，不要只写结论。

**题眼**：看到“每次访存 1 ms”与“缺页后阻塞 6 ms”同时出现，就要把一次访存拆成 CPU 段和阻塞段，用 RR 就绪队列推进；不要直接套缺页期望公式。

**卡在哪**：多数人会把缺页的 6 ms 也算进时间片，或者缺页完成后接着用旧时间片，导致就绪队尾顺序整体错位；还有人把同一时刻的磁盘完成和新到达按相反顺序处理，\(P_2\) 的完成时刻就偏了。

**分步**：① 画事件表：每个进程第 1–5 次访存各占 1 ms CPU，第 2、4 次后插入 6 ms 磁盘阻塞，标出释放回就绪队列的时刻。② 从 \(t=0\) 维护 RR 就绪队列：CPU 只累计 \(q=2\) ms，缺页时把进程移出就绪并放入磁盘 FCFS 队列；缺页完成则剩余时间片作废、重新入队尾。③ 按“先缺页完成、后新到达”的次序推进事件，检查 CPU 空闲时是否仍有就绪进程，记录 \(P_2\) 第 5 次访存完成时刻 \(F_2\)。④ 用 \(EAT_2=(F_2-A_2)/5\) 把等待和阻塞摊到 5 次访问上；再单独统计 \([0,20]\) 内所有进程都阻塞或未到达的区间，得到 CPU 空闲总时间。⑤ 把 \(q\) 改为 1 ms 重跑切分点，比较 \(P_2\) 在两种 \(q\) 下被抢占次数与等待的磁盘完成时刻，判断 EAT 是否一定下降。

**拿分骨架**：①→1 分　②→2 分　③→2 分　④→1 分　⑤→1 分

**结果锚点**：\(F_2=33\,\text{ms}\)，\(EAT_2=(33-1)/5=32/5=6.40\,\text{ms}\)；\([0,20]\,\text{ms}\) 内 CPU 空闲总时间 \(=10\,\text{ms}\)（空闲区间 \(6\sim8,\ 10\sim14,\ 16\sim20\)）。\(q=1\) 部分：锚点不可唯一确定：缺少“时间片到期”与同刻新到达的入队先后规则；若到期者先入队，\(F_2=33\,\text{ms},EAT_2=6.40\,\text{ms}\)；若新到达先入队，\(F_2=34\,\text{ms},EAT_2=6.60\,\text{ms}\)。判定：不一定会变小（上两种分别为等于和大于 \(q=2\) 的 \(6.40\,\text{ms}\)）。

**变式**：把磁盘改为两道并行且缺页服务时间改为 4 ms/8 ms 两档，问 EAT 判据如何从单队列 FCFS 改为双队列比较。

### L3-2 优先级 + 抢占 + 饥饿：给判据而不是给结论
**题干**：某单 CPU 系统采用抢占式固定优先级调度，优先级数值越小越高；任务释放后立即进入就绪队列，同优先级按到达先后。现有三个周期任务 \(A,B,C\) 和一个一次性低优先级任务 \(L\)，数据如下：

| 任务 | 优先级 | \(C_i\)/ms | \(T_i\)/ms | 首次释放 |
|---|---|---|---|---|
| \(A\) | 1 | 1 | 4 | 0 |
| \(B\) | 2 | 2 | 6 | 0 |
| \(C\) | 3 | \(x\) | 10 | 0 |
| \(L\) | 4 | 5（一次性） | — | 0 |

表中 \(C_i\) 为每次执行所需 CPU 时间，\(T_i\) 为周期；所有周期任务在 \(t=0\) 同时首次释放，之后分别在 \(T_i,2T_i,\dots\) 释放。\(L\) 在 \(t=0\) 到达，累计需要 5 ms CPU 才能完成，允许被抢占；\(x\) 为整数且 \(1\le x\le 6\)。问：(1) 不要直接断言 \(L\) 是否饥饿，写出用 \(x\) 表示的高优先级累计需求函数 \(W(t)\) 或利用率判据，并说明为什么该判据能判定 \(L\) 能否获得 CPU；(2) 若 \(x=3\)，写出求 \(L\) 完成时刻的响应时间递推式，并指出需要检查哪些释放点；(3) 若要求 \(L\) 从到达到完成不超过 20 ms，给出 \(x\) 应满足的判据（用不等式或递推式表示，不必展开数值）。

**题眼**：看到“固定优先级抢占 + 低优先级一次性任务 + 高优先级周期任务同在 0 释放”，就要先写累计需求/利用率判据，而不是先画甘特图找 \(L\) 的空隙。

**卡在哪**：多数人看到 \(L\) 在时间轴上迟迟不运行，就直接写“饥饿”；实际要证明高优先级队列从 0 起是否始终非空。另一种错法是只逐个检查 \(C_i<T_i\)，以为每个周期任务都不超周期就不会饿死，漏掉多个高优先级任务叠加后 \(U_{\text{high}}\) 可能达到 1。

**分步**：① 列 \(A,B,C\) 的释放序列，写 \(W(t)=\sum_i \lceil t/T_i\rceil C_i\) 与 \(U_{\text{high}}=\sum_i C_i/T_i\)，把 \(C\) 的 \(C_i=x,T_i=10\) 留作参数。② 判 \(L\) 饥饿：\(L\) 在 0 就绪，只要某时刻高优先级队列为空它就能运行；同步释放下检查 \(W(t)\) 是否可能小于 \(t\)，等价于比较 \(U_{\text{high}}\) 与 1，并说明等号时 0 时刻无空闲。③ 把 \(U_{\text{high}}\) 写成含 \(x\) 的表达式，给出 \(x\) 落入饥饿区/非饥饿区的判据，不写成具体数值结论。④ 对 \(x=3\)，用响应时间递推 \(R\leftarrow 5+\sum_i \lceil R/T_i\rceil C_i\) 迭代，检查 \(10,12,20\) ms 等释放点是否使 \(R\) 跨过新的 \(\lceil R/T_i\rceil\)。⑤ 将 20 ms 上限与递推收敛值比较，得到 \(x\) 的约束；若约束与饥饿区相交，要说明该上限不可能满足。

**拿分骨架**：①→1 分　②→2 分　③→1 分　④→2 分　⑤→1 分

**结果锚点**：\(W(t)=\lceil t/4\rceil+2\lceil t/6\rceil+x\lceil t/10\rceil\)，\(U_{\rm high}=1/4+2/6+x/10=(35+6x)/60\)；\(L\) 能获得 CPU 的判据：存在 \(t>0\) 使 \(W(t)<t\)，同步周期下等价于 \(U_{\rm high}<1\iff x\le4\)；\(x\ge5\) 时饥饿（等号时同步释放下 0 时刻起无空闲）。\(x=3\) 时 \(R_{k+1}=5+\lceil R_k/4\rceil+2\lceil R_k/6\rceil+3\lceil R_k/10\rceil\)，\(R:5\to12\to18\to22\to28\to31\to37\to41\to45\to48\)，\(F_L=48\,\text{ms}\)；需检查释放点 \(\{0,4,6,8,10,12,16,18,20,24,28,30,32,36,40,42,44\}\)。若要求 \(F_L\le20\,\text{ms}\)，判据为最小不动点 \(R^*(x)\le20\)（\(R=5+\lceil R/4\rceil+2\lceil R/6\rceil+x\lceil R/10\rceil\)），整数 \(x\) 满足：\(x=1\)（\(R^*(1)=18\,\text{ms}\)；\(x=2\) 时 \(R^*(2)=28\,\text{ms}\)；\(x\ge5\) 饥饿）。

**变式**：把 \(L\) 改成每 25 ms 到达一次的周期性低优先级任务，问判据如何从单次响应时间变成每个周期内可调度性条件。
