### CO-01 计算机系统概述

这一章看起来全是记忆性的东西，其实只讲一件事：一台机器为什么能被"描述"出来。你要建立的第一条线是——任何一台计算机，都可以用三个坐标定位：它属于哪一代（器件水平）、它分成哪几层（软件与硬件的分工界面）、它有多快（性能的度量方式）。

四代划分的实质是**逻辑元件的换代**：电子管、晶体管、中小规模集成电路、大规模及超大规模集成电路。每一次换代都在做同一件事——把更多功能压进更小的器件里，于是同样面积的硅片上能放下的门电路指数增长，这就是摩尔定律描述的趋势（约每 18–24 个月集成度翻一番）。摩尔定律会失效，但"软件硬件化"的趋势不会停：早年用程序实现的浮点运算，后来变成协处理器，再后来直接进 CPU；早年由操作系统模拟的加密算法，现在成了指令集扩展。这条趋势是整门课的一条主线——**凡是频繁执行、又适合并行或专用化的功能，迟早会从软件下沉为硬件**。理解了它，你后面学 Cache、学流水线、学 DMA 才不会觉得是一堆孤立设计。

冯·诺依曼结构的关键只有五个字：**存储程序**。五大部件是运算器、控制器、存储器、输入设备、输出设备，但真正定义冯·诺依曼机的是"指令和数据同样以二进制形式存放在同一个存储器里，按地址访问，顺序执行"。这一句话同时带来两个后果：一是机器可以像处理数据一样处理程序，通用性极高；二是**指令和数据共享同一条访存通路**，这就是后来一切瓶颈的源头——CO-03 的存储层次、指令流水线的结构冒险，追根溯源都在这里。注意"以运算器为中心"是早期冯·诺依曼机的特征，现代机器是"以存储器为中心"，这个区别常在选择题里挖坑。

多级层次结构要能从上往下数清楚：应用程序 → 高级语言级 → 汇编语言级 → 操作系统级 → 机器语言级（ISA）→ 微指令级 → 硬件逻辑级。**软硬件的分界线在 ISA 上**：ISA 之上是软件看到的机器，ISA 之下是实现。编译把高级语言翻成汇编或机器语言，汇编把汇编语言翻成机器语言，链接把多个目标模块和库合并成可执行文件。这里的位置要记准——编译器和汇编器都工作在"翻译"环节，链接在"拼接"环节，而操作系统在机器语言级之上提供系统调用，它本身也是软件。考试常问"哪些属于软件、哪些属于硬件"，你就抓 ISA 这条线。

性能指标是这一章唯一需要动笔的地方。字长是 CPU 一次能处理的二进制位数，直接决定运算精度和指令长度；主频 $f$ 是时钟周期的倒数。三条公式必须能随时写出来：

$$\text{CPU 执行时间}= \text{指令条数}\times CPI \times T = \frac{\text{指令条数}\times CPI}{f}$$

其中 $CPI$ 是每条指令平均时钟周期数，若不同指令占比不同，则 $CPI=\sum_i (CPI_i \times p_i)$。MIPS 是每秒百万条指令，$MIPS=\dfrac{f}{CPI\times 10^6}$；MFLOPS 是每秒百万次浮点运算。**MIPS 不能跨机器比较**，因为它不反映一条指令干了多少活。

最小例子：某机主频 2 GHz，程序共 $10^7$ 条指令，其中整数指令占 60%、$CPI=1$，浮点指令占 40%、$CPI=5$。则

$$CPI = 0.6\times 1 + 0.4\times 5 = 2.6,\quad T_{CPU}=\frac{10^7\times 2.6}{2\times 10^9}=13\ \text{ms}$$

若把浮点指令的 CPI 优化到 3，则 $CPI=0.6+1.2=1.8$，时间降到 9 ms——注意**优化后 MIPS 会变**，但真正有意义的是执行时间。

致命陷阱：拿主频高低直接判断快慢。主频高的机器 CPI 可能更大（比如 CISC 一条复杂指令要拆很多拍），执行时间反而长。另一处是"基准程序"——用一组有代表性的真实程序测性能（如 SPEC），比 MIPS 可靠，但基准程序本身也可能被编译器针对性地"讨好"，这是性能评价的经典坑：**测出来的快不等于实际用起来快**。

### CO-02 数据的表示和运算

上一章说机器里一切都是二进制，这一章回答：**二进制怎么表示数、怎么算、算错了怎么发现**。

先立住补码的模运算本质，这是整章的根。设字长 $n=8$，模 $M=2^8=256$。一个负数 $-x$ 的补码定义为 $M-x$，也就是 $256-x$。于是 $[A-B]_{补}=[A]_{补}+[-B]_{补}\ \text{mod}\ 256$，**减法被吃进了加法器**，这就是补码存在的全部理由：它让 ALU 只需要一个加法器。原码、反码、补码、移码的关系要能口算：正数三者相同；负数原码符号位为 1、数值位取绝对值，反码是数值位按位取反，补码是反码加 1；移码是补码符号位取反，所以移码保持了真值的大小顺序，专门用来比较浮点数的阶码。

以 8 位为例：$+0$ 的原码反码补码都是 `0000 0000`；$-0$ 的原码是 `1000 0000`、反码 `1111 1111`、补码 `0000 0000`——补码消除了负零，因此 8 位补码表示范围是 $-128\sim +127$，比原码（$-127\sim+127$）多一个负数。这个"多出来的一个数" $1000\,0000$ 是考点：它没有对应的原码。

进制转换练熟"除 2 取余、乘 2 取整"即可；十六进制与二进制按 4 位一组互换，这是读机器码的基本功。

字符与字符串部分要区分三层：ASCII 是 7 位字符编码（128 个字符，数字 0–9 的码是 $30H\sim39H$，大写字母 $41H$ 起、小写 $61H$ 起，大小写差 $20H$）；汉字有输入码、国标码、机内码、字形码，机内码 = 国标码 + $8080H$（两个字节各加 $80H$）；字符串按字节存储，大端是高位字节放在低地址，小端相反。**对齐**是隐藏考点：多字节数据要放在其长度的整数倍地址上，结构体会因此产生填充字节，算结构体大小时不能只把成员大小相加。

校验码解决"算错了怎么发现"。奇偶校验：加一位使 1 的个数为奇或偶，只能发现奇数个错，不能纠错。海明码：设信息位 $k$，校验位 $r$，需满足 $2^r \ge k+r+1$；校验位插在 $2^0,2^1,2^2,\dots$ 位置上，每个校验位覆盖"位置编号二进制中该位为 1"的所有位，整体异或得到指错字，指错字的值就是出错位的位置，故能**纠一位错**。CRC 用模 2 除法：信息位左移 $r$ 位（$r$ 为生成多项式最高次），除以生成多项式，余数作校验位；接收端再除一次，余数为 0 则认为无错。

定点运算的核心是溢出判据。补码加减法直接按位加、符号位参与运算，溢出有三种等价判据：①双符号位（变形补码）$00$ 正常、$11$ 正常、$01$ 正溢、$10$ 负溢；②最高位进位与次高位进位异或为 1；③两正数相加得负数、两负数相加得正数。手算例子：8 位下 $[+127]_{补}=0111\,1111$，$[+1]_{补}=0000\,0001$，相加得 $1000\,0000$，符号位由 0 变 1，判为正溢，结果不能当 $-128$ 用。

移位要分清：算术左移等同乘 2，低位补 0；算术右移保持符号位不变、高位补符号位，等同除以 2 并向负无穷取整；逻辑移位一律补 0。**算术右移对负数是"向下取整"，$-3$ 右移一位得 $-2$ 而不是 $-1$**，这是最容易错的一步。

乘除法部分不要求你逐位模拟，但要抓住 Booth 算法和恢复余数法的思想，以及**电路结构**。原码一位乘用"移位 + 加"：乘数最低位为 1 就加被乘数，然后部分积右移，$n$ 次后拼接符号位。Booth 算法（补码一位乘）看乘数相邻两位 $y_{i}y_{i-1}$：$01$ 加被乘数，$10$ 减被乘数，$00$ 和 $11$ 不动，再算术右移——它把"根据符号位做减法"统一进加法器，这是补码的又一次胜利。除法用恢复余数法（余数为负就加回除数、商上 0）或加减交替法（不恢复，余数为负时下一步改为加除数）。电路上要认得出：**乘法器 = 被乘数寄存器 + 乘数寄存器 + 部分积寄存器 + 加法器 + 移位控制**，除法器结构类似但多一个"够减判断"。

ALU 是组合逻辑部件，由加法器和各种逻辑运算、移位电路加上多路选择器组成，靠控制信号选择当前做哪种运算，并输出标志位（ZF、SF、OF、CF）。这几位标志是 CO-05 条件转移指令的依据，先把线埋在这里。

浮点数必须把 IEEE 754 刻进脑子。单精度 32 位：1 位符号、8 位阶码、23 位尾数；双精度 64 位：1 位符号、11 位阶码、52 位尾数。阶码用**移码（偏置）**，单精度偏移量是 127，双精度是 1023；尾数是**隐含最高位 1** 的规格化小数 $1.M$，所以实际有效位数比存储位数多 1。

于是单精度阶码真值范围是 $-126\sim+127$（全 0 和全 1 被征用）：阶码全 0 且尾数非 0 是**非规格化数**（此时不再隐含 1，阶码真值按 $-126$ 处理，用来平滑下溢到 0）；阶码全 1 且尾数 0 是 $\pm\infty$；阶码全 1 且尾数非 0 是 NaN。表示范围上界约 $3.4\times 10^{38}$，最小规格化正数约 $1.18\times 10^{-38}$。

手算一个例子：$-13.25$。先转二进制 $-1101.01$，规格化为 $-1.10101\times 2^3$，符号位 1，阶码 $3+127=130=1000\,0010$，尾数去掉隐含 1 得 $10101$ 后补零到 23 位，拼成 `1 10000010 10101000000000000000000`。

浮点运算的流程是：**对阶（小阶向大阶看齐，尾数右移）→ 尾数加减 → 规格化 → 舍入 → 判断溢出**。对阶时尾数右移会丢低位精度，这是浮点误差的来源；溢出的判据是**阶码是否超出范围**，尾数溢出可以通过右归一步修正，阶码溢出才是真溢出。

致命陷阱：把非规格化数也当规格化数处理，忘了它不含隐含位 1；或者在对阶时"大阶向小阶看齐"，那样会让尾数左移溢出。还有一处——单精度阶码全 1 不代表"最大阶码"，它已被无穷大和 NaN 占用。

### CO-03 存储系统

CO-01 留下的问题是冯·诺依曼瓶颈：CPU 和存储器之间只有一条通路，而 CPU 快得多。CO-02 解决了"数怎么表示"，现在要解决"数放在哪里、取多快"。这一章的整个框架就是一道不等式——**速度、容量、价格三者的矛盾，只能靠层次结构解决**。

存储器按存取方式分为 RAM（随机存取，访问时间与位置无关）、ROM（只读，断电不丢）、串行访问（磁盘按扇区、磁带按顺序）。三级层次是 Cache—主存—辅存：Cache 挡速度，主存挡容量和成本，辅存挡价格。往上走，速度更快、容量更小、每位价格更高，这个"倒金字塔"是整章的纲。

主存部分先分清 SRAM 与 DRAM。SRAM 用触发器存储，速度快、不用刷新、成本高，做 Cache；DRAM 用电容存储，需要**刷新**（电容会漏电），成本低，做主存。刷新有三种方式：集中刷新（在刷新周期内集中刷新所有行，存在"死区"，存取周期被拉长）、分散刷新（每个存取周期后跟一次刷新，无死区但周期加倍）、异步刷新（把刷新分散到最大刷新间隔内，折中，最常用）。刷新周期的计算要记牢：DRAM 按行刷新，若芯片有 $r$ 行、最大刷新间隔 2 ms，则异步刷新需每 $2\text{ms}/r$ 刷新一行，整个存储器一次全刷新要 $r$ 个刷新周期，但**刷新不占用 CPU 的访存时间，只占用存储器**，且刷新按行进行、与地址无关（由刷新计数器产生行地址）。

DRAM 芯片与内存条的关系是又一个坑：芯片本身按"位"组织，如 $64K\times 1$ 位；内存条由多片芯片**位扩展**拼成 8 位或 16 位宽。**位扩展**增加字长（地址线共用，数据线并联），**字扩展**增加容量（数据线共用，高位地址做片选），**字位同时扩展**两者兼有。地址线的分配要会算：若用 $16K\times 8$ 位芯片构成 $64K\times 8$ 位主存，需要 4 片，片内地址 14 位，剩 2 位高位地址经译码器产生 4 个片选信号，地址范围分别是 $0000H\sim3FFFH$、$4000H\sim7FFFH$、$8000H\sim BFFFH$、$C000H\sim FFFFH$。**片选信号的译码是全章最容易失分的步骤，务必先把地址位数拆清楚。**

外部存储器里磁盘要算三样东西：容量 = 记录面数 × 磁道数（柱面数）× 每道扇区数 × 扇区容量；平均存取时间 = 平均寻道时间 + 平均旋转延迟（转一圈时间的一半）+ 传输时间。例：转速 7200 r/min，则转一圈 $60/7200=8.33$ ms，平均旋转延迟约 4.17 ms，别拿整圈时间去算平均。SSD 用闪存，**读快写慢、按页写按块擦、擦除次数有限**，因此需要磨损均衡（把写分散到不同块）和垃圾回收，这是"为什么 SSD 不能像磁盘那样随便覆盖写"的答案。

Cache 的整个设计建立在局部性原理上：时间局部性（刚用过的还会用）和空间局部性（用过的附近也会用）。地址划分是核心考点：直接映射把地址切成"标记 | 行号 | 块内偏移"，全相联切成"标记 | 块内偏移"，组相联切成"标记 | 组号 | 块内偏移"。直接映射冲突多但硬件简单，全相联冲突少但比较器多、成本高，组相联折中。替换算法有随机、FIFO、LRU，**LRU 最符合局部性但实现代价大**。写策略分写直达（同时写 Cache 和主存，一致性好但慢）和写回（只写 Cache，置脏位，换出时才写回，快但一致性要靠协议维护）。

平均访问时间要能算：设命中率 $h$、Cache 访问时间 $T_c$、主存访问时间 $T_m$，则

$$T_a = h\,T_c + (1-h)(T_c+T_m)$$

这里假设"不命中时才先访问 Cache 再访问主存"，若题目说的是并行访问，公式要变——**看清题里给的是哪个模型**。

虚拟存储器解决的是"程序比主存大"的问题，是**存储层次到辅存的延伸**。页式由硬件完成地址转换，段式按逻辑结构划分、便于共享保护，段页式先分段再分页。页表存在主存，一次访存要查页表、再访数据，于是加 TLB（快表）做页表项的 Cache。完整转换过程是：虚拟地址 → 查 TLB，命中则得物理页号；不命中查主存页表，若该页不在主存还要触发缺页中断 → 查页表时页表项要带有效位、修改位、访问位 → 拼成物理地址 → 访问 Cache/主存。**TLB 不命中不代表缺页，缺页一定导致 TLB 不命中**，这个层级关系常考。

最后把 Cache 和虚拟存储器的分工钉死：Cache 由硬件管理、对程序员透明、解决"速度"；虚存由操作系统 + 硬件共同管理、对应用程序不透明、解决"容量"，二者都靠局部性，但一个装在主存前、一个装在主存后。

致命陷阱：算平均访问时间时忘了"不命中"那一次访问要先花 $T_c$ 再花 $T_m$；以及地址划分时把块内偏移位数数错——偏移位由块大小决定，$2^k$ 字节的块只要 $k$ 位，别把字节数直接当位数用。


### CO-04 指令系统

上一块把存储层次讲完，留下的问题是：CPU 凭什么知道从存储器里取出的那一串 0/1 是什么操作、操作数在哪里。这个问题的答案就是指令格式。指令字被切成两段：操作码段说明“做什么”，地址码段说明“对谁做”。地址码个数决定了指令能直接引用几个操作数——三地址指令 `a+b→c` 两个源一个目的；二地址指令通常让目的兼作源，`a←a+b`，所以源操作数被破坏；一地址指令默认隐含累加器 ACC，`ACC←ACC+x`；零地址指令要么操作数隐含（如栈机），要么根本不需要操作数（如 `HLT`）。

地址码要省，操作码就得可扩展。核心机制是**短操作码不能是长操作码的前缀**，否则译码时无法区分。具体做法是：设指令字长 16 位，用 4 位作基本操作码，若取 `0000`～`1110` 共 15 条三地址指令，剩下 `1111` 作为扩展标志，再用下一个 4 位扩展出 16 条二地址……手算一遍常见的考法：4 位基本码中留 1 个扩展窗口、每条扩展指令再占 4 位，若最终要求三地址 12 条、二地址 180 条、一地址若干，就要验算二地址是否放得下：15−12=3 个扩展窗口 ×16=48 个二地址码点，远不够 180，说明必须重新分配基本码长度。这类题的**致命陷阱**是算出条数后忘了校验“扩展窗口是否被上一级用完”，以及忘了零地址指令必须留出全 1 的译码出口。

数据在存储器里怎么摆，是第二个坑。**大端**把最高有效字节放在低地址，**小端**反之。存 `0x12345678` 到地址 100 起：大端是 `12 34 56 78`，小端是 `78 56 34 12`。这个差别只在按字节访问又按字解释时才暴露——若从 100 号单元读一个字节，大端得 `0x12`，小端得 `0x78`。**对齐**则规定：宽度为 $k$ 字节的数据，其起始地址必须是 $k$ 的整数倍。不对齐会怎样？若总线一次只能传一个对齐的字，跨边界访问就要拆成两次总线事务，甚至硬件直接抛异常。所以编译器会在结构体里插入填充字节：`struct{char a; int b;}` 在 4 字节对齐下占 8 字节而不是 5 字节。

寻址方式是这一章真正的主线，关键区分点是**有效地址怎么算、访存几次**。立即数寻址操作数就在指令里，访存 0 次；直接寻址地址码就是有效地址 EA，访存 1 次取操作数；间接寻址地址码指向的单元里存的才是 EA，访存 2 次；寄存器寻址操作数在寄存器里，访存 0 次；寄存器间接是寄存器里存 EA，访存 1 次；基址寻址 $EA=(BR)+A$，BR 由操作系统设定、面向系统；变址寻址 $EA=(IX)+A$，IX 由用户改变、面向用户，典型用途是数组遍历；相对寻址 $EA=(PC)+A$，A 是补码位移量，用于转移指令，**注意 PC 已自增到下一指令地址**；堆栈寻址隐含用 SP，进栈先减后存或先存后减取决于栈的生长方向。常见考法就是给一段指令序列问“某条指令的有效地址是多少、取操作数访存几次”。

把这些落到机器级表示上：`int x = a[i]` 编译出来大致是取 `i` 左移 2 位加基址得地址，再 `load`。`if` 编译成条件转移加无条件转移；循环编译成“判断—循环体—回跳”的骨架；过程调用是这一章的综合题——`call` 把返回地址压栈并跳转，被调过程先 `push` 旧 `bp`、`mov bp,sp` 建立栈帧，再在栈上分配局部变量，返回时 `leave; ret` 恢复。栈帧里从高地址到低地址依次是：实参、返回地址、旧 `bp`、局部变量。**缓冲区溢出**正是钻了这个结构：局部数组写在栈上，若 `strcpy` 不做长度检查，超长输入会覆盖旧 `bp` 和返回地址，`ret` 时跳向攻击者指定的地址。这是“数据被当作控制流”的经典失效。

最后是 CISC 与 RISC 的设计哲学对立：CISC 指令多、变长、寻址方式丰富、靠微程序控制，一条指令干很多事，代价是控制器复杂、难以流水；RISC 指令少而规整、定长、只有 load/store 访存、硬布线控制、寄存器多，代价是指令条数变多、对编译器要求高。权衡的落点是 CPI 与指令数的乘积：RISC 指令数多但 CPI 接近 1，CISC 指令数少但 CPI 可能是 4～10。这个“指令数 × CPI”的框架，正好是下一章 CPU 要拿来算性能和画数据通路的入口。

### CO-05 中央处理器

有了指令格式和寻址方式，接下来的问题是：这些动作由哪些部件、在哪些节拍里完成。CPU 的骨架是运算器加控制器，但考试真正要看的是寄存器组的分工：PC 存下一条指令地址，取指后自增；MAR 连地址总线，决定访问哪个单元；MDR 连数据总线，暂存放进或取出的数据；IR 存当前指令，其操作码送译码器、地址码送地址形成部件；PSW 存标志位，是条件转移的依据。**一条铁律**：CPU 与主存之间唯一的信息通路是 MAR 和 MDR，任何“从主存取指令”的微操作都必须经过 MDR 进 IR。

指令执行分四个工作周期：取指、间址、执行、中断。取指周期的微操作序列是固定的：`PC→MAR`，`M(MAR)→MDR`，`MDR→IR`，`(PC)+1→PC`。若指令采用间接寻址，进入间址周期：`IR(Ad)→MAR`，`M(MAR)→MDR`，`MDR→IR(Ad)`，把形式地址换成有效地址。执行周期随指令而异，比如加法要 `Ad(IR)→MAR`、读操作数到 MDR、再送 ALU 与 ACC 相加。中断周期则要保存断点：`(SP)-1→SP`、`PC→M(MDR)`、`向量地址→PC`。常见考法是给一条指令问“取指周期有哪几个微操作、哪些是公用的”。

数据通路的组织决定微操作的写法。单总线结构下，任何一次传送都要占用总线一个节拍，`R1→R2` 和 `R3→R4` 不能并行，所以一条加法要拆成“取操作数—送 ALU—存结果”多个时钟；多总线结构可以一个节拍内完成“两读一写”，CPI 直接下降。控制信号正是从微操作反推出来的：`PCout`、`MARin`、`MemR`、`MDRout`、`IRin` 一组信号对应一个节拍。**陷阱**在于总线上同一时刻只能有一个输出端有效，写出微操作时必须检查“源唯一”。

控制器有两种实现。硬布线控制器用组合逻辑直接由指令码和节拍产生控制信号，速度快但一旦指令系统改了就得重新设计电路。微程序控制器把每条机器指令编成一段微程序，存放在控制存储器 CM 里，执行时逐条取出微指令。微指令格式分水平型（一次能并行发出多个控制信号，微指令长、微程序短）和垂直型（一条微指令只控制少数部件，需要更多微指令）。**编码方式**考得最细：直接编码不压缩、速度最快；字段直接编码把互斥的微命令分在同一字段内，用译码器还原，留出一个码点表示“不操作”；字段间接编码再省位数但更慢。**微地址形成**决定下一条微指令在哪：计数器方式靠 $\mu PC+1$ 顺序执行；断定方式由微指令的下地址字段直接给出；两者结合时，操作码经微地址形成部件产生入口地址。致命错误是把“微程序入口地址”和“指令的地址码”混为一谈。

异常与中断是控制流的另一条线。内中断来自 CPU 内部（除零、溢出、缺页、非法指令），外中断来自外部设备（I/O 完成、时钟）。响应时机不同：内中断在指令执行过程中检测到就立即处理，外中断要等当前指令执行完、在下一条指令开始前检查中断请求。优先级上，内中断高于外中断，硬件故障高于软件中断。**中断隐指令**指响应中断时由硬件自动完成、不由程序编写的那段操作——关中断、保存断点 PC、引出中断服务程序。断点是 PC，现场是通用寄存器和 PSW，两者都要保存，少了 PSW 条件转移就会出错。

到这里，串行执行已经讲通。要提速就得流水。流水线把一条指令拆成取指 IF、译码 ID、执行 EX、访存 MEM、写回 WB 五段，理想情况下每个时钟周期流出一条指令，$k$ 段流水线执行 $n$ 条指令的时间是 $(k+n-1)\Delta t$，吞吐率 $TP=n/[(k+n-1)\Delta t]$，加速比 $S=k n/(k+n-1)$，当 $n\to\infty$ 时趋近 $k$。但有三类冒险在拆台：**结构冒险**是同一部件被两条指令同时要（如取指和访存争存储器），靠分离指令/数据 Cache 解决；**数据冒险**是后一条指令要用前一条还没写回的结果，靠转发（旁路）把 EX 段结果直接送下一指令的 ALU 输入解决，转发解决不了 load-use 就插入一个停顿气泡；**控制冒险**是转移指令改变 PC、后面的指令取错，靠分支预测、延迟槽或提前在 ID 段算出转移目标缓解。常见计算题是给定指令序列，判断需要几次停顿、插几个气泡、总周期数是多少。超标量再往上走一层，一个周期发射多条指令，靠同时取多条并做指令级并行调度，本质是把 $TP$ 的分母继续压小。


### CO-06 总线

上一块把 CPU 内部的数据通路、控制器、流水线拆到了寄存器一级，但 CPU 不是孤岛：它要取指令、要读写主存、要和外设交换数据。这些部件之间怎么连？最朴素的想法是两两连线，$N$ 个部件需要 $N(N-1)/2$ 条链路，$N=10$ 就是 45 条，引脚和布线都受不了，而且新增一个部件要改所有既有连接。总线就是把这件事反过来做：所有部件挂到同一组共享导线上，任意时刻只有一对部件在通信。共享带来了所有后续规则——因为共享，所以同时只能有一个主设备发号施令，这就必须有**仲裁**；因为共享，信号的传播延迟和各个设备的速度差异必须被统一约定，这就必须有**定时**；因为共享，单位时间能搬多少数据就由“一次搬几位”和“每秒搬几次”共同决定，这就是**带宽**。

带宽的算法必须吃透。若总线宽度为 $W$ 位、每个时钟周期完成一次数据传送、时钟频率 $f_{clk}$，则

$$B = \frac{W}{8}\times f_{clk}$$

单位是字节/秒。这里最容易错的是“每个时钟周期一次”这个前提：如果每个总线周期占 2 个时钟，数据传输次数就变成 $f_{clk}/2$；如果时钟双沿都传，就是 $2f_{clk}$。举个手算：宽度 32 位、时钟 100 MHz、每 2 个时钟周期传一次，则 $B = 4\text{B}\times 50\times10^6 = 200\text{ MB/s}$；把“2 个周期一次”漏掉就会算成 400 MB/s，整整差一倍。

宽度定下来之后，一次总线事务里地址和数据是分开占时间的。假设 32 位地址占 1 个时钟、32 位数据占 1 个时钟，传 8 个字需要 $8\times2=16$ 个时钟，有效数据只占一半时间。**突发传输**就是针对这个浪费：只发一次首地址，后续字地址隐含递增，8 个字变成 $1+8=9$ 个时钟，总线利用率从 $8/16=50\%$ 提到 $8/9\approx 89\%$。这就是为什么磁盘、显卡这类成块传输的设备都希望总线支持突发。

仲裁解决“谁能当主设备”。链式查询只用请求、允许、忙三根线，代价是优先级由物理位置决定，离控制器近的永远优先，且中间一个设备坏了后面全哑；计数器定时查询用 $\lceil\log_2 N\rceil$ 根设备线，可以轮转，公平性好；独立请求每个设备一对请求/允许线，响应最快、最灵活，但线数 $2N$ 且控制器复杂。三者的取舍就是“线数—速度—公平性”的三角。

定时分同步与异步。同步定时所有设备按统一时钟采样，协议简单、速度快，但总线周期必须按最慢的设备来定，快速设备被拖累，而且时钟偏移在长总线上会吃掉时间余量。异步定时用请求/应答握手，不互锁是双方各管各的撤销，半互锁是请求方收到应答才撤请求、应答方撤应答不等对方，全互锁是应答方也要等请求撤销才撤应答——可靠性递增，握手延迟也递增。

致命陷阱有两个。一是带宽计算的单位链条：宽度是“位”，带宽常要“字节/秒”，$W/8$ 这一步漏掉，答案差 8 倍；频率给的是 MHz，要乘 $10^6$，不是 $10^3$。二是同步定时里“总线周期由最慢设备决定”，常见考法是给几个不同速度的设备问能不能都接同一条同步总线——能接，但周期被最慢的拖死，性能瓶颈就在这里。

### CO-07 输入/输出系统

总线把“怎么连、什么时候采样”解决了，但它没回答两个问题：CPU 怎么知道外设准备好了？一次传送由谁发起、传多少？这就是 I/O 系统要管的。I/O 的本质矛盾是速度不匹配——CPU 是纳秒级，键盘是人的手速，磁盘是毫秒级。三种 I/O 方式其实是同一个思路的三个档位：CPU 的介入粒度从“每个字节都亲自盯着”逐步退到“只在一头一尾出现”。

先说 CPU 怎么摸到设备。接口里有三类寄存器：数据缓冲寄存器、状态寄存器、控制寄存器，统称 I/O 端口。端口编址有两条路：**统一编址**把它映射进内存地址空间，用普通的 load/store 就能访问，指令集不用加新指令，代价是占掉一部分地址空间、且地址译码要区分是内存还是端口；**独立编址**给端口单独的地址空间，必须用专门的 IN/OUT 指令，需要额外的控制信号线，好处是不占内存空间、程序一眼能看出这是 I/O。常见考法是给一段汇编问用的是哪种编址——看见 IN/OUT 就是独立编址。

外设这一块抓三个计算。键盘用行扫描法逐行拉低、读列线，配合消抖（软件延时或硬件滤波），按键的 ASCII 码送进键盘缓冲器并产生中断。显示器算显存容量：

$$1024\times768\times24\text{ bit} \div 8 = 2.25\text{ MB}$$

颜色深度、分辨率、刷新率三个量里任给两个常考第三个。磁盘沿用 CO-0304 的结论：平均存取时间 = 平均寻道时间 + 平均旋转延迟（半圈）+ 传输时间，这里不重复推导。

三种 I/O 方式用手算对比最清楚。设从磁盘读 4 MB 到内存，中断方式每次中断传 4 字节，需要 $4\text{MB}/4\text{B}=10^6$ 次中断，每次中断的响应、保护现场、服务、恢复按 100 个时钟周期算，共 $10^8$ 个周期，在 500 MHz 的 CPU 上是 0.2 秒——这 0.2 秒 CPU 基本被 I/O 吃光。换成 DMA：CPU 只在开始填 DMA 控制器的内存起始地址、传送字数、方向、设备号，传完后 DMA 发一次中断，全程 CPU 开销是几百个周期量级。差距三个数量级，原因不是 DMA“更快”，而是 CPU 介入的次数从 $10^6$ 次降到 1 次。程序查询更糟，CPU 在状态寄存器上死等，等待期间什么都干不了；中断方式至少设备准备数据的那段时间 CPU 可以跑别的进程，只有传送那一下被打断。

DMA 与中断的优先级是必考的一句：DMA 请求优先于中断请求。理由是 DMA 面对的是磁盘这种流式设备，数据来了不取就丢，而中断是程序级的，晚几个周期响应只是延迟，不会丢数据；而且 DMA 是周期挪用，只偷一个总线周期，本身就很短。

致命陷阱有三处。其一，以为中断方式下 CPU 全程被占用——错，设备准备数据期间 CPU 是自由的，被占用的只是传送和现场保护那几十上百个周期。其二，以为 DMA 完全不需要 CPU——错，初始化参数和结束处理都要 CPU，DMA 省的是“每个字的搬运”，不是“整件事”。其三，把 CPU 开销的度量对象搞反：中断方式的开销正比于传送的字（字节）数，DMA 方式的开销正比于传送的块数，题目一旦把块大小从 4 字节改成 512 字节，中断的账要重算，DMA 的账基本不动。


## 第三部分 · 口语版（最难的点讲透）

### 难点：补码不是“取反加一”，是模 $2^n$ 的同余

上一块讲字长时说“字长决定机器一次能处理多少位”，但没说负数怎么办。照搬原码，$+0$ 和 $-0$ 是两个编码，做加法前硬件得先判符号、再决定加还是减，等于造两套电路。补码的动机就是把减法从硬件里删掉。

类比是时钟：3 点要拨到 1 点，逆拨 2 格和顺拨 10 格结果一样，因为表盘一共 12 格，$10\equiv-2\pmod{12}$。表盘格数就是“模”。

最小例子：8 位补码，模 $2^8=256$。$-5$ 的编码是 $256-5=251=(11111011)_2$，算 $7+(-5)$：

$$(00000111)_2+(11111011)_2=(1\,00000010)_2$$

8 位截断得 $(00000010)_2=2$，最高位进位被扔掉——这是模运算的必然。范围因此是 $[-2^{n-1},\,2^{n-1}-1]$，负数多一个，因为 $(100\cdots0)_2$ 这个“$-0$”被征用去表示 $-2^{n-1}$，8 位就是 $-128\sim+127$。移码是补码符号位取反，数值上等于 $x+2^{n-1}$，于是成了无符号序，比大小直接按无符号比——浮点阶码用它，就为对阶时一条无符号比较指令搞定。

常见误解是拿“取反加一”去算 $-128$：8 位原码表示不出 $-128$（原码只到 $-127$），$(10000000)_2$ 是规定出来的、不是算出来的。另一个错是求相反数时只对数值位取反加一、符号位不动，那就退回原码了，必须全位取反加一。还有 $127+1=(10000000)_2=-128$ 看着“自洽”，其实是溢出，判据是最高位进位与次高位进位异或为 1。

一句话带走：补码是一次模 $2^n$ 的同余变换，减法被改写成加法，最高位的进位丢掉是设计的一部分。

### 难点：海明码把校验位放在 $2^k$ 的位置上

补码保证了机器内部算得对，可数据躺在存储器里、跑在总线上会翻位。奇偶校验只能发现奇数个错、还定位不了，海明码要的是“发现并纠正一位错”。

类比：一队人按 1、2、3……编号，让编号是 1、2、4、8 的人当组长，组长只检查组员。任何一个人出错，都恰好让某几个组长同时报警，报警组长的编号之和就是出错那位的编号。

最小例子：4 位数据 $D_1D_2D_3D_4$，校验位数 $k$ 满足 $2^k\ge n+k+1$，取 $k=3$（$8\ge 4+3+1$），总长 7。校验位占第 1、2、4 位，排列为 $P_1P_2D_1P_3D_2D_3D_4$，分组按位置编号的二进制：

$$G_1=P_1\oplus D_1\oplus D_2\oplus D_4,\quad G_2=P_2\oplus D_1\oplus D_3\oplus D_4,\quad G_3=P_3\oplus D_2\oplus D_3\oplus D_4$$

即 $G_1$ 管 1,3,5,7 位，$G_2$ 管 2,3,6,7 位，$G_3$ 管 4,5,6,7 位。接收方算 $G_3G_2G_1$，全 0 无错，否则十进制值就是出错位号，把该位取反即可。

常见误解有两个方向。一是把校验位顺手排到数据末尾，位置一错，$G_3G_2G_1$ 指出的位号全乱——放在 $2^k$ 位是为了让“位置编号 = 参与它的校验位编号之和”成立。二是以为海明码能纠两位错：不加全校验位时两位错算出的校验子会被误判成一位错，越纠越错；要 SEC-DED 必须再加一位对全体做偶校验。

一句话带走：海明码的本质是给每一位编一个二进制地址，每个校验位负责地址中某一位为 1 的所有位置。

### 难点：DRAM 的位扩展、字扩展与地址范围

数据放得住、错了能纠，可一片芯片装不下整个内存。上一块说字长决定宽度，内存条正是靠拼芯片拼出这个宽度和容量。

类比：位扩展是一页书由几个人同时抄，每人抄一列，必须同时开工；字扩展是每人分一段书架，各管各的。

最小例子：用 $1\text{M}\times4$ 位芯片拼 $2\text{M}\times8$ 位存储器。位扩展 $8/4=2$ 片并联，两片共用地址线和同一个片选，数据线各接高低 4 位；字扩展 $2\text{M}/1\text{M}=2$ 组，共 $2\times2=4$ 片。地址线：$1\text{M}=2^{20}$，片内地址 $A_0\sim A_{19}$；两组用 1 根 $A_{20}$ 经 $1:2$ 译码得 $\overline{CS_0}$、$\overline{CS_1}$，每条片选线同时接到一组的两片上。$A_{20}=0$ 那组占 $00000\text{H}\sim0FFFFF\text{H}$，$A_{20}=1$ 那组占 $100000\text{H}\sim1FFFFF\text{H}$。

常见误解：字扩展时按“片”给片选，忘了位扩展的两片必须同时选中，结果读出来高 4 位永远是旧的；把“$1\text{M}\times4$”的 1M 当总容量，其实它是 $2^{20}$ 个单元、每单元 4 位，地址线 20 根、数据线 4 根；算地址范围时没核对编址单位，两片拼成 8 位正好一字节，20 根地址刚好覆盖 1MB；以及忽略 DRAM 行列地址复用（RAS/CAS 分两次送），把复用前的根数当引脚数。顺带把刷新算清：$128\times128$ 阵列按行刷 128 次，$2\text{ms}$ 刷新周期下，集中刷新要连续占用 128 个存取周期形成死区，分散刷新摊进每个存取周期无死区但周期变长，异步刷新按 $2\text{ms}/128\approx15.6\,\mu s$ 的间隔刷一行，死区最小。

一句话带走：位扩展拼数据线、字扩展拼地址空间，组内的片必须同时被选中，高位地址译码既决定“选哪组”也决定地址范围。

### 难点：数据对齐

存储按字节编址，可 CPU 一次搬的是一个字。一个 4 字节数若横跨两个存储字，取一次数就要访存两次再拼装；对齐就是花几个字节买“一次访存搞定”。

类比：车位画好了，车必须停进一个位里，跨两个位就得多交一份钱、多挪一次车。

最小例子：32 位机器、按 4 字节边界对齐，结构体 `{char a; int b; short c;}`。`a` 在偏移 0 占 1 字节；`b` 起始地址必须是 4 的倍数，偏移 1~3 是填充，`b` 占 4~7；`c` 按 2 对齐占 8~9；总大小按最大成员 4 补齐，得 12 而不是 10 或 7。换成 `{char a; short c; int b;}` 则是 $1+1\text{ 填充}+2+4=8$ 字节，调整成员顺序就省下三分之一。

常见误解：以为对齐改变了数据的值——值一点没变，变的只是它落在哪个地址上；以为结构体大小就是成员大小之和，忘了尾部填充；把对齐和大端小端混为一谈，端序管的是一个多字节数内部字节的排布，对齐管的是起始地址，两回事；最后一处常被漏掉——指令也要对齐，指令字长 32 位时 PC 每次 $+4$，跳到非 4 倍数地址就是取指异常。

一句话带走：对齐规则只有两条，每个成员的起始地址是自身大小的整数倍，结构体总大小是最大成员大小的整数倍。


### 难点：取指周期的微操作序列——一条指令到底怎么“走”进 CPU

先想清楚一个问题：控制器凭什么能自动运行？因为一条指令的执行被拆成了若干个在时间上不可再分的基本动作，也就是微操作；每个微操作都由一个控制信号驱动。既然如此，**取指这件事必须对所有指令都成立**，因此它只能是公用的、固定不变的一段微操作序列。如果不同指令的取指方式不一样，控制器就无法建立一个统一的入口，也就无从“自动”。

生活类比：取指就像你去快递柜取件。不管这个包裹是书还是鞋（指令内容），动作序列完全一样：走到柜子前（把 PC 送进 MAR）→ 柜子系统读地址（译码选中存储单元）→ 柜门弹开、包裹滑出来（存储器把内容送到 MDR）→ 你拿走包裹，同时记住下一个柜号（PC+1）。**取件动作与包裹内容无关**——这正是取指周期被设计成公共序列的原因。

最小例子，按单总线结构走一遍（假设指令长 1 字，PC 初值 = 200）：

| 节拍 | 微操作 | 有效控制信号 |
|---|---|---|
| T0 | `PC → MAR` | PCout, MARin |
| T1 | `M(MAR) → MDR`，`PC+1 → PC` | MemR, MDRinE, PCinc |
| T2 | `MDR → IR` | MDRout, IRin |
| T3 | `OP(IR) → 控制单元`，译码 | — |

关键是 T1 那一拍把“读存储器”和“PC 加一”并行做掉，因为二者互不依赖；单总线结构下 MAR 和 PC 的写口不冲突，所以能合成一拍。若换成**多总线**，`PC→MAR` 与 `M(MAR)→MDR` 甚至能进一步压缩节拍数——多总线省的是节拍，并不是指令条数。取指结束后 IR 里是 200 号单元的指令，PC 已经指向 201，间址周期和执行周期都从这个状态出发。

常见误解有两个。其一，认为“PC 加一是在执行周期做的”——不对，必须在取指周期完成，否则遇到转移指令时，偏移量基准就算错了。其二，把 `M(MAR)→MDR` 写成 `M(MAR)→IR`。存储器数据线只能通到 MDR，IR 是 CPU 内部寄存器，**MDR 是存储器与 CPU 之间唯一的缓冲口**，这个“必经之路”是后面所有数据通路的骨架。

一句话带走：取指周期是一段与指令无关的固定微操作序列，`PC→MAR→MDR→IR` 这条链和 `PC+1` 并行完成，是所有指令共同的起跑线。

### 难点：中断周期与 PSW 的隐藏作用——断点到底存在哪

执行周期结束，一条指令本该“功成身退”，为什么还要多出一个中断周期？因为 I/O 设备、时钟、故障都是**异步**的，它们随时可能举手。如果 CPU 不设一个统一的“检查点”，而是在指令执行中途响应，那么现场就彻底碎了：寄存器值一半是旧指令的，一半是新指令的。所以硬件规定：**中断只在一条指令执行完之后采样**，这个采样点就是中断周期。没有它，程序就无法被打断后又正确地接回去。

生活类比：你在写作业，写到第 3 题的一半时电话响了。理智的做法不是立刻停笔，而是把这道题写完、记下“下次从第 4 题开始”（保存断点），再把书签夹好（保存 PSW），然后才去接电话。中断周期就是硬件替你做的“写完这题、夹书签”这一套。

最小例子：设当前指令地址为 200，已执行完，PC = 201（指向下一条），PSW 中进位位 C = 1、中断允许位 E = 1。中断周期微操作：

1. `SP-1 → SP`，`SP → MAR`（在栈上腾位置）
2. `PC → MDR`，`MDR → M(MAR)`，写存储器（**存断点 201**）
3. `PSW → MDR`，`MDR → M(MAR)`（存 PSW，含 C=1）
4. `向量地址 → PC`（PC 装入中断服务程序入口，比如 5000）
5. `0 → E`（关中断，防止嵌套）

注意断点存的是 **201 而不是 200**——存的是“下一条要执行的指令”，这样才能“接着往下走”。恢复时执行中断返回指令，从栈顶弹出 PSW 和 201 送回 PC 与 PSW，E 重新置 1。

常见误解：以为 PSW 只是“存放运算结果标志位的寄存器，供条件转移用”。在中断语境下，PSW 是**现场的一部分**：C、Z、O、S 这些标志若不在中断时压栈，服务程序里哪怕一条加法就会把原程序的标志冲掉，返回后条件转移就判错了。所以你会在很多设计题里看到“保存现场”必须包含 PSW。另一个误解是认为“关中断就是把所有中断都屏蔽”——关的只是**可屏蔽中断**，不可屏蔽中断（如电源故障）照样能打断。

一句话带走：中断周期是硬件强制的同步检查点，它把 PC（下一条）和 PSW 一起压栈保存，然后装入向量地址并关中断，这四件事的顺序不能颠倒。

### 难点：总线带宽与突发传输——“一次传多少”决定性能上限

为什么要有总线？因为如果每个部件都两两连线，n 个部件要 O(n²) 根线，成本不可接受；总线是用一组共享线换来了结构的规整。但共享必然带来争用，于是“一段时间内只能有一个主设备使用总线”成了铁律。这就引出核心问题：总线到底能跑多快，瓶颈在哪里。

生活类比：总线像一条高速公路，总线宽度是车道数，时钟频率是限速，一个总线周期是一次放行。**突发传输**就是“一次放行、连续通过一列车队”——领头的车报一次地址，后面的车按序跟上，不用每辆都停下来重新报地址。省的是地址传输和仲裁的时间，而不是数据本身。

最小例子：某同步总线宽度 32 位（4 B），时钟频率 100 MHz，每个总线周期含 1 个地址节拍 + 1 个数据节拍，问带宽。

不突发时，传 4 B 需要 2 个时钟：$T=2/100\text{M}=20\text{ ns}$，带宽 $=4\text{ B}/20\text{ ns}=200\text{ MB/s}$。

若采用突发传输，一次地址节拍后连续传 4 个数据节拍，共 5 拍传 16 B：$T=5/100\text{M}=50\text{ ns}$，带宽 $=16/50\text{ ns}=320\text{ MB/s}$。地址开销被摊薄，提升 60%。突发长度越长，带宽越趋近理论峰值 $4\text{ B}\times100\text{M}=400\text{ MB/s}$，但永远到不了——第一个地址节拍一定存在。

真正要记住的公式只有一条：**带宽 = 总线宽度（字节）× 总线频率 ÷ 每个总线周期所需时钟数**。常见考法就是给你宽度、频率、周期数求带宽，或者反过来问“要提高带宽有哪几条路”。

常见误解：以为“总线频率翻倍，带宽就翻倍”。若每个总线周期含固定个数的等待节拍（比如存储器跟不上插入 wait），频率上去了但等待节拍数不变，有效带宽远达不到线性增长——这正是**总线瓶颈**的现实版本：CPU 再快，数据供不上就是空转。另一个误解是把总线宽度和“地址线根数”混为一谈，宽度指数据线，决定一次能传几位，地址线根数决定寻址空间，两者独立。

一句话带走：带宽 = 宽度 × 频率 ÷ 每周期节拍数，突发传输靠摊薄地址开销逼近峰值，而总线周期里的等待节拍是性能永远的漏水口。

### 难点：I/O 端口编址与接口寄存器——CPU 怎么“看见”一个设备

I/O 设备的速度比 CPU 慢几个数量级，且形态各异，CPU 不可能为每个设备定制一套指令。所以需要一个**接口**做翻译：把 CPU 的总线周期翻译成设备能懂的控制动作，同时用寄存器把“快”和“慢”隔开。这就带来一个必须回答的问题：这些寄存器，CPU 用什么地址去访问？

生活类比：统一编址像“门牌号统一管理”——住宅和商铺用同一套编号，快递员（CPU）用同一套找门牌的方法就能送达，不需要学两套规则；独立编址则像“住宅区一套号、商业区另一套号”，找商铺得换一张地图和一套话术（专用 I/O 指令）。前者省指令、省译码，代价是占用了本可用于内存的地址空间。

最小例子：设内存地址空间 16 位（0~FFFFH），某接口有数据、状态、控制三个寄存器。若统一编址，给它们分配 FFF0H~FFF2H，则访问数据口就是一条普通的 `MOV R0, FFF0H`（读）或 `MOV FFF0H, R0`（写）——**用访存指令就能完成 I/O**，无需新指令。若独立编址，地址线可以是 8 位（0~FFH），用 `IN R0, 0F0H` / `OUT 0F0H, R0` 这类专用指令，并配一根 $\overline{\text{M/IO}}$ 信号线区分本次访问的是内存还是 I/O。

三个寄存器的分工必须分清：**数据寄存器**是数据缓冲区（比如键盘按下后字符暂存于此）；**状态寄存器**里有一位“忙/就绪”，CPU 反复读它来判断能不能传——这就是**程序查询方式**的本质，也是最原始的同步手段；**控制寄存器**接收 CPU 下发的命令（启动、允许中断、设置传输方向）。没有状态寄存器，CPU 就只能盲目地写数据，快慢不匹配立刻丢数据。

常见误解：以为“统一编址就是 I/O 端口和内存共用存储单元”。不是共用，是共用**地址空间与访问指令**，物理上仍是接口里的寄存器。另一个误解是把“接口”和“端口”混同：端口是接口里 CPU 可直接访问的那几个寄存器，接口还包括地址译码、状态逻辑、中断控制等 CPU 看不见的部分。还有一点常被忽略——独立编址下专用 I/O 指令通常只能做简单的数据搬运，功能弱于访存指令，这正是统一编址在 RISC 机器上流行的原因。

一句话带走：接口用数据/状态/控制三个寄存器把快慢隔开，统一编址让 I/O 借用访存指令和地址空间，独立编址则用专用指令加 M/IO 信号换取不占内存地址。

2. 能否比较链式、计数器、独立请求仲裁的线数、速度与公平性？
3. 能否用突发传输前后的时钟数算出总线利用率为何提升？
4. 能否说明同步定时为何被最慢设备拖累，并判断多设备能否共用？

### CO-07 输入/输出系统
1. 能否看 IN/OUT 判断独立编址，并说出统一编址占地址空间的代价？
2. 能否用中断次数乘每次开销，对比中断与 DMA 的 CPU 介入量？
3. 能否说明 DMA 请求优先于中断请求的理由，而非死记结论？
4. 能否指出中断方式只在传送时占用 CPU，而 DMA 仍需初始化与结束处理？
