# 408-CO-0506 指令流水线

> 章：CO-05 中央处理器　｜　档位：掌握　｜　真题落点：7 题：2016 #19；2017 #17；2018 #20；2019 #18；2020 #17；2023 #19；2024 #19

## 考法 1：给定 5 段流水线中的一段指令序列，判断冒险类型、数停顿拍

**题目一（2023#19，5 段流水线，I1 add s2,s1,s0 起的指令序列）**

**思路**：第一步画时空图，把每条指令的 IF/ID/EX/MEM/WB 排开；第二步只盯两个时刻——本条指令“读寄存器”在 ID 段末，前一条指令“写寄存器”在 WB 段末，看前者是否早于后者；第三步若早了，再判断这个值能否从 EX 段末或 MEM 段末提前转发过来，能转发就不停，转不过来才插气泡。

**坑**：一看到寄存器名相同就判“必须停 1 拍”。名字相同只说明可能有“写后读”，还要看两段错开了几拍、结果算出的时刻在哪个段末。另一个常见误判是：把“转发”和“停顿”当成互斥，认为发生了转发就一定不损失吞吐。

**题目二（变式）**：前一条是 load 指令，后一条立刻要用它装入的寄存器，问最少停几拍。

**思路**：第一步确认 load 的数据什么时候才有——在 MEM 段末才从存储器拿到，比 ALU 结果晚一整段；第二步看后一条指令需要该值的时刻（EX 段开始），两者一比较就知道差几拍、转发最多能挽回多少。

**坑**：把 load 和普通 add 一样对待，认为“反正都能转发，不用停”；或者反过来对所有相邻同寄存器指令都判 1 拍停顿。

**题目三（变式）**：指令序列中出现两条指令同时要用同一功能部件/同一端口，问是什么冒险。

**思路**：第一步分清三类冒险的判据——争同一个硬件资源是结构冒险，读写同一寄存器是数据冒险，分支转移改变 PC 是控制冒险；第二步再判断这件资源冲突能不能靠“重复设置部件”消除。

**坑**：看到两条指令挨着，条件反射答“数据冒险”，却没注意两条指令操作的是完全不同的寄存器，冲突只是共用了同一个 ALU 或同一次访存。

## 考法 2：转发与编译调度——给定冲突，问“能不能靠转发解决”

**题目一（变式）**：哪一类数据冒险即使有转发也必须停顿。

**思路**：第一步按“生产者把结果放在哪个段末”排序：ALU 结果在 EX 段末就有，load 结果要等 MEM 段末；第二步看消费者要用它的时刻是否早于该时刻，早就是“转发也来不及”。

**坑**：把“有转发机制”当作“所有数据冒险都消失”，于是认为任何情况下都不需要插气泡。

**题目二（变式）**：编译器和硬件分别用什么办法减少流水线停顿。

**思路**：第一步把手段分成两栏——硬件栏（转发、停顿、分支预测、延迟槽）与软件栏（指令重排、循环展开、调度填充分支延迟槽）；第二步看题干问的是“由谁完成”，别把软件手段记到硬件头上。

**坑**：把“编译器重排指令”当成硬件的乱序执行；或者把“插入 nop”当成唯一的停顿手段。

## 考法 3：控制冒险与分支预测

**题目一（变式）**：条件转移指令在流水线中造成多少拍损失，静态预测与动态预测分别怎么减小。

**思路**：第一步确定“转移结果在哪一段才知道”（通常在 EX 或 ID 段算出来），损失拍数等于它后面已取进流水线的指令条数；第二步按“预测失败要清空流水线”重新计算，动态预测靠历史记录提高命中率，命中时不损失。

**坑**：把“预测”当成“消除控制冒险”——预测错误时照样要清空，只是概率变小；也容易忽略“延迟转移/延迟槽”是把损失转嫁给编译器填充。

**题目二（变式）**：无条件转移、循环末尾的条件转移、调用返回三种情形，哪种最适合动态预测。

**思路**：第一步看历史规律性——循环分支有强烈的“连续跳、最后不跳”规律，适合用历史表预测；返回地址取决于调用点，适合用返回地址栈。

**坑**：把“分支预测”只理解成静态的“总猜跳/总猜不跳”，遇到“用历史信息”就反应不过来。

## 考法 4：加速比、吞吐率与超标量/超流水

**题目一（变式）**：$k$ 段流水线、各段 $\Delta t$，连续执行 $n$ 条指令，求实际吞吐率与加速比。

**思路**：第一步写总时间 $T=(k+n-1)\Delta t$，注意头尾的填满与排空；第二步套

$$TP=\frac{n}{(k+n-1)\Delta t},\qquad S=\frac{nk\Delta t}{(k+n-1)\Delta t}=\frac{nk}{k+n-1}$$

第三步看清题干问的是“实际吞吐率”还是“最大吞吐率”（后者为 $1/\Delta t$，只在 $n\to\infty$ 时逼近）。

**坑**：把总时间写成 $n\Delta t$，漏掉 $(k-1)\Delta t$；或者把加速比的分子分母写反。还有一个更隐蔽的坑：题目给的各段时间不相等时，直接套公式算，忘了流水线周期取最慢段，加速比会被最长段卡死。

**题目二（变式）**：比较超标量与超流水。

**思路**：第一步从“靠什么提高并行”入手——超标量是重复设置多个功能部件、一条流水线上每周期并发多条；超流水是把段再细分、每周期分时发射多次；第二步看题干强调的是“多条流水线/多套部件”还是“时钟更快、段更细”。

**坑**：把超标量理解成“一条流水线跑得更快”，于是仍按 $k$ 段去算加速比；其实超标量的 CPI 可以小于 1，衡量指标应换成每周期发射的指令数。

### 2016 #19 流水线数据冒险
在无转发机制的五段基本流水线中，下列指令序列存在数据冒险的指令对是（ ）。 I1: add R1, R2, R3; // (R2)+(R3)→R1 I2: add R5, R2, R4; // (R2)+(R4)→R5 I3: add R4, R5, R3; // (R5)+(R3)→R4 I4: add R5, R2, R6; // (R2)+(R6)→R5

A. I1 和 I2
B. I2 和 I3
C. I2 和 I4
D. I3 和 I4

**思路**：无转发时，前条指令的结果要到写回阶段才可被后条使用；逐对看后条是否在前条写回前就读取了前条要写的寄存器。

**坑**：只盯寄存器编号是否相同，把两条都读同一源寄存器误判成写后读冒险；或忽略中间相隔的时钟数，没看到后条读寄存器时前条结果尚未写回。

### 2017 #17 超标量流水线特性
下列关于超标量流水线特性的叙述中，正确的是（ ）。 Ⅰ. 能缩短流水线功能段的处理时间 Ⅱ. 能在一个时钟周期内同时发射多条指令 Ⅲ. 能结合动态调度技术提高指令执行并行性

A. 仅Ⅱ
B. 仅Ⅰ、Ⅲ
C. 仅Ⅱ、Ⅲ
D. Ⅰ、Ⅱ和Ⅲ

**思路**：超标量靠多条流水线或多个功能部件，在一个时钟周期同时发射多条指令；动态调度可发掘指令间并行。它不改变单个功能段自身的处理延迟。

**坑**：看到“流水线”就误认为能缩短每个流水段的处理时间；把“同时发射多条”误读成“提高主频或缩短时钟周期”。

### 2018 #20 流水线时钟周期
若某计算机最复杂指令的执行需要完成 5 个子功能，分别由功能部件 A~E 实现，各功能部件所需时间分别为 80ps、50ps、50ps、70ps 和 50ps，采用流水线方式执行指令，流水段寄存器延时为 20ps，则 CPU 时钟周期至少为（ ）。

A. 60ps
B. 70ps
C. 80ps
D. 100ps

**思路**：流水线时钟周期取最慢流水段时间，再叠加流水段寄存器延时，先找最大功能部件时间后加寄存器开销。

**坑**：只取最大部件时间 80ps 而漏加 20ps 寄存器延时；或误用平均时间、中间值。

### 2019 #18 五段流水数据冒险
在采用“取指、译码/取数、执行、访存、写回”5 段流水线的处理器中，执行如下指令序列，其中 s0、s1、s2、s3 和 t2 表示寄存器编号。 I1: add s2,s1,s0 // R[s2]←R[s1]+R[s0] I2: load s3,0(t2) // R[s3]←M[R[t2]+0] I3: add s2,s2,s3 // R[s2]←R[s2]+R[s3] I4: store s2,0(t2) // M[R[t2]+0]←R[s2] 下列指令对中，不存在数据冒险的是（ ）。

A. I1 和 I3
B. I2 和 I3
C. I2 和 I4
D. I3 和 I4

**思路**：按五段流水列出各指令读寄存器、写回寄存器的节拍，比较后条读取是否早于前条写回；再找寄存器依赖为空的指令对。

**坑**：看到两条指令共用 t2 就误判为数据相关；或只盯目的寄存器，忽略源寄存器的读写时刻和 load 的写回时机。

### 2020 #17 流水线CPI辨析
下列给出的处理器类型中理想情况下 CPI 为 1 的是（ ）。 I、单周期 CPU； II、多周期 CPU； III、基本流水线 CPU； IV、超标量流水线 CPU 流水线概念

A. I、II；
B. I、III;
C. II、IV;
D. III、IV.

**思路**：抓住 CPI 是平均每指令所需时钟周期数，再按各类处理器每周期能流出/完成多少指令判断；关键一步是区分理想基本流水线与可并发多指令的超标量。

**坑**：看到“流水线”就一律认为每周期一条指令，忽略超标量每周期可流出多条而 CPI 小于 1；也易把多周期误当成每周期完成一条。

### 2023 #19 流水线阻塞指令
5 段流水线，I1 add s2,s1,s0；I2 load s3,0(s2)；I3 beq t2,s3,L1；I4 addi t2,t2,20。采用转发 + 硬件阻塞，发生阻塞的指令是（ ）〔原卷有图〕

A. 仅 I3
B. 仅 I2、I4
C. 仅 I3、I4
D. 仅 I2、I3、I4

**要点**：load-use 冒险（I2→I3）转发也救不了，要停一拍；分支冒险靠硬件阻塞。

### 2024 #19 五段流水线的数据冒险
关于数据冒险处理，错误的是

A. 相邻指令操作数相关可能引起冒险
B. 插入气泡能避免冒险
C. 所有数据冒险都可通过转发解决
D. 所有数据冒险都能通过调整顺序和插 nop 解决

**思路**：`load` 之后紧跟使用其结果，数据要到 MEM 阶段末才出来，转发也来不及——必须停一拍。所以"所有都能靠转发解决"是错的。

**坑**：C 的"所有"是绝对化表述。load-use 冒险是转发解决不了的经典反例。
