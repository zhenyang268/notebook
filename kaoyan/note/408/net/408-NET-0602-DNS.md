# 408-NET-0602 DNS

> 章：NET-06 应用层　｜　档位：掌握　｜　真题落点：3 题：2016 #40；2018 #33；2020 #40

**在考什么**：区分递归与迭代的关键在于看清发起方是主机还是本地域名服务器，这一点判错就会导致报文数和 RTT 全盘对不上；常见错法是把本地域名服务器向上的查询也按递归计数，或漏算迭代过程多级串行的中间 RTT。

## 考法 1：域名空间的分层与四类域名服务器的职责划分

**思路**：第一步按“谁权威”排层：根只指路，只掌握顶级域服务器的地址；顶级域只管自己下一级的授权；只有权限域名服务器才对本区内的主机名给出权威回答。第二步把本地域名服务器单独拿出来看——它是替主机跑腿并带缓存的代理，不属于域名层次中的任何一级。数“最坏情况要问几台”时按 本地→根→顶级→权限 逐级数。

**坑**：把本地域名服务器当成层次结构中的一层，误以为它给出的回答一定权威；或者反过来以为根服务器“什么域名都知道”，实际上它只知道顶级域服务器在哪儿。

## 考法 2：递归查询与迭代查询的区分，以及查询报文数的计数

**思路**：第一步抓住唯一判据——被问的那台服务器有没有义务替你继续问下去。主机→本地通常是递归（我要最终结果，你负责跑完）；本地→根/顶级/权限通常是迭代（你给我下一跳的地址，我自己再去问）。第二步数报文：迭代时每一级都要本地再发一次请求并收一次响应；递归对主机而言只有一次请求一次响应，但被问方的负担重。

**坑**：只要看到“本地域名服务器发出的查询”就一律按递归计报文，忽略了它向上通常是迭代；或者在算时延时把迭代的多级串行当成一次往返，漏掉中间的若干次 RTT。

## 考法 3：缓存与 TTL 对查询路径和时延的影响

**思路**：第一步先判断这次查询命中的是缓存还是权威——缓存未过期时，直接跳过根与顶级，把结果原路返回，报文数与时延立刻降一个量级。第二步对“同一个域名短时间内查第二次”的计时，先假设本地缓存命中，只算主机与本地之间那一次往返；只有题干明说缓存已过期或从未查过，才走完整路径。

**坑**：忘记缓存也可能存在于主机侧（浏览器/解析器 stub），把第二次查询仍按完整迭代计；另一个坑是忽略 TTL 到期的条件，误认为缓存一旦建立就永久有效，从而把任意两次查询都判成命中。

## 考法 4：资源记录类型与“这次到底该查哪条记录”

**思路**：第一步由“我要的是 IP、是别名、还是邮件服务器”反推类型：名字→IPv4 用 A，名字→IPv6 用 AAAA，别名→规范名用 CNAME，域名→邮件服务器用 MX，反向解析用 PTR，区传送与授权用 NS/SOA。第二步看回答报文里哪条记录才真正给出了所求的值——如果拿到的是 CNAME 或 MX 的交换器名字，说明还差一次解析。

**坑**：把 MX 记录里给出的邮件服务器名字当成最终 IP，漏掉了还要再查一次 A 记录这一步；或者把 CNAME 指向的规范名误认为已经拿到地址；还有把 PTR 当成正向解析记录的。

### 2016 #40 DNS迭代查询次数
假设所有域名服务器均采用迭代查询方式进行域名解析。当 H4 访问规范域名为 www.abc.xyz.com 的网站时，域名服务器 201.1.1.1 在完成该域名解析过程中，可能发出 DNS 查询的最少和最多次数分别是（ ）。〔原卷附图，纯文本从略〕

A. 0，3
B. 1，3
C. 0，4
D. 1，4

**思路**：最少看本地域名服务器缓存中是否已有完整解析结果；最多则按迭代查询沿本地、根、顶级、权威逐级询问来计。

**坑**：把主机本机缓存和本地域名服务器缓存混淆，或把迭代查询误按递归查询的次数计算。

### 2018 #33 无连接应用层协议
下列 TCP/IP 应用层协议中，可以使用传输层无连接服务的是（ ）。

A. FTP
B. DNS
C. SMTP
D. HTTP

**思路**：先看各应用层协议对可靠性的要求，再判断其传输层通常使用连接还是无连接服务；关键一步是抓住“无连接”对应传输层 UDP 的典型使用场景。

**坑**：把 HTTP 的应用层短连接、无状态误判为传输层无连接；或受 DNS 也可用 TCP 的情况干扰而忽略其常见查询走 UDP。

### 2020 #40 DNS与HTTP时延
假设下图所示网络中的本地域名服务器只提供递归查询服务，其他域名的服务器均只提供迭代查询服务；局域网内主机访问 Internet 上各服务器的往返时间（RTT）均为 10ms，忽略其他各种时延，若主机 H 通过超链接 http://www.abc.com/index.html ，请求浏览纯文本 Web 页 index.html，则从点击 超链接开始到浏览器接收到 index.html 页面为止，所需最短、最长时间分别是： 路由器 本地域名服务器 局域网 H www.abc.com Internet com 顶级 域名服务器 根域名 服务器 abc.com 域名服务器〔原卷附图，纯文本从略〕

A. 10ms，40ms；
B. 10ms，50ms；
C. 20ms，40ms；
D. 20ms，50ms;

**思路**：分别考虑本地已有域名解析结果的最短情形，和需从本地域名服务器逐级迭代查询根、顶级、abc.com 域名服务器的最长情形，再叠加 TCP 建链与 HTTP 请求响应时延。

**坑**：把主机到本地域名服务器的查询也按每次 10ms 累加，或漏掉 TCP 建立连接、HTTP 响应，或把递归查询误算成主机逐级访问各级 DNS。
