# 408-NET-0603 FTP 与电子邮件

> 章：NET-06 应用层　｜　档位：掌握　｜　真题落点：2 题：2017 #40；2018 #40

## 考法 1：FTP 双连接的分工与端口

**思路**：第一步把两条连接拆开看：控制连接整个会话只保持一条，传的是命令与应答，服务器侧端口是 21；数据连接每传一个文件就新开一条，传完立即关闭，主动模式下服务器用 20 端口主动连客户端。第二步判断“这次是谁发起数据连接”：主动模式是服务器发起，被动模式是客户端发起。记住一句话——控制连接贯穿全程，数据连接随用随建。

**坑**：把“一条 TCP 连接既传命令又传文件”套到 FTP 上，直接与 HTTP 混同；把数据连接的端口写成 21；或者看到 FTP 有应答码就以为它跑在 UDP 上。

## 考法 2：带外控制与带内控制（FTP 对 HTTP）

**思路**：第一步只问一个问题——控制信息与数据走不走同一条连接：FTP 分开走，属于带外控制；HTTP 挤在同一条连接里，属于带内控制。第二步用这个结论解释现象：为什么 FTP 传一个大文件传到一半还能插进一条中止命令？因为控制连接一直空闲着。

**坑**：看到“FTP 也用 TCP、也可靠”就以为它和 HTTP 一样一问一答、彼此无状态；忽略了 FTP 在整个会话期间要记住登录用户与当前工作目录，是有状态的，从而把“断开数据连接”误判成“退出登录”。

## 考法 3：SMTP / POP3 / IMAP 的分工与方向

**思路**：第一步按“推还是拉”定位：SMTP 是推，把信从用户代理推到自己的发送服务器，再推到对方的接收服务器；POP3 与 IMAP 是拉，收信人从自己所在的服务器把信取下来。第二步据此排除错误搭配——POP3/IMAP 只管取，不能把信推到别人的服务器上去。

**坑**：把“用户代理→自己邮件服务器”这一段误判成 POP3 或 IMAP；或者以为 IMAP 和 POP3 一样，取完就把服务器上的邮件删掉，忽略了 IMAP 的默认行为是服务器端保留并同步邮箱文件夹，支持多端看到同一状态。

## 考法 4：MIME 补的是什么、补在哪一层

**思路**：第一步先回忆 SMTP 的先天限制：只认 7 位 ASCII 文本，二进制附件、非英语字符都过不去。第二步看 MIME 的位置：它是在 SMTP 之上对报文体的编码扩展，靠新增首部（内容类型、传输编码）加上 Base64 或 quoted-printable 编码，把任意内容伪装成 7 位 ASCII 再交给 SMTP 搬。它不改变 SMTP 的命令交互。

**坑**：把 MIME 当成一个独立的邮件传输协议，误以为它能替代 SMTP 直接投递；或者把 MIME 的作用说成“压缩”，而它实际做的是把任意字节编码成可打印的 ASCII 字符，既不追求压缩，也不保证长度变短。

### 2017 #40 FTP连接特性
下列关于 FTP 协议的叙述中，错误的是（ ）。

A. 数据连接在每次数据传输完毕后就关闭
B. 控制连接在整个会话期间保持打开状态
C. 服务器与客户端的 TCP 20 端口建立数据连接
D. 客户端与服务器的 TCP 21 端口建立控制连接

**思路**：抓住 FTP 的控制连接与数据连接生命周期不同：控制连接贯穿会话，数据连接按传输需要建立和关闭；再注意数据连接端口使用还受主动/被动模式影响。

**坑**：容易把 TCP 20 端口建立数据连接当成任何模式下都绝对固定，忽略被动模式由双方协商；也可能把控制连接误认为每次传文件都重建。

### 2018 #40 SMTP直接传输内容
无需转换即可由 SMTP 协议直接传输的内容是（ ）。

A. JPEG 图形
B. MPEG 视频
C. EXE 文件
D. ASCII 文本

**思路**：SMTP 最初只支持 7 位 ASCII 文本；二进制多媒体或可执行内容需要先经 MIME、Base64 等编码。关键一步是判断哪种内容本身就是 ASCII 文本。

**坑**：看到“文件”就以为 JPEG、MPEG、EXE 都能被 SMTP 原生直接传输；忽略二进制内容必须重新编码。
