# 408-NET-0404 分片与配套协议

> 章：NET-04 网络层　｜　档位：掌握　｜　真题落点：1 题：2021 #36

## 考法 1：给 MTU 与数据报总长，问分几片、每片多长、片偏移填几（2021#36）

**思路**：第一步不是拿总长除以 MTU，而是先求“一片最多能装多少数据”：$L_{\max}=\left\lfloor \dfrac{MTU-20}{8}\right\rfloor\times 8$。向下取整到 8 的倍数，是因为片偏移字段以 8 B 为计数单位。然后从原数据部分长度 $L-20$ 中按 $L_{\max}$ 逐片扣除：除最后一片外，其余各片都装满 $L_{\max}$，只有末片是余数。片偏移按“本片数据的第一个字节在原数据部分中的序号 ÷ 8”逐片递推，MF 位则是“除末片置 0 外全置 1”。总长字段每片都要再加 20 B 首部。

**坑**：看到题目给的总长比 MTU 大就直接相除，忘了每个分片都要各带 20 B 首部，属于重复计算。也容易把“算出的数据字节数”直接填进片偏移而不除以 8。还有一种：把末片的 MF 顺手写成 1，以为“还没传完、后面还有”。

## 考法 2：围绕 DF / MF / 片偏移三个字段的语义判断

**思路**：先把三个字段各自负责什么分开记：DF 管“能不能分”，MF 管“后面还有没有”，片偏移管“这一片位于原数据报的什么位置”。判断“能不能通过某段链路”时只盯一种组合：DF=1 且长度超过出接口 MTU。判断“是否已收全”时只盯 MF=0 的那片是否到达。还要记住重组只在目的主机做，中间路由器只分片、不重组。

**坑**：把 DF=0 误读成“禁止分片”；或看到某片 MF=0 就以为“这个数据报只有一片”，而它其实只表示“我是最后一片”。另外，在多段链路串联的题里，容易只在源端算一次分片，忘了每经过一段链路都要按该段 MTU 重新判断，可能二次分片。

## 考法 3：ARP 的广播请求 / 单播响应，以及“该解析谁的 MAC”

**思路**：第一步一定是先判断目的 IP 与本机是否同网段——用自己的子网掩码与运算，不看地址“长得像不像”。同网段就 ARP 解析目的主机 IP；不同网段就 ARP 解析默认网关 IP，因为帧必须交给网关。再记两条硬事实：请求是广播帧、响应是单播帧；ARP 缓存里存的是“IP—MAC”对，区别于交换机 MAC 表里的“MAC—端口”对。

**坑**：看到“主机要访问另一个网段的服务器”，就答“ARP 解析服务器的 MAC 地址”。也常把请求写成单播、把响应写成广播。还有把 ARP 归到网络层，它其实封装在以太网帧里、没有 IP 首部。

## 考法 4：DHCP 四个报文的方向与“为什么只能广播”

**思路**：按 Discover→Offer→Request→Ack 排好顺序。抓住一条主线：客户端此时还没有 IP，所以报文只能广播，源地址填 0。服务器回送时也常借广播送达，因为客户端还不可单播寻址。同时记住 DHCP 不只给 IP，还下发子网掩码、默认网关、DNS 服务器。

**坑**：把 Offer 和 Request 的发送方向弄反，以为服务器先“确认”；或以为只有“手工配置”和“静态路由”能给主机配默认网关，漏掉 DHCP 下发这条途径。

## 考法 5：ICMP 差错报文的“不该发”清单与 ping / traceroute 的分工

**思路**：先分清这条 ICMP 是差错报告还是询问报文，再套“不再出错”原则：对 ICMP 差错报文本身、对非首片的分片、对组播或广播地址、对非唯一源地址（如 0.0.0.0）都不再发差错报文。涉及工具时：ping 用回送请求/应答；traceroute 靠逐步加大 TTL，让沿途路由器 TTL 减到 0 时回超时报文。

**坑**：看到“分片丢失”就答“回送一个 ICMP 差错报文”，忘了非首片报错会被抑制。也容易把 traceroute 说成“由目的主机返回差错报文”，而回超时报文的其实是沿途每一跳路由器。
