# 408-NET-0501 服务与端口

> 章：NET-05 传输层　｜　档位：掌握　｜　真题落点：2 题：2018 #39；2021 #39

**在考什么**：把监听 socket 与 accept 返回的已连接 socket 混成一个，就会因 socket 少算而整题崩，而非"同一服务器同一端口只建一条连接"。

## 考法 1：给通信场景，问要建几条连接、几个 socket

**变形：一台主机上两个浏览器进程同时访问同一台 Web 服务器**

**思路**：第一步把 socket 写成四元组 $(\text{源IP},\text{源端口},\text{目的IP},\text{目的端口})$，再注意服务器侧的目的端口固定，能区分两条连接的只有客户端源端口。第二步抓住“一个四元组对应一条 TCP 连接、一对 socket”。

**坑**：看到“同一服务器、同一端口”就认定只建一条连接；服务器监听 socket 与 accept 返回的已连接 socket 混成一个，socket 数少算。

**变形：UDP 通信要不要先建连接、服务端要几个 socket**

**思路**：先判协议：UDP 无连接，发报文前无握手，服务端一个 socket 靠四元组区分来源。

**坑**：把 TCP 的“每条连接一个 socket”直接套到 UDP 上，以为每个客户端都要新建 socket。

## 考法 2：端口号与协议归属匹配

**变形：给一批应用层协议，判断谁用 UDP、对应哪个熟知端口**

**思路**：第一步按“要可靠还是要快”分两堆：文件传输、邮件、Web 走 TCP；DNS 查询、DHCP、TFTP、SNMP、RIP 走 UDP。第二步再落端口号，把 53、67/68、69、161 与 80、25、110、20/21、23 分开记。

**坑**：把 DNS 一律判成 UDP（域名解析查询走 UDP，区域传送走 TCP）；把 DHCP 的 67 与 68 在服务器端、客户端之间写反。

## 考法 3：无连接与面向连接的表述辨析

**变形：判断“UDP 提供无连接、不可靠、面向报文的传输”这类说法是否成立**

**思路**：把“是否建立连接、是否可靠、是字节流还是报文、有无拥塞控制、首部开销”列成两列表格，逐格对照 TCP 与 UDP。

**坑**：把“UDP 不保证按序到达”与“UDP 不保证数据完整性”混为一谈；看到“面向报文”就反推它可靠。

### 2018 #39 UDP分用依据
UDP 协议实现分用 (demultiplexing) 时所依据的头部字段是（ ）。

A. 源端口号
B. 目的端口号
C. 长度
D. 校验和

**思路**：传输层分用是接收方剥去首部后，把数据交给正确的应用进程；关键一步是找能标识“接收端应用进程”的字段，并区分源端字段用于回信、目的端字段用于交付。

**坑**：把源端口号误当成定位接收进程的字段；或把长度、校验和也当成进程交付依据。
