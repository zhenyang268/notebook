# 408-NET-0403 IPv4 地址与子网

> 章：NET-04 网络层　｜　档位：掌握　｜　真题落点：12 题：2016 #38、#39；2017 #36、#38；2018 #38；2019 #7、#37；2021 #35；2022 #35、#36；2023 #38、#39

**在考什么**：借位数目与借位位置一旦取错，后面的主机数和地址范围就都会错；最常见的错法是把“划分成 3 个子网”直接当作借 3 位，而忘了 2²=4 已够用。

## 考法 1：借位划分子网（2021#35）

**思路**：第一步把“要划分成几个子网”换算成“至少要借几位”：满足 $2^n \ge$ 子网数，并注意题目是否允许使用全 0、全 1 子网。借来的位插在原网络位之后，形成“网络号 + 子网号 + 主机号”。接着把每个子网的网络地址、可用主机范围、广播地址依次排出来，再回头看题目给定的地址或主机数落在哪个子网里。

**坑**：看到“划分成 3 个子网”就直接当作借 3 位，或忘了 $2^2=4$ 已够用，从而多借一位，把主机位挤掉，导致后面可用主机数全错。另一个误判是借位位置找错：借的是主机位的高位，不能加到网络号前面去。

## 考法 2：由 IP 与掩码求网络地址、广播地址、地址范围（2022#35、2023#39）

**思路**：第一步把掩码或前缀长度翻译成“网络位有多少位”，再把 IP 的相关字节展开成二进制，逐位与掩码对齐：网络地址等于 IP 与掩码按位与；广播地址是把网络地址的主机位全部置 1；可用地址范围是网络地址加 1 到广播地址减 1。前缀题先把 /20 一类换算成“前两个字节全为网络位，第三字节的高 4 位是网络位”。

**坑**：一道题（掩码落在字节中间）的坑在于：看到 183.80.72.48 这样的地址，就按字节切分网络位与主机位。掩码的网络位很可能结束在某个字节的内部，必须按位对齐，按字节算会把网络地址算错。另一道题（/20）的坑在于：看到 84 就把整个第三字节清零当作最小地址。/20 的分界在第三字节中间，第三字节的低 4 位属于主机位，最小地址要把这 4 位清零而不是整字节清零，最大地址同理不能把第三字节全置 1。

## 考法 3：主机地址配置与默认网关是否合法（2022#36）

**思路**：第一步按图算出主机所在子网的网络地址与广播地址，得到该子网的可用地址区间；然后逐条校验：主机 IP 是否落在区间内、掩码是否使各主机同处一个子网、默认网关是否也在同一子网内且不是网络地址或广播地址、有没有地址重复。核对时先算区间，再比网关。

**坑**：看到网关地址和某台主机 IP “长得很像”就判为合法。网关必须与本主机在同一子网内，且不能等于网络地址、广播地址或本机地址。另一个误判，是只看 IP 是否同段而忽略掩码：掩码写错时，两台看似相邻的主机其实不在同一子网。

## 考法 4：CIDR 路由聚合与最长前缀匹配

**思路**：第一步把待聚合的多个前缀写成二进制，从左往右数公共前缀的位数，得到聚合后的前缀长度；再检查聚合结果是否把不属于这些网络的空间也包含了进来。做转发判断题时，把目的地址与每个表项逐位与，凡匹配的候选中取前缀最长（最具体）的那条，默认路由 /0 只是最后兜底。

**坑**：看到“聚合后能覆盖所有条目”就收工，忽略了聚合结果顺带把别的网络也吞进来，说明公共前缀取得太短。最长前缀匹配时容易选“表里第一个能匹配的”，而不是“匹配且前缀最长”的那条。

## 考法 5：NAT 的转换表与地址改写（2023#38）

**思路**：第一步判断报文的走向：内网主机发往 Internet 时，NAT 路由器改写源 IP 与源端口，并在转换表中记下“私有地址与端口、公网地址与端口”的映射；回程报文按目的地址与目的端口查表换回私有地址。看清题目问的是报文在哪个位置、哪一个字段被改写。

**坑**：看到“改写 IP 地址”就以为只动 IP。NAPT 同时改写端口，靠端口区分同一个公网 IP 上的多条并发连接，漏掉端口就无法解释多台内网主机同时上网。另一个失分点，是私有地址范围记混，把 172.16.0.0/12 误写成 172.0.0.0/8 那一整段。

### 2016 #38 NAT后IP地址
假设连接 R1、R2 和 R3 之间的点对点链路使用 201.1.3.x/30 地址，当 H3 访问 Web 服务器 S 时，R2 转发出去的封装 HTTP 请求报文的 IP 分组的源 IP 地址和目的 IP 地址分别是（ ）。〔原卷附图，纯文本从略〕

A. 192.168.3.251，130.18.10.1
B. 192.168.3.251，201.1.3.9
C. 201.1.3.8，130.18.10.1
D. 201.1.3.10，130.18.10.1

**思路**：经过 NAT 后源地址应换成路由器外网接口地址，目的地址保持 Web 服务器公网地址；再从 /30 子网中排除网络地址、广播地址和已被占用地址。

**坑**：看到私网源地址就误以为原样保留，或把目的地址误判成下一跳路由器接口地址；/30 可用地址很少，容易把边界地址算进去。

### 2016 #39 子网与默认网关
假设 H1 与 H2 的默认网关和子网掩码均分别配置为 192.168.3.1 和 255.255.255.128，H3 与 H4 的默认网关和子网掩码均分别配置为 192.168.3.254 和 255.255.255.128，则下列现象中可能发生的是（ ）。〔原卷附图，纯文本从略〕

A. H1 不能与 H2 进行正常 IP 通信
B. H2 与 H4 均不能访问 Internet
C. H1 不能与 H3 进行正常 IP 通信
D. H3 不能与 H4 进行正常 IP 通信

**思路**：先用子网掩码划分各主机所在子网，同子网直通、跨子网须经默认网关；再核对默认网关地址是否属于本网段且对应正确路由器接口。

**坑**：只看 IP 地址前缀相近就判断能通，忽略默认网关配置错误；或把同网段通信和访问 Internet 混在一起判断。

### 2017 #36 特殊IP地址用途
下列 IP 地址中，只能作为 IP 分组的源 IP 地址但不能作为目的 IP 地址的是（ ）。

A. 0.0.0.0
B. 127.0.0.1
C. 200.10.10.3
D. 255.255.255.255

**思路**：逐个回忆特殊地址语义：本机源地址/默认路由占位、回环地址、普通单播地址、受限广播地址，重点区分“能否作为目的地址”。

**坑**：看到回环地址就误以为不能作目的地址；也可能把受限广播地址误判为只能作源地址。

### 2017 #38 等长子网地址数
若将网络 21.3.0.0/16 划分为 128 个规模相同的子网，则每个子网可分配的最大 IP 地址个数是（ ）。

A. 254
B. 256
C. 510
D. 512

**思路**：由 128 个等长子网确定为 2 的几次方，从原 16 位主机位中借出相应位数作子网号，剩余主机位数再算可用地址数，并扣除网络地址与广播地址。

**坑**：容易忘记扣除网络地址和广播地址而直接填 2 的主机位次方；也可能把 128 当成主机数来倒推借位。

### 2018 #38 路由表项聚合
某路由表中有转发接口相同的 4 条路由表项，其目的网络地址分别是 35.230.32.0/21、35.230.40.0/21、35.230.48.0/21 和 35.230.56.0/21，将该 4 条路由聚合后的目的网络地址为（ ）。

A. 35.230.0.0/19
B. 35.230.0.0/20
C. 35.230.32.0/19
D. 35.230.32.0/20

**思路**：路由聚合要保留各地址的公共前缀，再把公共前缀之后的位清零；关键一步是把第三段 32、40、48、56 写成二进制，比较它们最多有多少位相同，并据此缩短前缀长度。

**坑**：看到这些地址都落在 32～63 范围，就误判公共前缀只到 /20；或只拿首尾地址比较而忽略逐位求共同前缀。

### 2019 #7 变长子网最小块
若将 101.200.16.0/20 划分为 5 个子网，则可能的最小子网的可分配 IP 地址数是（ ）。

A. 126
B. 254
C. 510
D. 1022

**思路**：要让最小子网尽量小，就让其余子网尽量大，按变长划分依次取大块，最后对剩余地址块算可用主机数。

**坑**：看到“划分为 5 个子网”就平均分，或算主机数时忘记扣除网络地址和广播地址。

### 2019 #37 变长子网最小子网
若将 101.200.16.0/20 划分为 5 个子网，则可能的最小子网的可分配 IP 地址数是（ ）。

A. 126
B. 254
C. 510
D. 1022

**思路**：变长子网划分要让其中一个子网尽可能小，就要让其余子网尽可能大；从 /20 剩余地址块中依次切出尽可能大的块，逐步增加子网号位数，最后剩到最小的 /24 块；可分配数还要扣除网络地址和广播地址。

**坑**：看到“划分为 5 个子网”就按等分用 3 位子网号，把每个子网都当成 /23，误判最小可分配数；或算出 /24 的主机数 256 后忘记减去 2。
