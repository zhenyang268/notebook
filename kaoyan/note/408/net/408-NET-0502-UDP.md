# 408-NET-0502 UDP

> 章：NET-05 传输层　｜　档位：掌握　｜　真题落点：1 题：2024 #39

**在考什么**：能否把伪首部计入，按16位补零求反码和并回加溢出，再用首部与分片长度换算判断何时选UDP。

## 考法 1：手算 UDP 校验和（含伪首部）

**2024#39**

**思路**：第一步默写伪首部 12B：源 IP（4B）、目的 IP（4B）、全 0（1B）、协议号 17（1B）、UDP 长度（2B）。第二步把伪首部、UDP 首部、数据一起按 16 位分组求和，进位回卷加回低位，最后取反。

**坑**：一是伪首部里的“长度”字段填成数据长度而不是“UDP 首部 8B 加数据长度”；二是把首部里的校验和字段本身遗留在参与运算的值里（发送端应先置 0 再算）；三是数据为奇数字节时忘了在末尾补一个 0 字节参与运算，但这个补的字节不发送。

**变形：算出来恰好是全 0 或全 1 时怎么处理**

**思路**：分两端想：发送端算出的结果若为全 0，按规范要写成全 1 再填入；接收端若看到首部里校验和字段本身为全 0，表示发送端根本没算校验和。

**坑**：把“填入全 1”误判成“计算出错”；把“字段为全 0”当成“校验通过”。

## 考法 2：应用数据 → UDP 数据报 → IP 分片的长度换算

**2021#39**

**思路**：第一步写出三层长度关系：应用数据 $L$，UDP 数据报长 $L+8$，封装成 IP 数据报后长 $L+8+20$。第二步拿它与 MTU 比较，不超就一片，超了才分片。第三步分片时，每个分片的“数据字段”长度必须是 8 的倍数，片偏移按 8 字节为单位填写。

**坑**：把 UDP 首部中“长度”字段填成应用数据长度；把片偏移填成字节数而不是除以 8 后的值；以为分片只切数据、忘了每个分片都要复制一份 20B 的 IP 首部，导致总字节数算少。

## 考法 3：什么场景该选 UDP

**变形：给若干应用场景，判断用 UDP 还是 TCP**

**思路**：第一步抓主要矛盾：实时性优先选 UDP，完整性优先选 TCP。第二步看题干有没有“应用层自己实现序号与重传”的暗示，若有，说明应用在补 UDP 的短板，仍选 UDP。

**坑**：一看到“要求可靠”就选 TCP，忽略题干已说明应用层自己做确认重传；看到“广播、多播”仍按 TCP 处理。

### 2024 #39 UDP 校验和
中间结果 `1011 1001 1011 0110`，再加 `0110 0101 1100 0101`，最终校验和是

A. `0001 1111 0111 1011`
B. `0001 1111 0111 1100`
C. `1110 0000 1000 0011`
D. `1110 0000 1000 0100`

**思路**：三步。① 反码求和（**最高位进位要回卷加到最低位**）；② 若结果全 1 需再处理；③ 最后**取反**得到校验和。

**坑**：① 忘了回卷（进位直接丢弃会少 1）；② 忘了最后取反——选项 A/B 是"取反前"，C/D 是"取反后"，出题人就在这里设套。
