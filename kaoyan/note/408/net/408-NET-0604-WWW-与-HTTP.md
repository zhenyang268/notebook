# 408-NET-0604 WWW 与 HTTP

> 章：NET-06 应用层　｜　档位：掌握　｜　真题落点：2 题：2022 #40；2024 #40

**在考什么**：URL 里 `#` 后的片段根本不会进入请求行，误把它算进去或漏掉默认 80/443 端口，连接个数和 RTT 计数就全错。

## 考法 1：URL 各段的语义与“哪一段不发给服务器”

**思路**：第一步按 `协议://主机[:端口]/路径?查询#片段` 切段：主机加端口决定连谁，路径决定要哪个资源，查询串是交给服务器端程序的参数，片段是浏览器本地用来定位锚点的。第二步在写请求行时只保留“路径 + 查询串”，主机信息已经在连接和 Host 首部里体现了。

**坑**：把 `#` 后面的片段也算进请求行的 URL 里带出去；或者看到端口被省略就以为没有端口这个概念，答不出 HTTP 默认 80、HTTPS 默认 443，从而在算连接个数时把不同端口的资源当同一条连接。

## 考法 2：非持续连接的往返次数计数（2024#40）

**思路**：第一步先画时间轴，把三类往返分开摆：DNS 解析一次、每条 TCP 连接建立一次握手、每个对象请求—响应一次。第二步针对非持续连接的关键一句：每个对象都要“新建连接 1 RTT + 请求并收到响应 1 RTT”，这两段是串行的，不能折叠成一次；若允许 $k$ 条并行连接，就按轮数 $\lceil n/k\rceil$ 数对象，而最初那次建连仍要单独计入。

**坑**：把三次握手算成 3 个 RTT（实际前两次之后第三次可以在其中带上请求，整体只算 1 个 RTT）；把建连的 1 RTT 与请求响应的 1 RTT 合并成一个；允许并行时仍按 $n$ 个对象串行累加，导致往返数偏大。

## 考法 3：持续连接与流水线的计时（2022#40）

**思路**：第一步分清两种“持续”：非流水线持续是“一问一答，上一个响应回来才发下一个请求”，流水线持续是“请求连续发出、响应按序回来”。第二步把“主页本身”和它引用的对象分开计时：每份数据的传输时间按 $\frac{\text{大小}}{\text{带宽}}$ 单独算，$1$ MSS 的对象也要老老实实算 $\frac{1\text{MSS}}{R}$，然后把 RTT 段与传输段在时间轴上逐段拼接，标清楚哪一个对象的发送与哪一个往返重叠。

**坑**：把“持续连接”直接当成“零往返”，忘掉第一个对象仍要 1 个 RTT 建连；把 $1$ MSS 的发送时延当可忽略量丢掉；流水线情形下仍按“每个对象各耗一个 RTT”累加，多算了往返次数。

## 考法 4：HTTP 报文的行、首部与状态码语义

**思路**：第一步区分请求行/状态行与首部行，把方法的语义定住：GET 取资源，POST 提交实体，HEAD 只要首部不要主体，PUT/DELETE 用于上传与删除。第二步看状态码首位定类别：1xx 提示、2xx 成功、3xx 需要进一步动作、4xx 客户端出错、5xx 服务器出错。第三步判断“条件请求”时按成对字段找：If-Modified-Since 对应 Last-Modified，If-None-Match 对应 ETag。

**坑**：把 304 当成请求失败，实际它是“缓存仍然有效，本次不带实体”，容易误判成需要重传整个对象；把 HEAD 当成“根本没有响应报文”，实际是有首部、无主体；把 GET 与 POST 的语义互换，说成 GET 把参数放在实体里、不可缓存。

## 考法 5：Cookie 与代理缓存的存放位置和命中判断

**思路**：第一步分清“状态存在谁那里”：Cookie 存在客户端，由浏览器按域自动携带，服务器端要另配数据库记录，所以 HTTP 本身仍然是无状态的。第二步判断代理缓存是否命中：看请求方法、URL 与新鲜度（Cache-Control / Expires），命中就直接由代理返回，不产生到源服务器的往返；未命中才由代理代为取回并留副本。

**坑**：把 Cookie 说成“服务器端的会话表”，或反过来以为 Cookie 让 HTTP 变成了有状态协议；把代理缓存的命中仍按一次到源服务器的往返计时；忽略 `no-store`（禁止存储）与 `no-cache`（可存但用前必须验证）的区别，把不该缓存的对象判成命中。

### 2022 #40 网页传输时间计算
HTTP/1.1，主页 1MSS + 同目录 1 图 3MSS，RTT=10ms，从建连到收完至少（ ）

A. 30ms
B. 40ms
C. 50ms

### 2024 #40 非持久 HTTP 的 RTT 数
HTTP/1.0 非持久、不支持并行，1 个主页 + 7 个小图，从建连到收完，至少几个 RTT

A. 4
B. 9
C. 14
D. 16

**思路**：非持久 = **每个对象一条 TCP 连接**，共 8 个对象。每个对象：1 RTT 建连 + 1 RTT 请求/响应。但**主页面必须先拿到才能知道图在哪**，所以主页面的 2 个 RTT 是串行的，之后 7 个图各自 2 RTT（不能并行，也是串行）。

**坑**：① 只数 7 个图忘了主页；② 以为图片可以并行（题干明确说不支持并行）。
