# 408-OS-0202 CPU 调度

> 章：OS-02 进程与线程　｜　档位：掌握　｜　真题落点：13 题：2021 #24、#25、#27、#31；2022 #25、#26、#28；2023 #27、#29；2024 #24、#25、#28、#30

## 考法 1：给若干事件，问“哪些会引起进程调度”

**思路**：第一步把“调度的时机”归成两类入口：**当前进程不能再运行了**（运行结束、阻塞、被终止）和**有更该运行的进程出现了**（时间片到、更高优先级进程被创建或唤醒、中断处理结束返回到用户态）。判断一个选项时只问：这个事件发生后，调度程序是否需要重新比较一次优先级或重新分配 CPU。

**坑**：把“任何中断”都算成调度点——中断处理程序执行期间并不发生调度，只有当中断处理结束、准备返回用户态时，才检查是否该切换；另一处是把“进程被创建”想当然地当成必然触发调度（新进程可能进就绪队列排队，并不抢占）。

## 考法 2：分时系统实现时间片轮转“需要什么”

**思路**：第一步问自己：轮转是**剥夺式**的，剥夺必须由一个进程无法抗拒的力量完成，所以一定要有**定时产生中断的硬件与相应的时钟中断处理**；同时为了能“切走再切回”，必须有能力保存和恢复运行现场，即每个进程要有 PCB。把“必须有 PCB”（共性的、任何多道系统都要求）与“必须有定时中断”（轮转特有的）分别核对选项，凡是属于“非剥夺式调度也能正常工作”的机制就不构成轮转的必要条件。

**坑**：因为题干出现“分时系统”就把“必须有人机交互终端”或“必须有优先级”也算进去；相反地，只盯着 PCB，而忽略了轮转真正依赖的是“时钟中断”这一剥夺来源。

## 考法 3：优先级调度的表算法（给出到达时间、优先级、运行时间）

**思路**：第一步确认三件事再动笔：优先级数字**越小越高**还是越大越高、是**抢占式**还是非抢占式、进程是否同时到达。然后画一条时间轴，只在两种时刻停下来判断——**新进程到达的时刻**与**进程运行结束的时刻**；抢占式下每次到达都要回头比较“当前运行者的优先级 vs 新到达者”。每个进程记两个数：完成时刻与周转时间，周转 = 完成 − 到达，带权周转 = 周转 ÷ 运行时间，等待 = 周转 − 运行。

**坑**：抢占式下漏掉“进程被抢占后剩余运行时间要带着走”，把剩余时间重置成原始运行时间；以及算等待时间时用“完成 − 到达 − 运行”却忘了该进程可能被多次抢占又多次恢复，中途的排队时间要全算进去。还有一个高频疏漏：优先级相同时没有按“先来先服务”或题面给的规则打破平局。

## 考法 4（常见考法）：典型算法的特性与指标比较

**思路**：第一步给每个算法贴一张“性格标签”：FCFS 对长作业有利、对短作业与 I/O 繁忙型不利；SJF 平均等待时间最短但长作业可能饿死，且必须预知运行时间；HRRN 用响应比 $R=\dfrac{w+s}{s}$（$w$ 为已等待时间、$s$ 为要求服务时间）兼顾两者，短作业优先又不饿死长作业；RR 的响应时间有保证但上下文切换频繁，时间片过大退化为 FCFS、过小则开销占比过高；多级反馈队列按“队列优先级越低、时间片越长”来兼顾交互型与计算型。答“哪个平均周转最小”时，先判断题目是否允许抢占与是否已知运行时间。

**坑**：把“响应比”写成“等待时间 ÷ 运行时间”而漏掉分子里的运行时间；以及把“RR 的时间片越小响应越快”当成无条件的正确结论——当时间片小到与切换开销可比时，有效 CPU 利用率反而下降。
