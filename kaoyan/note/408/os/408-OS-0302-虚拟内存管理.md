# 408-OS-0302 虚拟内存管理

> 章：OS-03 内存管理　｜　档位：掌握　｜　真题落点：8 题：2021 #28、#29；2022 #29、#30；2023 #25、#28、#30；2024 #27

## 考法 1：缺页异常处理流程的“必然/不必然”

**2022#29**（缺页异常处理过程中不一定包含的操作）
**思路**：第一步把处理流程按“陷入内核并保存现场 → 查页表判断合法性/保护 → 在内存中找空闲页框（不够就选牺牲页）→ 必要时写回脏页 → 从外存调入所需页 → 修改页表项与快表 → 返回用户态重新执行被中断的指令”排成一条有序链路。然后对每个候选项问一句“这一步在什么条件下才做”，凡是带条件的（如牺牲页是否脏、内存是否已满），就是“不一定”的候选。
**坑**：把“不一定包含”读成“一定不包含”；把“重新执行引发缺页的那条指令”误认为从下一条指令继续（缺页是故障，返回后要重执行）；把地址变换中的常规动作（如查快表）也算进缺页处理。

## 考法 2：页面置换算法的模拟与 Belady 异常

**2021#28**（页大小 4KB、改进型 Clock、页表）
**思路**：第一步把访问序列里的地址按页大小右移（4KB 就是去掉低 12 位）转成页号序列，再在草稿纸上画“页框 $\times$ 访问次序”的表逐列推进。改进型 Clock 要先按 $(A,M)$ 分成 $(0,0),(0,1),(1,0),(1,1)$ 四类，扫描按“先找 $(0,0)$，途中把遇到的 $A=1$ 清成 0；找不到再找 $(0,1)$”的顺序，并且指针位置要在每轮结束处标注下来，下一列从这里继续。
**坑**：把它当普通 Clock，看到 $A=0$ 就换，忽略 $M$ 位；扫描中把 $A$ 位清零的动作漏掉，导致下一轮分类全错；指针忘了从上轮停留处继续而每次从头扫；地址转页号时用十进制除法算错十六进制地址。

**常见考法变形（自拟）**：FIFO / LRU / OPT 三者命中次数比较与 Belady 异常。
**思路**：第一步先判断题目给的页框数是否足够，再分别按“淘汰最先进来的”“淘汰最久未使用的”“淘汰将来最晚再用的”推进；比较命中次数时每个算法单独一张表，别共用状态。出现“页框数增加而缺页次数反而上升”的现象只在 FIFO 一类算法上讨论。
**坑**：把 LRU 的“最近最久未使用”按“进入时间最早”判；OPT 用过去的信息看将来；Belady 异常套到 LRU/OPT 上；访问序列中重复页未命中时忘记刷新其“最近使用”次序。

## 考法 3：缺页率的影响因素

**2022#30**（不会影响系统缺页率的是）
**思路**：第一步把缺页率写成“缺页次数 $\div$ 访问次数”，然后只从“改变访问序列的局部性、改变可用页框数、改变置换策略、改变页大小”这几个入口判断；对每个选项追问“它改变的是缺页次数，还是只改变缺页发生后的处理快慢”。只影响“处理一次缺页要多久”的量，不改变缺页率。
**坑**：把磁盘 I/O 速度、缺页服务时间当成缺页率的影响因素；把“页表项大小”“页表级数”与“页大小”混为一谈；把进程数增多（会挤占页框）与“页框总数固定时局部性变差”当成同一件事。

## 考法 4：进程虚拟地址空间的性质

**2023#28**（关于进程虚拟地址空间的错误说法）
**思路**：第一步列出虚拟地址空间的三条硬性质：它是进程看到的逻辑地址集合，大小由地址位数决定而与物理内存大小无关；每个进程各有一份、相互独立；其内部按用户区/内核区、代码段/数据段/堆/栈/共享库等划分。逐项核对选项是否违背这三条。
**坑**：默认“虚拟地址空间 = 物理内存大小”；认为“不同进程的同一虚拟地址一定指向同一物理单元”；把共享库映射到各进程同一虚拟地址当成错误；把“进程不能访问内核区”与“内核区不属于该进程的虚拟空间”混为一谈。

## 考法 5：内存映射文件与共享页的页号对应

**2023#30**（data 在进程 R、S 中的页号 p1、p2）
**思路**：第一步判断 R 与 S 的关系是 fork 还是各自 mmap 同一文件，再把“虚拟页号”和“物理页框号”分开记：映射同一文件的同一区段时共享的是物理页框，虚拟页号是否相同取决于各自的映射起始地址是否与页边界对齐。第二步算 data 在文件内的偏移，用偏移对页大小取模得到页内偏移，再结合映射起始虚拟地址所在的页号推出虚拟页号。
**坑**：把“共享同一物理页”直接等同于“虚拟页号相同”；忽略映射起始地址未页对齐，导致同一数据在两边落到的页号相差 1；忘记 fork 后写时复制会让 data 所在页先共享、写后才分离，把两种情况套同一结论。

## 考法 6：抖动与工作集

**常见考法（自拟）**：判断系统是否发生抖动、给工作集窗口问工作集大小。
**思路**：第一步抓住抖动的因果链：分配给进程的页框数少于其活跃页面集合 → 缺页频繁 → 频繁换入换出 → CPU 利用率骤降。判断是否抖动，比较 $\sum$ 各进程工作集大小与可用页框总数；工作集则是“最近 $\Delta$ 次访存所涉及的页的集合”，随时间滑动。
**坑**：把抖动原因归为“置换算法选得不好”，忽略页框分配不足；把工作集窗口 $\Delta$ 当成页框数；把工作集大小当成固定不变；认为增加多道程序度一定能提高 CPU 利用率（超过阈值后反而下降）。
