# 408-OS-0102 发展与分类

> 章：OS-01 操作系统概述　｜　档位：掌握　｜　真题落点：1 题：2016 #23

**在考什么**：由使用场景判定操作系统类型，并说清它解决什么问题、付出什么代价，能区分网络与分布式及硬实时与软实时。

## 考法 1：给出使用场景，判断属于哪一类操作系统

**思路**：第一步抓“这一场景最怕什么”：怕 CPU 空转、追求吞吐量 → 批处理；怕用户等、追求响应时间 → 分时；怕错过截止期、追求确定性与可预测性 → 实时。抓住“最怕什么”再回头核对系统特征（是否有交互、是否有时间片、是否有 deadline）。

**坑**：看到“多个用户同时使用一台机器”就直接判成分布式。分布式要求多台自治计算机通过通信协同完成同一任务，而分时系统仍是一台主机给多个终端分时——两者的判据是“计算机台数”和“是否存在统一资源视图”，不是“用户数”。

## 考法 2：判断各类系统“解决了什么问题、付出了什么代价”

**思路**：把每一类系统看成一对“收益—代价”：批处理用作业调度换取资源利用率，代价是无交互、周转时间长；分时用时间片轮转换取响应时间，代价是切换开销与调度复杂；实时用优先级/抢占换取截止期保证，代价是吞吐量下降、资源常留余量。

**坑**：把“分时系统响应快”误认为“吞吐量高”。分时系统的响应时间好，但频繁切换使单位时间完成的作业量未必高；反过来批处理吞吐量高但响应慢。题干只要出现“单位时间完成作业数”，就要往吞吐量上想，而不是往响应时间上想。

## 考法 3：实时系统内部再细分，以及“硬/软”的判据

**思路**：第一步看“错过截止期是否有灾难性后果”：有 → 硬实时；只是服务质量下降 → 软实时。再看实时系统与分时系统的调度目标差异——实时系统追求**最坏情况**可预测，分时系统追求**平均**响应快。

**坑**：把“实时”理解成“速度快”。实时系统的关键不是快，而是**确定**：最坏响应时间可界定、可保证。看到“实时系统一定比非实时系统处理得快”这类表述，要立刻判为可疑。

## 考法 4（常见考法）：网络操作系统与分布式操作系统

**思路**：先看“有无单一系统映像”：网络 OS 中各机有各自的操作系统与资源管理，用户清楚知道自己在用哪台机器，共享是“显式”的（登录、远程拷贝）；分布式 OS 把多台机器统一成一个逻辑整体，资源调度与任务分配由系统自动完成，用户无感。

**坑**：把“能互相通信、能共享文件”就当成分布式。只要用户还必须显式指定远端主机、各结点各自为政，就是网络 OS；判据是**透明性与全局统一调度**，而不是“有没有联网”。

### 2016 #23 批处理系统特征
下列关于批处理系统的叙述中，正确的是（  ）  
Ⅰ.批处理系统允许多个用户与计算机直接交互  
Ⅱ.批处理系统分为单道批处理系统和多道批处理系统  
Ⅲ.中断技术使得多道批处理系统的 I/O 设备可与 CPU 并行工作

A. 仅Ⅱ、Ⅲ
B. 仅Ⅱ
C. 仅Ⅰ、Ⅱ
D. 仅Ⅰ、Ⅲ

**思路**：抓住批处理非交互特征，再回忆由单道到多道的演化，以及多道切换依赖中断使 I/O 与 CPU 并行；关键一步是逐条判断用户能否直接干预。

**坑**：看到多个用户、多道程序就误判为可交互；把中断只理解成异常，忽略其调度切换作用。
