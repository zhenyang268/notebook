# 408-OS-0101 基本概念

> 章：OS-01 操作系统概述　｜　档位：掌握　｜　真题落点：3 题：2017 #28；2018 #23；2022 #23

**在考什么**：能否沿多道程序的得失推出运行特征的因果链，并分清“同时”的两种含义与哪些操作必须经系统接口。

## 考法 1：把“多道程序系统”的得失落到具体后果上，而不是背定义

**思路**：先问自己“为什么要引入多道”，答案只有一个——让 CPU 与 I/O 设备重叠工作，提高**系统**资源利用率与吞吐量。把这条主线抓住后，逐项检查选项是否与“宏观上宏观并行、微观上交替执行”这一事实相容；关键一步是拿“单道程序的封闭性、可再现性”当基准，看哪一条性质被打破。凡是说“提高了某一道作业自身的速度”的表述，都要立刻起疑。

**坑**：看到“多道程序系统提高了……”就默认全对。最容易误判的是把“提高了资源利用率/吞吐量”和“缩短了每道程序自己的执行时间”当成一回事——多道恰恰可能让某道作业的周转时间变长，而且会破坏程序的封闭性与可再现性，导致结果不确定。

## 考法 2：判断一个操作需不需要经过操作系统（用户接口题）

**思路**：第一步先问“这个动作要不要动用硬件或操作系统管理的资源”。凡涉及设备、文件、进程创建与撤销、内存分配的动作，用户程序自己无权直接完成，只能请求操作系统代办；纯算术运算、用户态变量赋值、函数内部的参数传递都在用户态内解决。第二步再把“库函数调用”与“系统调用”区分开：库函数跑在用户态，只有它内部真正需要内核服务的那一步才陷入。

**坑**：看到“函数调用”就想到系统调用。最容易错的是把库函数（如格式化输出）直接判成系统调用——它只是在内部某一步触发了写操作；另一个高频错是把“用户自己写的函数”和“需要特权才能完成的操作”混为一谈。

## 考法 3（常见考法）：四大特征之间的因果顺序与“并发/并行”辨析

**思路**：遇到“关于操作系统特征下列叙述正确的是”，第一步先摆出主线：**并发是前提**，没有并发就谈不上共享、虚拟、异步。然后逐项检查选项有没有把“因”当“果”（例如说“因为虚拟所以并发”），或把“并发”的范围扩大到单处理机不可能达到的程度。

**坑**：把“并发”读成“并行”——单处理机上同一时刻只有一个程序在运行，并发是宏观同时、微观交替；另一个误判是把“虚拟”只理解成虚拟存储器，漏掉 CPU 虚拟（分时轮转）与设备虚拟（SPOOLing 把独占设备改造成共享设备）。

### 2017 #28 多道程序优点
与单道程序系统相比，多道程序系统的优点是（  ） Ⅰ.CPU 利用率高 Ⅱ.系统开销小 Ⅲ.系统吞吐量大 Ⅳ.I/O 设备利用率高

A. 仅Ⅰ、Ⅲ
B. 仅Ⅰ、Ⅳ
C. 仅Ⅱ 、Ⅲ
D. 仅Ⅰ、Ⅲ、Ⅳ

**思路**：多道程序通过组织多个作业提高 CPU、吞吐量和 I/O 设备利用率，但管理切换会带来额外开销；关键一步是识别“系统开销小”与多道特征相反。

**坑**：把多道程序提高资源利用率误推为系统开销也小。

### 2018 #23 多任务系统特点
下列关于多任务操作系统的叙述中，正确的是（  ）。 Ⅰ.具有并发和并行的特点 Ⅱ.需要实现对共享资源的保护 Ⅲ.需要运行在多 CPU 的硬件平台上

A. 仅Ⅰ
B. 仅Ⅱ
C. 仅Ⅰ、Ⅱ
D. Ⅰ、Ⅱ、Ⅲ

**思路**：抓住多任务的核心是并发执行与共享资源管理，再判断是否必须在多处理器上运行。

**坑**：把“并行”与“多 CPU 硬件平台”强行绑定，误以为单 CPU 不能运行多任务系统。

### 2022 #23 多道程序系统特征
关于多道程序系统，不正确的是（ ）

A. 支持进程并发执行
B. 不必支持虚拟存储管理
C. 需对共享资源管理
D. 进程数越多 CPU 利用率越高

**要点**：进程数超过资源承载会频繁切换、抖动，利用率反而下降。
