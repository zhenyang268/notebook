# 408-OS-0103 运行环境

> 章：OS-01 操作系统概述　｜　档位：掌握　｜　真题落点：9 题：2021 #23、#32；2022 #23、#24、#27、#31；2023 #23、#24、#26

## 考法 1：判断一条指令是否只能在内核态执行（特权指令）

**思路**：第一步问“这条指令会不会改变机器级状态或绕过操作系统的资源管理”。凡是直接操纵硬件状态与机器配置的——开关中断、设置时钟、修改程序状态字/模式位、I/O 指令、修改页表基址或基址/限长寄存器、停机——都属于特权指令，只能在内核态执行；普通的访存、算术、跳转属于非特权指令。第二步再区分“谁发起”：陷入（trap）指令恰恰是用户态主动执行的。

**坑**：把“访存指令”“取指”“陷入指令”判成特权指令。最容易错的是 trap 指令——它正是用户程序用来进入内核态的手段，必须在用户态执行；其次是把“读中断”与“关中断”混淆，关中断是特权指令，而中断的发生与响应并不是一条指令。

## 考法 2：用户态与内核态的切换方向

**思路**：第一步抓住“切换是单向受控的”：用户态 → 内核态只有一条路——中断、异常或陷入，且由硬件在响应时自动完成；内核态 → 用户态由特权指令修改 PSW 中的模式位完成。然后逐项检查选项是否违反“用户程序不能自己提权”这条底线。

**坑**：误认为用户程序可以执行特权指令“把自己提升到内核态”；另一个高频错是认为“系统调用返回时 CPU 仍在内核态”——返回时已经切回用户态，只是返回值通过寄存器带回。

## 考法 3：系统调用全过程，谁在哪一态做了什么

**思路**：第一步把整个过程从“陷阱指令执行完”处一刀切成两段。陷阱指令之前是**用户态的准备**：把系统调用号放入约定寄存器、传参数、执行陷入指令；陷进去之后全部是**内核态的处理**：硬件保存现场与 PSW、按系统调用号查系统调用表、转到对应服务例程、执行、恢复现场、返回用户态。判据只有一条：这件事发生时 CPU 处于哪一态。

**坑**：把“保存用户现场”划给用户程序自己做。它发生在陷入之后，由内核入口代码（或硬件+内核）完成，属于操作系统一侧；另一个容易漏的是“传递系统调用参数”——它是用户在用户态做的准备动作，不是内核完成的。

## 考法 4：中断/异常的分类与中断向量表的数据结构选择

**思路**：分类先看“来源”：由 CPU 内部指令执行引起（除零、越界、缺页、陷入）的是内中断/异常；由外部设备或时钟引起的是外中断。再按“是否可屏蔽”“返回后执行哪条指令”细分。至于向量表，第一步先问“它怎么被访问”：以中断类型号为下标、各项等长、几乎只做随机读、不插入不删除——按这个特征去比对各种结构。

**坑**：把“缺页”当成外中断，把“时钟中断”当成异常；在数据结构上，看到“表”字就选链表或哈希表。向量表的本质是**按下标 $O(1)$ 定位的定长数组**，把它想成需要查找的容器就会选错。

## 考法 5：宏内核与微内核，哪些是收益、哪些是代价

**思路**：第一步先明确微内核“把什么搬出去了”——只保留进程调度、中断处理、基本 IPC 等最核心部分，文件系统、驱动、网络协议等作为用户态服务进程运行，服务之间靠消息传递通信。第二步把每条陈述贴上“收益”或“代价”标签：内核代码少、易移植、可靠性与可扩展性好是收益；态切换频繁、消息拷贝开销大、性能下降是代价。

**坑**：把“性能更好”当成微内核的优点——恰恰相反，服务间通信要反复穿越内核边界；也容易把“内核代码量小、便于裁剪与移植”误判为缺点。看到“微内核”就先默念一句：**结构清晰、可靠性高、性能差**。

## 考法 6：操作系统初始化过程中会创建什么

**思路**：第一步还原开机时序：加电自检 → 引导程序 → 内核装入并初始化 → 建立第一个/第零个内核进程 → 再由它创建后续进程。判据是“这个对象有没有可能在此之前就存在”：此刻还没有任何用户进程，所以只能由内核自己造出来的东西（空闲进程、init 类进程、各类系统表、设备与中断的初始化）才符合。

**坑**：把“命令解释程序/用户登录后的进程”当成初始化创建的——它们要等用户登录或由已有进程派生；也容易混淆“由内核直接创建”与“由父进程 fork 出来”这两条路径，凡是必须有父进程才能产生的对象，都不属于初始化阶段。

## 考法 7（常见考法）：三种装入方式与三种链接方式的对应

**思路**：第一步只问一句——**地址在什么时刻被最终确定**。编译时就定死 → 绝对装入（只适合单道、地址已知）；装入时一次性加上基址 → 可重定位装入（静态重定位），装入后不能移动；直到访问时才由硬件加法机构换算 → 动态运行时装入（动态重定位），需要重定位寄存器，可在内存中移动、便于共享。链接同理按“何时把目标模块拼起来”分成静态链接、装入时动态链接、运行时动态链接。

**坑**：把“可重定位装入”与“需要重定位寄存器”绑在一起——需要寄存器的是**动态运行时**装入；另一个常见混淆是把“动态链接”和“动态装入”当同一件事，前者解决模块何时拼接，后者解决地址何时换算。

## 考法 8（常见考法）：程序运行时的内存映像与地址空间

**思路**：第一步画一条从低地址到高地址的竖线，按固定次序填：代码段 → 已初始化数据段 → 未初始化数据段 → 堆（向高地址生长）→ 共享库映射区 → 栈（向低地址生长）→ 高地址的内核区。填完之后再判断某个名字落在哪：全局变量在数据段、函数内局部变量在栈、动态申请的内存在堆、命令行参数与环境变量在栈顶附近、函数代码在代码段。地址空间题则先分清逻辑地址（相对地址）、线性地址与物理地址各自在哪个阶段出现。

**坑**：把局部变量说成在堆、把 `malloc` 得到的内存在栈——判据是“生存期由谁管、生长方向朝哪”；另一个高频错是忽略栈向低地址生长，导致在比较两个局部变量地址大小时方向判反。看到“未初始化全局变量”时也别急着放进已初始化数据段。
