# 408-OS-0501 概述与控制方式

> 章：OS-05 输入/输出管理　｜　档位：理解　｜　真题落点：2 题：2017 #32；2024 #31

**在考什么**：给设备或过程描述，先抓数据单位和谁搬数据，再定接口、控制方式及软件层次。

## 考法 1：给设备贴标签或判断端口编址方式——按“传输单位 / 使用特征 / 共享属性”三条线索定位

**题目 1（设备分类判断）**

**思路**：先把设备按三条线索各过一遍——传输单位（字符 / 块）、使用特征（存储 / 输入输出）、共享属性（独占 / 共享 / 虚拟），再看题干问的是哪条线，别三条线混答。关键一步是抓“有没有固定大小的块、能不能寻址”：块设备以固定大小的块为单位传输、可寻址可随机访问，字符设备以字符流为单位、无寻址概念。

**坑**：看到“允许多个进程同时使用”就把打印机判成共享设备（打印机物理上是独占设备，只有加了 SPOOLing 才是“逻辑共享”）；也容易把“按块传输”和“可按块编址、随机访问”当成一回事，从而把某些只能顺序访问的块设备判成共享设备。

**题目 2（I/O 端口编址方式）**

**思路**：先判断这台机器是存储器映射（统一编址）还是端口映射（独立编址），判据只有一条——访问 I/O 端口用的是普通访存指令还是专门的 I/O 指令，地址空间是否与主存共用。关键一步：去看指令系统里有没有 in/out 一类指令、端口地址是否占用了主存地址空间。

**坑**：把“统一编址”误读成“端口地址的数值和内存地址相同”，或者看到“用访存指令访问端口”就断言不需要地址译码；另一个高频是把“I/O 端口”和“I/O 接口（设备控制器）”当成同义词，其实端口只是控制器里可被读写的寄存器。

## 考法 2：四种 I/O 控制方式的对比——看“数据单位 + 谁在搬数据 + CPU 被卷入几次”

**题目 1（控制方式判别）**

**思路**：用两个坐标轴筛——每传送一个数据单位，CPU 被卷入几次；数据搬运的主体是 CPU 还是控制器。轮询是 CPU 反复读状态寄存器、亲自搬；中断方式是数据就绪后由 CPU 搬一个字节/字；DMA 由控制器成块搬运、只在整块结束时中断一次；通道更进一步，能执行通道程序同时控制多台设备。关键一步：数“一次完整 I/O 里 CPU 参与的次数与粒度”。

**坑**：看到“中断”二字就认为 CPU 不参与数据传送、I/O 与 CPU 完全并行；或者把 DMA 的“成块”误解成“不需要中断”，忘了 DMA 传送结束时仍要发中断请求；还有把通道说成“一种中断控制器”，混淆了通道与中断控制器在体系中的位置。

**题目 2（2024#31 键盘中断后数据的存放位置）**

**思路**：把中断处理当成一条数据通路来追——设备控制器（键盘接口）里的数据寄存器 → 中断响应后由中断处理程序/驱动程序读走 → 落在内核空间的缓冲区（驱动程序维护的输入缓冲区）→ 之后才由系统调用交付给用户进程。关键一步：先问“此刻是内核态还是用户态、这段代码属于哪一层”，再定位数据落点。

**坑**：一看到“缓冲区”就默认是用户进程的缓冲区，跳过了“内核缓冲区 → 用户区”这一步；或者把数据落点说成“直接进入就绪队列 / 直接被用户进程读走”，把数据结构（缓冲区）与调度对象（进程、队列）混在一起。

## 考法 3：I/O 软件层次——给一段功能描述，找它属于哪一层

**题目 1（层次归属）**

**思路**：按自上而下四层走：用户层 I/O 软件 → 设备独立性软件 → 设备驱动程序 → 中断处理程序，硬件在最底下。逐层问一句“做这件事需不需要知道设备的具体型号和寄存器细节”，越往下越依赖硬件。关键一步：判断该功能是否在“对设备种类做屏蔽”。

**坑**：把“缓冲管理、设备分配、逻辑设备名到物理设备名的映射、统一命名与保护”错放到驱动程序层——这些恰恰是与设备无关的活；反过来把“中断处理程序”和“设备驱动程序”当成同一层，导致层次题全盘错位。

**题目 2（层间接口的传递内容）**

**思路**：想清楚层与层之间传的是“逻辑 I/O 请求”还是“具体寄存器操作序列”：上层交给下层抽象命令（读/写、逻辑块号、逻辑设备名），驱动程序再把它翻译成设备命令。关键一步：看题干描述的动作是“翻译成设备指令、读写寄存器”还是“管理请求队列、做映射与保护”。

**坑**：把“将逻辑设备名转换为物理设备名”当成驱动程序的职责；也容易把“驱动程序向上提供统一接口”理解成“向上提供与设备无关的接口”，其实“统一接口”是驱动层的形态，“屏蔽设备差异”是设备独立性软件层的职责，两者不在同一层。

## 考法 4：I/O 应用程序接口——按设备类型选接口、按返回时机辨阻塞

**题目 1（字符 / 块 / 网络三类接口）**

**思路**：看数据单位与有没有“位置”概念。字符设备接口按字节流、无寻址；块设备接口以块为单位、可 seek；网络设备接口要处理“地址 + 连接”，通常表现为 socket 的 open/connect/send/receive，并自带异步、不可靠语义。关键一步：先问“这次操作有没有偏移量/块号这种位置参数”。

**坑**：把网络 socket 当成字符设备（都像字节流），忽略它需要地址参数、需要建立连接；或者把块设备的 read 当作“从当前位置顺序读”，忘了它要带块号/偏移，也忘了块设备接口通常还要处理缓存与预读。

**题目 2（阻塞 / 非阻塞 / 异步）**

**思路**：只看两点——调用返回时数据是否已就绪、进程是否被挂起。阻塞 I/O：调用后进程睡眠，直到数据就绪并完成复制；非阻塞 I/O：立即返回，靠返回值判断、由进程自己再发起或轮询；异步 I/O：立即返回，内核把整件事做完后再通知。关键一步：严格区分“立即返回”和“立即完成”。

**坑**：把“非阻塞”和“异步”当同义词——非阻塞只是不睡眠，后续仍要进程自己再调用；异步则是内核负责到底并回告。另一个坑是把“非阻塞”误读成“不经过内核、直接在用户态完成”。

### 2017 #32 DMA读盘顺序
系统将数据从磁盘读到内存的过程包括以下操作： ① DMA 控制器发出中断请求 ② 初始化 DMA 控制器并启动磁盘 ③ 从磁盘传输一块数据到内存缓冲区 ④ 执行“DMA 结束”中断服务程序 正确的执行顺序是（ ）。

A. ③→①→②→④
B. ②→③→①→④
C. ②→①→③→④
D. ①→②→④→③

**思路**：抓住 DMA 传输由主机初始化启动、控制器直接搬数据、完成后才中断主机这条主线，再排“中断请求”和“中断服务”的先后。

**坑**：看到“DMA 控制器发出中断请求”容易误判为最先发生；也可能把“执行中断服务程序”误放到“发出中断请求”之前。

### 2024 #31 键盘中断后数据的存放位置

> 〔回忆版缺题干：本段只有标题与选项〕

A. 用户缓冲区
B. 通用寄存器
C. 内核缓冲区
D. 键盘控制器数据寄存器

**思路**：中断服务例程属于**内核**，它把设备数据读进内核缓冲区，再由系统调用 `read` 拷到用户缓冲区。中断处理阶段**不能直接写用户空间**。

**坑**：以为中断直接把数据给用户。用户缓冲区要等应用调用 read 才拿到。
