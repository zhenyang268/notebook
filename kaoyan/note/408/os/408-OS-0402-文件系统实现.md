# 408-OS-0402 文件系统实现

> 章：OS-04 文件管理　｜　档位：掌握　｜　真题落点：6 题：2021 #26、#30；2023 #31；2024 #26、#29、#32

## 考法 1：分配方式与（混合）索引的寻址计算

**思路**：连续分配先做边界检查——逻辑块号 $i$ 是否小于文件块数；通过后物理块号 = 起始块号 $+ i$，定位只需一次读数据块。算“访问第 $i$ 块共几次访盘”时，若目录项/inode 不在内存，还要加上取 inode 的那一次。

**坑**：直接套“起始块 + 逻辑块号”而不判越界；或者把题目给的“起始块号”当成逻辑块号代进去，物理块号整体偏移。

**思路**：隐式链接只能顺序走，访问第 $i$ 块必须先读前 $i-1$ 块里的指针，访盘次数与 $i$ 同阶。显式链接（FAT）把指针集中到一张表里，而这张表通常常驻内存，于是访问第 $i$ 块只需查内存中的 FAT 链 + 1 次读数据块。

**坑**：把 FAT 也当成“每块都要读一次盘”，算出和隐式链接一样的次数。关键差别就是 FAT 在内存里这一步有没有想到。

**思路**：多级索引先分段。把直接地址项数 $\times$ 块大小算出来，定出直接区、一次间接区、二次间接区各自覆盖的逻辑块号区间，再看目标块号落在哪一段。求最大文件长度时，一块 $B$ 字节、指针 4 字节，则一块能装 $B/4$ 个指针，一次间接可索引 $B/4$ 块，二次间接是 $(B/4)^2$ 块。

**坑**：求最大长度时漏加直接地址项；或把二次间接写成 $2 \times B/4$。另一个易错点是问“访问某逻辑块要读几次盘”时，忘了每一级间接索引块各要读一次（未缓存时）。

## 考法 2：空闲空间管理

**思路**：位示图的大小只由磁盘总块数决定：字数 $=\lceil \text{总块数}/\text{字长}\rceil$，与当前有多少空闲块毫无关系。给块号求位置时，字号 = 块号 / 字长，位号 = 块号 % 字长。

**坑**：拿“空闲块数 ÷ 字长”去算位示图大小。误判点在于把位示图当成“只为空闲块建的图”。（对应 2024#26：位示图占用空间与空闲块数无关）

**思路**：位示图换算还要盯住编号起点。块号、字号、位号都从 0 开始时，直接取整取余；只要有一方从 1 开始，就要先减 1 再算。

**坑**：块号从 0 起、位号从 1 起这类混编场景下直接除，结果整体错一位。

**思路**：成组链接要抓住“一组”这一层：超级块/栈里存的是若干空闲块号和指向下一组的指针；分配从栈顶弹出，栈空才读下一组；回收是压栈，压满就把整栈写进新回收的块并置新栈。算一次分配/回收的访盘次数时，先判断“栈是否为空/是否已满”这个分支。

**坑**：把成组链接当成普通空闲链表（每块只存一个后继指针），于是把“读一组”算成“读一块”，次数差一个数量级。

**思路**：空闲表、空闲链表天然适合连续分配（能直接看出连续空闲区）；位示图、成组链接适合离散分配。题目问“哪种方法便于找连续空闲区”就往空闲表/链表上想。

**坑**：不问场景一律答位示图，忽略“连续 vs 离散”这个前提。

## 考法 3：inode、打开文件表与文件操作

**思路**：先分清 inode 与目录项的分工：目录项只放“文件名 + inode 号”，inode 放类型、权限、链接计数、块指针。这样目录项小、一个盘块能装更多项，按名检索更快。

**坑**：认为 inode 里也存文件名，或者把 inode 当成目录项的一部分，算“一个盘块能装多少目录项”时把 inode 也算进去。

**思路**：打开文件是三级结构：进程的 fd 表（fd → 系统打开文件表项）→ 系统打开文件表（读写偏移、打开计数、指向内存 inode）→ 内存 inode 表。同一个文件被多个进程打开时，系统打开文件表可能只有一项、也可能每进程一项，取决于是否共享同一表项；读写偏移是否共享就由这一层决定。

**坑**：把“打开计数”和 inode 的“链接计数”当成同一个量。误判点在于题目说“文件被打开两次”时，去改链接计数。

**思路**：关闭文件（close）做的事情是：释放本进程 fd 表中的那一项，系统打开文件表项打开计数减 1，减到 0 才删除该表项；inode 的链接计数不变，文件仍在磁盘上。

**坑**：看到“关闭”就往“删除 inode / 释放磁盘块”上想。（对应 2023#31：文件仅被一个进程打开，该进程关闭它时发生什么）

**思路**：删除文件要先列出“必须做”的清单：删目录项、链接计数减 1、计数为 0 时回收 inode 和它指向的数据块。题目问“内核不必完成的是”，就用这份清单去反选。

**坑**：把“释放磁盘块”理解成“把块内容清零/擦除”，或者把“回收 inode 号”当成删除时立刻要做的事。（对应 2021#30：删除 file1 时内核不必完成的操作）

## 考法 4：虚拟文件系统 VFS 与文件系统挂载

**思路**：VFS 是内核里的一层抽象，向上提供统一的 open/read/write 接口，向下用超级块对象、inode 对象、目录项对象、文件对象四个对象描述“任意”文件系统；具体文件系统（ext2、FAT 等）各自提供实现。判断某结构“是否在磁盘上有对应物”时，先问它在 VFS 层还是在具体文件系统层。

**坑**：把 VFS 当成一种具体文件系统，或以为 VFS 的四个对象都必须在外存有实体。

**思路**：挂载是把一个文件系统的根接到另一个文件系统的某个目录（挂载点）上，拼成一棵目录树。挂载后原挂载点目录的内容被遮蔽而未被删除，卸载后重新可见。

**坑**：以为挂载会覆盖或删掉原目录的内容；或以为挂载后新旧两个目录的内容能同时看到。
