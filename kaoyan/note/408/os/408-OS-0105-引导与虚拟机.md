# 408-OS-0105 引导与虚拟机

> 章：OS-01 操作系统概述　｜　档位：掌握　｜　真题落点：本考点 2016–2024 无对应题目

**在考什么**：这道题真正拉开差距的是「建立中断向量表、初始化页表」这类动作到底归引导程序还是内核初始化，一旦把装入内核当成初始化内核，整道时序题全错。

## 考法 1：把「谁在什么时候创建了谁」放回引导时间轴上定位

这类题给出若干「对象 / 动作」，问其中哪一项是在操作系统初始化过程中（或由引导程序、由固件）完成的。本质是排序题：先排出时间轴，再定位每个选项。

**思路**：第一步默写五段链条，并在纸上标出分界：加电自检（固件）→ 定位并读入引导扇区 / 引导程序 → 把内核映像装入内存并移交控制权 → 内核初始化（建立中断处理机制、初始化存储管理与设备、创建第一个内核级进程 / 初始进程）→ 转入用户态启动 init、登录界面。第二步把每个选项丢到轴上对号入座：落在「内核初始化」这一段里的才是本题要的答案；落在「内核装入之前」的（固件或引导程序做的事）都要排除。

**坑**：最容易错的一步是把「装入内核」和「初始化内核」当成同一件事，于是把「建立中断向量表、初始化页表、创建设备驱动结构」这类内核初始化阶段的工作，误判成引导程序已经做完的事。另一个具体误判是：看到「创建」二字就去选「创建引导程序 / 创建分区表」，而组装引导扇区是安装系统时或固件阶段的行为，不在内核初始化范围内。

**思路**：遇到「排序」形式的变形题，第一步抓住一个硬约束：主引导扇区只有 $512$ 字节，装不下内核映像。因此它的内容必然是「一小段引导加载程序」，由它再去读入更完整的引导程序与内核。第二步用这条约束去排「主引导扇区→引导加载程序→内核映像」的先后，凡把「直接由主引导扇区装入完整内核」写进去的选项，顺序一定错。

**坑**：把「引导程序」与「内核」的加载次序调换，或者把「启动固件」排在「加电自检」之前；还有一种隐蔽错误是把用户态的 init / 登录界面排在设备初始化、中断机制建立之前——用户态进程只有在整套内核服务就绪后才可能被创建。

## 考法 2：第一类 / 第二类虚拟机的判定与 VMM 的职责边界

这类题通常给一段部署描述，或直接问「下列关于 VMM 的说法」。判定的唯一支点是「虚拟化层下面还有没有一个宿主操作系统」。

**思路**：第一步只问一句：VMM 是直接跑在裸硬件上，还是作为某个操作系统之上的一个应用程序在跑？直接压在最底层、自身承担资源分配职责的是第一类（裸机型）；需要在宿主操作系统上安装、依赖宿主 OS 的驱动与调度的是第二类（宿主型）。第二步再顺着这个判定去推性能与场景：第一类少了宿主 OS 这一层，开销更小，多用于服务器 / 云平台；第二类部署方便、可与其他应用共存，但每次 I/O 往往要多绕一层。

**坑**：看到「虚拟化软件是安装上去的应用程序」却仍判成第一类；或者反过来，题干里明明写了「运行在宿主操作系统之上」，只因为出现「服务器 / 云」就判第一类。判类只看「有无宿主 OS」，不看用途。

**思路**：回答 VMM 职责，第一步先立住它的唯一核心：对 CPU、内存、I/O 等物理资源做多路复用与隔离，为每台虚拟机呈现一台「看起来完整」的假想计算机。第二步从特权级切入：VMM 处在比客户操作系统更高的特权级，客户 OS 的「内核态」只是虚拟机内部概念上的内核态；客户 OS 执行敏感 / 特权指令时会被 VMM 截获并代为模拟或拒绝。

**坑**：把「客户 OS 的内核态」当成真实的最高特权级，从而认为客户 OS 可以随意操作物理设备；另一个常见错误是把「客户 OS 内部的进程调度、文件管理」算成 VMM 的工作——VMM 只管「机器之间」的分配，不管「机器内部」的管理。

**思路**：遇到虚拟机与容器（OS 级虚拟化）的对比，第一步抓分界：虚拟机虚拟的是「硬件 / 体系结构」，每台虚拟机里有独立的客户内核，因此能跑不同操作系统；容器共享宿主内核，只隔离用户态的运行环境。第二步据此推代价：虚拟机隔离更彻底、启动更慢、开销更大；容器更轻、启动更快，但内核共享，隔离强度弱。

**坑**：把「容器启动快、资源占用少」误推成「容器隔离性更强」；或者把容器也说成「需要 VMM 支持」。看到「共享同一个内核」这个描述，就必须把它从虚拟机那一侧划出去。
