# 408-DS-0601 顺序查找与分块查找

> 章：DS-06 查找　｜　档位：掌握　｜　真题落点：1 题：2016 #9

**在考什么**：失败 ASL 的分子是否区分有序表与无序表：无序表每个失败空档都要扫到表尾，比较次数全是 $n$；写成「越靠前失败得越早」就会丢掉最后缝隙那一项。

## 考法 1：成功 ASL 与失败 ASL 是两套账

**思路**：第一步先写分母。成功 ASL $=\sum p_i c_i$，等概率时 $p_i=1/n$，分母是 $n$；失败 ASL 的分母是**失败位置的个数**，无序顺序表有 $n+1$ 个空档（表头前、每两个元素之间、表尾后）。分子逐个位置数"比到第几个才判定失败"。分母定了，分子就不会串。

**坑**：把失败 ASL 也除以 $n$。更隐蔽的一层是分子也错——无序表里每个失败空档都必须扫到表尾才敢判失败，比较次数全是 $n$；很多人下意识写成"越靠前失败得越早"，那是**有序表**才有的性质。

**思路**：（哨兵）：第一步把"关键字比较次数"和"循环条件判断次数"分成两本账。设哨兵（如 `a[0]=key`、从后往前扫）删掉的是每次循环里的下标越界判断，比较的**总次数一次没少**。所以问"哨兵能否降低 ASL"，答案取决于 ASL 的定义里算不算边界判断——按 408 的定义，ASL 只数关键字比较。

**坑**：看到"哨兵减少了判断"就顺手写成"平均查找长度减小"。哨兵优化的是常数时间里的分支开销，不是比较次数；另外往表头放哨兵后下标从 1 开始，数比较次数时容易把哨兵本身那次比较漏掉。

## 考法 2：有序表上顺序查找的判定树与"提前终止"

**思路**：第一步把"有序"翻译成"可以提前停"：查到第 $i$ 个元素时若发现 $key<a_i$，立刻判失败，不必扫到表尾。接着画判定树——成功结点是 $n$ 个内部结点，第 $i$ 个元素的比较次数就是 $i$；$n+1$ 个失败结点挂在每个元素左边那个"缝隙"上，缝隙越靠左，路径越浅。判失败所需的比较次数，等于"走到该缝隙的父结点为止"的次数。

**坑**：套用无序表的失败 ASL，或者把失败结点画成 $n$ 个。另一个高频错法是忘了"最后一个缝隙（$key>a_n$）仍要走满 $n$ 次"，把它和别的缝隙按同一规律编号，导致分子少一项。

## 考法 3：分块查找（索引顺序表）的 ASL 与最优块长

**思路**：第一步把分块查找认成**两段串联**：先在索引表里定位块（对"块"做查找），再在块内顺序查找（对"元素"做查找）。两段串联的期望代价是两段 ASL **相加**，不是相乘。设块数 $b$、块长 $s$、$n=bs$，索引段按"$b$ 个块"算、块内段按"$s$ 个元素"算，两条公式分母不同；再用 $b=n/s$ 消元成一元函数，对 $s$ 求极小，就得到块长与 $\sqrt n$ 的关系。

**坑**：把两段的 ASL 相乘（"先 A 再 B 所以乘起来"）；或者两段的分母都用成 $n$。还有一处容易误判：算出最优块长是 $\sqrt n$ 之后，顺手把最优 ASL 也写成 $\sqrt n$——把 $s$ 代回原式时 $(s+1)/2$ 里那个常数项是留着的，两者数值不等。

**思路**：（索引表可否折半）：第一步只看分块查找的硬性要求——**块间有序**（第 $i$ 块所有关键字小于第 $i+1$ 块的所有关键字），块内可以无序。索引表本身天然有序，因此索引段这一段可以换成分块……换成折半查找，块内段仍是顺序查找，两段依旧是相加。

**坑**：把"块内必须有序"当成必要条件而否掉正确表述；或反过来，因为"块内无序"就断定索引表不能用折半。另外注意：块内改成折半的前提是块内也有序，题目若只说"块间有序"，块内那一段不能换。

### 2016 #9 跳跃查找比较次数
在有 n(n>1000) 个元素的升序数组 A 中查找关键字 x。查找算法的伪代码如下所示。 k = 0; while (k < n 且 A[k] < x) k = k + 3; if (k < n 且 A[k] == x) 查找成功； else if (k - 1 < n 且 A[k - 1] == x) 查找成功； else if (k - 2 < n 且 A[k - 2] == x) 查找成功； else 查找失败； 本算法与折半查找算法相比，有可能具有更少比较次数的情形是（）

A. 当 x 不在数组中
B. 当 x 接近数组开头处
C. 当 x 接近数组结尾处
D. 当 x 位于数组中间位置

**思路**：该伪代码每次跨 3 个位置向后扫描，再回看最近两格；关键是比较次数随目标位置靠前而减少，而折半查找的比较次数较稳定。

**坑**：看到“升序数组”就默认折半查找一定更少；也会误以为 x 不在数组中时这种跳跃查找更占优，而实际往往要扫到较后位置。
