## 一、三条铁律

### 铁律 0：三层分工（2026-11-01 定）

```
syllabus/  L1 大纲：一个 KP 一行（坐标系，唯一）
quick/     L2 详解：一门学科一份（共 4 份），按 syllabus 主键逐条展开
exam/      L3 详细：一个 KP 一个文件（完整讲解与题型）
```

**判断新内容该放哪**：只要能对上某个 KP，就进 `exam/`；
只有"跨多章的骨架、必考量级、致命陷阱汇总"才进 `quick/`。
`quick/` **不写完整推导、不贴长代码、不做题型训练**。

### 铁律 1：一个 KP 节 = 一个 md 文件 = 一个复习单元

这条同时解决三个老问题：文件膨胀（粒度天然有界）、复习无依据（有主键可排期）、
「文件名承诺 A、实际装 B」（旧 `12-同步与互斥.ipynb` 里一条 PV 都没有，就是反例）。

- 文件路径：`exam/<科目>/<子科>/<章>-<节>-<名>.md`，章节目号取自 `syllabus/`。
- 一个文件里可以有多个 `##` 小节，但它们必须**同属这一个 KP 节**。
- 装不下 = 说明它其实是两个节，回 `syllabus/` 拆 KP，别在一个文件里堆。

### 铁律 2：双线物理隔离，单向引用

| | `exam/` 考试线 | `projects/` 工程线 |
|---|---|---|
| 目的 | 拿分 | 兴趣与能力 |
| 内容 | 只有考纲里的东西 | 项目设计、代码、调试、复盘 |
| 能不能提对方 | **不写工程细节**。允许一行 `> 工程锚点：projects/xxx.md` 做指针 | **只写 KP 号 + 考点名**，禁止复制 `exam/` 正文 |

- `projects/` 每个文件顶部必须有「对位考点（单向引用）」表。
- `tools/lint.py` 检查：`exam/` 正文出现工程仓名（CS144 / CS149 / CSAPP / nand2tetris / 6.824 / jos / craft）
  → **提示级**（不阻断，供清理）；`projects/` 大段复制 `exam/` 正文 → 提示。

### 铁律 3：状态与内容分离

- **复习档位不写进正文**。正文只管知识；档位、到期日、通过与否全部在 `reviews/REVIEWS.md`。
  （旧机制往 cell 末尾追加「复习计划」行：88 个 cell 里 43 个漏填，61 个档位 58 个逾期。）
- **进度不写进正文**。`exam/` 文件头「状态」只有三档：`未开始` / `已归档` / `已验收`。
  更细的进度（学到第几层、错在哪）进 `PROGRESS.md` 的模块表或 `CHANGELOG.md`。

## 三、一个 KP 文件的骨架

```markdown
# <节标题>

> **KP**：`408-DS-0505` ｜ 状态：**已归档** ｜ 最后更新：YYYY-MM-DD
>
> 来源：学习对话 / 真题 YYYY 年第 N 题 / `projects/xxx.md`（仅指针）
> 工程锚点：（可选）`projects/algorithm.md` §3

---

## ① 机制层

（表格 / Mermaid 图 / 手算模板）

## ② 设计层

（为什么这样设计、站在哪一层、与相邻概念的边界）

## ③ 验收层

### 题型清单
| # | 题型 | 模板要点 | 代表例 | 优先级 |

### 代表例题
### 易错点（配反例）
### 待解决

---

## 复习记录

- YYYY-MM-DD · R1 · 通过 ｜ 未通过（归因：概念不清 / 计算失误 / 没记住 / 审题错 / 存疑待核）
```

**要求**：
- 缺失部分写「待补充」，**不编造**（尤其真题年份、题号、大纲页码）。
- 公式用 KaTeX：行内 `$…$`、独占行 `$$…$$`；不写 Unicode 上下标。
- 图用 **Mermaid**（`flowchart` / `stateDiagram-v2` / `sequenceDiagram` / `gantt`），不贴图片文件。
- 考场要手画的样子另起一段「考场画法」，见 `TOOLKIT.md`。

## 四、归档流程

1. **定位 KP**：先在 `syllabus/` 里找这一条落在哪一节。找不到 → 不建文件，进 `temp.md` 标 `[待归类]`；
   是否新增 KP 由用户决定（**KP 只能由 `syllabus/` 增加，不能由内容倒推**）。
2. **读目标文件**（存在则读；不存在按 §三 骨架新建）。
3. **追加**到对应 `##` 小节末尾；新知识点另起 `##`。
4. **登记 `reviews/REVIEWS.md`**：首次归档 → 加一行，R1 = 明天；已有 → 更新档位。
5. **追加 `CHANGELOG.md`** 一条：`- YYYY-MM-DD · 408 / 网络 / 05-05 · 慢开始逐轮表格法`。
6. **更新 `PROGRESS.md`**：只动自己那一行与「下一站」。
7. 跑 `python3 tools/lint.py` 自检。

**只追加，不改写历史**：错的地方不要就地改，另起 `> **修正（YYYY-MM-DD）**：…`，
让错误本身留下（它是复习素材）。唯一例外是路径失效与格式错误。

## 五、归属判定

```
1. 对话在谈考试内容吗？
   是 → 2　　否（在谈项目 / 代码 / 调试）→ projects/<项目>.md
2. 能对上 syllabus/ 里的哪个 KP 节？
   能 → exam/<科目>/<子科>/<该 KP 的文件>.md
   不能 → temp.md，标题加 [待归类]
3. 一段话跨两个 KP？→ 拆两段各归各的
   （例：滑动窗口的两条约束 → TCP 的进 05-04，链路层 GBN 的进 03-03）
4. 一句里既有考点又有工程实现？
   → 考点进 exam/，工程那半句只留 `> 工程锚点：projects/...`
```

**双归属点（两边互写一行「见」指针，不复制正文）**：

| 主题 | 主文件 | 互见 |
|---|---|---|
| 虚拟存储器 | `408-OS-0301/0302`（策略侧） | `408-CO-0306`（硬件转换侧） |
| 磁盘调度 | `408-OS-0403` | `408-CO-0304`（结构参数） |
| 中断与异常 | `408-OS-0103`（OS 视角） | `408-CO-0505`（CPU 视角） |
| I/O 方式 | `408-CO-0704`（硬件） | `408-OS-0501`（软件层次） |
| CRC | `408-NET-0302`（链路用法） | `408-CO-0203`（编码原理） |
| 红黑树 / B+ 树 | `408-DS-0605` / `0606` | `408-DS-0600`（共同动机） |
