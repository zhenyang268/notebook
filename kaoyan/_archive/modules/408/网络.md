## 0. 总纲地图 ★核心

### 0.1 机制层（①）
五层模型（TCP/IP）的职责、PDU 与典型设备/标识：

```
  层            职责                  PDU               设备 / 标识
  应用层     面向具体应用           报文 message        ——
  传输层     进程 ↔ 进程、端到端     报文段 / 用户数据报   端口号
  网络层     主机 ↔ 主机、选路       分组 / 数据报       路由器、IP 地址
  链路层     相邻结点、成帧与差错     帧 frame           交换机 / 网桥、MAC 地址
  物理层     比特流传输             比特 bit           中继器 / 集线器
```

- **封装与解封装**：数据自上而下逐层加首部（应用数据 → TCP 段 → IP 分组 → 帧 → 比特）。
- **socket 的位置**：夹在应用层与传输层之间，是**编程接口**而非一层。`SOCK_STREAM` = TCP、`SOCK_DGRAM` = UDP；`listen/accept` 背后的半连接 / 全连接队列对应三次握手。

### 0.2 设计层（②）
- **为什么分层**：把「端到端可靠性 / 选路 / 相邻结点可靠性 / 信号」四类问题**解耦**，各层独立演进、独立复用（上层不关心下层怎么实现）。
- **为什么是五层而非 OSI 七层**：OSI 的会话层 / 表示层在 TCP/IP 里并入应用层——工程上无独立价值。
- **现实对照**：Linux 网络栈（`socket` → `tcp/ip` → `netdev` → 驱动）。**边界**：408 考模型、封装、各层职责，不考内核实现。
- **socket 的边界（重要）**：socket 能锚定**传输层**直觉，**看不到网络层**（仅 IP 地址间接可见）。它是入口，不是主线。

### 0.3 验收层（③）
- **题型**：判定「某功能 / 协议 / 设备属于哪一层」；写出某次通信自顶向下的封装过程。

### 块1 端口与复用 / 分用 ★核心（2026-10-11 展开）

**块1.1 机制层（①）**
- **传输层定位**：提供**进程 ↔ 进程**的逻辑通信；网络层只到**主机 ↔ 主机**。
- **端口 port**：16 位，取值 0–65535，做进程级寻址。
  - 服务器端：**熟知端口 0–1023**（HTTP 80 / HTTPS 443 / FTP 21·20 / SMTP 25 / DNS 53 / POP3 110 / IMAP 143）；**登记端口 1024–49151**。
  - 客户端：**临时端口 49152–65535**（系统动态分配）。
- **套接字（408 定义）**：socket = **(IP 地址, 端口号)**。一条 TCP 连接由**一对套接字**（四元组：源 IP、源端口、目的 IP、目的端口）唯一确定。
- **复用 / 分用**：
  - **复用（发送方）**：多个进程的数据 → 传输层加端口 → 汇入同一条网络层通道（多 → 一）。
  - **分用（接收方）**：网络层送上来的数据段 → 按端口号交给对应进程（一 → 多）。
  - **分用依据**：UDP 用 (目的 IP, 目的端口)；TCP 用四元组。

**块1.2 设计层（②）**
- **为什么需要传输层**：网络层解决「送到哪台机器」，但一台机器上多个进程并发通信——需要**进程级寻址**，这就是端口存在的理由。
- **为什么 TCP 用四元组、UDP 只用目的端口分用**：TCP 面向连接，每条连接是独立逻辑通道，必须四元组才能区分；UDP 无连接，同一 socket 可收多个源。
- **为什么用端口而不用 PID**：PID 跨机器无意义且会变；端口是全网统一约定的稳定抽象。（理解性说明，408 不直接考）
- **现实对照**：Linux socket API（`socket()` → `bind(IP, port)` → `connect()`），`ss` / `netstat` 看端口占用。**边界**：408 考端口 / 套接字概念与分用依据，不考 API 调用细节。

**块1.3 验收层（③）**
- **代表例**：主机 A 的 P1(:5000)、P2(:5001) 同时连 B 的 :80 —— B 用四元组区分出两条不同连接。
- **易错**：把「进程 ↔ 进程 / 主机 ↔ 主机」记反；TCP 分用只写目的端口（漏掉四元组）。

## 4. 数据链路层 ★核心

> 覆盖：组帧、差错控制（CRC）、流量控制 / 可靠传输（GBN / SR）、介质访问控制（CSMA/CD、CSMA/CA）、以太网与交换机。归档 → `14-网络分层与链路层.ipynb`

**题型清单**：

| # | 题型 | 模板要点 | 优先级 |
|---|---|---|---|
| 1 | **CRC 计算** | 生成多项式做模 2 除法，余数即校验码 | ★核心 |
| 2 | CSMA/CD 退避 | 二进制指数退避；第 k 次冲突的退避区间 | ★核心 |
| 3 | 以太网帧格式 | 目的 / 源 MAC、类型、数据、FCS；最小帧长 64B | ☆常规 |
| 4 | GBN vs SR | 窗口限制（GBN ≤ 2^n − 1，SR ≤ 2^(n−1)）；重传策略 | ★核心 |
| 5 | 交换机自学习 | 按源 MAC 建表、按目的 MAC 转发 / 泛洪 | ☆常规 |

- **易错**：CRC 模 2 除法（借位即异或）算错；CSMA/CD 与 CSMA/CA 混用（CD 用于有线以太网，CA 用于无线）；GBN 重传的是「全部未确认」而非单个帧。
