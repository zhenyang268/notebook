## 1. 块1 概述与运行机制 ☆常规

> 覆盖：OS 概念与四大功能、四大特征、发展史（多道程序设计）、用户态/核心态、中断/异常、系统调用、体系结构（大内核/微内核）。
> 归档 → `00-计算机系统概述.ipynb`（拆分规则见 §0.1）

### 1.1 机制层（①）
- **OS 定义**：管理硬件资源、控制程序执行、提供人机接口与程序接口的**系统软件**。四大功能：处理机管理、存储管理、文件管理、设备管理。
- **四大特征**：并发、共享、虚拟、异步。**并发与共享互为存在条件**（无并发则无资源争用，无共享则无并发意义）。
- **发展史一句话**：被「CPU 与 I/O 速度差」逼出来的——单道批处理 CPU 空等 I/O → **多道程序设计**（内存中同时驻留多道程序交替执行，提高利用率）→ 分时（时间片轮转 + 交互）→ 实时（及时 + 可靠）。
- **双模式运行**：CPU 分**用户态（目态）**与**核心态（管态）**；**特权指令**只在核心态可执行（I/O 启动、置时钟、修改 PSW/页表基址寄存器、清内存等）。
- **中断（外中断）vs 异常（内中断）**：
  - 外中断：与当前指令无关，来自外部——时钟中断、I/O 完成中断。
  - 内中断（异常）：当前指令引发——**陷入 trap**（系统调用入口）、故障 fault（如缺页）、终止 abort（如非法指令）。
- **系统调用过程**：用户程序传参 → 执行**陷入指令**（用户态执行，但引发切换）→ 切核心态 → 查系统调用入口表 → 执行内核服务例程 → 返回用户态 → 取返回值。
- **体系结构**：大内核（宏内核）/ 微内核 / 分层式 / 模块化 / 外核（○了解）。

### 1.2 设计层（②）
- **为什么要双态**：保护。OS 是裁判，不能让运动员改记分牌——用户程序若能直接执行 I/O 指令或改页表，隔离与安全全失效。
- **为什么用户态→核心态只能经中断/异常**：这是**硬件强制**的入口，用户程序无法直接改 PSW（改 PSW 是特权指令）；核心态→用户态则是**中断返回**时由内核修改程序状态字完成的。
- **为什么多道程序提高利用率**：程序 A 等 I/O 时，CPU 切去跑程序 B——用并发掩盖 I/O 延迟。
- **现实对照**：x86 的 ring0/ring3；Linux 的 `syscall` 指令与中断描述符表。**边界**：408 只考概念与流程判断，不考具体汇编与寄存器细节。

### 1.3 验收层（③）
**题型清单**：

| # | 题型 | 模板要点 | 优先级 |
|---|---|---|---|
| 1 | 特权指令判断 | 碰「资源分配/全局状态/I/O/PSW」即特权；读类操作（读时钟/取数）不是 | ★核心 |
| 2 | 用户态→核心态切换时机 | 只有三类：**系统调用（陷入）、外中断、内异常**；核心态→用户态只在返回时 | ★核心 |
| 3 | 系统调用流程排序 | 传参→陷入→切态→查表→执行→返回；陷入指令本身**非特权** | ★核心 |
| 4 | 中断 vs 异常分类 | 看是否由当前指令引发 | ☆常规 |
| 5 | OS 四特征辨析 | 并发+共享互为存在条件；虚拟=物理→逻辑多份 | ☆常规 |
| 6 | 多道/分时/实时特点比较 | 分时=时间片+交互；实时=及时+可靠 | ☆常规 |
| 7 | 大内核 vs 微内核 | 微内核=内核只留最基本功能，其余用户态服务 | ○了解 |

- **代表例（题型2）**：下列哪些事件引起用户态→核心态？除零异常（是，内中断）、时钟中断（是，外中断）、调用 `printf`（看情况：库函数本身用户态执行，内部触发系统调用陷入才切换）。
- **常见易错**：把「陷入指令」当特权指令（错——它恰恰在用户态执行）；把「进程切换」当用户态→核心态的诱因（进程切换**发生在核心态内部**，不是切换的原因）；把库函数与系统调用划等号（`strlen` 不涉及系统调用）。
