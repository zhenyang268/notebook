## 1 定位与现状

### 1.1 一句话

> **CS336 教的不是"怎么用 LLM"，而是"怎么从零造一个 LLM"——从原始网页数据、字节级 tokenizer、每一个 Linear 层、每一个 Triton kernel、每一卡 all-reduce，一路写到 GRPO 对齐，整条 LLM 生命周期自己走一遍。**

官网原话：仿照"从零写操作系统"的 OS 课，带学生走完 language model 的每个环节——pre-training 数据的收集与清洗、Transformer 模型构建、训练、部署前评测。5 个学分，官方原话警告："This is a very implementation-heavy class"。

三个决定课程气质的事实：
1. **先修要求里写明"minimal scaffolding"**——给的脚手架比其他 AI 课少一个数量级，代码量比其他课大一个数量级。
2. **Honor code 明确禁止看现有实现**（handout 自包含），且强烈建议关掉 AI 自动补全。课程认为"AI autocomplete 让你很难深入内容"。
3. **官网 schedule 给 A1/A2/A4 挂了 leaderboard 链接**（A3/A5 无）——这门课把"工程做得好不好"变成了可排名的量化指标。

### 1.2 LLM 生命周期阶梯：5 个作业就是 5 个落点

```
  数据（Common Crawl）            A4 Data: 抽取/过滤/去重 → 高质量预训练集
        |
  Tokenizer（byte-level BPE）     A1 Basics: 从字节训练 BPE，encode/decode
        |
  模型（Llama 式 Transformer）    A1 Basics: RMSNorm/RoPE/SwiGLU/causal attention
        |
  优化器与训练循环                 A1 Basics: AdamW + cosine + clipping + checkpoint
        |
  系统（GPU/多卡）                A2 Systems: profiling/混合精度/FlashAttention2/DDP/ZeRO-1
        |
  缩放（实验科学）                A3 Scaling: isoFLOPs 幂律拟合 → 外推大模型超参
        |
  对齐（SFT → RL）               A5 Alignment: SFT/DPO/GRPO + 评测（GSM8K/MMLU/safety）
```

注意这条线是**真实的 LLM 生产管线顺序**（数据 → 模型 → 训练 → 系统 → 规模化 → 对齐），但课程交付顺序是 A1 模型先行、A4 数据靠后——因为模型侧的反馈最直接（loss 曲线），数据侧需要先有可信的训练管线。

### 2.4 一条贯穿全课程的方法论

CS336 的作业设计重复同一个循环，本质与 CS149 的"run-measure-hypothesize-change"同构，但对象从"并行程序"换成了"训练管线"：

```
1. 核算    先算再跑：这一步的理论 FLOPs / 显存字节 / 通信量是多少？
2. 测量    timeit / nsys / memory profiler，拿到实际数字
3. 对账    实测 MFU（每秒 FLOPs / 硬件峰值 FLOPs）到不到 50%？显存对不对得上手算？
4. 归因    差距来自 kernel 效率、通信、还是 Python 开销？
5. 改进    换实现（torch.compile / Triton / bf16 / 分桶通信），回到 2
```

A2 是这个循环的主战场，但 A1 的"written assignment"（官方要求 FLOPs 核算与内存分析，社区提交里普遍含 write_up.md）和 A4 的"数据质量 → 验证 loss"都在练同一件事：**先有数量级预估，再看测量结果**。

## 3 设计理念（最值钱的一节）

### 3.1 "从零"不是姿态，是控制力：抽象栈全栈打通

一般 LLM 工作者的世界被 HuggingFace 切成了三层：tokenizer 是个黑盒、model.forward 是个黑盒、trainer 是个黑盒。CS336 的赌注是：**只有每一层都亲手写过一遍，你才可能在任何一层 debug**。五个作业正好对应五层抽象：

| 层 | 平时怎么用 | CS336 怎么造 |
|---|---|---|
| Tokenizer | `AutoTokenizer.from_pretrained(...)` | byte-level BPE 从 merge 学习算法开始写（A1） |
| 模型 | `AutoModelForCausalLM` | Linear/Embedding/RMSNorm/RoPE/attention 手写并过数值快照测试（A1） |
| 训练循环 | `Trainer.train()` | AdamW、cosine schedule、clipping、checkpoint 全手写（A1） |
| 性能 | `torch.compile` 一把梭 | 先手算 FLOPs/带宽，再用 Triton 手写 FlashAttention2，DDP 手写两档（A2） |
| 数据 | 下载现成数据集 | Common Crawl → 抽取/过滤/去重全链路（A4） |

"造轮子"的回报在 A2 立刻兑现：**你优化的对象是你自己写的模型**，所以瓶颈在哪、哪一层值得 fusion，你比任何人都清楚。

### 3.2 契约式开发：adapter 模式 + 数值快照 = 把"接口"和"实现"解耦

这是 CS336 工程上最值得学的一手。每个作业的官方测试不 import 你的代码，而是调用 `tests/adapters.py` 里的一组 `run_*` 函数，全部初始为 `raise NotImplementedError`；你填上"我的实现"的引用，测试就活了。效果：

1. **你可以自由组织代码结构**（叫什么文件名、拆几个类都行），课程只约束**函数签名与语义**——这正是工业界"接口契约 + mock 测试"的做法。
2. **数值对拍用 snapshot**：`_snapshots/*.npz` 存了 staff 参考实现在固定输入下的输出，`numpy_snapshot.assert_match(actual, atol=1e-4)` 逐元素对拍。你写的不只是"能跑"，而是"和参考实现逐位一致（容差内）"。
3. **测试即规格书**：A1 有 21 个 adapter 函数，每个 docstring 就是最精确的作业需求文档（形状、含义、边界）。动手前先通读 adapters.py 与 test 文件，等于先读一份机器可执行的 spec。

复习启示：**"这个组件我要实现什么"的第一来源不是 handout 正文，而是测试**。测试会把 handout 里模糊的措辞钉死成形状与数值。

### 3.3 架构共识：A1 造的是一个"现代 Llama"，不是 2017 年的 Transformer

A1 的 state_dict 契约（tests/adapters.py:279 起，本地实测）写死了架构选型：

- `token_embeddings` + 独立 `lm_head`（不强制共享权重）
- 每层 `attn.q_proj / k_proj / v_proj / output_proj`——**分离的 QKV 投影，无 bias**
- `ln1` / `ln2` / `ln_final` 全是 **RMSNorm**（一维 gain，无 bias、无均值中心化）
- FFN 是 `w1/w2/w3` 三矩阵——**SwiGLU**：`w2(silu(w1 x) * w3 x)`，d_ff 通常取约 8/3 倍 d_model 再取整到 64 的倍数
- 位置编码是 **RoPE**（`rope_theta` 是 LM 的构造参数，默认 10000）

这不是复古练习：GPT-2（post-LayerNorm、绝对位置、GELU MLP）到 Llama（pre-RMSNorm、RoPE、SwiGLU）的演进，就是 2019→2024 的主流开源架构演进。**A1 让你复刻的是"今天的标准件"**，所以直接可以对着 Llama 配置理解每个旋钮（theta 影响长度外推、d_ff 配比、head 数与 d_k 的权衡）。消融（no-norm/post-norm/no-RoPE/无门控 SiLU）是 handout 明确建议的实验（社区提交普遍包含这些变体），能亲眼看到"为什么是 pre-norm"。

### 3.4 资源核算先行：FLOPs / 显存 / 通信，三本账都要会算

L2（resource accounting）是整门课的"物理课"，三本账贯穿后面每个作业：

1. **FLOPs 账**：Transformer 前向约 `2*N*D`（N 参数量、D token 数），前向+反向约 `6*N*D`。这是 A3 scaling law 里 C ≈ 6ND 的来源，也是 A2 里 MFU 的分母。
2. **显存账**：fp32 下参数 4N 字节、AdamW 动量+方差各 4N、梯度 4N——**优化器状态才是大头**（共约 16N 字节，A2 的 sharded optimizer 就是为它而生）。混合精度再叠加 fp32 master weights 与 bf16 激活两套账。
3. **通信账**：DDP 每步 all-reduce 梯度约 `2 * 4N` 字节（ring all-reduce 的 2 因子）；ZeRO-1 把优化器状态按卡数分片后，通信量不变但显存除以卡数。A2 要求你手算并与实测对账（社区提交里的 communication_accounting / optimizer_state_sharding_accounting）。

**先算后测、算测对齐**是 LLM infra 面试的第一道筛子（"7B 模型 AdamW 训练要多大显存？"是送分题，前提是你会这三本账）。

### 3.5 Scaling laws 是实验科学，不是查表

A3 的立场：幂律不是背出来的常数，是**用一组受控实验点在 log-log 空间拟合出来的经验规律**。方法论三件套：

- **isoFLOPs 实验**：固定计算预算 C，扫模型规模 N（数据量 D = C/(6N) 自动定），每个 C 找 loss 最低的 N_opt(C)；
- **log 空间拟合**：对 (log C, log N_opt) 做最小二乘，得 N_opt ≈ k * C^a（本地数据 72 个点，社区复算 a ≈ 0.47，D_opt 指数 ≈ 0.53，两者相加 ≈ 1，与 6ND 约束自洽）；
- **外推 + 预测**：把幂律外推到 10^23 / 10^24 FLOPs，提交"该预算下该训多大的模型、喂多少 token"。Kaplan（2020）与 Chinchilla（2022）的分歧（参数优先 vs 数据优先）就是这两条拟合线的分歧。

理念要点：**小规模实验的价值在于"可外推的函数形式"，而不是"小模型本身好用"**。这正是 DeepMind/OpenAI 用 1e18 FLOPs 级实验指导 1e23 级训练决策的逻辑。

### 3.6 数据是模型的"真实规格说明"

L1 原话（可执行讲义）：模型能做什么几乎完全由数据决定——多语言数据给多语言能力，代码数据给代码能力。A4 把这条理念工程化：

- **质量是过滤链**：抽取 → 语言识别 → 质量分类（模型分类器 + Gopher 启发式规则）→ 毒性/NSFW → PII 脱敏。每一环都是"定义什么算好数据"的价值判断。
- **去重分两级**：精确去重（行/文档级 hash）解决完全重复；模糊去重（MinHash + LSH 近似 Jaccard）解决"洗稿式"近似重复。经典结论：去重显著降低记忆化（memorization）并提升下游能力。
- **闭环验证**：A4 的 leaderboard 用**不可修改的 staff 训练代码**在不同学生过滤出的数据上训模型，比 validation loss——把"数据工程做得好不好"变成单一可比数字。这是工业界"数据质量 → 模型质量"回归测试的缩影。

### 3.7 对齐是优化问题：从 SFT 到 GRPO 是一条"约束越来越少的梯度链"

A5 的三个阶段其实是同一个思想（把人不能直接写出的目标变成可微/可采样的损失）的三种实现：

- **SFT**：把"好行为"示范出来（监督信号 = 示范 token 的交叉熵，response mask 保证只对回答算 loss）；
- **DPO**（可选 Part 2）：不训 reward model、不跑 RL，直接从偏好对 (chosen, rejected) 构造隐式 reward 的闭式损失；
- **GRPO**（主作业的 RL 部分）：连偏好标注都不要——同一 prompt 采一组回答，组内归一化的奖励当 advantage（`A_i = (r_i - mean(r)) / std(r)`），再套 PPO 式 clip。R1-Zero 证明这条路能"涌现"出长推理。

数学 grader（`drgrpo_grader.py`，取自 understand-r1-zero 的 math_grader）负责把 `<answer>...</answer>` 里的数学答案判成 0/1 奖励——**RL 的"环境"就是一个正则 + sympy 的判分器**。对齐的去魅：reward 是代码，优势是减均值除标准差，损失是 clipped surrogate——每一步都可以在一张 A 卡上复现。

### 3.8 一个隐藏主题：课程在教"工程品味"

把 3.1–3.7 连起来看，CS336 真正的产品不是"你训出了一个 30M 的玩具模型"，而是几条可迁移的判断力：

- 看到任何训练数字，先问**数量级对不对**（3.4）；
- 看到任何结论，先问**它是哪个实验设计推出来的**（3.5 的 isoFLOPs、3.6 的对照训练）；
- 看到任何黑盒，先问**接口契约是什么、我能不能写个对拍**（3.2）;
- 看到任何"对齐/能力"，先问**这在数据或奖励函数里是怎么定义的**（3.6/3.7）。

### 4.1 A1 · Basics：tokenizer + Transformer + 优化器 + 训练

**抓重点**
1. 四大块：**byte-level BPE tokenizer**（训练 + encode/decode + special tokens）、**Llama 式模型**（RMSNorm/RoPE/SwiGLU/causal MHA）、**优化器与训练组件**（AdamW、SGD、cosine warmup、clipping、cross entropy、get_batch）、**序列化**（save/load checkpoint）。
2. 21 个 adapter 函数 = 21 份机器可执行的需求文档，先通读再动手。

**细节与易错点**
- BPE 必须在 **pre-token 划分后**的词内统计 merge，不能跨词；vocab 前面 256 个是字节本身；special token 占独立 id 且**永不参与 merge**（测试断言非 special 词中不含 b"<|"）。
- attention 的 scale 是 1/sqrt(d_k)；causal mask 用 additive(-inf) 形式；测试同时考 3 维与 **4 维**（batch × heads × seq × d_k）SDPA。
- RoPE 作用在**每对维度**（i, i + d/2 旋转），且 **q、k 都旋转、v 不旋转**；theta 默认 10000。
- cross entropy 要对 logits 做 logsumexp 稳定化；batch 维展开时注意忽略 padding。
- checkpoint 要存 model/optimizer/schedule 状态才能断点续训（test_serialization 有 ts_tests fixture）。

**设计理念**：§3.2（契约式）+ §3.3（现代架构共识）——A1 是"用测试驱动的接口思维复刻一遍 Llama 论文里的每个标准件"。

### 4.2 A2 · Systems：benchmark、混合精度、FlashAttention2、DDP、ZeRO-1

**抓重点**
1. 三大件：**性能工程**（timeit 基准表、nsys 剖析、显存剖析、torch.compile、bf16 autocast 对比）、**FlashAttention2**（先用纯 PyTorch op 写一版 forward+backward，再写 Triton 版）、**分布式**（逐参数异步 DDP → 分桶 DDP → 优化器状态分片）。
2. 这是唯一必须 GPU 的"写 kernel"作业（Triton 测试 device="cuda"）。
3. 测试对拍口径：FlashAttention 输出 **O 与 LSE（logsumexp）双对拍**，前向反向、causal 与非 causal 全覆盖。

**关键路径**：bench A1 各层（CPU/GPU 时间表）→ nsys 看时间线 → PyTorch 版 FA2（先正确）→ Triton 版 FA2（再快）→ 单机 all-reduce 基准 → DDP 逐参数 → DDP bucketed → sharded optimizer → writeup（通信/显存核算表）。

**细节与易错点**
- online softmax 的核心是**重缩放**：新块进来时旧累加和要乘 exp(m_old - m_new)（§7.1 伪代码）。
- Triton 反向要处理 **dQ 的原子累加**或分块重算（官方 CHANGELOG 提过更新 dQ 的说明）。
- DDP 逐参数版：梯度 ready 一个发一个（async all-reduce），与反向计算重叠；bucketed 版把多个梯度拼桶再发，**桶越大通信越少但重叠越差**，测试参数化 bucket_size_mb。
- sharded optimizer 注意：**optimizer step 之前必须先 all-gather 梯度**（或 reduce-scatter），别在分片状态直接 step。

**设计理念**：§2.4 的核算循环在真实硬件上闭环；"正确 → 快 → 省显存 → 可扩展"是层层叠加的独立决策，不是一锅炖。

### 4.3 A3 · Scaling：组件消融 + isoFLOPs 拟合 + 外推

**抓重点**
1. 两部分：**组件消融**（用 staff 给的 BasicsTransformerLM，逐个换掉组件看 loss 曲线差异——对应官网"理解 Transformer 各组件的作用"）+ **scaling law 拟合与外推**（对 72 条 isoFLOPs 记录拟合，提交更大预算的超参预测）。
2. 手算公式只有三个：C ≈ 6ND、D_opt = C/(6 N_opt)、log-log 线性回归。

**关键路径**：读 isoflops_curves.json → 每个 compute_budget 分组、取 loss 最小的 parameters → 得 (C_i, N_opt_i) 序列 → log-log 最小二乘 → 外推 10^23/10^24 → 消融实验报告。

**细节与易错点**
- 拟合一定在 **log 空间**做（幂律在 log-log 下是直线；在原空间拟合等于让大数点独占权重）。
- 每条预算曲线的点数不均衡，别把全部 72 个点直接回归 N(C)——**先取每个 C 的最优，再拟合最优序列**。
- 消融一次只动一个变量（L3 的"架构超参"讲座就是这个精神）。

**设计理念**：§3.5——实验设计（isoFLOPs）+ 函数形式（幂律）+ 外推决策，这就是"用小实验买大模型的超参"的完整逻辑。

### 4.4 A4 · Data：Common Crawl → 预训练集

**抓重点**
1. 六环过滤链：**HTML 抽取 → 语言识别（fastText）→ 质量过滤（分类器 + Gopher 规则）→ 有害内容分类（NSFW/毒性）→ PII 脱敏（email/电话/IP）→ 去重（精确 + MinHash/LSH 模糊）**，tests 六个文件一一对应。
2. Gopher 规则五条（本地测试可核实）：非符号词数 50–100000、平均词长 3–10、省略号结尾的行 <= 30%、含字母的词 >= 80% 等。
3. 收官：用**不可修改的 staff 训练代码**在过滤后数据上训模型、比 validation loss（leaderboard）。

**关键路径**：先过六个单测（纯 CPU）→ 拼 pipeline 处理一小批 WARC/WET 样本 → 全量跑 → tokenize（用你 A1 的 tokenizer）→ 训练对照 → writeup 分析每环过滤率与 loss 的关系。

**细节与易错点**
- HTML 抽取要容错（坏编码、坏标签；测试函数签名是 bytes 进、文本出）。
- fastText 语言识别输出 top-1 语言 + 概率，阈值截断要定；中文样例在测试里单列（简体）。
- MinHash：签名维度、band 数的取舍决定"近似的召回/精度"；测试同时考**完全重复**与**模糊重复**两种输入。
- PII 用正则掩码即可，但注意别把已有掩码串重复处理（测试有 existing_string 用例）。

**设计理念**：§3.6——每一环都是显式的价值判断；数据管线的产出用**受控训练对照**来打分，而非"看起来干净"。

### 4.5 A5 · Alignment：SFT + GRPO（+ 可选 DPO/safety）

**抓重点**
1. 主线：**SFT**（prompt+output 的 tokenize 与 response mask、packed dataset、microbatch 训练步）→ **GRPO**（组内奖励归一化、naive/clip policy gradient loss、entropy、response log probs、microbatch 训练步）→ **评测解析**（GSM8K/MMLU 答案抽取）。
2. 底座是官方 fixture 里的 **Meta-Llama-3-8B**；R1-Zero 式 prompt（`<think>...</think><answer>...</answer>`）+ math grader 判分。
3. 可选 Part 2（supplement PDF）：safety alignment、instruction tuning、RLHF/DPO——per-instance DPO loss 在主 tests 里也考（test_dpo.py）。

**关键路径**：tokenize_prompt_and_output（mask 语义）→ masked_mean / masked_normalize → SFT microbatch step → parse_gsm8k/mmlu_response → 奖励与组归一化 → policy gradient（naive → clip）→ GRPO microbatch step → DPO loss → 跑通一次小规模 GRPO 训练。

**细节与易错点**
- `input_ids` 是 prompt+output 切掉最后一个 token，`labels` 是左移一位（无第一个 token），`response_mask` 只在 labels 的 response 区间为 1——**三个张量长度相等**，差一位对齐是最大坑。
- GRPO advantage：组内 `(r - mean) / (std + eps)`，`normalize_by_std` 可关；**prompt 不参与 loss**（response-only）。
- clip loss 形同 PPO：`min(ratio * A, clip(ratio, 1-eps, 1+eps) * A)`，但 ratio 对象是**序列级**还是 token 级要按 handout 口径。
- DPO 损失：`-log sigmoid(beta * ((log pi(chosen) - log pi_ref(chosen)) - (log pi(rejected) - log pi_ref(rejected))))`，易漏 beta 和 reference model。

**设计理念**：§3.7——SFT/DPO/GRPO 是"人给信号的形式"递减（示范 → 偏好 → 只有个判分器）而优化难度递增的一条链；把 RL 拆到"一个判分器 + 组内归一化"的粒度，就没有魔法了。

## 5 A1 展开（一）：byte-level BPE tokenizer

### 5.1 为什么 byte-level：词表永远够用

BPE 的输入如果不是字节，就有"遇到训练时没见过的字符怎么办"的问题（UNK）。byte-level BPE（GPT-2 引入）把任意 UTF-8 文本先落到**字节序列**（256 种），词表从 256 个字节出发向上 merge，**任何字符串都可编码**，永不 OOV。

GPT-2 还做了一步"字节→可打印字符"的映射（`gpt2_bytes_to_unicode()`，tests/common.py 本地自带）：把 256 个字节映射到可打印 unicode 区间，纯粹为了让 merges 文件可读。**你内部实现可以全程用 bytes，不必真做这层映射**——但读官方 gpt2_merges.txt / gpt2_vocab.json fixtures 时要用它反向解码（test_train_bpe.py:40-49 就是这么干的）。

### 5.2 pretokenization regex：BPE 只在词内进行

L1 讲义明确（可执行代码原文）：A1 的 encode 要"Use pre-tokenization (e.g., the GPT-2 tokenizer regex)"。GPT-2 的正则（Python `regex` 库，不是 `re`）：

```
's|'t|'re|'ve|'m|'ll|'d| ?\p{L}+| ?\p{N}+| ?[^\s\p{L}\p{N}]+|\s+(?!\S)|\s+
```

逐段读：
- `'s|'t|'re|'ve|'m|'ll|'d`：英文缩写拆出来；
- ` ?\p{L}+`：可选前导空格 + 连续 unicode 字母（" dogs" 带空格成一个 pre-token）；
- ` ?\p{N}+`：可选空格 + 连续数字；
- ` ?[^\s\p{L}\p{N}]+`：可选空格 + 连续标点/符号；
- `\s+(?!\S)`：**结尾是最后一个词前的那段空白**（负向前瞻：后面不是非空白才吃），保证"词前空格归属该词"；
- `\s+`：其余连续空白。

两个工程要点：
1. 用 `regex` 库（`\p{L}` 这类 unicode property 类 `re` 不支持）；
2. 空格是 `\x20`，落到字节后是可 merge 的普通字节——所以 GPT-2 词表里的 " the" 之类带空格 token 是自然学出来的。

**为什么必须 pre-tokenize**：不让 merge 跨词边界（"dog" 与 "cat" 之间不该产生合并），同时大幅压缩统计空间（词内 pair 种类远少于全文 pair 种类）。

### 5.3 train_bpe：merge 学习算法

签名（tests/adapters.py:565 起，本地实测）：输入 `input_path`、`vocab_size`、`special_tokens`，输出 `(vocab: dict[int, bytes], merges: list[tuple[bytes, bytes]])`。

```
算法（词内 BPE）：
1. 读文件为 bytes；先按 special token 切开，special 段丢弃（不参与统计）
2. 对每段跑 pretokenization regex → pre-token 流
3. 每个 pre-token 转为 bytes 序列，统计词频：
   word_counts: {tuple[bytes, ...]: int}
4. vocab ← {0..255: 单字节}（再预留 special token 的 id）
5. 重复直到 len(vocab) == vocab_size：
   a. 统计所有词内相邻 pair 的加权频次：sum(count * 词内出现次数)
   b. 取频次最大的 pair（并列时取字典序最小的，保证与参考输出一致）
   c. merges.append(pair)；vocab[new_id] = pair[0] + pair[1]
   d. 对每个词做一遍该 pair 的替换（word 内所有出现处合并）
6. 返回 vocab, merges
```

易错点逐条：
- **频次是词频加权**：pair (a, b) 的统计数 = sum over words (count(w) * count_of_(a,b)_in_w)，不是 pre-token 去重数；
- **并列取字典序最小**：参考 merges 是确定性的，随机 tie-break 会对不上 fixture（test_train_bpe 与 train-bpe-reference-merges.txt 逐条比对）；
- **special tokens 不进语料**：先用 `<|endoftext|>` 切语料再统计；special token 只作为独立 id 进 vocab，**永不作为 merge 的成分**（test_train_bpe_special_tokens 断言非 special 词不含 b"<|" 子串）；
- **vocab_size 包含 256 个字节与 special**：merge 次数 = vocab_size - 256 - len(special_tokens)，别多数或少做一轮；
- **性能**：朴素实现（每轮全量重扫全词表）过不了 test_train_bpe_speed——fixtures/corpus.en、vocab_size=500 限时 **1.5s**（staff 参考实现 0.38s）。标准优化：增量维护 pair 计数（合并一个 pair 只影响含该 pair 的词）、用 `dict[tuple[bytes,...], int]` 聚合同形词、必要时用官方 `find_chunk_boundaries`（pretokenization_example.py，本地 62 行）多进程分块——它按 `<|endoftext|>` 找块边界，保证 special token 不被从中间切开。

### 5.4 encode / decode 流程

```
encode(text):
1. 按 special_tokens 把 text 切段（special 段原样映射为 special id）
2. 非特殊段跑 pretokenization regex 得 pre-tokens
3. 每个 pre-token 独立 BPE 编码：
   bytes 序列 → 反复套用 merges 中出现的规则（按 merges 顺序优先级）
   → 得到 token id 序列
4. 拼接返回 list[int]

decode(ids):
  bytes(b"".join(vocab[i] for i in ids), errors="replace") → str
  special token 的 bytes 直接拼（它就是字面字符串）
```

decode 是 O(n) 查表，无坑。encode 的两个性能要点（L1 讲义原话）："Only loop over merges that matter"——
- 对每个 pre-token 建 `bytes → id` 缓存（词会高度重复，缓存命中率极高）；
- 长词不必扫全部 merges：可按词内实际存在的 pair 建优先队列，只考虑候选 merge（或用"每轮找该词内可应用的最高优先级 merge"的循环）。

### 5.5 special tokens 的边界语义

tests（本地实测）钉死的语义：
- 构造 Tokenizer 时传 `special_tokens=["<|endoftext|>"]`，`encode` 默认**不允许**文本里出现 special（出现要抛错，与 tiktoken 的 allowed_special 语义一致）；
- `encode(text, allowed_special={"<|endoftext|>"})` 时，文本中的 `<|endoftext|>` 必须整体成为一个 id（test_string = "Héllò hôw <|endoftext|><|endoftext|> are ü? 🙃<|endoftext|>" 计数 3 个）；
- 若 special_tokens=["<|endoftext|>", "<|endoftext|><|endoftext|>"]，**先按更长的匹配**：连续两个 endoftext 应输出"双 token"的 id（测试断言单字符形式只出现 1 次、双形式出现 1 次）——即 special 匹配是"最长优先"的切分问题，不是简单 split；
- 多字节 unicode（é、ü、🙃）是字节级编码自然覆盖的考题点。

### 5.6 与 tiktoken 对照（自验方法）

## 6 A1 展开（二）：模型、优化器与训练组件

### 6.1 模块清单与整体数据流（按 adapter 契约）

```
in_indices (B, S)
  → Embedding(vocab, d_model)               token_embeddings.weight
  → [blocks x L]
       RMSNorm(ln1) → MHA(q/k/v/output_proj, RoPE, causal) → residual add
       RMSNorm(ln2) → SwiGLU FFN(w1,w2,w3)  → residual add
  → RMSNorm(ln_final)
  → Linear lm_head (vocab, d_model)         lm_head.weight
  → logits (B, S, vocab)   [未归一化 logits，不做 softmax]
```

契约细节（tests/adapters.py:279-358，本地实测）：
- **Linear 无 bias**（只有 weight）；Embedding 是纯查表；
- MHA 内部：`q = x W_q` 按 head 切成 (num_heads, d_k)，**q、k 过 RoPE**，SDPA 带 causal mask，输出过 output_proj 回残差流；
- FFN：`w2(silu(w1 x) * w3 x)`，w1/w3 形状 (d_model, d_ff)、w2 (d_ff, d_model)——门控分支乘性组合是 SwiGLU 的全部；
- 返回**原始 logits**，softmax 留给 loss 层（数值稳定与灵活性）。

### 6.2 attention 细节（SDPA 与 4D 形状）

```
scaled_dot_product_attention(q, k, v, mask):
    # q: (..., S_q, d_k); k,v: (..., S_k, d_k)
    scores = q @ k^T / sqrt(d_k)          # (..., S_q, S_k)
    if mask is not None:
        scores = scores + mask            # additive mask；causal 时下三角 0、上三角 -inf
    return softmax(scores, dim=-1) @ v
```

- 测试考 3 维与 4 维两种形状（4D = batch × heads × seq × d_k，test_4d_scaled_dot_product_attention.npz 对拍）——实现别写死维数，用 `...` 语义（einsum 或 matmul 广播）；
- causal mask 的 additive 形式：`mask[i, j] = 0 if j <= i else -inf`（-inf 而不是大负数，softmax 后才是精确 0）；
- RoPE 伪代码：

```
rope(x, positions, theta):        # x: (B, S, num_heads, d_k) 或按 head 逐个
  对每对维度 (2i, 2i+1)：
      angle = position / theta^(2i / d_k)
      x[2i]   = x[2i] * cos(angle) - x[2i+1] * sin(angle)
      x[2i+1] = x[2i] * sin(angle) + x[2i+1] * cos(angle)
```

维度配对方式（相邻配对 vs 前后半split）在不同实现有差异，**以测试快照为准**（fixtures 的 staff state_dict 是权威口径）；只旋转 q/k、不旋转 v。

### 6.3 AdamW 与 lr schedule

AdamW 更新（decoupled weight decay，与 Adam+L2 的区别就在 decay 项不经过 m/v 的自适应缩放）：

```
m = beta1 * m + (1 - beta1) * g
v = beta2 * v + (1 - beta2) * g^2
m_hat = m / (1 - beta1^t)          # bias correction
v_hat = v / (1 - beta2^t)
W = W - lr * (m_hat / (sqrt(v_hat) + eps)) - lr * weight_decay * W
```

- **Adam（耦合）**：把 `weight_decay * W` 加进梯度 g 再过 m/v——等效 decay 强度被 v 自适应缩放，大梯度参数 decay 变弱，行为不符合"权重衰减"本意；
- **AdamW（解耦）**：decay 作为独立项直接作用于 W。这是 LLM 训练的标准选择；
- 测试（test_adamw.npz 快照）会卡默认超参（beta1=0.9、beta2=0.95 或 0.999、eps=1e-8，以 handout/快照为准——不确定就跑一下测试读 conftest）。

cosine schedule with warmup（run_get_lr_cosine_schedule 契约）：前 `warmup_steps` 步线性 0→lr_max，之后按 `lr_min + 0.5*(lr_max-lr_min)*(1 + cos(pi * t/T))` 衰减到 `lr_min`。**warmup 的存在理由**：训练初期 Adam 二阶矩估计噪声大、大 batch 初期梯度方向不稳定，小 lr 起步能防早期发散。

### 6.4 训练组件三件套（tests/test_nn_utils / test_data / test_serialization）

- `run_softmax`：数值稳定版（减 max 再 exp/sum）；
- `run_cross_entropy`：`mean over batch(非padding)` 的 `-log softmax(logits)[target]`，内部用 logsumexp；注意 (B*S, vocab) 展开与 ignore_index 语义；
- `run_gradient_clipping`：全局范数裁剪——先算 `sqrt(sum over all params ||g||^2)`，超过 max_l2_norm 才整体缩放 `g *= max_norm / global_norm`。**是全局范数，不是逐参数**；
- `run_get_batch`：从 uint16 numpy memmap 语料上按随机位置切 (B, T) 窗口，输入与目标错一位——**目标就是输入右移一位**（teacher forcing）；
- `run_save_checkpoint / run_load_checkpoint`：model + optimizer + schedule 状态整体序列化（fixtures/ts_tests 有 model.pt + model_config.json 对照），能 load 后继续训练且 loss 曲线无缝衔接才算合格。

### 6.5 训练跑通的最小验收

在 TinyStories 上（官方 README 数据源）：tokenizer（10k vocab）→ 配置一个小模型（社区参考：d_model 512 级别、10 层上下，约 10-30M 参数）→ AdamW + cosine → 数千步内 validation loss 降到 1.5 以下、能生成通顺小故事（社区报告 TinyStories 最好 ~1.3）。OpenWebText（32k vocab）是进阶：同架构训到 loss ~3.9（perplexity ~50）量级即超过 leaderboard 朴素基线（社区数字，非官方线）。

## 7 A2 展开：FlashAttention、混合精度与分布式

### 7.1 FlashAttention 的 online softmax（重缩放 + tiling）

朴素 attention 的显存瓶颈：`S x S` 的 attention matrix 要完整物化（写回 HBM）。FlashAttention 用两个手段消灭它：
1. **tiling**：K/V 按块（Br 列）进 SRAM，逐块算部分结果，永远不存完整 S x S；
2. **online softmax**：running max m 与 running sum l 随块更新，**旧结果按新 max 重缩放**。

```
forward（单 query 行块 Br x d_k，K/V 块长 Bc）：
m = -inf (Br,),  l = 0 (Br,),  O = 0 (Br, d_k)
for K_j, V_j in blocks(K, V):                 # j = 0..S/Bc
    scores_j = Q @ K_j^T / sqrt(d_k)          # (Br, Bc)
    m_new = max(m, rowmax(scores_j))
    p_j     = exp(scores_j - m_new)           # 稳定化
    l_new   = exp(m - m_new) * l + rowsum(p_j)      # 旧 l 重缩放！
    O       = exp(m - m_new)[:, None] * O + p_j @ V_j   # 旧 O 重缩放！
    m, l    = m_new, l_new
O = O / l[:, None]                             # 最后归一化
```

核心不变式：任意时刻 `(O, l, m)` 是"到目前为止所有块的、以 m 为数值锚的未归一化加权和"。**忘掉重缩放因子 exp(m - m_new)** 是第一大 bug 来源。

测试对拍口径（本地 test_attention.py）：除 O 之外还要对拍 **LSE = m + log l**（logsumexp 向量）——反向传播需要它，`_attention_and_lse` 同时返回两者。backward 公式（标准结果）：

```
给定 dO：
P = exp(Q K^T / sqrt(d_k) - LSE)      # 无需存矩阵，逐块重算
dV = P^T dO ;  dP = dO V^T
dQ = dP K * (1/sqrt(d_k)) ;  dK = dP^T Q * (1/sqrt(d_k))
```

### 7.2 两版实现路径：PyTorch 先对，Triton 再快

- **PyTorch 版**（get_flashattention_autograd_function_pytorch）：用 `torch.autograd.Function` 手写 forward/backward，forward 内只许用标准 PyTorch op（测试明确"no Triton"）——目的是逼你把 backward 数学写对；
- **Triton 版**（get_flashattention_autograd_function_triton）：forward/backward 都换成 Triton kernel。要点：block 尺寸选择（BLOCK_M/BLOCK_N 与 shared memory 容量）、causal 时跳过上三角块（按块判断整块跳过，省一半计算）、**dQ 原子累加问题**（多个 K 块都往同一 dQ 加，用 atomic_add 或重算一遍 K 循环分两段处理；官方 CHANGELOG 专门更新过 dQ 的说明）；
- 实现顺序永远是：朴素 reference（直接 matmul+softmax）→ PyTorch FA2 过全部测试（causal/非 causal、forward/backward、O 与 LSE）→ Triton 版对拍 PyTorch 版 → 最后才看性能。

### 7.3 benchmark 与 profiling：这门课的"测量课"

A2 第一部分是对 A1 组件的系统测量（社区提交的标准动作清单，来自 handout 各节）：
- **timeit 基准表**：对 Linear/Embedding/attention/FFN/整个 block，CPU 与 GPU、不同 batch/seq/d_model 的耗时表（CSV）；
- **nsys 剖析**：NVIDIA Nsight Systems 时间线，看 kernel 间隙、memcpy、Python 开销；
- **显存剖析**：torch.cuda.max_memory_allocated 分层记录；
- **torch.compile 前后对比**：kernel fusion 的免费午餐有多少；
- **bf16 autocast vs fp32**：吞吐与数值差异（autocast_dtypes 实验：哪些 op 落到 fp16/bf16、哪些保持 fp32）。

验收指标：**MFU = 实测 FLOPs/s ÷ 硬件峰值 FLOPs/s**。一个 7B 级训练的 MFU 40-50% 算健康；低于 20% 说明有系统性浪费（通信不重叠、kernel 太碎、Python 循环）。

### 7.4 混合精度：三种数的角色分工

| 格式 | 角色 | 说明 |
|---|---|---|
| fp32 | master 权重 + 优化器状态 + 归约累加 | 精度锚点；m/v/权重更新必须 fp32 |
| bf16 | 前向/反向的主计算与激活 | 指数位宽与 fp32 相同（8 位），**动态范围大，不需要 loss scaling** |
| fp16 | 早期方案的主计算 | 尾数多（10 位）但指数只有 5 位，**大张量乘加容易上溢/下溢**，必须配 loss scaling |

loss scaling 的机制：反向梯度通常远小于 1，fp16 下大量梯度落到 subnormal 区被清零；把 loss 乘一个大常数 S 让梯度整体抬进可表示区，优化器 step 前再除回 S。**bf16 为什么不需要**：指数位与 fp32 一样多，可表示的量级范围不变，小梯度不会被清零（牺牲的是精度而非范围）。A2 handout 的 mixed precision 实验要求你在真实张量上复现这些结论（community 提交含 mixed_precision_accumulation.py：fp32 累加 vs bf16 直接累加的误差对比——**归约/累加永远回 fp32**）。

### 7.5 DDP：从朴素到分桶的演进逻辑

问题设定：数据并行，每卡一份完整模型副本，各卡吃不同 batch，梯度需保持一致。基准通信量：每步 **all-reduce 梯度 2*4N 字节**（ring 算法因子 2）。

| 实现 | 做法 | 通信次数 | 问题 |
|---|---|---|---|
| naive | backward 后逐参数 all-reduce | N_params 次 | 延迟串行，见 test 外的基准 |
| individual async（逐参数异步） | 某参数梯度一 ready 就 async all-reduce，与后续反向计算重叠 | N_params 次（小包） | 与计算重叠，但小包效率低 |
| bucketed（分桶） | 相邻（按反向就绪逆序排列的）参数梯度攒到 bucket_size_mb 再一起 reduce | N/bucket 次（大包） | 大包带宽利用率高，但必须等桶满——**桶大小是重叠与带宽的权衡**（测试参数化 bucket_size_mb） |

实现要点（adapters 契约）：
- `ddp_*_on_train_batch_start`：每步开始时把参数广播到各卡对齐（或仅首步）；
- `ddp_*_on_after_backward`：确保所有梯度同步完成（等未决 async 句柄）再 optimizer.step()；
- 测试在 **CPU 上以多进程** 跑（test_ddp.py 的 DistributedDataParallelCPU fixture），正确性口径是"与单卡数值一致"。

### 7.6 sharded optimizer：ZeRO-1 的最小实现

显存账（fp32，每参数）：权重 4B + 梯度 4B + AdamW m 4B + v 4B = 16B/参数，其中 **m/v（8B）归优化器**。ZeRO-1 的主张：m/v 按卡分片，每卡只存自己那 1/K 的优化器状态。

最小正确实现（get_sharded_optimizer 契约）：
1. 参数按卡切分，本卡只为自己分片内的参数建 m/v；
2. backward 后梯度 **reduce-scatter**（每卡拿到自己分片参数的完整平均梯度）；
3. 各卡独立 step 自己分片的参数；
4. step 后参数 **all-gather** 回全量（下一轮前向要用完整模型）。

通信量对比：all-reduce = reduce-scatter + all-gather，所以 ZeRO-1 **不省通信，只省显存**（m/v 从 8B/参数 降到 8B/K）。ZeRO-2（梯度也分片）、ZeRO-3/FSDP（参数也分片）是同一逻辑的递进。A2 只要求到 ZeRO-1。

## 8 A3 展开：scaling laws 的完整工作流

### 8.1 两派结论的分歧点

- **Kaplan et al. 2020**（OpenAI）：固定算力下最优参数规模增长快——"大模型优先"（对固定 C，N_opt ~ C^0.73 量级，推导自其拟合形式；具体指数以论文为准），推论是"在数据不够时先训大模型再停"；
- **Hoffmann et al. 2022**（DeepMind，Chinchilla）：修正 Kaplan 的（后来被指偏小的）学习率 schedule 与数据范围后，得 N_opt ~ C^0.5、D_opt ~ C^0.5，经验法则 **D* ≈ 20N**——"模型与数据同步增长"，70B Chinchilla 以 1.4T tokens 打败了更大的 Gopher。

方法论教训（比结论重要）：两派的差别不在拟合，而在**实验设计**（Chinchilla 用了三种方法交叉验证：固定模型扫数据、固定数据扫模型、isoFLOPs 曲线）。A3 用的正是 isoFLOPs 法。

### 8.2 isoFLOPs：本地数据的工作流（72 个点，实测结构）

本地 `assignment3-scaling-main/data/isoflops_curves.json`（已解压核实）每条记录形如 `{"parameters": 49999999, "compute_budget": 6e18, "final_loss": 7.19}`，共 72 条，覆盖多个 compute_budget 档位 × 每档多个参数规模。

```
步骤：
1. 按 compute_budget 分组（isoFLOPs 线：同预算下扫 N）
2. 每组内取 final_loss 最小的 parameters → (C_i, N_opt_i)
   同时恢复该点的数据量：D_opt_i = C_i / (6 * N_opt_i)
3. 在 log-log 空间做最小二乘：
   log N_opt = a_N * log C + b_N  ⇒  N_opt ≈ exp(b_N) * C^a_N
   log D_opt = a_D * log C + b_D  ⇒  D_opt ≈ exp(b_D) * C^a_D
4. 检查自洽性：a_N + a_D ≈ 1（由 C ≈ 6ND 的乘法约束）
5. 外推：C = 1e23 / 1e24 代入，给出预测的 N_opt、D_opt、
   以及"给定预算下的 batch size / 训练步数"等提交项
```

社区复算（对同一份数据）：N_opt ≈ 1.16 * C^0.469、D_opt ≈ 0.14 * C^0.531，外推 1e23 FLOPs 得约 70B 参数 / 240B tokens——即 Chinchilla 口径。你的数字允许小差别（拟合细节），**指数和 ≈ 1 的自洽检查**与**log 空间拟合**是硬要求。

### 8.3 组件消融：把"为什么是这个架构"变成实验

staff 给的 `cs336_scaling/model.py`（BasicsTransformerLM，已解压核实）就是 A1 的参考版，构造参数含 attn_pdrop/residual_pdrop——消融实验的做法：同一数据、同一步数预算，逐个替换（pre-norm → post-norm / 去 norm / 去 RoPE / SwiGLU → 无门控 SiLU），比较验证 loss。社区 A1 提交的普遍结论可当预期：去 RMSNorm 几乎发散、post-norm 略差于 pre-norm、去 RoPE 最伤、无门控 SiLU 在小规模出人意料地接近（1.33 vs 1.35）。**消融一次只动一个变量**，这是 L3 讲座的实验纪律。

### 8.4 易错点

- 在原空间拟合幂律（没取 log）→ 大 C 的点独占回归权重，指数严重偏；
- 直接对 72 个点回归 loss(C) 而不是"每预算取最优再拟合 N_opt(C)"——两条曲线语义完全不同；
- 忘了 D = C/(6N) 的恢复关系，把 N_opt 与 D_opt 当独立量拟合；
- 外推时把 6ND 的 C 定义换掉（比如把 embedding 参数排除在 N 外却不同步换系数）。

## 9 A4 展开：Common Crawl 数据管线

### 9.1 原料与总览

Common Crawl 是对全网 的周期性抓取存档，格式为 WARC（原始 HTTP，含 HTML）/ WAT（元数据）/ WET（抽取后的纯文本）。A4 的对象是原始 dump：从 HTML/坏编码/多语言/垃圾页里榨出干净的预训练语料。六环管线（tests 六个文件一一对应，本地已核实）：

```
WARC/HTML bytes
  → ① extract_text_from_html_bytes     抽取正文
  → ② identify_language                fastText 语言识别
  → ③ classify_quality + gopher 规则    质量过滤
  → ④ classify_nsfw / classify_toxic    有害内容过滤
  → ⑤ mask_emails / mask_phones / mask_ips   PII 脱敏
  → ⑥ exact line dedup + minhash 去重   去重
  → 干净语料 → 用 A1 tokenizer 编码 → staff 训练代码 → leaderboard
```

各环的资产（get_assets.sh 下载）：fastText 语言模型（lid.176.bin 类）、质量分类器（wiki-vs-CC 类训练的 fastText 模型）、NSFW/毒性分类器——**过滤器的本质是"别人训好的分类器 + 你定的阈值"**。

### 9.2 逐环要点（测试口径）

**① HTML 抽取**：输入 bytes（可能是坏编码），输出文本。要容错：`errors="ignore"` 解码、script/style 标签内容剔除、实体处理。工业级工具是 resiliparse / trafilatura（社区实现普遍用 resiliparse + 多编码回退）；测试只考"从 HTML bytes 里拿到正文"的语义。

**② 语言识别**：fastText 输出 top-k (语言, 概率)；按目标语言（如 en 或多语言集合）过滤，阈值自定（社区常用 0.5-0.9，写进 writeup 说明）。测试考英语与简体中文两个用例。

**③ 质量过滤**两层：
- 分类器层：fastText 质量分类器（区分维基风格正文 vs 乱七八糟网页）打分过阈值；
- 启发式层（Gopher 规则，tests 可核实）：非符号词数在 [50, 100000]、平均词长在 [3, 10]、以省略号结尾的行 <= 30%、含字母字符的词 >= 80% 等。每条规则的动机都是某类垃圾页的特征（词太少=导航/碎片页；词超长=爬虫故障页；省略号行多=书爬站）。

**④ 有害内容**：NSFW 与 toxic speech 两个分类器分别过阈值（tests 分别考）。这一环同时是"数据政策"的体现——过滤掉什么，是在定义模型的边界。

**⑤ PII 脱敏**：正则掩码 email / 电话 / IPv4。测试细节：掩码串不能二次处理（existing_string 用例——已含掩码的文本再跑一遍不应变形）。

**⑥ 去重两级**：
- **精确去重**：对整行或整文档取 hash，重复即删（test_exact_line_deduplication）。成本 O(n)，解决"完全相同的副本"；
- **MinHash + LSH 模糊去重**：文档 shingle → k 个随机哈希签名（每签名取最小值）→ 签名切成 b 个 band、同 band 碰撞进同一桶 → 桶内候选对算精确 Jaccard，超阈值判重。参数直觉：签名数 k 越多估计越准；band 数 b 越多召回越高的同时误报越多。测试考**完全重复**（应 100% 抓住）与**模糊重复**（改写/局部变动也应抓住）两种。

去重的已知收益（讲义层结论，源自 Deduplicating Language Data 等工作）：更少记忆化（memorization）、下游能力提升、epoch 数实际上限抬高。

### 9.3 闭环：leaderboard 的对照实验设计

A4 README（本地核实）：staff 训练代码**不许改**（"your leaderboard submission must use it exactly"），比的是同一训练预算下不同过滤管线产出数据的 validation loss。这是教科书级的**受控实验**：训练代码 = 控制变量，数据管线 = 自变量，loss = 因变量。写 writeup 时每一环给出"过滤掉的比例 + 对 loss 的影响"，就是一份迷你数据消融报告。

### 9.4 易错点

- 先去重后过滤还是先过滤后去重？顺序影响成本与召回（正确直觉：便宜的规则过滤在前、贵的 MinHash 在后，但要注意"过滤-induced 的近重复"现象）；
- fastText 阈值定太紧把好数据杀掉——写up 里要给出每环保留率，别只报最终 loss；
- MinHash 只做 LSH 不做精确 Jaccard 复核，误报会把不同文档错误合并；
- 全流程在 pandas/DataFrame 里逐文档 Python 循环——数据管线要用批处理思维（生成器/stream，语料远大于内存）。

## 10 A5 展开：SFT、DPO 与 GRPO

### 10.1 SFT：数据形态与训练步

核心函数 `run_tokenize_prompt_and_output`（本地 adapters 实测）的返回契约：

```
input_ids:     (B, L-1)   prompt+output token 序列，切掉最后一个 token
labels:        (B, L-1)   input_ids 左移一位（去掉第一个 token）
response_mask: (B, L-1)   在 labels 上，属于 response 的位置为 1，其余（prompt/padding）为 0
```

三个张量**同长**，`input_ids[i, t]` 的预测目标是 `labels[i, t]`——错位一位是 next-token 训练的 tensor 化。SFT loss 只对 response token 算（`masked_mean`），**prompt 不产生梯度**。

`get_packed_sft_dataset`：把多条样本拼接（packing）成定长序列提高利用率——难点是**跨样本边界不能互相注意**：需要 block-diagonal 的 attention mask（样本 i 的 token 看不到样本 i-1 的 token），以及逐样本的 position_ids 重置。`run_sft_microbatch_train_step`：大 batch 切 microbatch 累加梯度的标准操作（A5 测试同样考 GRPO 的 microbatch 版）。

底座：官方 fixtures 直接给了 **Meta-Llama-3-8B**（57MB zip 的大头就是它），配 alpaca_sft.prompt 模板（Alpaca 格式指令微调）。

### 10.2 DPO：从偏好对到闭式损失

`run_compute_per_instance_dpo_loss` 的目标函数（可选 Part 2 主题，主 tests 也考）：

```
pi_r(y)   = log pi_theta(y|x)   - log pi_ref(y|x)     # 隐式 reward，theta 相对 ref 的 log 比
loss = -log sigmoid( beta * ( pi_r(chosen) - pi_r(rejected) ) )
梯度方向：拉大 chosen 与 rejected 的隐式 reward 差
```

与 RLHF（PPO 路线）的关系：RLHF = 训 reward model + PPO 优化（要 reward model、value model、在线采样，工程重）；DPO 证明了偏好数据下存在**闭式解**的 reward（最优策略与参考策略的 log 比），于是损失直接作用于策略本身——离线、无 RM、无 rollout。代价：离线分布偏窄、易过拟合偏好数据（beta 是温度）。一句话：**DPO 是 RLHF 目标的监督化重写**。

### 10.3 GRPO：R1-Zero 式推理 RL

数据流（adapters 契约串起来）：

```
prompt x --采样 G 个回答--> y_1..y_G
  → drgrpo_grader 判分（<answer> 数学答案 vs 真值，sympy 级判定）
  → r_i = format_reward + answer_reward（可拆可合）
  → 组内归一化：A_i = (r_i - mean(r_group)) / (std(r_group) + eps)
     （normalize_by_std 可关，即只减均值——Dr.GRPO 的修正方向）
  → policy gradient loss（naive 或 clip 版）：
       naive: -mean( A_i * log pi_theta(y_i|x) )
       clip:  -mean( min(ratio * A, clip(ratio, 1-eps, 1+eps) * A) )
     其中 ratio = pi_theta(y_i|x) / pi_old(y_i|x)（重要度采样修正）
  → 加 entropy 项（run_compute_entropy：从 logits 算 -(p*log p).sum()）防坍缩
```

与 PPO 的差别：**没有 value network/critic**——advantage 不靠估值函数估计，而是"同题多解"的组内相对比较（这就是 Group 的含义）。这使得它对"0/1 判分"这类稀疏奖励特别友好。DeepSeekMath 提出 GRPO，DeepSeek-R1 用它 + 规则奖励复现了推理涌现。

`run_get_response_log_probs`：只取 response 段的 log prob 求和（mask 与 10.1 同一语义）。`run_grpo_microbatch_train_step` 里注意：rollout 用旧策略（no_grad），更新时才建图——**采样与更新分离**是 on-policy RL 的纪律（配 importance ratio 后允许轻微 off-policy）。

R1-Zero prompt（本地 r1_zero.prompt 原文）：system 段声明"reasoning in <think> </think>，answer in <answer> </answer>"，assistant 以 `<think>` 开头——**格式奖励（format_reward）就是判输出是否守这个格式**，answer_reward 判数学正确性。判分器（drgrpo_grader.py）来自 sail-sg/understand-r1-zero，支持 sympy/latex 的等价判定。

### 10.4 评测解析与安全

- `run_parse_gsm8k_response` / `run_parse_mmlu_response`：从模型输出里抽答案（GSM8K 的 `#### 数字` 或 think/answer 标签；MMLU 的选项字母），解析器鲁棒性直接决定指标可信度；
- data/ 里带了 `mmlu/possibly_contaminated_urls.txt`——**评测污染**（benchmark 题目泄进预训练语料的检查清单）是 L12 evaluation 的主题在作业里的落地：数据管线（A4）与评测（A5）在这里握手；
- scripts/evaluate_safety.py + simple_safety_tests.csv：安全评测（可选 Part 2 的安全对齐入口）；alpaca_eval：指令跟随的 LLM-judge 评测（脚本按 llama-3.3-70b 作裁判的口径命名）。

### 10.5 易错点

- response_mask 覆盖到 labels 而非 input_ids（错位一位后同一 token 在两个张量里身份不同）；
- 组归一化对**整组**做（同 prompt 的 G 个回答），不是全 batch——A_i 比较的是"同题的相对好坏"；
- ratio=1 的第一步更新（pi_old == pi_theta）时 clip 分支应与 naive 分支相同——单元测试的好抓手；
- GRPO rollout 忘了 `torch.no_grad()` → 采样图与更新图混在一起，显存爆炸且梯度语义错；
- DPO 忘了 reference model 项（变成纯 likelihood 训练，会同时拉高两者的绝对概率）。

## 11 从零实现的调试与对拍兵器库（全作业通用）

从零写 21 个组件，bug 的形态和"调包"时代完全不同：没有默认值兜底、没有报错信息指路，只有 snapshot 对拍失败时的 atol 超限。救援清单（按命中率排序）：

### 11.1 对拍三板斧

1. **降维复现**：snapshot 失败先把 batch/head/seq 全降到 1、d_model 降到 4，手算期望值写死断言。4 维 SDPA 错了，90% 是 reshape 时 head 维度排错——在最小形状上手 print 就现形；
2. **参考实现分治**：不 import 参考代码（Honor code），但可以用 `torch.nn.functional.scaled_dot_product_attention` / `torch.optim.AdamW` 生成对照数值（在 fixtures 的 state_dict 与输入上跑一遍存下来），逐层 diff 自己的输出与对照——**先定位是哪一层错，再看错在哪个元素**；
3. **相对误差读法**：`atol=1e-4, rtol=1e-2` 的容差下，如果误差在 1e-6 量级是 dtype 累加序问题（无害），在 1e-2 量级是公式错（如忘了 1/sqrt(d_k)），在完全随机量级是 shape 广播错（如 mask 广播到了错误维度）。

### 11.2 形状与 dtype 排查表

| 症状 | 高概率原因 |
|---|---|
| 全 NaN | softmax 前忘减 max；mask 用了 0/1 而不是 0/-inf（乘法 mask 遇 log）；lr 过大（该开 warmup） |
| loss 不降 | labels 与 input_ids 没错位；response_mask 全 0；optimizer 没拿到参数（传了 list 而非 generator 的坑）；lr schedule t 没递增 |
| 反向报 in-place 错误 | residual add 写成了 `x += ...`（改 `x = x + ...`）；norm 里的 in-place 除法 |
| 快照误差 1e-2 级稳定复现 | 公式缺项：忘 scale、忘 bias correction、RoPE 维度配对方式与参考不同 |
| GPU 上慢得离谱 | 张量按 head 维拆成了 Python list 循环（应合并成一个大 matmul）；每次 forward 重建 causal mask（应缓存） |

### 11.3 确定性与可复现

- 对拍前固定所有随机源：`torch.manual_seed` / numpy seed / `torch.use_deterministic_algorithms(True)`（某些 kernel 不支持时至少固定 dropout seed）；
- checkpoint 测试的"续训无缝"判据：load 后先跑一个 eval step，loss 应与中断前完全一致——不一致说明 optimizer/schedule 状态没存全；
- Triton kernel 调试：先用 `TRITON_INTERPRET=1`（解释模式，CPU 上逐元素对拍）再上真 GPU；块边界错误（off-by-one 的 causal 边界、mask 不含边界列）几乎只在奇数长度输入上现形——**测试用例要故意造非 2 的幂的序列长度**。

### 11.4 pytest 的用法纪律

- `uv run pytest tests/test_model.py -k "rope and not multihead" -x -q`：按组件逐个点亮，别一次全跑（错误淹没）；
- 快照测试失败时读 conftest 的 snapshot 机制（`--snapshot-update` 只在确认自己是对的时候才用——它会把错误输出固化为新基准）；
- A2 的分布式测试要 `torchrun` 起多进程（test 文件头部有运行命令口径）；CPU 上的 DDP 测试（gloo backend）先过，再上 NCCL。

### 12.1 L2 · PyTorch 与 resource accounting（全课的地基，A1 writeup 直接考）

- PyTorch 侧：einsum/broadcast 语义、autograd 的计算图、`torch.no_grad`/`detached` 的区别——A1/A5 全部在用；
- 核算侧：**参数量估算**（一个 L 层 Transformer ≈ 12*L*d_model^2，大头在 FFN 与 attention 投影）、**FLOPs 估算**（前向 2ND、加反向 6ND）、**显存估算**（权重 4N、AdamW 后 16N/参数、激活随 batch*seq 线性）、**算术强度** = FLOPs / 字节搬运，以及 roofline 模型（算术强度低于硬件平衡点 → memory-bound）。

### 12.2 L4 · Mixture of Experts（无作业，架构叙事的关键一块）

- 思想：FFN 层替换成 E 个 expert + 一个 router（gate），每个 token 只发给 top-k 个 expert——**参数量与计算量解耦**（总参数巨大，单 token 计算只走一小部分）；
- 关键问题：负载不均（expert 容量与 auxiliary loss）、router 的可训练性（噪声/稀疏路由）、MoE 的 scaling law（参数量怎么计）；
- 这讲是理解 Mixtral / DeepSeek-V3 / Qwen-MoE 架构报道的钥匙。**未核实**：Spring 2025 这讲的具体深度以讲义 PDF 为准（官网只给标题）。

### 12.3 L10 · Inference（无作业，推理侧的唯一系统讲）

主题（按课程口径 + 领域通识）：
- **KV cache**：自回归解码时缓存历史 token 的 K/V，每步只算新 token——显存 = 2 * L * S * d_model * batch * 字节，是长上下文推理的第一瓶颈；
- **PagedAttention / vLLM**：把 KV cache 按"页"管理，消灭显存碎片、支持 batch 内不同长度——工业推理引擎的核心思想；
- **量化**：weights-only 量化（W8A16/W4A16）、KV cache 量化、以及量化对质量的折衷；**未核实**：Spring 2025 L10 是否细讲 speculative decoding 与连续批处理，以讲义为准；
- 训练-推理的不对称：训练 compute-bound（大 GEMM），推理 decode 阶段 memory-bound（每步一个 token、读全部权重）——这个不对称解释了为什么推理优化全是"减少搬运"。
