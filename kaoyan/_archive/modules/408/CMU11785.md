## 1 定位与现状

### 1.1 一句话定位

> **11-785 教的不是"怎么用 PyTorch 训模型"，而是"PyTorch 里面是什么，以及从 1943 年的 McCulloch-Pitts 到 2025 年的 diffusion，表示学习这条路是怎么一步一步走出来的"。**

### 2.1 四个 HW 一张表（F25 口径，S25 旁证）

每个 HW 固定两截：**P1 = Autolab（NumPy 手写组件，考察底层正确性）**，**P2 = Kaggle（PyTorch 端到端系统，考察工程与调优）**。

### 2.2 一条暗线：同一个语音任务，四种架构

官网学生视角的原话："The task for all the homeworks were similar and it was interesting to learn how the same task can be solved using multiple Deep Learning approaches." 落到近年的实际任务序列：

```
语音(mel 频谱帧)
  |-- HW1P2  MLP 逐帧分类          （只看当前帧，上下文靠拼接窗口）
  |-- HW3P2  RNN/CTC 整句音素序列   （标签不对齐 → CTC）
  |-- HW4P2  transformer 端到端 ASR （字符级输出，CER 计分）
  +-- HW2P2  人脸（唯一的视觉岔路，练 CNN + 度量学习）
```

这是有意的设计（§3.4）：**任务是控制组，架构是变量**。到 HW4P2 你能清楚看到同一份语音数据在三种归纳偏置下的表现差异——这比"每个作业换一个数据集"的课能多学到一层东西。

### 2.3 关键路径：复习/动手顺序

推荐 **HW1P1 → (autograd 引擎) → HW2P1 → HW3P1 → HW4P1**，P2 按 §15 的取舍另排。理由是概念依赖：

1. **HW1P1 层式组件先落地**：linear 的 forward/backward 是一切的地基，BatchNorm 反向是全课程最繁琐的一块，先过它。
2. **autograd 引擎插队**（F20 风格 bonus）：做完层式手写反传再写 autograd，你会**立刻理解引擎替你省掉的是什么**——这正是 F20 handout 那句"it will save a lot of future time and effort"的体感版。且 HW2P1 Autograd 要求把它扩到 conv，先有引擎后扩算子顺理成章。
3. **HW2P1 CNN**：conv 反向 = "把 im2col 的索引映射想清楚"，本质仍是矩阵微积分。
4. **HW3P1 RNN/LSTM**：BPTT 是"把网络在时间轴展开成一个更深的前馈网"，依赖已掌握的反传。
5. **HW4P1 attention/transformer**：纯矩阵运算的组合，难度反而主要是工程性的（mask、形状）。

### 2.4 评分机制（理解它的导向）

- **Autolab 按组件正确数给分**：P1 是"软件工程"式的评分（官网原话 "AutoLab: Software Engineering"），单元测试逐个组件打钩——这就是为什么 §6–§9 的展开都配"对拍验证"。
- **Kaggle 按 performance cutoff 插值给分**：官方公布 HIGH 90% / MEDIUM 70% / LOW 50% / VERY LOW 30% 四档，线性插值；on-time 提交且进前列可拿最多 5 分 bonus（最高 105）。
- **10 个 slack days 只能用在 P2**：官方明示 P2（开放调优）才是时间黑洞，P1 有硬 deadline。
- **设计导向**：P1 考"你懂不懂底层"，P2 考"你会不会做系统"——两条腿分开打分，偏科藏不住。

## 3 设计理念（最值钱的一节）

### 3.1 先造轮子，再用轮子：MyTorch 是本课的灵魂

这门课最出名的设计：**每个 HW 的 P1 都在往同一个"MyTorch"库里加组件，P2 才允许用真 PyTorch**。handout 原话（S20 起延续）："The culmination of all the Homework Part 1's will be your own custom deep learning library... It will act similar to other deep learning libraries like PyTorch or Tensorflow."

理解这个设计的正确姿势：

1. **深度学习框架的本体是"带记忆的链式法则"**。你用 NumPy 手写三层反传之后，会自然长出三个需求：想少写重复代码（→ 每层封装 forward/backward）、想不推公式（→ autograd 引擎）、想换更新规则不换网络（→ optimizer 与 model 解耦）。**MyTorch 的目录结构（nn/、optim/、loss 单列）不是模仿 PyTorch 的文件树，而是这条需求链条的自然形状**——PyTorch 长成那样也是因为同样的力。F20 把这个逻辑推到顶：直接让你写 autograd_engine.py 和 tensor.py。
2. **"禁止 import 框架"不是苦行，是控制变量**。用 PyTorch 训模型时，梯度对不对、是 optimizer 的锅还是 loss 的锅，你分不清；全手写时每一行都是你的，bug 只能出在你写的链式法则里。
3. **对你（求职向）的映射**：面"框架/infra 岗"时，"我按 F20 handout 规格实现过 autograd 引擎 + 反向拓扑排序 + broadcasting 归约"是一句硬通货（§14）。

### 3.2 覆盖面哲学：一座"表示学习博物馆"

对比同类课（详见 §16）：cs231n 是"视觉 + 现代架构"深井，CS336 是"LLM 全栈"深井，11-785 是**广度优先的通史**——28 讲里从 McCulloch-Pitts/Rosenblatt 讲起（L1 的推荐阅读就是 1943/1958 的原始论文），经 universal approximators、训练六讲、CNN、RNN/CTC、attention/transformer、LLM、AE/VAE、diffusion、GAN、表示学习、GNN，最后两讲落在 **Hopfield 网络与 Boltzmann 机**收尾。

这个课程表的隐含主张：**理解一个思想的最快方式是看它从哪个旧思想演化出来**。attention 不是天上掉下来的，它是"对齐/翻译"问题的解；对比学习不是新发明，它的直系祖先是 RBM 的对比散度（§10.3）。Bhiksha 把课程讲成博物馆，是在训练你"读新论文时能定位它在谱系上的坐标"的能力。

代价也要说清：广度 = 每个专题只有 1–2 讲，动手只覆盖 MLP/CNN/RNN/transformer 四类。**想深挖 LLM 训练/推理，这门课只是入口，接 CS336。**

### 3.3 为什么 CMU 坚持保留 energy-based 老派内容

大部分学校的 intro DL 课早已删掉 Hopfield/Boltzmann 机。CMU 留着（F25 倒数第二、第三讲），理由值得吃透：

1. **它们是"显式定义好坏"的框架**：现代网络用 loss 直接定义目标；energy-based 框架先定义一个能量 E(x)（"这个构型有多不好"），学习 = 压低数据能量、抬高其他构型能量。**"生成模型 = 学一个打分函数"这个视角在 diffusion 时代全面复活**（diffusion 模型的 noise-prediction 网络本质就是学一个 score function 的近似）——你说这是历史课，它其实是前沿的语法。
2. **"负样本难获取"是贯穿问题**：RBM 的负相（采样"看起来像但不是"的构型）在 2010 年代训练不动，但**"用对比压低负样本分数"的思想残影**一路传到 InfoNCE/SimCLR/CLIP—— contrasts/负采样就是这条线的现代形态（§10.3）。删掉源头，就看不清 SimCLR 的 loss 为什么长那样。
3. **文化传承**：Bhiksha 这一辈人（speech/LTI 背景）亲历过 Boltzmann 机时代，Hinton 的 DBN 就诞生在 CMU 附近的语境里。这门课把这个谱系当"家史"讲。

### 3.4 同一任务贯穿学期：架构是变量，任务是控制组

见 §2.2。这个设计的复习价值：当你以后要回答"我该给这个问题选什么架构"，你手里有的不是四个孤立的记忆，而是**一次受控实验**：同一份语音数据、同一套评测，MLP/CNN/RNN/transformer 各自的天花板和失败模式你都见过。面试聊"架构选型"时这是能展开讲的东西。

### 3.5 双轨评分：底层正确性 vs 系统工程

Autolab（组件逐个打钩）+ Kaggle（排行榜插值）不是简单的"笔试+实验"，而是刻意的两种能力分轨：**写对一个 conv 反向**和**把一个 Kaggle 榜刷进 HIGH 档**是完全不同的技能——前者要微积分和边界条件，后者要 pipeline 纪律、ablation 习惯、算力预算。自学者应该两边都给自己设验收（§13），只做 P1 会变成"会推公式不会训模型"，只做 P2 会变成"会调包不懂底层"。

## 4 各作业大纲（抓重点 / 关键路径 / 细节与易错点 / 设计理念）

> 本节是大纲层。逐块的可动手级展开（伪代码/公式/逐条易错点）见 §5–§11。

### 4.1 HW1P1 · MLP 组件（层式 MyTorch）

**抓重点**
1. 五件套：Linear、激活（Sigmoid/Tanh/ReLU）、MSE/CE、SGD(+momentum)、BatchNorm——这就是"最小可用的深度学习库"。
2. 全部实现成 `forward(x)` / `backward(grad)` 两方法的类，手写反传。
3. bonus 两条线：Adam/AdamW/Dropout（优化器与正则）；**Autograd 引擎**（见 §5，单列）。

**关键路径**
Linear(前向 xW+b，反向 dL/dW = x^T dL/dy) → 激活（ReLU 的反向是 mask）→ CE+softmax 合并推导（不要分开写）→ SGD+momentum（两行状态）→ BatchNorm（最繁琐，先写前向再硬推反向）→ 对拍验收。

**细节与易错点**
- CE loss 若先显式 softmax 再取 log，数值上必炸；要写 logsumexp 合并版。
- BatchNorm 训练/推理两套统计（batch 均值 vs running mean），mode 标志忘切是经典 bug。
- momentum 的更新式有"速度累加在前"还是"在后"两种等价写法，和 PyTorch 对拍时注意口径。

**设计理念**
做完这题你对"框架在替我做什么"的感知会具体到函数级：所谓深度学习库，第一步就是把这三样东西正交化——**层（计算）、loss（目标）、optimizer（更新规则）**。PyTorch 的 nn.Module/optim/Loss 三分结构就是这个正交性的工程化。

### 4.2 HW1P2 · frame-level 音素分类（Kaggle）

**抓重点**
1. 任务：WSJ 朗读语音 → mel 频谱帧 → 每帧 138 类左右的音素状态分类（类别数以当学期为准，未核实具体值）。
2. 这是你第一次用真 PyTorch 跑端到端 pipeline：dataloader/训练循环/验证/提交格式。
3. 变长 utterance 的处理：帧级分类可以滑窗拼上下文，不必序列建模。

**关键路径**
先把 dumb MLP 跑通提交（early deadline 机制逼你先交一次）→ 加上下文窗口 → 调宽/深 + 正则 → 进 HIGH 档。

**细节与易错点**
- mel 特征的归一化（per-dim mean/var）对收敛影响巨大，忘了归一化第一个 epoch 就能看出来。
- train/dev 切分要按 utterance 切不能按帧切，否则相邻帧泄漏，dev 分数虚高。
- 类别不平衡（音素频率差很多量级）时看混淆矩阵比看 accuracy 有用。

**设计理念**
官方把它放在第一个 Kaggle 的用意：**让你在见到 CNN/RNN 之前，先撞上 MLP 的天花板**——逐帧模型没有时序上下文概念，你怎么拼窗口都只是"更宽的 MLP"。这个体感是 HW3P2 的伏笔。

### 4.3 HW2P1 · CNN 组件

**抓重点**
1. Conv1d/Conv2d 的前向与反向、pooling（含 max pooling 的路由）、flatten。
2. bonus：Dropout2d/BatchNorm2d/ResNet block；**Autograd 扩展到卷积**（若走 §5 引擎线）。
3. 核心认知：conv = "扫描的 MLP + 权重共享"，反向传播的所有公式都能从这一句推出来。

**关键路径**
直接循环版 conv 前向 → 循环版反向 → im2col 重写前向（自动获得反向 = 前向的转置）→ pooling/flatten → 对拍。

**细节与易错点**
- conv 反向 = "输入侧的 full convolution + 权重侧的相关运算"，两个 dL/d 混着写必错；用 im2col 后全部退化为 matmul 的转置乘，反而不容易错。
- max pool 反向必须记录前向的 argmax 位置；多个像素取等值 max 时的路由约定要和参考一致。
- stride/padding 的边界：输出尺寸公式 `out = (in + 2p - k)/s + 1` 对不整除的情况，不同库有不同约定。

**设计理念**
权重共享不是一个 trick，是**把"平移不变"这个先验编译进参数化**。手写 conv 反向后你会记住：前向里每一次索引复用，反向里都对应一次梯度累加——这是 §5.8 梯度累加规律最直观的实体。

### 4.4 HW2P2 · 人脸分类 + 验证（Kaggle）

**抓重点**
1. 双任务：闭集分类（训练集见过的 ID）+ 开集验证（两张图是否同一人，用 embedding 距离）。
2. 度量学习入场：Triplet Loss / ArcFace（公开仓库记载，当学期 handout 为准）；backbone 通常是 ResNet 系。
3. 验证任务的本质：学一个**线性可分的 embedding 空间**，而不是分类头。

**关键路径**
分类 baseline（ResNet + CE）→ 加 embedding 头 → 换/混度量 loss → 测试时 embedding 归一化 + 相似度阈值扫描。

**细节与易错点**
- 验证集的人不出现在训练集——用分类 accuracy 代理验证性能会误导，直接优化验证指标。
- embedding L2 归一化前后选阈值，结果差别很大；提交前固定随机种子重跑一遍。
- 数据增强里颜色抖动对人脸任务未必有益（肤色是身份特征的一部分）。

**设计理念**
这是全学期唯一一次"分类头之外的目标函数设计"。同一个 backbone，换 loss 就换了空间结构：CE 拉开类间即可，Triplet/ArcFace 额外压缩类内——**目标函数决定了表示空间的几何**，这句话是后面 §11（生成模型）和表示学习讲座（L25）的前置概念。

### 4.5 HW3P1 · RNN/LSTM/GRU + seq2seq 组件

**抓重点**
1. RNN cell（一步）与 BPTT（沿时间展开）是两件事：cell 是 O(1) 的图节点，BPTT 是把序列展开成深前馈网再反传。
2. LSTM 的四门结构与"记忆单元 c 沿时间线性传递"——这是它能缓解梯度消失的机制核心。
3. seq2seq：encoder 终态作为 decoder 初始化，decoder 自回归生成，teacher forcing 训练。

**关键路径**
RNN cell 前向 → 单序列 BPTT → LSTM cell（把 RNN cell 的单门换成四门，反传照抄结构）→ GRU → encoder-decoder 拼装。

**细节与易错点**
- 隐藏状态 h 在时间步之间传递，**梯度沿同一条 h 链累加**——忘累加/多累加是 BPTT 最常见 bug。
- 反向要按时间**逆序**（t = T-1 → 0），且每个 t 的 dL/dh_t 要加上来自 t+1 的分量与当前输出 loss 的分量。
- 截断 BPTT（TBPTT）是工程必需，但注意截断点上的状态要 detach 语义。
- LSTM 里 c 的梯度链是纯线性乘法（+门控），h 的链经过 tanh 压缩——"缓解梯度消失"只对 c 成立，说"LSTM 消灭了梯度消失"是错的。

**设计理念**
LSTM 的设计是"**加一条无损信息高速公路**"：让重要信息可以不经过非线性压缩地流过长序列。这个"跳跃连接保梯度"的思想在残差网络（HW2P1 bonus 的 ResNet）里以另一种形式出现，又在 transformer 的残差流里第三次出现——**同一个解法，三次独立发明**，这是 §3.2 "博物馆"价值的最好例证。

### 4.6 HW3P2 · utterance→phoneme（CTC，Kaggle）

**抓重点**
1. 标签不对齐（知道整句音素序列，不知道哪帧对哪个音素）→ CTC loss + blank 符号。
2. 解码：greedy（collapse 重复 + 去 blank）→ beam search（含 prefix beam 的字典树去重）。
3. 变长输入/输出贯穿整个 pipeline。

**关键路径**
理解 CTC 的对齐求和（forward-backward over 路径）→ 调 `torch.nn.CTCLoss` 跑通 → 换 backbone（BiLSTM）→ 上 beam search 刷榜。

**细节与易错点**
- CTC 的输入必须**时间规范对齐**：log_softmax 在时间维上，序列长度递减会导致 loss=inf 或 NaN。
- blank 在重复折叠规则里的地位：`a a blank a` → `a a`（blank 分隔的两个 a 都保留），`a a` → `a`——beam 实现里这条规则出错榜上就掉好几个点。
- CTC 假设各帧输出条件独立，这正是它和 attention 的本质差异（也是 HW4P2 存在的理由）。

**设计理念**
CTC 教的是"**结构化输出的无对齐学习**"：当监督信号比输出序列粗一层（整句 vs 逐帧），就把 loss 定义成对所有可能对齐的边缘化。这个"隐变量边缘化"的模式在 HMM、EM、注意力对齐里反复出现——是 408 之外、但 ML 面试里高频的思想模式。

### 4.7 HW4P1 · attention/transformer 组件

**抓重点**
1. 全套 NumPy 组件：embedding、dot-product attention（含 scaling 与 mask）、multi-head 拆接、位置编码、FFN、encoder-decoder 堆叠。
2. 这一块没有新的数学，全部是矩阵乘法——难点全在形状与 mask 的工程管理。
3. 各学期附加子任务不同（文本预测/翻译等，以当学期 handout 为准）。

**关键路径**
单头 attention 前向 → 加 mask → multi-head（reshape 大法）→ 位置编码 → 整装 encoder-decoder → 逐组件对拍。

**细节与易错点**
- QK^T 除以 sqrt(d_k) 忘写，softmax 进入饱和区，梯度消失在第一层就发生。
- padding mask（负无穷填 -1e9 而不是 0）与 causal mask（下三角）是两种不同 mask，序列到序列任务两处都要。
- multi-head 的 reshape 顺序：(B, T, H*d) → (B, T, H, d) → (B, H, T, d)，错一层维度安静地算出错误形状。
- 位置编码 sin/cos 的实现要向量化，双重 for 循环在数据量上来后慢到没法做实验。

**设计理念**
Transformer 是"**把归纳偏设降到只剩局部连接和平移等变，其余全交给注意力 + 数据**"的极端实验。做完 NumPy 版你会看清：自注意力本质是一个**内容寻址的软查表**——Q 是查询、K 是索引、V 是存储，这与 §10 Hopfield 网络的"按内容取回关联记忆"是同一个母题的现代版。

## 5 autograd 引擎展开（重点中的重点，可动手级）

> 本节按 F20 handout《Autograd and MLPs》的规格（tensor.py + autograd_engine.py + mytorch/nn 目录树）展开，对齐 micrograd 的思路写成通用版。目标：**只依赖 NumPy，300 行以内实现一个能训 MLP 的小型 autograd**。

### 5.1 要造什么

```
输入:  y = f(W1, W2, x)   （f 由算子组合而成，前向时记录计算图）
输出:  dL/dW1, dL/dW2    （对任意标量 L，自动、只算一次前向 + 一次反向）
本质:  带记忆的链式法则 —— 前向把"每个算子用了哪些张量"记下来，
       反向沿图逆序问每个算子要"局部导数"，乘上上游梯度往下传。
```

F20 handout 的分工（它的分值结构也说明了难度分布）：

| 部件 | 文件 | 说明 |
|---|---|---|
| Tensor | `tensor.py` | data/grad/parents/op 四件套，操作符重载 |
| Autograd 引擎 | `autograd_engine.py` | 反向拓扑排序 + 逐节点调 op.backward |
| 网络层 | `mytorch/nn/` | Linear/ReLU/BatchNorm/loss/Sequential（用引擎实现，不再手写 backward） |
| 优化器 | `mytorch/optim/` | SGD(+momentum) |
| 端到端验收 | MNIST 训练 | F20 版是 784-20-10 的 MLP 训 MNIST（Linear → BatchNorm → ReLU → Linear） |

### 5.2 Tensor 类设计

核心字段（对齐 F20 handout Appendix A 的 Tensor attributes）：

```
class Tensor:
    data        # np.ndarray，前向数值
    grad        # np.ndarray 或 None，dL/dself，形状必须与 data 相同
    parents     # list[Tensor]，产生本张量的算子吃了哪些输入
    op          # 记录"我是被哪个算子算出来的"（叶节点为 None）
    requires_grad  # 参数张量为 True；中间量可顺路全 True
```

三条纪律：

1. **grad 与 data 同形状**。PyTorch 到今天还是这个约定，对拍时形状不符直接报错比静默广播好一万倍。
2. **parents + op 就是计算图的全部**。不需要显式的 Graph 对象——图是"嵌在张量里的"，谁算出来的、吃了谁，反向时就够了。
3. **操作符重载让建图无感**：`a + b`、`a * b`、`a @ b` 全部返回新 Tensor 并登记 parent 关系。用户代码长得和 NumPy 一样，图就已经建好了。

### 5.3 Operation 抽象：forward + backward

每个算子是两个纯函数：forward 吃输入吐输出（可能缓存中间量），backward 吃"上游梯度 dL/dout"吐"对各输入的梯度"。

```
class Op:
    def forward(self, *inputs) -> np.ndarray:
        # 计算并缓存反向需要的东西（如 relu 的 mask、matmul 的输入）
    def backward(self, grad_out) -> list[np.ndarray]:
        # 返回与 inputs 顺序一致的梯度列表
```

关键决策：**缓存什么由算子自己决定**。这是所有手写反传的"记忆管理"问题的通用解——每个 op 的 backward 恰好用它 forward 时本可丢掉的信息（sigmoid 的输出、max pool 的 argmax……），引擎只管传递，不管保存。

### 5.4 前向建图

以 `y = ((x @ W1 + b1).relu() @ W2 + b2).softmax()` 为例，前向后从 y 向下看：

```
y (softmax)
 └─ z2 = h @ W2 + b2        parents=[h, W2, b2], op=Add(MatMul...)
     └─ h = relu(z1)
         └─ z1 = x @ W1 + b1    parents=[x, W1, b1]
```

每个中间张量自带 (parents, op)，所以**从任意一个标量 loss 出发都能走回所有参与过的参数**——这就是 requires_grad 不需要显式注册的原因：路径可达即需要梯度。

### 5.5 backward：反向拓扑排序

引擎的全部工作：

```
def backward(loss):                    # loss 是标量 Tensor
    1. 从 loss 出发 DFS/BFS 收集所有可达节点
    2. 对收集到的子图做拓扑排序，得到"计算顺序的逆序"
    3. 逆序遍历：
         for node in topo_reversed:
             g = node.grad             # 已累加的上游梯度之和
             grads = node.op.backward(g)
             for parent, dg in zip(node.parents, grads):
                 parent.grad += dg     # 梯度累加（见 5.8）
    4. 叶参数的 .grad 就是答案
```

两个必答的"为什么"：

- **为什么必须拓扑排序**：一个节点必须等它**所有下游消费者**的梯度都到齐（都累加完）才能执行自己的 backward。随手写 DFS 不排序，会在梯度没到齐时提前反传——这是手写引擎 bug 排行榜第一名。
- **为什么 loss 必须是标量**：链式法则 dL/dx = sum over paths (dL/dy_i * dy_i/dx)，起点是标量才有良定义的"总梯度"。PyTorch 的 `backward()` 默认对非标量报错、要求传 gradient 参数，就是同一个原因。

### 5.6 逐算子前向/反向公式表

形状约定：x 是 (B, d_in)，W 是 (d_in, d_out)，b 是 (d_out,)，y = xW + b 是 (B, d_out)；L 是标量 loss。

| 算子 | forward | backward（grad_out = dL/dy） |
|---|---|---|
| add (y = a + b) | 逐元素加 | da = grad_out; db = grad_out |
| mul (y = a * b) | 逐元素乘 | da = grad_out * b; db = grad_out * a |
| div (y = a / b) | 逐元素除 | da = grad_out / b; db = -grad_out * a / b^2 |
| matmul (y = x @ W) | (B,d_in)@(d_in,d_out) | dx = grad_out @ W^T; dW = x^T @ grad_out |
| bias (y = x + b) | 广播加 | dx = grad_out; db = sum(grad_out, axis=0) |
| relu (y = max(0,x)) | 逐元素 | dx = grad_out * (x > 0) |
| sigmoid (y = 1/(1+exp(-x))) | 逐元素 | dx = grad_out * y * (1 - y)（缓存 y，不用 x） |
| tanh (y = tanh(x)) | 逐元素 | dx = grad_out * (1 - y^2) |
| softmax+CE 合并 (loss) | p = softmax(x); L = -mean(log p[range(B), t]) | dx = (p - onehot(t)) / B |
| MSELoss | L = mean((y - t)^2) | dy = 2*(y - t) / (B*d_out) |

三个必须内化的细节：

1. **matmul 的反向是"换位重乘"**：dW = x^T @ grad_out、dx = grad_out @ W^T——"谁转置、谁在前"由形状唯一决定（dW 必须是 W 的形状 (d_in, d_out)，只有 x^T @ grad_out 是这个形状）。面试手推就按形状凑，又快又不会错。
2. **softmax 和 CE 永远合并实现**。分开推 softmax 的雅可比（d_out x d_out 的满矩阵）既慢又数值不稳；合并后反向是 `(p - onehot)/B`，一行完事。这也解释了为什么 PyTorch 的 `nn.CrossEntropyLoss` 直接吃 logits。
3. **sigmoid/tanh 的反向都只缓存输出 y**，不缓存输入 x——反向公式的因变量选择决定了前向要存什么。

### 5.7 broadcasting 的梯度归约（unbroadcast）

`y = x + b` 里 b 从 (d_out,) 广播到 (B, d_out)。反向时 dL/db 必须归约回 (d_out,)。**这是 autograd 实现里最容易写错、面试最爱问的一块**：

```
def unbroadcast(grad, shape):          # grad: 广播后的梯度, shape: 原形状
    # 1. 归约掉前端多出来的轴
    while grad.ndim > len(shape):
        grad = grad.sum(axis=0)
    # 2. 归约掉原形状里为 1、广播时被拉长的轴
    for i, s in enumerate(shape):
        if s == 1 and grad.shape[i] != 1:
            grad = grad.sum(axis=i, keepdims=True)
    return grad
```

心法一句话：**前向广播 = 复制；反向穿过复制 = 求和（沿被复制的轴）**。所有算子的 backward 最后都套一层 `unbroadcast(grad, input.shape)`，广播问题就一劳永逸。mul 的广播版（a 是 (B,1,d)、b 是 (B,d_out) 这类）同理：先按逐元素规则算，再 unbroadcast 回各自形状。

### 5.8 同一节点多次使用：梯度累加

```
h = relu(x)
y1 = h @ W1
y2 = h @ W2
L  = y1.sum() + y2.sum()
```

h 有两条到 L 的路径，dL/dh = dL/dy1 * dy1/dh + dL/dy2 * dy2/dh。引擎层的实现就是一句：`parent.grad += dg`（不是赋值）。三条推论：

- `zero_grad()` 必须存在的原因：grad 是跨 step 累加的，不清零会把上一个 batch 的梯度混进来。
- 任何参数共享（conv 的权重共享、RNN 的时间展开、ALBERT 的层共享）在图语言里都是**同一个节点多条出边**，autograd 天然处理，无需特判。
- 反过来说，你手写层式反传时必须**手动把梯度加起来**（BPTT 沿时间、conv 沿空间扫描位置）——引擎存在的意义就是让你不再做这件事。

### 5.9 类骨架伪代码（完整可抄）

```
# ---- tensor.py ----
class Tensor:
    def __init__(self, data, parents=(), op=None, requires_grad=False):
        self.data = np.asarray(data)
        self.grad = None
        self.parents = list(parents)
        self.op = op
        self.requires_grad = requires_grad

    def backward(self):                 # 只对标量调用
        topo, visited = [], set()
        def build(t):
            if id(t) in visited: return
            visited.add(id(t))
            for p in t.parents: build(p)
            topo.append(t)
        build(self)                      # 后序 = 拓扑序
        self.grad = np.ones_like(self.data)   # dL/dL = 1
        for t in reversed(topo):
            if t.op is None: continue
            grads = t.op.backward(t.grad)
            for p, g in zip(t.parents, grads):
                g = unbroadcast(g, p.data.shape)
                p.grad = g if p.grad is None else p.grad + g

    # 操作符重载：建图入口
    def __add__(self, other):  return Tensor(*Add.forward(self, other), op=Add, parents=(self, other))
    def __matmul__(self, other): ...     # 同上
    def relu(self): ...
    ...

# ---- autograd_engine.py（也可并进 Tensor，如 micrograd）----
# 每个算子：类持 forward(缓存) + backward(grad_out) -> [d_in1, d_in2, ...]
class Add:
    cache = None
    @staticmethod
    def forward(a, b): return a.data + b.data
    @staticmethod
    def backward(g): return [g, g]

class MatMul:
    @staticmethod
    def forward(a, b): return a.data @ b.data
    @staticmethod
    def backward(g, cache): return [g @ cache.b.data.T, cache.a.data.T @ g]

# ---- 在引擎之上包一层 PyTorch 风格的 API ----
class Linear:
    def __init__(self, d_in, d_out):
        self.W = Tensor(rng(d_in, d_out), requires_grad=True)
        self.b = Tensor(zeros(d_out), requires_grad=True)
    def __call__(self, x):
        return x @ self.W + self.b      # 全部经重载算子建图

class SGD:
    def __init__(self, params, lr): self.params, self.lr = params, lr
    def step(self):
        for p in self.params: p.data -= self.lr * p.grad
    def zero_grad(self):
        for p in self.params: p.grad = None
```

训练循环从此和 PyTorch 长得一样（这正是 F20 MNIST 部分要你写的）：

```
for x, t in loader:
    out = model(x)
    loss = cross_entropy(out, t)
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()
```

### 5.10 与 PyTorch autograd / Karpathy micrograd 对照

| 维度 | micrograd | 本节实现（F20 风格） | PyTorch |
|---|---|---|---|
| Tensor | 标量 Value 类 | NumPy ndarray + 形状 | ndarray + 形状 + 设备 + 稀疏/混合精度 |
| 图 | 动态、每次前向重建 | 同左 | 动态图 + 反向对 pytree 泛化 |
| 拓扑排序 | build_set 后序 | 同左 | 引擎内化为节点入度/就绪队列（C++） |
| broadcasting | 无 | unbroadcast 手写 | grad 按语义自动归约 |
| 累加语义 | 有（+=） | 有 | 有 + accumulate_grad 融合优化 |
| 差异点 | 教学 | 能训真 MLP/MNIST | 算子数、性能、分布式、保存/恢复 |

micrograd 证明"autograd 的核心 100 行"；本节实现证明"加上形状和广播，300 行就能训 MNIST"；PyTorch 与两者的差距**全在工程面**（算子覆盖、内存规划、kernel 融合、DDP/FSYP）——这三级台阶正好是"理解框架本体"到"理解框架工程"的路径（§14.4 的延伸路线按这个顺序走）。

### 5.11 验收：梯度对拍（没有 Autolab 的替代方案）

```
对每个算子、每层、整个模型:
  1. 随机小尺寸输入（覆盖广播场景：b 从 (d,) 广播、标量*矩阵等）
  2. y = f(x); L = y.sum()  （sum 保证逐元素梯度为 1，全面覆盖）
  3. 自己的 backward 得 g_mine
  4. 数值梯度: g_num[i] = (L(x + e_i) - L(x - e_i)) / (2*eps), eps=1e-5
  5. assert allclose(g_mine, g_num, atol=1e-6)
```

再补三个端到端检查：单步训练后 loss 应下降；MNIST（或 sklearn digits）上 10 epoch 内 accuracy 应明显高于随机（10 类随机基线 10%）；同结构 PyTorch 模型同超参 loss 曲线应同量级。**数值对拍过不了，先查 unbroadcast 和累加，再查拓扑序**——bug 分布就这样。

## 6 层式 MyTorch 展开（近年主线口径）

近年主线不建图：每层是一个带 `forward(x)` / `backward(grad)` 的类，backward 手写、输入输出显式传递。相比 §5，少了一个引擎、多了"每个网络手拼反传"的重复劳动。

### 6.1 Linear

```
forward:  y = x @ W + b                 # x:(B,d_in) W:(d_in,d_out)
backward: dx = grad @ W^T
          dW = x^T @ grad               # 记住：x^T 在前
          db = sum(grad, axis=0)
```

易错：dW/db 存到层内（self.dW），因为参数的梯度属于层、不属于某次输入。

### 6.2 BatchNorm（主线 HW1P1 最繁琐的一块）

前向（训练态）：

```
mu    = mean(x, axis=0)                 # (d,)
var   = mean((x - mu)^2, axis=0)
xhat  = (x - mu) / sqrt(var + eps)
y     = gamma * xhat + beta
running_mean = m * running_mean + (1-m) * mu     # 推理态用
```

反向（对 B 个样本、d 维，grad = dL/dy）：

```
dgamma = sum(grad * xhat, axis=0)
dbeta  = sum(grad, axis=0)
dxhat  = grad * gamma
dx     = (1/B) / sqrt(var+eps) * (B*dxhat - sum(dxhat,0) - xhat * sum(dxhat*xhat,0))
```

最后这行是"均值和方差都依赖 x"的二阶效应，**硬背不如记推导路径**：x → (mu, var, xhat) → y 是三段复合，mu/var 对 x 的导数都要算。对拍不过时 90% 错在这里。推理态反向要简单得多（统计量是常数）。

### 6.3 损失函数

- MSE：`L = mean((y-t)^2)`，`dy = 2(y-t)/N`（N 取 B 还是 B*d，按 handout 定义，和参考对齐）。
- SoftmaxCrossEntropy：logits → log_softmax（logsumexp 稳定化：`x - max(x) - log(sum(exp(x-max)))`）→ 取目标类 → 反向 `(p - onehot)/B`。

### 6.4 优化器（含 bonus：Adam/AdamW）

```
SGD+momentum:  v = m*v + g;       W -= lr*v          # 或 v = m*v - lr*g，注意口径
Adam:          m = b1*m + (1-b1)*g
               v = b2*v + (1-b2)*g^2
               mhat = m/(1-b1^t); vhat = v/(1-b2^t)  # 偏差修正，t 从 1 起
               W -= lr * mhat/(sqrt(vhat)+eps)
AdamW:         同 Adam，但权重衰减项从梯度里拿出来：W -= lr*(mhat/(sqrt(vhat)+eps) + wd*W)
```

Adam 易错点：t 忘自增（偏差修正失效，初期步长爆炸）；eps 在 sqrt 外（`sqrt(v)+eps`，不是 `sqrt(v+eps)`，两种实现不等价，PyTorch 是前者）。AdamW 与 Adam+L2 的区别一句话：**解耦——衰减直接作用于参数而不是经过自适应缩放的梯度**。

## 7 CNN 用自己框架实现（HW2P1 展开级）

### 7.1 conv 前向：先循环后 im2col

直觉定义（2D、单通道、stride=s、pad=p）：

```
out[i,j] = sum_{u,v} x[i*s+u, j*s+v] * K[u,v]     # 卷积核 k x k
out_size = (in + 2p - k)/s + 1
```

四重循环版本 30 行写完，用来对拍；生产版用 im2col：

```
im2col:  把每个感受野拉成一行 -> X_col: (B*out_h*out_w, k*k*C_in)
         权重拉成矩阵       -> W_col: (k*k*C_in, C_out)
forward: Y = X_col @ W_col + b                # 一步 matmul
backward: dX_col = dY @ W_col^T -> col2im（累加回重叠位置！）
          dW_col = X_col^T @ dY
```

### 7.2 conv 反向的两句话总结

- **对输入**的梯度 = "感受野重叠处的梯度累加"——col2im 里重叠区域天然 `+=`，这就是 §5.8 累加规律的空间版。
- **对权重**的梯度 = "输入与输出梯度的相关"——dW_col = X_col^T @ dY，和 Linear 的 dW = x^T @ grad 同构。**conv 就是对每个扫描位置共享参数的 Linear**，im2col 把这句话变成字面事实。

### 7.3 pooling 与 flatten

```
maxpool 前向: 分窗取 max，记录 argmax
maxpool 反向: 梯度只发给 argmax 那一格（路由，不是分配）
avgpool 反向: 梯度均分给窗口内所有格
flatten    : reshape，反向 reshape 回去（纯形状操作，零数学）
```

### 7.4 若走 Autograd 线：conv 作为算子

把 im2col 的 (X_col, W_col) 包成 Tensor，前向建图自动反传——这就是 S25 bonus "Applying Autograd to Convolutional Networks" 的实质：**新算子只有 im2col/col2im 这一对"形状操作"，matmul 部分复用已有引擎**。这个设计观察值得写进面试叙述："conv 的新增反向逻辑可以压缩到形状变换层，说明算子库的组合性设计是对的。"

## 8 RNN/LSTM 展开（HW3P1 展开级）

### 8.1 RNN cell 与 BPTT

```
cell:   h_t = tanh(W_xh^T x_t + W_hh^T h_{t-1} + b)
BPTT:   把 T 步展开成深度 T 的前馈网，损失 L = sum_t L_t(y_t)
反向:   dh_T 起步，沿 t 逆序：
          dh_{t-1} += (W_hh @ dh_t_raw)        # 来自未来的分量
          dh_t_raw  = dh_t * (1 - h_t^2)       # 过 tanh
        每步再把 dh_t_raw 分给 W_xh/W_hh/b 的梯度累加
```

RNN 梯度消失/爆炸的根源就在 `dh_{t-1} = ... * W_hh * tanh'... * W_hh * tanh'...`——**同一个 W_hh 的 T 次连乘**，谱半径 <1 消失、>1 爆炸。梯度裁剪（clip 全局范数）治爆炸，消失要靠结构。

### 8.2 LSTM：加一条线性传递的记忆线

```
i_t = sig(W_i [x_t, h_{t-1}])     输入门：写多少
f_t = sig(W_f [x_t, h_{t-1}])     遗忘门：留多少
o_t = sig(W_o [x_t, h_{t-1}])     输出门：读多少
g_t = tanh(W_g [x_t, h_{t-1}])    候选内容
c_t = f_t * c_{t-1} + i_t * g_t   ★ c 的传递是纯线性乘加
h_t = o_t * tanh(c_t)
```

为什么缓解梯度消失：dL/dc_{t-1} 沿 c 链传递是 `f_t * dL/dc_t`，**没有 tanh' 的反复压缩，也没有固定矩阵的连乘**（f_t 由当前输入动态决定，可学到接近 1）。面试标准答法就到这层；再加分是提 GRU（合并门、少一个状态，参数少 25%）和"梯度Highway"与 ResNet 残差的思想同构（§4.5）。

### 8.3 seq2seq 与 teacher forcing

```
训练:  encoder 吃完整源句 -> 终态 (h, c)
       decoder 每步输入 = 真实上一个 token（teacher forcing），比自回归稳定得多
解码:  decoder 每步输入 = 自己上一步的输出（自回归），直到 <eos>
```

teacher forcing 的训练/解码分布差异（exposure bias）是必踩的认知：训练时永远看正确前缀，解码时看自己的错误输出。这是后续 attention 论文（L15 讲的 LAS）要处理的真实问题。

### 8.4 CTC 展开要点（HW3P2）

```
对齐规则:  输出序列先去重相邻再删 blank
           (a,a,blank,a) -> (a,a)     blank 是"分隔符"
           (a,a)         -> (a)       直接去重
loss:      L = -log sum_{所有能折叠成标注的对齐路径} prod_t p(y_t | x)
           用 forward-backward 算这个 sum，O(T * |label'|)，label' 是插 blank 后的序列
反向:      对 log 路径和求导 = 按前后向概率给每个 t 的 softmax 输出回灌梯度
```

自学者不必手写 CTC 反传（那是 HMM 时代的老手艺），但**对齐折叠规则和"blank 分隔重复"必须能手算**——beam search 解码的坑全在这一条规则上。

## 9 attention/transformer 展开（HW4P1 展开级）

### 9.1 从 QKV 到 scaled dot-product

```
Q = x @ W_q    K = x @ W_k    V = x @ W_v          # 全部 (B, T, d)
scores = Q @ K^T / sqrt(d_k)                       # (B, T, T)
attn   = softmax(scores, axis=-1)
out    = attn @ V                                   # (B, T, d)
```

- **为什么除 sqrt(d_k)**：Q·K 是 d_k 个乘积的和，量级随 d_k 增长；不缩放则 softmax 进饱和区，梯度趋零。一句话答法："控制 logits 方差，避免 softmax 饱和。"
- **理解模型**：attn 矩阵的第 i 行 = "生成第 i 个 token 时对序列各位置各看多少"；out 是 V 的加权平均——**软查表**（内容寻址），与 Hopfield 的按内容取回同构（§4.7/§10.1）。

### 9.2 mask：两种，别混

```
padding mask:   key 侧无效位置 scores -> -1e9（不是 0！softmax 前加）
causal mask:    scores 上三角 -> -1e9，防止看到未来（decoder 自注意力用）
组合:           encoder 自注意力只 padding；decoder 自注意力两个都要
```

### 9.3 multi-head：reshape 大法

```
(B, T, d) --投影--> (B, T, H * d_h) --view--> (B, T, H, d_h) --transpose--> (B, H, T, d_h)
每个头独立做 9.1，concat 回 (B, T, H*d_h)，再过 W_o
```

意义：H 个头在 d_h 维子空间里各自学一种对齐模式（句法/位置/共指……）。实现层面全部难点就是上面两次 reshape 的轴序。

### 9.4 整装：encoder-decoder

```
block(x) = x + MultiHeadAttn(LayerNorm(x))         # pre-LN，训练更稳
        = block + FFN(LayerNorm(block))            # FFN = Linear-ReLU-Linear, 4x 扩张
encoder: N 个自注意力 block 堆叠
decoder: N 个（自注意力 + 交叉注意力 + FFN）block
         交叉注意力: Q 来自 decoder、K/V 来自 encoder 输出 —— 这就是"对齐"的现代形态
位置编码: sin/cod 或可学习，加在 embedding 上（架构唯一的位置信息来源）
```

自学者检查清单：embedding 尺度 sqrt(d) 缩放（原论文做法，影响不大但要一致）、warmup 学习率（Noam scheduler）、label smoothing 0.1——这三个"原论文细节"是复现结果对不对的分水岭。

## 10 energy-based models 概念线（11-785 特有的保留曲目）

> F25 的课程在 L27（Hopfield Networks）和 L28（Boltzmann Machines）收尾。更早学期（如 S20）这条线更长（Hopfield/BM 连讲三讲、RBM 单列）；近年压缩到两讲，但**思想脉络完整**。本节把"谁是谁的基础"讲清——这是这门课区别于所有速成课的部分。

### 10.1 Hopfield 网络（1982）：按内容取回的记忆

```
神经元 s_i ∈ {-1, +1}，对称权重 W（对角为 0）
能量:   E(s) = -1/2 * sum_{i!=j} W_ij s_i s_j
学习:   W = sum_p x_p x_p^T     （Hebbian：一起激活就连一起，外积和）
取回:   迭代 s_i <- sign(sum_j W_ij s_j)，能量单调下降，落到最近的最小能量构型
```

要点：
- **记忆 = 能量面的局部最小**；存 P 个模式 = 凿 P 个坑；含噪/残缺输入滚回最近的坑 = "按内容寻址"（address by content），不是按地址寻址。
- 容量约 0.14N（N 个神经元存约 0.14N 个模式），超存则坑串味——这个"容量极限"正是引出分层/概率化下一代的动机。
- 呼应：§9.1 的注意力是"软的、连续的按内容取回"——Transformer 的 QKV 谱系上溯就是 Hopfield。现代论文里"attention is a modern Hopfield network"的说法指的就是这个同构。

### 10.2 Boltzmann 机与 RBM：把记忆变成分布

在 Hopfield 上加两件事：(1) **随机神经元**（依温度依能量做 Gibbs 采样）；(2) **隐藏单元**（可见层之外加一层，用来表示数据不能直接表达的特征）：

```
Boltzmann 分布:  P(s) = exp(-E(s)) / Z,   Z = sum_s exp(-E(s))
训练目标:       最大化数据的似然 = 压低数据构型的 E、抬高全空间其他构型的 E
问题:           Z 不可算（构型指数多）、负相采样要跑马尔可夫链到平稳 —— 不可行
RBM:            限制连接（可见-隐藏二部图，层内不连）→ 给定一侧，另一侧可独立采样
                 一步"重构"采样代替跑到平稳 —— Contrastive Divergence（CD-1，Hinton 2002）
```

负对数似然的梯度天然裂成两项（**正相/负相**）：

```
dL/dW = <v h>_data  -  <v h>_model      # 数据分布上的相关 - 模型自己采样出的相关
          正相：压低数据能量                负相：抬高模型幻觉出来的构型的能量
```

**负相永远算不准、采不动**，这就是 2010 年代深度学习离开这条路的原因。

### 10.3 思想残影：负采样/对比的直系后代

这条线没有死，它换了三次形态活到今天：

```
RBM 的 CD        : 抬高模型采出的负样本能量
  →  word2vec negative sampling (2013): 用噪声分布的负词压 softmax 分母
  →  InfoNCE / CPC (2018):  判别"真未来 vs 假未来"，负样本来自队列
  →  SimCLR / MoCo (2020):  同图两增强为正对、别的图为负对，对比温度即能量尺度
  →  CLIP (2021):           图-文配对为正、错配为负 —— 二十亿"负样本"的能量模型
```

看 InfoNCE 的形式 `L = -log[ exp(s(x,y+)/tau) / sum_i exp(s(x,y_i)/tau) ]`——分子是正相（拉近正对），分母是负相（推开其他），**和 RBM 的正相/负相逐项对应**（Oord 的 CPC 论文里就明确引了 energy-based 的谱系）。所以 §3.3 那句话的操作版：**面试问对比学习，你能从 SimCLR 一路讲到 CD-1，就比只背"温度参数"的候选人多一整层深度**。

### 10.4 一张谱系小结

```
Hopfield(1982) --概率化--> Boltzmann 机(1985) --二部图化--> RBM(1986/2002)
    |                            |                          |
 按内容寻址                    能量=分布                 CD 负采样
    |                            |                          |
  attention(QKV 软寻址)   score-based/diffusion        InfoNCE/SimCLR/CLIP
```

三条现代主线（attention、diffusion、对比学习）各继承了这个祖先的一项遗产。11-785 把这两讲放在学期最后，正是博物馆的出口设计：**从 2025 年走回 1982 年，你会发现出口就是入口**。

## 11 生成模型线：AE → VAE → GAN → diffusion（L21–L24 + lab）

### 11.1 自编码器与 VAE：把"隐变量"请回来

```
AE:   x --encoder--> z --decoder--> x'，L = ||x - x'||    # z 只是压缩，无分布约束
VAE:  z ~ N(mu(x), sigma(x)) 而不是确定值                  # 重参数化: z = mu + sigma * eps, eps~N(0,I)
      L = E[||x - x'||] + KL( q(z|x) || p(z) )            # ELBO 的直觉版
```

三个必须能答的点：

1. **为什么重参数化**：不能对"采样"这个操作求导；把随机性挪到 eps 上，mu/sigma 变成确定性函数，梯度能流过去。一句话："把随机性从计算图里搬到输入侧。"
2. **ELBO 是什么**：log p(x) = ELBO + KL(q||p(x|z))，最大化 ELBO = 同时做好重构和把后验拉向先验；KL 项有闭式解（两个高斯的 KL）。
3. **AE 与 VAE 的本质差**：AE 的隐空间没有任何结构保证（插值/采样无意义）；VAE 用 KL 项把隐空间正则成接近 N(0,I) 的形状，换采样的能力，付重构模糊的代价。

### 11.2 GAN：博弈代替似然

```
G: z -> 假样本；D: x -> 真/假概率
min_G max_D E[log D(x)] + E[log(1 - D(G(z)))]
```

- **交替训练**是它一切的根源：D 太强（G 梯度消失）或太弱（G 学不到东西）都不行，训练是走钢丝。
- 不稳定清单（面试常问）：模式崩塌（G 只输出少数样本骗过 D）、不收敛、梯度消失——实践中 DCGAN 的工程约束、谱归一化、WGAN 的 Lipschitz 替换都是补丁。
- 一句话定位：**GAN 用"可微的判别器"替代了 energy-based 模型算不动的负相**——判别器指哪，生成器打哪。它也是 §10 谱系里"对抗式负采样"的形态。

### 11.3 diffusion：加噪再去噪

```
前向(固定): x_t = sqrt(a_t)*x_{t-1} + sqrt(1-a_t)*eps     # 逐步加高斯噪，T 步到纯噪声
反向(学习): 网络预测 eps_t = eps_theta(x_t, t)，L = ||eps - eps_theta||^2
采样:       从纯噪声出发，逐步去噪
```

两句话本质：(1) 反向去噪的每一步是"给定噪声图，预测藏在里面的噪声"——**学的是 score（对数密度的梯度）**，这就是 §10.2 能量视角的现代复活；(2) 训练天然稳定（纯回归损失，无 GAN 的博弈），代价是推理要多步迭代。知道这两点 + "为什么 DDIM 能把采样步数从 1000 压到 50"，面试 diffusion 入门题就齐了。lab 有 NF（normalizing flow）与 stable diffusion 的上机，讲座本身一讲带过——深度在 lab，不在 lecture。
