# 外部排序：为什么"排序"这事在磁盘上完全变了样

> **面向**：408 考研。外部排序是块9 里最容易丢分的一节，因为它**不讲"怎么比较"，只讲"怎么少搬数据"**。

## 1. 先建立直觉：为什么不能"直接排"

### 1.1 内存里排序的前提是什么

快排、堆排、归并，都假设一件事：**所有数据都在内存里，随便访问。**

`std::sort` 排 1 亿个 int（400MB）—— 内存够，几百毫秒。

但如果是 100GB 的日志文件呢？**内存放不下。** 你不可能 `new` 出 100GB。

**外部排序 = 在"数据放不进内存"的前提下排序。**

### 1.2 关键：磁盘 I/O 比内存访问慢 10 万倍

| 操作 | 耗时 | 相对倍数 |
|---|---|---|
| CPU 一次运算 | ~0.3 ns | 1 |
| 内存随机访问 | ~100 ns | 300 |
| **SSD 一次随机读** | ~100 μs | **30 万** |
| **机械硬盘一次寻道** | ~10 ms | **3000 万** |

**结论（整个外部排序的所有设计都从这句推出来）**：

> **比较次数的多少几乎不重要，I/O 次数才决定快慢。**

所以外部排序的算法设计**完全不是为了"少比较"，而是为了"少读盘/写盘"**。
这就是为什么它和内存排序看起来完全不一样。

### 1.3 记账单位：块（block / page）

磁盘读写的**最小单位是块**，不是字节。常见 4KB（数据库）或 16KB（文件系统）。

**你要读 1 个字节，也必须搬一整块进内存。**

于是**所有代价都用「块数」来算**，不是用「元素个数」。

```
设：文件共 n 个元素，每块能装 b 个元素 → 文件共 n/b 块
一次 I/O = 搬一块
```

**记这个符号体系**，后面所有公式都用它：

| 符号 | 含义 |
|---|---|
| n | 待排序记录总数 |
| b | 每块能装的记录数 |
| **n/b** | **文件的总块数**（这是"搬一遍"的代价） |
| m | 初始归并段的个数 |
| k | 归并的路数（k 路归并 = 同时合并 k 个段） |
| S | 归并的趟数 |

## 2. 外部排序的四个阶段

整个算法分四步，**只有第一步用到内部排序算法**：

```
① 生成初始归并段（内部排序）  →  ② 多趟归并  →  ③（可选）优化初始段  →  ④（可选）最佳归并树
```

### 2.1 阶段一：生成初始归并段

**做法**：把文件切成若干块能装下的片段，每片读进内存，用**内部排序**（快排/堆排/归并）排好，写回磁盘。

每个排好的片段叫一个**初始归并段**（run），也叫"顺串"。

```
磁盘文件：  [7 3 9 1 | 5 2 8 4 | 6 0 ...]
              ↓ 每次读一块进内存
内存排序：    [1 3 7 9]  [2 4 5 8]  [0 6 ...]
              ↓ 写回磁盘
初始归并段：  R1=[1,3,7,9]  R2=[2,4,5,8]  R3=[0,6,...]
```

**代价**：读一遍文件 + 写一遍文件 = **2 × (n/b) 次 I/O**。

**段数 m 的算法**：
$$m = \left\lceil \frac{n}{内存能装的记录数} \right\rceil$$

例：1 亿条记录，内存放 100 万条 → `m = 100` 段。

**这一步的 I/O 是固定成本，逃不掉。**

### 2.2 阶段二：多趟归并（核心）

现在有 m 个有序段，要把它们合成 1 个。

**k 路归并**：同时打开 k 个段，每次从这 k 个段的头部选最小的输出。

**为什么不用 2 路？** 因为趟数 `S = ⌈log_k m⌉`，k 越大趟数越少。
而 **每趟都要把整个文件读一遍、写一遍**，所以趟数直接决定总 I/O。

$$总 I/O = 2 \times \frac{n}{b} \times S = 2 \times \frac{n}{b} \times \lceil \log_k m \rceil$$

其中 `2` 是"一读一写"，`n/b` 是总块数。

**实算一下（1GB 文件、4KB 块 → 262144 块；m=1000 段）**：

| 归并路数 k | 趟数 S | 总 I/O 次数 |
|---|---|---|
| 2 | 10 | 5,242,880 |
| 4 | 5 | 2,621,440 |
| 8 | 4 | 2,097,152 |
| 16 | 3 | 1,572,864 |
| 64 | 2 | 1,048,576 |

**这就是整个外部排序的主线**：**想尽办法减少趟数 S。**

减少 S 有两条路：
1. **增大 k**（路数）→ 但 k 受内存限制（k 个输入缓冲区 + 1 个输出缓冲区）
2. **减小 m**（初始段数）→ 这就是 §3 的「置换-选择」

### 2.3 阶段三：k 到底能多大（内存约束）

k 路归并需要内存里同时有：
- k 个**输入缓冲区**（每个段一个，至少 1 块）
- 1 个**输出缓冲区**

所以：**k ≤ 内存块数 − 1**

例：内存 10 块 → k 最大 9；实际为了效率每个缓冲区给 2 块 → k 最大 4。

> **408 常考**：给内存大小和块大小，问最大归并路数。
> 公式：`k_max = ⌊内存块数 ⌋ − 1`（最省的做法，每缓冲区 1 块）

### 2.4 阶段四：收工，得到有序文件

最后再写一遍到磁盘。**总 I/O = 以上各阶段的读+写之和。**

## 3. 三个优化（408 的采分点全在这）

### 3.1 优化一：多路归并（增大 k）

**问题**：k 路归并时，每次从 k 个候选里选最小，如果用"逐个比较"，要比较 k−1 次。
k=64 时每次输出一个记录要比较 63 次 —— **比较次数爆炸**。

**解法：败者树（loser tree）**

**核心思想**：用一棵完全二叉树，把"选最小"的代价从 **O(k) 降到 O(log k)**。

```
              ┌─── 总冠军（最小值）───┐
              │                       │
         ┌────┴────┐            ┌─────┴────┐
       b3        b1          b5        b7
      (输)      (输)        (输)      (输)
       │          │           │         │
   ┌───┴──┐   ┌──┴───┐   ┌───┴──┐  ┌───┴──┐
   R1     R2  R3     R4  R5     R6 R7    R8
```

**败者树 vs 胜者树**（这个区别常考）：

| | 胜者树 | 败者树 |
|---|---|---|
| 内部结点存 | **胜者**（最小值） | **败者**（输的那个） |
| 输出后更新 | 需要**重新比较**该路径上所有结点 | 只需沿**一条路径**向上比较（因为父结点已存着"另一个孩子"） |
| 比较次数 | 完全相同 | 完全相同（都 log k），但败者树**常数更小** |

**为什么败者树更新更快**：因为每个内部结点记着"败者"，所以当胜者被替换后，
只要拿新来的值和"结点里记的败者"比一次就够了，不用再回到叶子重新比。

**408 考法**：
- "败者树的作用是什么" → **减少比较次数**（从 O(k) 降到 O(log k)）
- **不是**减少 I/O！I/O 由趟数 S 决定，败者树不影响 S
- 这是最常见的陷阱题

### 3.2 优化二：置换-选择排序（减小 m）

**问题**：阶段一用内部排序生成初始段，段长 = 内存容量。
**但如果数据不是完全随机的，段可以更长。**

**置换-选择（replacement selection）的做法**：

1. 从文件读满内存（假设内存装 M 个）
2. 输出其中**最小值**到当前段
3. 从文件读**下一个**记录进内存空出的位置
   - **如果新记录 ≥ 刚输出的值** → 它能进当前段（继续参与）
   - **如果新记录 < 刚输出的值** → 它进不了当前段了（因为段必须有序），**冻结**它，等下段
4. 重复，直到内存里所有记录都被冻结 → 本段结束
5. 解冻，开始下一段

**关键结论（要记住这个数）**：

> **随机数据下，置换-选择生成的平均段长 ≈ 2 × 内存容量**
> 即：段数 m 减半 → **趟数 S 少一次**（在 log 的台阶上可能少 1）

**我实际跑数据验证过（N=20000 随机数据）**：

| 内存容量 | 内部排序法段数 | 置换-选择段数 | 平均段长 | 倍数 |
|---|---|---|---|---|
| 100 | 200 | 101 | 198.0 | **1.98×** |
| 500 | 40 | 21 | 952.4 | **1.90×** |
| 1000 | 20 | 11 | 1818.2 | **1.82×** |
| 2000 | 10 | 6 | 3333.3 | **1.67×** |

实测倍数在 1.67~1.98 之间，**理论值 2 是对的**（内存越大越接近 2，因为边界效应小）。

> ⚠️ **但「段数减半」不等于「趟数减一」**。我实测了：k=4 时
> - 内存 100：200 段 → S=4；101 段 → S=4（**持平**，因为 log₄200=3.8→4，log₄101=3.3→4）
> - 内存 1000：20 段 → S=3；11 段 → S=2（**省 1 趟**）
> - 内存 2000：10 段 → S=2；6 段 → S=2（持平）
>
> **这是 log 的台阶效应** —— 段数减半只在跨过 k 的整数次幂时才省趟。
> 408 一般不考这么细，但如果题目给了具体数字，**要实算不要想当然**。

### 3.3 优化三：最佳归并树（让"长的段少归并"）

**问题**：如果初始段**长度不等**（置换-选择就会产生不等长），按固定顺序归并是浪费的。

**类比**：这里和**哈夫曼树**完全一样。

- 哈夫曼：让**权重小**的叶子路径**长**（少编码）
- 最佳归并树：让**长度短**的段**先合并**（少搬运）

**做法**：把每个段的长度当"权重"，建 **k 路哈夫曼树**（每次取 k 个最小的合并）。

**总 I/O = 所有内结点权重之和 × 2**（每个元素每趟读+写各一次）

**虚段（关键细节）**：k 路哈夫曼要求「每次都能取到 k 个」，所以段数必须满足：

$$(n - 1) \bmod (k - 1) = 0$$

不满足就**补长度为 0 的虚段**，补的个数：

$$补虚段数 = (k - 1) - (n - 1) \bmod (k - 1)$$

**验证过的虚段表**（n=2..11，k=3/4）：

| n | k=3 补几个 | k=4 补几个 |
|---|---|---|
| 2 | 1 | 2 |
| 3 | 0 | 1 |
| 4 | 1 | 0 |
| 5 | 0 | 2 |
| 6 | 1 | 1 |
| 7 | 0 | 0 |
| 8 | 1 | 2 |
| 9 | 0 | 1 |
| 10 | 1 | 0 |
| 11 | 0 | 2 |

（k=3 时 n 为奇数补 0、偶数补 1；k=4 时按 `(n-1) mod 3` 查）

#### 经典题完整演算

**9 个初始段，长度 `9, 30, 12, 18, 3, 17, 2, 6, 24`，k=3，求最佳归并树的 I/O 与读写次数。**

**第 1 步：算虚段**
`n=9, k=3` → `(9−1) mod (3−1) = 8 mod 2 = 0` → **补 0 个虚段**。

**第 2 步：建 3 路哈夫曼（每次取 3 个最小）**

```
初始：2, 3, 6, 9, 12, 17, 18, 24, 30

第1次：取 2,3,6 → 合并 11    累计 11
第2次：取 9,11,12 → 合并 32   累计 43
第3次：取 17,18,24 → 合并 59  累计 102
第4次：取 30,32,59 → 合并 121 累计 223
```

**总读写次数 = 223**

**第 3 步：对比"平衡归并"**

平衡归并（每趟按顺序 3 个一组）：
```
第1趟: (9,30,12)=51, (18,3,17)=38, (2,6,24)=32  → 和=121
第2趟: (51,38,32)=121                           → 和=121
总 = 242
```
**哈夫曼 223 vs 平衡 242 → 省 19 次（7.9%）**

> **注意「读写次数」的口径**：408 里常问「总 I/O 次数」，有时按「每个记录每趟读一次写一次」算（= 2 × 223），
> 有时按「块数」算。**题目问法决定乘不乘 2**，看清是"记录访问次数"还是"块 I/O 次数"。

## 4. 与 B+ 树的联系（就是你感觉到的那个点）

你直觉很准。它们不是"有点像"，而是**同一个物理约束下的两种技术**。

### 4.1 共同的约束：一次 I/O 只能搬一个块

两者都在跟同一个事实打交道：

> **磁盘一次 I/O 搬一整块（4KB/16KB），块内访问几乎免费，跨块访问极贵。**

**推论**：**尽量让一次 I/O 搬进来的块"用满"，不要浪费。**

这个推论在两边分别导致：

| | 外部排序 | B+ 树 |
|---|---|---|
| 怎么"用满"一块 | **k 路归并**：同时开 k 个输入缓冲区，一次读到 k 个段的数据 | **一个结点装 m−1 个关键字**：一次 I/O 比较 m−1 次 |
| 代价指标 | **趟数 S**（每趟搬一遍全文件） | **树高 h**（每层 I/O 一次） |
| 优化目标 | 减少 S | 减少 h |
| 记账公式 | `2 × (n/b) × S` | `h` 次块 I/O |

**注意到没有：两者的"账"是同构的 —— 层数 × 每层搬的块数 = 总 I/O。**

### 4.2 对应关系一览

| 概念 | 外部排序 | B+ 树 |
|---|---|---|
| 基本单位 | 块（page） | 块（page） |
| 分支因子 | **k**（归并路数） | **m**（阶数） |
| 深度 | **S**（趟数） | **h**（树高） |
| 深度公式 | `S = ⌈log_k m段⌉` | `h ≈ log_m n` |
| 内存约束 | k 个输入缓冲 + 1 输出 | 只缓冲当前路径（h 个块） |
| 减少深度的手段 | 增大 k / 减少段数 | 增大 m（内部结点只存索引） |
| **共同的"变瘦"技巧** | **减少每路缓冲区到 1 块，换取更大的 k** | **内部结点不存数据，换取更大的 m** |

**最后一行是关键**：两边都做了同一个交易 —— **"少存点东西，换更大的分支因子"**。

B+ 树内部结点不存数据 → m 从几十涨到几百 → 树高从 4 层降到 3 层。
外部排序每路缓冲区只给 1 块 → k 从 4 涨到 64 → 趟数从 5 降到 2。

**（严格说外部排序是"用缓冲区换 k"，但精神一样：用空间换分支因子。）**

**实算一下这个"降层"效果**（分支因子 vs 1 亿记录的树高）：

| 分支因子 | 能覆盖 1 亿记录的高度 | 说明 |
|---|---|---|
| **255**（4KB 块，key+指针各 8B） | **4 层** | 普通 B+ 树 |
| **510**（同上，块或 key 更小） | **3 层** | 差一层 = 少一次 I/O |

也就是说，**分支因子翻倍就能砍掉一层**。这就是为什么数据库要拼命压缩索引进块
（前缀压缩、整数主键不用字符串）—— 不是为了省空间，是为了**少一次 I/O**。

### 4.3 更深的一层：B+ 树的叶子链表 = 已经归并好的段

这是两者真正的"接口"。

**B+ 树的叶子层是一个有序链表。** 它和"外部排序的最终结果"在结构上是同一个东西：

```
外部排序的最终产物：
  有序文件 = [1][2][3][4][5][6][7][8]...（一条有序序列）

B+ 树的叶子层：
  [1,2] → [3,4] → [5,6] → [7,8]  （有序链表，块内有序 + 块间有序）
```

**所以在真实数据库里，这两件事是连着做的**：

```
① 先外部排序把数据排好        ← 本讲义的内容
② 再用 bulk load 直接建 B+ 树  ← 因为数据已经有序，可以从左到右
                                  "填叶子 + 往上补索引"，不用逐个 insert
```

**MySQL 建索引、`SORTED` 文件加载、LSM 树的 SSTable 合并**，都是这个流程。

### 4.4 反过来：B+ 树怎么帮外部排序

B+ 树还有一个外部排序用不到但相关的性质：**天然支持"按范围顺序读"**。

如果数据已经建了 B+ 索引，那你**不需要排序了** —— 顺着叶子链表扫一遍就是有序的。
这就是为什么 `ORDER BY 主键` 在 InnoDB 里常常不用排序（索引本身有序）。

> **一句话总结这个联系**：
> **外部排序 = 在"块式 I/O"的约束下，用最少趟数造出一条有序序列。
>  B+ 树 = 在同一个约束下，用最少层数把这条有序序列切片存起来。
>  它们的目标产物是同一条有序序列。**

### 4.5 408 会怎么考这个联系

**不会直接考「B+ 树和外部排序的关系」**（大纲没这条），但**可以间接考**：

1. **计算题**：「100 万条记录建 B+ 树索引，块大小 4KB，问需要多少次 I/O」→ 用树高算
2. **对比题**：「B+ 树适合磁盘索引的原因」→ 内部只存索引增大分支因子 → 树高低 → I/O 少
3. **概念题**：「外部排序中败者树的作用」→ 减少比较次数，**不减少 I/O**（和 B+ 树里"增大 m 才减少 I/O"对照记）
4. **应用题**：给一个场景（大数据文件排序 + 建索引），问整体流程

**答题时如果能主动补一句「外部排序的趟数和 B+ 树的树高是同一类账，都是层数×块数」，
阅卷印象会很好** —— 这说明你不是死记公式。

## 5. 真题题型模板

### 题型 1：算归并趟数与 I/O 次数

**模板**：
```
1. 算总块数         n/b
2. 算初始段数       m = ⌈n / 内存容量⌉
3. 算趟数           S = ⌈log_k m⌉
4. 总 I/O = 2 × (n/b) × S        （一读一写，每趟一遍）
```

**例题**：文件 10000 个记录，块大小 100 个记录，内存 500 个记录，做 4 路归并。

```
总块数 = 10000/100 = 100
初始段数 m = ⌈10000/500⌉ = 20
趟数 S = ⌈log₄ 20⌉ = ⌈2.16⌉ = 3
总 I/O = 2 × 100 × 3 = 600 次块 I/O
```

> **易错**：忘记乘 2（一读一写）；忘记先算初始段生成那一趟（有些题口径是含在内）。

### 题型 2：最大归并路数

**模板**：`k_max = 内存块数 − 1`（每路 1 块输入缓冲 + 1 块输出缓冲）

**例题**：内存 8 块，块 4KB，问最大几路归并？
→ `k_max = 8 − 1 = 7`

若要求每路至少 2 块缓冲：`k = ⌊(8−1)/2⌋ = 3`

### 题型 3：最佳归并树 + 虚段

**模板**：
```
1. 算虚段数   add = (k-1) - (n-1) mod (k-1)     （若已整除则 0）
2. 补 add 个长度 0 的段
3. 建 k 路哈夫曼：每次取 k 个最小合并
4. 总读写次数 = 所有内结点权重之和
```

**例题**：见 §3.3 的完整演算（9 段 k=3 → 223，补 0 个虚段）

### 题型 4：置换-选择生成的段数

**模板**：随机数据下 **平均段长 ≈ 2×内存容量**，所以 `m ≈ ⌈n / (2×内存容量)⌉`

**例题**：10000 个记录，内存放 500 个，用置换-选择生成初始段，问段数约多少？
→ `m ≈ ⌈10000 / (2×500)⌉ = ⌈10⌉ = 10`（对比内部排序法的 20 段）

### 题型 5：败者树 / 胜者树概念

| 问题 | 答案 |
|---|---|
| 败者树的作用 | **减少比较次数**（O(k) → O(log k)） |
| 会影响 I/O 次数吗 | **不会**。I/O 只由趟数 S 决定 |
| 败者树内部结点存什么 | **败者**（输的那个段的当前值） |
| 与胜者树比较次数 | **相同**，但败者树常数更小、更新更快 |
| k 路归并比较次数 | 每输出一个记录 O(log k) |

---

## 6. 易错清单（按丢分概率排序）

1. **「败者树减少 I/O」——错**。它只减少比较次数。I/O 由趟数决定。这是最高频陷阱。
2. **归并趟数忘记 log 的底是 k**（不是 2）。`S = ⌈log_k m⌉`。
3. **虚段公式记反**：是 `(k-1) - (n-1) mod (k-1)`，不是 `(n-1) mod (k-1)` 本身。
4. **总 I/O 忘记乘 2**（读一遍 + 写一遍）。
5. **最佳归并树和哈夫曼树混**：最佳归并树是 **k 路**哈夫曼（每次合 k 个），不是二叉。
6. **置换-选择段长记成"= 内存容量"**：是 **≈ 2×内存容量**。
7. **初始段生成那一趟算不算进总 I/O**：看题目口径，不确定就写清楚"含/不含初始段生成"。
8. **k_max 算错**：是 `内存块数 − 1`（输出缓冲占 1 块），不是 `内存块数`。

---

## 7. 手算纪律（外部排序全靠算，不靠画）

外部排序不像 B 树要画图，它是**纯算术题**。所以纪律是：

1. **先把符号列出来**：n、b、n/b、m、k、S。**不要跳步直接写答案。**
2. **每步写公式再代数**，不要心算。
3. **归并趟数用手算 log**：`⌈log₄ 20⌉` → 4²=16 < 20 ≤ 4³=64 → **3**。
4. **最佳归并树画出来**（三层树状图即可），避免漏合并。
5. **最后检查量级**：趟数一般 2~5 趟。算出 20 趟就是错了。
