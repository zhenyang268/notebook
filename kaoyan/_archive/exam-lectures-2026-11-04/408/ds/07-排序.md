## 二、正文

### 7.1 基本概念：稳定性是"可组合性"的保证

排序是把记录序列按关键字重排。**稳定性**：若排序前 $R_i$ 在 $R_j$ 之前且 $key_i=key_j$，排序后 $R_i$ 仍在 $R_j$ 之前，则该算法稳定。

为什么需要它：当记录有多个关键字、要"先按次要关键字排、再按主要关键字排"时，只有稳定算法才不会把前一次的顺序冲掉。基数排序能成立，全靠每一趟分配-收集是稳定的——这一点在第 7.6 节会看到它直接决定正确性。

**内部排序**全程在内存；**外部排序**数据量大，需在内外存之间分批归并。二者的复杂度度量不同：前者数比较/移动次数，后者数磁盘读写次数（趟数）。

"一趟之后序列长什么样"是本章最高频的判据，先记住骨架：

| 算法 | 第 $i$ 趟后能确定什么 |
|---|---|
| 直接插入 | 前 $i+1$ 个元素**局部有序**，但都不是最终位置 |
| 冒泡 | 末端（或首端）$i$ 个元素**就位** |
| 简单选择 | 首端 $i$ 个元素是全局最小的 $i$ 个，**就位** |
| 堆排序 | 末端 $i$ 个元素**就位** |
| 快速排序 | 至少 1 个（枢轴）**就位**，且左小右大 |
| 二路归并 | 每个长度 $2^i$ 的段内有序，段间无序 |
| 基数排序 | 按某一位"相对有序"，整体通常仍无序 |

### 7.2 插入排序

**直接插入**：设 $A[1..i-1]$ 已有序，把 $A[i]$ 插入其中。教材版用 $A[0]$ 当**哨兵**存放 $A[i]$，于是内层循环的边界判断 `j>=1` 被省掉（哨兵必然在 $j=0$ 处"挡住"），循环条件变成纯关键字比较：

```
A[0]=A[i]; j=i-1;
while (A[0]<A[j]) { A[j+1]=A[j]; j--; }
A[j+1]=A[0];
```

最好情况（已升序）每趟比较 1 次、不移动，$O(n)$；最坏（逆序）比较与移动均 $\frac{n(n-1)}{2}$，$O(n^2)$；平均 $O(n^2)$；空间 $O(1)$；**稳定**（`<` 才后移，等号时停下，$A[i]$ 落在相等元素之后）。

**例**：$A=[49,38,65,97,76,13,27,49']$，逐趟结果：

- $i=2$：$38<49$ → $[38,49,65,97,76,13,27,49']$
- $i=3,4$：$65,97$ 均大于前驱，不动
- $i=5$：$76$ 退过 $97$，停在 $65$ 后 → $[38,49,65,76,97,13,27,49']$
- $i=6$：$13$ 退到最前 → $[13,38,49,65,76,97,27,49']$
- $i=7$：$27$ → $[13,27,38,49,65,76,97,49']$
- $i=8$：$49'$ 退过 $97,76,65$，比较 $49'$ 与 $49$ 时 $49'\ge 49$ 立即停 → $[13,27,38,49,49',65,76,97]$

注意最后一步：$49'$ 落在 $49$ 之后，这就是稳定性在代码里的落点。

**折半插入**：有序段上二分找插入点，比较次数降到 $O(n\log n)$，但**移动次数不变**仍为 $O(n^2)$，故总时间仍是 $O(n^2)$。稳定（二分取上界时须走到相等元素之后）。

**希尔排序**：取增量 $d_1>d_2>\cdots>d_t=1$，对每个 $d$ 把序列分成 $d$ 组做直接插入。$d>1$ 时元素跳跃移动，**不稳定**；时间依赖增量序列（Hibbard 序列可到 $O(n^{1.5})$），最坏仍 $O(n^2)$；空间 $O(1)$。最后一趟必是 $d=1$ 的直接插入，但此时序列已"基本有序"，总代价远小于一次性直接插入。

### 7.3 交换排序

**冒泡**：每趟相邻比较，把当前最值"冒"到一端并**就位**。加 `flag` 后若某趟无交换即可提前结束，最好 $O(n)$；最坏/平均 $O(n^2)$；稳定（相等不交换）。

**快速排序**：取枢轴 $p$，用双指针把序列分成"$\le p$"与"$\ge p$"两半，枢轴就位后递归。教材版划分：`low` 从首找 $>p$ 的，`high` 从尾找 $<p$ 的，互相填坑，最后 `A[low]=pivot`。

**例**：$[49,38,65,97,76,13,27,49']$，$pivot=49$，$low=1,high=8$：

1. $high$ 左移：$49'\ge49$ 跳过，$27<49$ → $A[1]=27$；序列 $[27,38,65,97,76,13,27,49']$
2. $low$ 右移：$27,38<49$，$65>49$ → $A[7]=65$；$[27,38,65,97,76,13,65,49']$
3. $high$ 左移：$13<49$ → $A[3]=13$；$[27,38,13,97,76,13,65,49']$
4. $low$ 右移：$13<49$，$97>49$ → $A[6]=97$；$[27,38,13,97,76,97,65,49']$
5. $high$ 左移到 5：$76>49$ 跳过，到 4 时 $low=high=4$，落 $pivot$。

结果 $[27,38,13,\mathbf{49},76,97,65,49']$。检验：左段全 $<49$，右段全 $\ge 49$，**枢轴落到最终位置 4**，但左右段内部都没序——这就是"一趟划分的性质"，也是 2024 #8 要辨的点。

复杂度：平均 $O(n\log n)$；最坏 $O(n^2)$，触发条件是**每次划分极不均衡**——序列已基本有序/逆序且取首元素为枢轴时，划分恒为 $1$ 与 $n-1$。递归深度最好 $\lceil\log_2(n+1)\rceil$，平均 $O(\log n)$，最坏 $n$；栈空间同阶，$O(\log n)\sim O(n)$。不稳定。

### 7.4 选择排序与堆

**简单选择**：第 $i$ 趟在 $A[i..n]$ 中选最小者与 $A[i]$ 交换。比较次数恒为 $\frac{n(n-1)}{2}$（与初态无关），移动次数至多 $n-1$；时间恒 $O(n^2)$；空间 $O(1)$；**不稳定**（把远处的最小值与 $A[i]$ 交换会跨过相等元素）。

**堆**是完全二叉树且满足 $A[i]\ge A[2i],A[i]\ge A[2i+1]$（大根堆）。下坠调整沿"较大的孩子"走，代价 $O(h)$。

**自底向上建堆为什么是 $O(n)$**：高度为 $h$ 的结点数不超过 $\lceil n/2^{h+1}\rceil$，每个下坠 $O(h)$：

$$T(n)=\sum_{h=0}^{\lfloor\log_2 n\rfloor}\left\lceil\frac{n}{2^{h+1}}\right\rceil h \le n\sum_{h\ge 0}\frac{h}{2^h}=2n=O(n)$$

## 三、真题落点

- 2021 #10 选择：考的是基数排序某一趟「分配—收集」后序列的重排结果，即按当前位把元素分到各队列再依次串回这一步。
- 2021 #11 选择：考的是给定关键字序列上排序过程的中间状态还原，即每趟比较、交换后序列的具体走向，需要一步一步手动推导。
- 2022 #10 选择：考的是归并排序中「二路归并操作」的功能定位，即把两个有序子表比较取小、合并成一个有序表这一步；它是归并排序的核心操作，并非整趟递归。
- 2022 #11 选择：考的是算法选型的判据，即给定场景（规模、初始有序程度、稳定性要求、最坏时间限制）下直接插入优于快排的理由。
- 2023 #10 选择：考的是稳定性判定这一步，即逐个检查各算法在「相等元素相对次序是否保持」上的表现。
- 2023 #11 选择：考的是快速排序一趟划分的结果判定，即由划分后序列反推枢轴归位位置，以及左右子区间元素与枢轴的大小关系。
- 2024 #8 选择：考的是快速排序一趟划分的性质辨析，即枢轴最终位置确定、左小右大成立，但子区间内部仍无序。
- 2024 #9 选择：考的是大根堆连续删除两次堆顶的完整过程，即「末元素补位 → 自上而下筛选下沉」执行两轮后的堆序列。

## 四、易错清单

1. 建堆时从叶子往上筛选，误从根往下 → 正确做法：从 $\lfloor n/2\rfloor$ 号结点起，逆序逐个向下筛选到 1 号结点。
2. 删除堆顶后把堆尾元素补到根上却忘记堆长减一 → 正确做法：先 `heap[n]` 补根、$n\leftarrow n-1$，再对新根执行下沉。
3. 下沉时只与左孩子比较就交换 → 正确做法：先选出左右孩子中较大者，再与待下沉元素比较，大者上移。
4. 快排划分只写「左小右大」而不跟踪指针 → 正确做法：用 `low/high` 双指针交替扫描，`high` 找小于枢轴者填 `low`，`low` 找大于枢轴者填 `high`，最后枢轴落位。
5. 认为一趟划分后两侧子区间也有序 → 正确做法：一趟划分只保证枢轴归位、左右分区，子区间内部仍需递归。
6. 归并排序把「归并操作」与「整趟归并排序」混为一谈 → 正确做法：归并操作只合并两个已有序子表，时间 $O(n)$；整趟需 $\lceil\log_2 n\rceil$ 趟。
7. 判断稳定性时凭「看起来是否交换相邻元素」→ 正确做法：逐个算法核对，插入/冒泡/归并/基数稳定，选择/快排/堆排不稳定。
8. 基数排序按最高位优先分配 → 正确做法：LSD 从最低位开始，每趟对全部元素做一次分配与收集，收集时保持队列内先进先出。
