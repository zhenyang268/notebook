## 一、核心方法论：三层问答（①②③）

一切知识点的学习，都拆成三层，逐层推进：

| 层 | 名称 | 要产出什么 | 回答 |
|---|---|---|---|
| **①** | 机制层（What / How） | 状态机图 / 时序图 / 数据流图 | "它是什么、怎么运作" |
| **②** | 设计层（Why / Where） | 设计动机 + 层级定位 | "它为什么这么设计、站在哪一层" |
| **③** | 验收层（Can-do） | 题型清单 + 模板 + 变式作答 | "怎么考、我能不能在纸上复现" |

**关系（关键，不可误解）**：
- ①② 是**理解的地基**，③ 是**得分的验收**。
- **③ 是最终判据，但不是唯一动作**：③ 通过才算学完；③ 不通过 → 归因 → 回补 ①② 的漏洞。
- 只做 ①②（画图、看动画）会产生**理解幻觉**——能点头，但考场推不出来。**计算型知识必须动笔过 ③。**

## 二、三视角模型（每个子块都要过三关）

对每个知识单元，从三个视角各讲一遍：

| 视角 | 内容 | 产出 |
|---|---|---|
| **课本视角** | 教材定义、特征、标准表述 | "408 原话怎么说" |
| **现实视角** | xv6 / Linux / 真实源码对象 | "真机怎么实现"，及与课本的**边界差异** |
| **应试视角** | 题型、模板、变式、易错 | "怎么考、能否复现" |

**现实视角的边界（重要）**：项目源码只用于**建立直觉、锚定差异**，不作为考核目标。
写现实视角时**必须标注"可用 / 不可用边界"**——即"这段代码帮助理解什么，但 408 不直接考什么"，避免被项目误导（归因维度之一）。

**实践代码引用规则（2026-10-11 起，硬规则）**：
复习 408 时用户想看对应的实践代码，agent **必须**去 `learning-408/` 仓引用真实代码，
**禁止凭记忆/想象编造代码、路径或文件内容**。流程：

1. 读 `~/develop/learning/learning-408/README.md`（主题 → 代码映射的**唯一真源**），定位子仓与文件路径。
2. 进对应子仓读真实代码（`jos/` 操作系统、`csapp/` 组成），引用时标注「仓库名 + 文件路径」。
3. 子仓尚未实现的部分（如 jos 的文件系统）**如实说明"该部分代码尚无"**，
   不得拿其他项目的代码冒充，也不得现编"示例实现"充当实践代码。
4. 现实视角的边界标注照旧适用：项目代码只建直觉，不是考核目标。

## 三、模块化结构

学习单位是**模块（Module）**，不是零散知识点。每个模块 = **1 个总纲 + N 个有序子块**。

- 总纲（块0）：画**总图**——本模块站在 OS/系统的哪一层，与相邻模块如何衔接。
- 子块：按"**是什么 → 怎么生/建 → 怎么运作 → 怎么协作 → 怎么分配**"的逻辑排序。
- 例：进程模块 = 总纲 + 定义抽象 / 创建控制 / 调度 / 同步互斥 / 资源与 IPC（见 `note/408/os/` 下 408-OS-02xx 各文件）。

**子块的标准格式**（每个子块都长这样）：
```
## 块N 名称  [优先级标签]
### N.1 机制层（①）   → 图 + 说明
### N.2 设计层（②）   → 动机 + 层级定位 + 现实对照（含边界）
### N.3 验收层（③）   → 题型清单 → 模板 → 代表例 → 变式
### N.4 归档          → 落到哪个 md（按 AGENTS.md）
```

## 四、题型驱动机制（③ 的落地）

**核心认知**：408 是**封闭题库**，计算题的"题型"**有限且可穷举**。所以学一个知识点的正确粒度是"**覆盖它的全部题型**"，而不是"做几个例子"。

每个知识点在验收层必须给出一张**题型清单**：

| # | 题型 | 模板要点（通用步骤） | 优先级 |
|---|---|---|---|
| 1 | … | … | ★ |

**每个题型配三样东西**：
1. **代表例**（1 个，讲透）
2. **通用模板**（可迁移的解题步骤，比例子更值钱）
3. **变式**（1 个，换条件验证）

**"学会了"的判据**：给定一个**没见过的变式**，能套模板做出来；而不是"记得那个例子的答案"。

**负向考法也要覆盖**：题目可能给出一段代码/一个设计，问"**哪里错了 / 会不会死锁 / 何时退化**"——这考的是模板的**校验步骤**，纯正例覆盖不到，必须专门练。

## 五、侧重原则（"有侧重"的落地机制）

**侧重不是口号，是可执行字段。** 依据是 408 分值权重：

| 科目 | 分值 | 高权重模块（优先投入） |
|---|---|---|
| 数据结构 | 45 | 树/堆、图、查找/排序、散列表 |
| 计算机组成原理 | 45 | Cache、流水线、浮点运算、指令周期/数据通路 |
| 操作系统 | 35 | 调度计算、PV、页面置换、地址翻译、文件系统索引 |
| 计算机网络 | 25 | 子网划分/CIDR、TCP 拥塞控制、CRC |

**优先级标签（全库统一）**：

| 标签 | 含义 | 处理 |
|---|---|---|
| `★核心` | 高频、分值大、必考 | **优先排入**，必须过 ③ |
| `☆常规` | 常考、需掌握 | 正常推进 |
| `○了解` | 低频、了解即可 | 可快速过，不深追 |

每个**模块**和每个**题型**都要打标签。agent 排学时**先推 ★**。

## 六、agent 引导循环（代替网课）

**开场机制（连贯的第一步）**：每次学习会话开场，agent 只做两件事 —— 读 `syllabus/<科>.md` 主键表
+ 跑 `python3 tools/mastery.py` 取档位分布，生成**状态面板**（≤ 5 行，不含建议）：

```
【状态面板】（YYYY-MM-DD）
范围：408 112 KP / 数一 72 KP
档位：M0 x / M1 x / M2 x / M3 x / M4 x   ← 仅索引，不是进度
入口：quick/<科>.md（主线）｜ note/<KP>.md（考法）｜ drill/（拔高）
（不排今日任务、不报欠账 —— 进度与安排都在 learning-todo/daily/）
```

**中断点恢复**：用户说"继续"即可 —— agent 从 `CHANGELOG.md` 最近一条 + `syllabus/` 掌握列恢复上下文，
不要求用户复述学到哪。

**引导循环**（接到"学 X 模块"或"继续"后按此推进）：

```
1. 规划：按模块结构拆出子块，标注优先级，给出本轮范围（默认单子块）
2. 讲解：对当前子块，按 ①②③ 三层逐层展开
3. 出题：按题型清单出题（agent 生成，不依赖用户喂题）
4. 判卷：用户作答后，按归因维度诊断
5. 归因 → 回补：不过 → 定位到具体层，回补；通过 → 归档
6. 归档：按 AGENTS.md 写入对应 md，报告结果；`mastery.py --set` 改档（进度另有渠道，不在此写）
7. 推进：进入下一子块，或按用户指令跳转/复习
```

**效率纪律（连贯 ≠ 拖长）**：
- **一轮一闭环**：讲解 → 出题 → 判卷 → 归档在同一轮完成，不跨天挂着——挂两天就是假性理解滋生。
- **讲解量与错题密度成正比**：连续答对的题型快速过模板，错题处才展开 ①② 回补。不平均用力。
- **计时反馈**：限时作答记录实际用时，面板跟踪**限时正确率**趋势（冲刺期唯一有意义的指标）。
- **必考点前置**（限数学/408 复习主线）：每个子块讲解开头先亮**必考点清单**（= ③ 题型清单的高频子集 + 大纲/分值权重依据）。你自主刷题时拿它对号入座——刷到哪个考点、哪个考点还没刷到，一眼可见。英语/政治不适用（脱离主线，见 §6A）。
- **复习主线与自主刷题并行**：复习主线（本循环）agent 主导，范围限**数学/408**；刷题节奏**用户自主**，agent 只提供节点/量建议与判卷服务（见 §6B.3），不安排怎么刷。**英语/政治脱离主线**：英语以对话问答随学随归档（agent 应答 + 按归属规则落 md），政治自主刷题 + 判卷服务；两科不进今日面板的"今日建议"。

**归因维度（判卷必用）**：`概念不清 / 计算失误 / 没记住 / 审题错 / 项目误导 / 存疑待核`。

**粒度纪律**：默认**单子块**推进。用户说"继续"才进入下一块；用户说"跳过/复习某块"则按指令。**不要一次性讲完整个模块**（防止信息过载与假性理解）。

**出题纪律**：
- agent 负责规划与出题，**效率优先**，不要求用户喂题。
- 用户的习题册仅作**题型同源锚定**：agent 出的题与用户册子里的题型对齐，防止 AI 自由发挥导致方向偏移。
- 出题难度默认对齐 **408 真题**；可另设"挑战档"（见 §八）。
- **限时作答**：验收出题默认注明**建议用时**（对齐真题：单选约 2 分钟、计算大题约 15–20 分钟）；用户可明确说不限时。**作答超过建议用时，即使全对也按"部分通过"处理**——考场拼的是限时正确率。

## 6B、判卷与记账

### 6B.1 判卷边界（什么算「通过」）

- **客观题（选择/填空）**：以题面为唯一事实源。答案冲突时必须写明依据；无法判定的归
  「存疑待核」，不硬裁。**答对但路径错也要标出**——换个数就露馅。
- **大题（计算/综合）**：按**步骤给分**，不只看最终答案。根节点算错但思路对 → 记「计算失误」，
  不算概念错误。
- **归因维度**：`概念不清 / 计算失误 / 没记住 / 审题错 / 存疑待核`。

### 6B.2 掌握度（取代遗忘曲线）

- 五档 `M0–M4` 的判据见 `BOUNDARY.md` §4；**M2 以上必须有证据**（哪道题、哪天默写的）。
- 不做 `R1/R2/R3` 到期调度：那是日历，不是掌握度。
- 记账：`python3 tools/mastery.py --set <KP> <档>`；总览：`python3 tools/mastery.py`。

### 6B.3 纸质刷题与判卷服务

- 介质：纸质真题 + 模拟卷（用户自备）。刷题节奏用户自主。
- 提交：**一页一图、拍正拍满**；配一行元信息（卷名年份 + 题号范围 + 限时与否）。
- 判卷后只做两件事：① 把该题的「坑」补进对应 `note/` 文件；② `mastery.py --set` 改档。
- **不写模考报告文件**（旧版写进 `temp.md`，从没人回看）。趋势只看掌握度分布。
- 反查：错题 → `syllabus/` 的 KP → `note/` 该条（反向走 `exam/真题/` 的章标注）。

## 七、完整性与归档

### 7.1 学习单元归档格式

沿用 `AGENTS.md` 第三节的 KP 文件骨架（**只追加，不改写历史**）。
每个 KP 文件必备三层与四段：

```markdown
## ① 机制层   → 表格 / Mermaid / 手算模板
## ② 设计层   → 为什么这样设计、站在哪一层、边界在哪
## ③ 验收层   → 题型清单 → 代表例 → 易错点（配反例）→ 待解决
## 复习记录   → 日期 · 档位 · 通过与否 · 归因
```

缺失部分写「待补充」，**不编造**。归档的**具体落盘文件**按 `AGENTS.md` 第四节与 `syllabus/` 的 KP 表判定。

### 7.2 完整性自检清单（每完成一个模块必查）

| 维度 | 检查项 |
|---|---|
| **子块完整** | 模块的子块是否全部展开？有无遗漏子块？ |
| **三层完整** | 每个子块是否都有 ①②③？有没有只讲机制、没给题型的？ |
| **三视角完整** | 每个子块是否都过了课本 / 现实 / 应试？现实视角是否标了边界？ |
| **题型完整** | 该知识点的题型清单是否穷举？每类是否配了代表例+模板+变式？ |
| **图完整** | 该模块该画的图（甘特图、状态机、架构图…）是否都画了？（见 TOOLKIT.md） |
| **侧重落实** | 优先级标签是否打了？★ 是否优先推进？ |
| **归档完整** | 该模块的 KP 节是否都已在 `exam/` 建文件？（对照 `syllabus/`） |
| **掌握度有记录** | 学过的 KP 是否都在 `syllabus/` 主键表改了档？（`tools/mastery.py` 查） |

**任一维度不达标 → 不得标记本模块"学完"。**

- ❌ 不得只讲机制（①）就宣布"学完"——**没过 ③ 不算学完**。
- ❌ 不得用"几个例子"冒充"题型覆盖"——必须**列题型清单**。
- ❌ 不得把项目源码当考核目标——现实视角只用于建直觉，**必须标边界**；工程细节留在 `projects/`。
- ❌ 不得一次性倾倒整个模块——默认**单子块**推进。
- ❌ 不得让用户喂题作为主流程——agent 负责出题，习题册只作锚定。
- ❌ 不得改写已归档内容——**只追加**（错的地方另起「修正」段，让错误本身留下）。
- ❌ 不得把掌握档位写进正文——只在 `syllabus/` 主键表最后一列。
- ❌ 不得编造未提供的内容——缺失写「待补充」，真题年份题号尤其不许猜。
- ❌ 不得偏离应试主线——项目/可视化服务于理解，**分数靠真题与 ③**。
- ❌ **不得继续扩写 `note/`**（2026-11-08 用户定）：note 只回填错题，每次 ≤5 行，只写「错的那一步」；
  不许再新开考法小节。
- ❌ **不得为省篇幅删减 `quick/`**：它是用户与考点逐条对照、探测真实水平的入口，必须保持完整；
  同时它也不许复制 `syllabus/` 的主键表（那是两处维护）。
- ❌ 不得在本仓写进度（阶段 / 欠账 / 时间预算 / 距初试 / 今日建议）——见 §6C。
