## 一、它在做什么

给一类算法问题搭一个能反复使用的实验台，然后用它把分治、贪心、动态规划、图算法四条路线各走一遍，每一条都留下三样东西：能单独编译运行的纯 C 实现、一条能画出来的代价曲线、一份能说服自己没写错的证据。

输入是一个问题的描述加约束：规模 n 的取值范围、权值能否为负、图是否连通、数据是随机还是近乎有序。输出有两样：一是一批不依赖任何第三方库的单文件实现；二是一份代价报告，其中每个算法都给出在 8 个规模点上的操作计数（比较次数、松弛次数、递归调用次数）和 log-log 拟合斜率。

验收不看“样例跑出了正确答案”。验收看三件事：把 n 放大十倍后斜率是否稳定；在小规模上是否与暴力穷举逐个一致；把输入形态换掉（已排序、全相同、非连通、带负权）之后是否仍然对。举个具体的：交付一个排序，不是一个 `sort` 函数，而是“三种排序 × 六种输入形态 × 八个规模”的计数表，外加一条能解释“快排为什么在这里退化成平方”的曲线。

## 二、为什么这样做（功能设计）

**（1）把复杂度从背下来的结论换成自己数出来的量。**

关键决策是弃用墙钟时间作主判据，改用操作计数器。接口接在最底层——**元素比较**这一层：所有算法不许直接写 `a[i] < a[j]`，必须走 `LT(a, b)`，自增藏在宏里；图的松弛走 `RELAX(u, v, w)`；递归入口走 `ENTER()`。

这一层选对了，计数就绕不过去。如果反过来在算法外面包一层计时器，能得到时间，但得不到“比了多少次”，也就没法把实测值和理论式对上。代价是每个算法里都要贯穿这些原语，代码比裸写啰嗦，而且只要漏掉一处比较，整条曲线就系统性偏低——所以测试里要专门检查“计数为 0 但结果非平凡”这种情形。

顺带回答为什么不干脆计时：常数项在小 n 上淹没信号，缓存和编译器优化在大 n 上改变斜率，换台机器数字全变。计数是机器无关的，这是它唯一但决定性的优势。

**（2）正确性用“可否证”代替“看起来对”。**

贪心和 DP 的答案对不对，跑一个样例说明不了任何问题。所以实验台必须带一个暴力 oracle：n ≤ 10 时用全排列、子集枚举或记忆化搜索求出真正的最优解，再跑上千个随机小实例做对拍，不一致就 dump 出那个实例。

这一步的价值在于：贪心的正确性本来要靠交换论证，而交换论证写错是最常见的失败模式。对拍证明不了它对，但能在一个下午之内否证掉一个错误假设——这比在考场上发现划算太多。代价是要额外写一份“明知很慢”的参考实现，而且 oracle 本身也可能错，所以 oracle 要用两种独立写法互验一次。

DP 还要多一层：同一个递推写两遍，一遍自顶向下记忆化（状态即函数参数），一遍自底向上填表（注意遍历顺序）。两遍结果必须逐点相同。这一条能抓住绝大多数“状态定义漏维”和“填表顺序错”——不加这一层，你无法区分是转移写错了还是边界写错了。

**（3）数据形态才是复杂度的主要不可靠来源。**

生成器必须覆盖六种形态：随机、已排序、逆序、全相同、几乎有序、少量不同值。快排的平方退化只在后几种里出现，只跑随机数据等于没测。图的生成器还要额外造：非连通、自环、重边、链状、菊花状、带负权边（专门用来验证 Dijkstra 会给出错误答案）。

报告里必须给出多次运行的分布而不是单点。随机化算法跑一次得到的数没有意义，取 21 次的中位数并附四分位区间。代价是每个实验要多跑二十倍时间，但一个点的数字本来就无法支撑任何结论。

**（4）图算法靠互相验证，而不是各写一堆 assert。**

Dijkstra 的结果必须和 Bellman-Ford 在正权图上逐点相同；有负权时二者必须不同，并且要能指出是哪条边导致的。Prim 和 Kruskal 在同一张图上的 MST 权和必须相同（边集可以不同，这一点要在报告里写清楚，否则会误判成 bug）。拓扑排序的入度版和 DFS 版序列可以不同，但都必须通过“所有边方向一致”的检查，含环图必须报环。

这比给每个算法单写断言有效，因为它检验的是**定义**而不是实现细节——你写错的那一半，会被没写错的另一半顶出来。

**为什么不用更简单的做法：** 直接背一张复杂度表半小时就完事，代价是遇到变形题（改成求第 k 大、加一个约束、换一种权值）就崩，因为你手上没有能测量的东西。全程用库函数也很快，但库函数不产生计数，等于把项目唯一的生产物扔掉了。

## 三、章节大纲

**第 1 章 实验台。** 计数器原语、六种形态生成器、暴力 oracle、对拍驱动、可复现的随机种子。知识点：宏与函数指针、返回值约定、确定性复现。做完能验证：同一个冒泡排序在六种形态上的比较次数可以被打印，且两次运行完全一致。

**第 2 章 渐进度量。** Θ/Ο/Ω 的区分、log-log 最小二乘拟合、常数项与低阶项的影响、摊还分析入门。知识点：如何从离散点反推阶。做完能验证：三种排序的斜率分别落在 2、1.1~1.3、1 附近，且能把偏差归因到具体的实现细节上。

**第 3 章 分治。** 归并排序、快排划分、二分查找的边界、最近点对、大整数乘法。知识点：递归树、主定理、划分不变式、递归深度与栈空间。做完能验证：归并的递归调用次数接近 2n−1，与递归树推出来的一致。

**第 4 章 贪心。** 区间调度、Huffman 建树、硬币找零、最小延迟调度。知识点：贪心选择性质、交换论证的写法、拟阵（点到为止）。做完能验证：每个贪心要么被对拍抓出反例，要么留下一份写完整的交换论证。

**第 5 章 动态规划。** LIS、LCS、0-1 背包、编辑距离、矩阵链乘。知识点：最优子结构、状态与转移的设计、填表顺序、滚动数组压缩。做完能验证：记忆化与填表逐点一致，且都与暴力 oracle 在小规模上一致。

**第 6 章 图的表示与遍历。** 邻接矩阵与邻接表、BFS/DFS、拓扑排序、连通分量。知识点：两种存储的代价对比、手写队列与栈、时间戳。做完能验证：两种拓扑实现互相通过边方向检查，非连通图的分量数正确。

**第 7 章 带权图。** Dijkstra（含手写堆）、Bellman-Ford、Floyd、Prim、Kruskal、并查集。知识点：松弛、优先队列、负权与负环、INF 相加溢出。做完能验证：正权图上 Dijkstra 与 Bellman-Ford 逐点相同，负环能被检出且报出环上的点。

**第 8 章 策略选择复盘。** 同一个问题（建议用带权区间选择）分别用暴力、分治、DP、贪心写四遍，把四条代价曲线画在一张图上。知识点：问题归约、贪心失效的判据、精确解的成本。做完能验证：能指着图说清每一条曲线在什么规模下不可用。

## 四、不做什么

不碰 NP 完全性的证明，也不实现近似算法和随机化算法（快排的随机取样除外）。它们不改变“四种策略的手感”这个目标，投入产出不划算。

不做工程化：不写除单文件 Makefile 之外的构建，不做内存池，不做泛型。元素统一 `int`，权值统一 `long long`。类型泛化会让计数器贯穿变得极难，收益为零。

不追求代码短。用 `qsort` 一行解决排序在别的项目里是优点，在这里等于没做，因为它不产生代价曲线。

不写题解，不整理常见面试题——那是另一个项目的职责。也不做“把每个算法都讲一遍原理”的讲义，原理在教材里，这里只留能被执行的判断。

实现自由度：C99 之内的代码风格自选；优先队列可以手写堆，也可以用有序数组代替，但报告里要说明这个替换把哪一段复杂度换掉了；图的主存储两种任选其一，另一种至少要能转出来。

常见跑偏有四个：把力气花在让计时更准上（应该花在计数上）；为了对拍去写一个通用测试框架（三十行够了）；只跑随机数据（退化形态才是考点）；把 DP 的填表顺序当成要背的结论，而不是从状态依赖关系推出来的东西。
