# nand2tetris · 从与非门到俄罗斯方块 · 设计文档

> 本文是该项目的设计说明，不是教程。
> 大纲见 `OUTLINE.md`，一小时上手见 `QUICK.md`，详细记录见 `NOTES.md`。

## 一、定位与边界

本项目把“计算机从 NAND 长出来”这条链做成一条可执行、可差分验证的单一路径：12 类 HDL 芯片 → Hack 机器语言 → 汇编器 → 两层虚拟机 → Jack 编译器 → Jack 操作系统，最终让官方 Pong 在自研 CPU 上跑起来。

它不解决：工艺与版图、流水线与中断异常、Cache 与虚拟内存；Hack 没有浮点部件，因此不实现 IEEE 754；也不追求生成代码的质量，只保证与官方参考实现语义等价。

与相邻项目的分工：数字电路仿真项目负责通用的门级综合与时序分析，本项目只固定课程规定的芯片集合；编译原理项目覆盖优化与寄存器分配，本项目止于栈式代码生成；操作系统项目覆盖进程与文件系统，本项目只做内存、数学、字符串、屏幕、键盘这五组系统调用。

## 二、整体架构

整体自下而上分为五层，依赖方向严格单向，下层不回调上层；唯一的反向通道是测试层读取官方 `.cmp` 作为判据。

1. 硬件层（HDL）：Nand → Not/And/Or/Xor/Mux/DMux → 16 位逐位门 → HalfAdder/FullAdder/Add16/ALU → DFF/Bit/Register/RAM8…RAM16K/PC → CPU/Memory/Computer。
2. 机器层：指令编码（A 指令为 `0` 加 15 位常量，C 指令为 `111accccccdjjj`）与内存映射 I/O（SCREEN 起始于 16384，KBD 位于 24576）。
3. 翻译层：Assembler 与 VMTranslator，二者均为“读文本、写文本”的无状态模块。
4. 编译层：Tokenizer → Parser → CodeGen，产出 `.vm`。
5. 运行层：OS 的 Jack 实现（Math/Memory/Array/String/Screen/Keyboard/Output/Sys）与 CPU 模拟器。

## 三、技术选型与理由

- **HDL 沿用课程定义，不用 Verilog**：HDL 把时钟语义限制为每 tick 求值一次，因而不需要事件调度器，并且官方 `.tst` 可直接充当判据；若换成 Verilog，就要处理 `always` 块与竞争语义，超出本项目已有的验证能力。
- **软件链使用 Python 3.11，仅依赖标准库**：处理符号表、字符串切分和递归下降所需的代码量约为 Java 的三分之一。不选 Java，是因为官方实现即为 Java，使用同一语言容易诱使照抄参考实现，从而削弱差分校验的价值；不选 Rust，是因为借用检查对“可变符号表 + 递归下降”这类结构收益极低。
- **手写递归下降，不用 ANTLR**：Jack 文法为 LL(1)，需要最长匹配的只有 `<` 与 `<=`、`/` 与注释这两处；手写解析器 200 行内即可覆盖，并且可以避免与生成器的版本绑定。
- **测试使用 pytest 做逐行差分**，不自造断言框架。

## 四、数据流

`Foo.jack` → Tokenizer 产出 `Token(type, value, line)` 序列 → Parser 产出 AST（`ClassNode.subroutines`、`SubroutineNode.locals/params/body`）→ CodeGen 产出 VM 指令列表 `(op, arg1, arg2)` → VMTranslator 输出汇编文本，同时维护静态变量表与函数标签表 → Assembler 分两遍处理：第一遍收集标签地址，第二遍编码，输出长度不超过 32768 的 `list[int]` ROM 镜像 → CPU 模拟器以 A/D/PC 三个寄存器加 32K 字 RAM 解释执行，并写 512×256 位图与键盘字 → 输出到内存映射设备。

关键不变量：栈指针存于 RAM[0]，LCL/ARG/THIS/THAT 存于 RAM[1..4]，`call`/`return` 用 R13–R15 中转返回地址与被保存的段指针。

## 六、验收判据

1. 硬件：12 组 HDL 芯片全部通过官方 `.tst`，与 `.cmp` 的差异行数为 0；ALU 的 6 个控制位共 64 种组合全覆盖，`zr`/`ng` 判定 64/64 正确。
2. RAM16K：向 16384 个地址全写入递增模式后回读，出错字数为 0。
3. 汇编器：官方 5 个 `.asm` 全部通过；翻译 Pong.asm 耗时 < 0.5 s，峰值内存 < 100 MB。
4. VM：官方 8 个 `.vm` 测试通过；递归 Fibonacci(10) 返回 55，10 层递归返回后栈指针回落到调用前值。
5. 编译器：7 个 `.jack` 程序生成的 XML 与官方 `.cmp` 差异为 0；产出的 `.vm` 在官方 VMEmulator 上运行没有报错。
6. OS：Math.multiply 与 Math.divide 各做 $10^5$ 组随机输入，与精确值误差为 0；Memory.alloc/free 循环 $10^4$ 次后空闲块数回到初值。
7. 端到端：Pong 在自研 CPU 模拟器上连续运行 60 s 不崩溃，模拟吞吐 ≥ 1.5 M 指令/秒。

## 七、风险与已知坑

- ALU 的 `zr`/`ng` 必须对输出取判，`ng` 取结果最高位；对输入取判会漏掉输入为零的边界。
- 时序：Register 的输入要在时钟沿前稳定，RAM 的地址译码须与 load 位同步，否则写入会张冠李戴。
- 汇编器：预定义符号 R0–R15、SCREEN、KBD 要先入表；变量从地址 16 起分配；标签作用域是整个文件，不是子程序。
- VM 的 `call`/`return`：保存 LCL/ARG/THIS/THAT 与恢复的顺序写反，会导致递归第二层即错，必须用 Fibonacci 专门压测。
- 编译器：字符串常量、数组越界与 null 检查的生成位置必须统一，否则 OS 与用户代码行为不一致。
- 性能：Python 逐指令解释时 Pong 帧率偏低，屏幕需用整数位运算而非布尔列表表示。
