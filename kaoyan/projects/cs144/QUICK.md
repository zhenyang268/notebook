## 1 这一小时只做一件事

**把"乱序到达的片段"变成"连续字节流"**。

为什么先做这个？因为它是**所有可靠传输的地基**：
```
收到 [3-5] → 暂存，等 [0-2]
收到 [0-2] → 拼成 [0-5]，交付 0..5
收到 [2-4] → 重叠部分丢弃，只写 4
```
**408 里 GBN/SR 说的"按序交付""去重"，代码里就是这一个类。**

## 2 最小可跑（30 分钟）

### 2.1 数据结构（10 分钟）

```cpp
class Reassembler {
  uint64_t next_seq_ = 0;              // 下一个要交付的序号
  std::map<uint64_t, std::string> buf_; // 已到达但未连续的片段，按起点排序
  bool eof_ = false;
public:
  void insert(uint64_t seq, const std::string& data, bool eof);
  std::string read();                   // 取出当前连续可交付的部分
};
```

**关键选择**：用 `std::map<seq, string>` 而不是数组，因为片段**可能重叠、可能乱序、可能重复**。

### 2.2 插入逻辑（20 分钟）

```
对每个新片段 (seq, data)：
  1. 裁掉 [next_seq_ 之前] 的部分（已经交付过了）
  2. 与已有片段比对，裁掉重叠（保留先到的）
  3. 插入 map
  4. 循环：若 map.begin()->first == next_seq_，拼接到输出，next_seq_ 前进，删除该片段
```

**必须处理的三个边界**：
- 片段完全在 `next_seq_` 之前 → 整个丢弃。
- 片段与已有片段部分重叠 → 只写不重叠的部分。
- 片段恰好接上 → 立即合并并推进。

---

## 3 三个核心难点

### 3.1 重叠怎么裁

**规则：先到的优先**（因为先到的可能是对的重传，后到的是重复）。

```
已有 [3,5)，新来 [4,8)
→ 保留 [3,5) 不变，新片段裁成 [5,8)
```

代码上：遍历 map，对每个已有区间求交，扣除后插入剩余部分。

### 3.2 什么时候"交付"

**只有 `map` 的最小 key == `next_seq_` 时才交付**。这是"按序交付"的字面实现。

**这对应 408 里的什么**：GBN 的接收窗口 = 1（只收按序的）；SR 的接收窗口 > 1（可缓存乱序）——**`map` 就是那个缓存**。

### 3.3 EOF 不能提前报

`eof=true` 只表示"这个片段是最后一个"，**不表示可以立刻结束**——要等它真正变成连续流的一部分。

## 4 卡住怎么办

| 现象 | 原因 | 修法 |
|---|---|---|
| 输出有重复字节 | 插入前没裁重叠 | 先求交再插 |
| 该交付的不交付 | `map.begin()->first > next_seq_` 时强行拼接 | 必须**严格等于**才拼 |
| 内存暴涨 | 片段永不合并 | 每次插入后尝试合并相邻片段 |
| 收到旧片段崩溃 | 没处理 `seq < next_seq_` | 先裁剪再走后续逻辑 |

**调试方法**：打印每次 `insert` 后的 `next_seq_` 与 `map` 的 key 序列，对照手算结果。**不要打印整个 string**（太长）。
