### 1. 希尔排序增量判定

对初始数据序列 (8, 3, 9, 11, 2, 1, 4, 7, 5, 10, 6) 进行希尔排序。若第一趟排序结果为 (1, 3, 7, 5, 2, 6, 4, 9, 11, 10, 8)，第二趟排序结果为 (1, 2, 6, 4, 3, 7, 5, 8, 11, 10, 9)，则两趟排序采用的增量（间隔）依次是（ ）。 排序算法
A. 3,1
B. 3,2
C. 5,2
D. 5,3

**思路**：按候选增量把结果序列分成若干组，逐组检查组内元素是否已按非递减排列；第一趟结果用于筛出可行增量，第二趟结果用于进一步确认后一增量。
**坑**：容易把“相隔一个增量的元素”误当成连续位置上的元素，或只检查前几个元素就下结论；看到局部相邻元素有序就误判为整体已按某增量分组有序。

→ `DS-07`

### 2. 栈与队列输出序列

现有队列 Q 与栈 S，初始时 Q 中的元素依次是 1,2,3,4,5,6（1 在队头），S 为空。若仅允许下列 3 种操作： ① 出队并输出出队元素 ② 出队并将出队元素入栈 ③ 出栈并输出出栈元素 则不可能得到的输出序列是（ ）。
A. 1，2，5，6，4，3
B. 2，3，4，5，6，1
C. 3，4，5，6，1，2
D. 6，5，4，3，2，1
**思路**：抓住“队列只能从队头依次取出，进栈后只能后进先出”；关键一步是检查候选序列中某元素输出后，栈内尚未输出的元素是否还能满足后进先出的次序。
**坑**：看到序列像某种逆序，就误判成可借栈任意重排；实际一旦先输出靠后的元素，前面元素在栈中的先后关系就被固定，不能随意调换。
→ `DS-03`

### 3. 对称矩阵压缩下标

设有一个 12 × 12 的对称矩阵 M ，将其上三角部分的元素 m_{i,j} ( 1 ≤ i ≤ j ≤ 12 ) 按行优先存入 C 语言的一维数组 N 中，元素 m_{6,6} 在 N 中的下标是（ ）。
A. 50
B. 51
C. 55
D. 66
**思路**：按上三角逐行计数；关键一步是先算 m_{6,6} 前面完整的 5 行共有多少元素，再看它在本行是第几个，最后把“第几个”转成 C 数组从 0 开始的下标。
**坑**：看到 12×12 就按每行 12 个元素硬算，忽略上三角每行长度递减；或数出“第几个元素”后忘记数组下标从 0 开始而直接当作下标。
→ `DS-03`

### 4. 满二叉树结点数

设一棵非空完全二叉树 T 的所有叶结点均位于同一层，且每个非叶结点都有 2 个子结点。若 T 有 k 个叶结点，则 T 的结点总数是（ ）。
A. 2k−1
B. 2k
C. k^2
D. 2^k−1
**思路**：由“叶结点同层且非叶结点均有 2 个子结点”先判定这是满二叉树；关键一步是用满二叉树中内部结点数比叶结点数少 1 的关系求总结点数。
**坑**：看到“完全二叉树”就套一般完全二叉树的编号或叶数关系，误把叶结点数直接当总结点数或漏掉内部结点；应先识别它实际是满二叉树。
→ `DS-04`

### 5. 哈夫曼编码判定

A. 00, 1011, 01, 1010, 11, 100
B. 00, 100, 110, 000, 0010, 01
C. 10, 1011, 11, 0011, 00, 010
D. 0011, 10, 11, 0010, 01, 000
**思路**：按频次合并最小两棵子树构造哈夫曼树，或从编码长度反推权值匹配；关键一步是同时检查前缀关系与“高频字符码长应较短”的最优性。
**坑**：只检查任意编码是否互为前缀，看到满足前缀码就放过，忽略出现次数很高的字符若被分到较长码长则不可能符合哈夫曼构造。
→ `DS-04`

**坑**：看到根在中间就按层序或图面上下左右目测比较，误把左右子树的位置关系当成简单大小关系；应严格按中序先后判断。

**思路**：拓扑排序每次选入度为 0 的结点输出并删除其出边；关键一步是动态检查删除前驱后各后继结点的入度是否依次变为 0。
**坑**：看到首元素属于初始入度为零的结点就放过，误把“开头合法”当成整个序列合法；还要检查中途是否提前输出了仍有前驱未删除的结点。

### 10. 希尔排序增量判定

对初始数据序列 (8, 3, 9, 11, 2, 1, 4, 7, 5, 10, 6) 进行希尔排序。若第一趟排序结果为 (1, 3, 7, 5, 2, 6, 4, 9, 11, 10, 8)，第二趟排序结果为 (1, 2, 6, 4, 3, 7, 5, 8, 11, 10, 9)，则两趟排序采用的增量（间隔）依次是（ ）。 排序算法
A. 3,1
B. 3,2
C. 5,2
D. 5,3
**思路**：希尔排序每趟按当前增量把序列分成若干子序列分别做直接插入排序；应检查结果中相隔该增量的元素是否各自构成有序子序列。用第一趟结果验证第一个候选增量，再用第二趟结果验证第二个候选增量，逐步排除不符合的间隔。
**坑**：容易把“一趟排序后”误看成整个序列相邻元素都有序，看到结果中仍有相邻逆序就误判间隔不合理；实际只需看间隔为候选值的同组元素是否有序。

A. 6,1,7,9,8,4,5 → 6,9,7,1,8,4,5 → 9,6,7,1,8,4,5 → 9,8,7,1,6,4,5
B. 6,9,5,1,8,4,7 → 6,9,7,1,8,4,5 → 9,6,7,1,8,4,5 → 9,8,7,1,6,4,5
C. 6,9,5,1,8,4,7 → 9,6,5,1,8,4,7 → 9,6,7,1,8,4,5 → 9,8,7,1,6,4,5
D. 6,1,7,9,8,4,5 → 7,1,6,9,8,4,5 → 7,9,6,1,8,4,5 → 9,7,6,1,8,4,5 → 9,8,6,1,7,4,5
**思路**：从最后一个非叶结点开始向前逐个调整，每次与较大的子结点比较，若逆序则交换，并沿被破坏的子树继续向下调整。
**坑**：容易从根开始调整或只交换一次就停止，忽略交换后子树需继续下沉，导致初始几步误判。

## 二、计算机组成原理（12–22）

### 12. 冯诺依曼用二进制

冯诺依曼结构计算机中数据采用二进制编码表示，其主要原因是（）。 Ⅰ.二进制的运算规则简单 Ⅱ.制造两个稳态的物理器件较容易 Ⅲ.便于用逻辑门电路实现算术运算
A. 仅Ⅰ、Ⅱ
B. 仅Ⅰ、Ⅲ
C. 仅Ⅱ、Ⅲ
D. Ⅰ、Ⅱ和Ⅲ
**思路**：逐条对照二进制的状态数、物理器件可实现性和与二值逻辑的契合度，判断三条是否都能作为原因。
**坑**：看到“逻辑门”便以为只管逻辑运算，从而把“实现算术运算”排除；或把器件制造容易与运算规则简单混为同一条。
→ `CO-01`

### 13. 补码求值及差

假定带符号整数采用补码表示，若 int 型变量 x 和 y 的机器数分别是 FFFF FFDFH 和 0000 0041H，则 x、y 的值以及 x-y 的机器数分别是（ ）。 补码
A. x=-65，y=41，x-y 的机器数溢出
B. x=-33，y=65，x-y 的机器数为 FFFFFF9DH
C. x=-33，y=65，x-y 的机器数为 FFFFFF9EH
D. x=-65，y=41，x-y 的机器数为 FFFFFF96H
**思路**：先由补码符号位判断正负，负数取反加一化原码求真值；做减法时转为加上减数的相反数补码，并按 32 位截断。
**坑**：看到全 F 开头就直接当作 -65 等错值；或计算差时忘记对减数连同符号位一起取反加一。
→ `CO-02`

### 14. 最小规格化正数

IEEE 754 单精度浮点格式表示的数中，最小的规格化正数是 (  )
A. 1.0 × 2^(−126)
B. 1.0 × 2^(−127)
C. 1.0 × 2^(−128)
D. 1.0 × 2^(−149)
**思路**：单精度阶码 8 位、偏置 127，规格化数阶码字段最小取 1，尾数取全 0，阶码真值为 1−127。
**坑**：把阶码字段可取 0 的非规格化情况混入，或把最小正数误算成尾数最低位对应的极小值。
→ `CO-02`

### 15. 小端指令机器码

某 32 位计算机按字节编址，采用小端（Little Endian）方式。若语句  int i=0  对应指令的机器代码为  C7 45 FC 00 00 00 00 ，则语句  int i=-64  对应指令的机器代码是（ ）。
A. C7 45 FC C0 FF FF FF
B. C7 45 FC 0C FF FF FF
C. C7 45 FC FF FF FF C0
D. C7 45 FC FF FF FF 0C
**思路**：先由零值机器码确认立即数存放在后四字节，再把 −64 写成 32 位补码，并按小端“低字节在前”填入这四个字节。
**坑**：知道小端却把整个补码顺序完全倒置，看到 C0 FF FF FF 与 FF FF FF C0 时容易混淆。
→ `CO-02`

### 16. 逻辑与算术右移

整数 x 的机器数为 11011000，分别对 x 进行逻辑右移 1 位和算术右移 1 位操作，得到的机器数各是（ ）。
A. 1110 1100、1110 1100
B. 0110 1100、1110 1100
C. 1110 1100、0110 1100
D. 0110 1100、0110 1100
**思路**：区分逻辑右移空位补 0、所有位参与移动；算术右移保持符号位，空位补原符号位。
**坑**：把算术右移当成符号位也一起右移，或把逻辑右移误补符号位，导致最高位结果颠倒。
→ `CO-02`

### 17. DRAM行列与刷新

假定 DRAM 芯片中存储阵列的行数为 r、列数为 c，对于一个 2K×1 位的 DRAM 芯片，为保证其地址引脚数最少，并尽量减少刷新开销，则 r、c 的取值分别是（ ）。
A. 2048、1
B. 64、32
C. 32、64
D. 1、2048
**思路**：DRAM 行列地址复用，引脚数由行、列地址位数的较大者决定，先使行列接近；刷新按行进行，再在相近方案中选行数较少的。
**坑**：只盯着总容量直接取 2048×1，忽略刷新开销；或忽略 DRAM 按行刷新而在两个行列互换方案间不比较行数。
→ `CO-03`

### 18. 变址寻址求下标

按字节编址的计算机中，某 double 型数组 A 的首地址为 2000H，使用变址寻址和循环结构访问数组 A，保存数组下标的变址寄存器初值为 0，每次循环取一个数组元素，其偏移地址为变址值乘以 sizeof(double)，取完后变址寄存器内容自动加 1。若某次循环所取元素的地址为 2100H，则进入该次循环时变址寄存器的内容是（ ）。
A. 25
B. 32
C. 64
D. 100
**思路**：变址寻址有效地址为首地址加“变址值×元素字节数”，先求地址差，再除以 double 的字节数并做十六进制转十进制。
**坑**：直接把地址差 100H 当作变址值而漏除元素字节数；或把 double 误当成 4 字节。
→ `CO-04`

### 19. 减法CF与OF

减法指令  sub R1,R2,R3  的功能为  (R1)-(R2)→R3 ，该指令执行后将生成进位/借位标志 CF 和溢出标志 OF。若  (R1)=FFFFFFFFH ， (R2)=FFFFFFF0H ，则该减法指令执行后，CF 与 OF 分别为（ ）。
A. CF=0，OF=0
B. CF=1，OF=0
C. CF=0，OF=1
D. CF=1，OF=1
**思路**：减法用补码加法实现，溢出看最高位进位与次高位进位是否不同；借位标志则由无符号数大小关系或加法进位取反判断。
**坑**：把 CF 与 OF 混为一谈，看到操作数接近全 1 就误认为有借位或溢出。
→ `CO-02`

### 20. 流水线时钟周期

若某计算机最复杂指令的执行需要完成 5 个子功能，分别由功能部件 A~E 实现，各功能部件所需时间分别为 80ps、50ps、50ps、70ps 和 50ps，采用流水线方式执行指令，流水段寄存器延时为 20ps，则 CPU 时钟周期至少为（ ）。
A. 60ps
B. 70ps
C. 80ps
D. 100ps
**思路**：流水线时钟周期取最慢流水段时间，再叠加流水段寄存器延时，先找最大功能部件时间后加寄存器开销。
**坑**：只取最大部件时间 80ps 而漏加 20ps 寄存器延时；或误用平均时间、中间值。
→ `CO-05`

### 21. 同步总线传输率

下列选项中，可提高同步总线数据传输率的是（ ）。 Ⅰ. 增加总线宽度 Ⅱ. 提高总线工作频率 Ⅲ. 支持突发传输 Ⅳ. 采用地址/数据线复用
A. 仅Ⅰ、Ⅱ
B. 仅Ⅰ、Ⅱ、Ⅲ
C. 仅Ⅲ、Ⅳ
D. Ⅰ、Ⅱ、Ⅲ和Ⅳ
**思路**：从传输率公式和每次传输的开销入手，关注带宽、频率以及突发传输减少地址开销的作用。
**坑**：看到“地址/数据线复用”容易误判为提高并行度、提高传输率，其实主要节省线数。
→ `CO-06`

### 22. 外部I/O中断

下列关于外部 I/O 中断的叙述中，正确的是（ ）。
A. 中断控制器按所接收中断请求的先后次序进行中断优先级排队
B. CPU 响应中断时，通过执行中断隐指令完成通用寄存器的保护
C. CPU 只有在处于中断允许状态时，才能响应外部设备的中断请求
D. 有中断请求时，CPU 立即暂停当前指令执行，转去执行中断服务程序

**坑**：容易把通用寄存器保护误归给中断隐指令，或把“有请求”误判成可立即打断当前指令。
→ `CO-07`

## 三、操作系统（23–32）

### 23. 多任务系统特点

下列关于多任务操作系统的叙述中，正确的是（  ）。 Ⅰ.具有并发和并行的特点 Ⅱ.需要实现对共享资源的保护 Ⅲ.需要运行在多 CPU 的硬件平台上
A. 仅Ⅰ
B. 仅Ⅱ
C. 仅Ⅰ、Ⅱ
D. Ⅰ、Ⅱ、Ⅲ

### 24. 非抢占优先级调度

某系统采用基于优先权的非抢占式进程调度策略，完成一次进程调度和进程切换的系统时间开销为 1us。在 T 时刻就绪队列中有 3 个进程 P1、P2 和 P3，其在就绪队列中的等待时间、需要的 CPU 时间和优先权如下表所示。若优先权值大的进程优先获得 CPU，从 T 时刻起系统开始进程调度，则系统的平均周转时间为（）。 进程  等待时间  需要的 CPU 时间  优先级      P1  30us  12us  10    P2  15us  24us  30    P3  18us  36us  20            处理机调度算法
A. 54us
B. 73us
C. 74us
D. 75us
**思路**：先按优先权确定执行次序，再把等待时间、CPU 时间以及每次调度切换的固定开销计入各自周转时间。
**坑**：容易漏算每次 1us 的调度切换开销，或把就绪队列中的等待时间从周转时间里扣掉。
→ `OS-02`

### 25. 并发加1序列数

属于同一进程的两个线程 thread1 和 thread2 并发执行，共享初值为 0 的全局变量 x。thread1 和 thread2 实现对全局变量 x 加 1 的机器级代码描述如下： thread1 mov R1, x   // (x) → R1 inc R1      // (R1) + 1 → R1 mov x, R1   // (R1) → x thread2 mov R2, x   // (x) → R2 inc R2      // (R2) + 1 → R2 mov x, R2   // (R2) → x 在所有可能的指令执行序列中，使 x 的值为 2 的序列个数是（）。
A. 1
B. 2
C. 3
D. 4
**思路**：把每个线程的三条指令看成对共享变量的读改写临界区，关键看两个读改写能否交叉覆盖。
**坑**：误以为只要两个线程各执行一次加 1 就必得 2，忽略交叉执行时后写覆盖前写。
→ `OS-02`

### 26. 安全性检测结果

假设系统中有 4 个同类资源，进程 P1、P2 和 P3 需要的资源数分别为 4、3 和 1，P1、P2 和 P3 已申请到的资源数分别为 2、1 和 0，则执行安全性检测算法的结果是（）。
A. 不存在安全序列，系统处于不安全状态
B. 存在多个安全序列，系统处于安全状态
C. 存在唯一安全序列 P3、P1、P2，系统处于安全状态
D. 存在唯一安全序列 P3、P2、P1，系统处于安全状态
**思路**：先算系统剩余资源，再算各进程尚需资源，按“能完成则回收再继续试分配”的方式检查安全序列。
**坑**：只看到某进程尚需资源等于剩余资源就过早判定安全，忽略它完成后释放的资源仍可能不够其他进程。
→ `OS-02`

### 27. 进程阻塞事件

A. 仅Ⅰ
B. 仅Ⅱ
C. 仅Ⅰ、Ⅱ
D. Ⅰ、Ⅱ、Ⅲ
**思路**：按进程状态转换判断，阻塞通常来自等待资源或等待 I/O 完成，CPU 重新分配只影响就绪/运行。

### 28. 条件变量wait

B. 唤醒一个在 x 上阻塞的进程

D. 阻塞该进程，并将之插入 x 的阻塞队列中
**思路**：抓住管程内条件变量的 wait/signal 配对语义，wait 是主动睡眠并让出管程，signal 才是唤醒。

### 31. 文件访问优化方法

### 32. 让权等待同步机制

D. TestAndSet 指令
