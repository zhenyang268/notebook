## 0. 这条线为什么必须「看懂代码」——定位与边界

### 0.1 数据结构是 408 里唯一"代码即定义"的科目

其它三门课可以靠文字与图撑住：OS 的进程状态图、网络的时序图、组成的流水线时空图。数据结构不行 ——
**它的定义就是「结构 + 操作」这一对**。只说「二叉树是每个结点最多两个孩子的树」是定义了一半；
另一半是「遍历怎么走、建树怎么递归、线索怎么穿」。**离开操作，结构没有内容。**

## 2. 总纲地图 ★核心

### 2.1 机制层（①）—— 数据结构这科到底在考什么

**一句话**：408 数据结构考的不是"有哪些结构"，而&#x662F;**「给定操作，选结构；给定结构，算代价」**&#x8FD9;个双向映射。

```
        逻辑结构                存储结构                 操作代价
   ┌──────────────┐      ┌──────────────┐      ┌──────────────────┐
   │ 线性  线性表   │ ──→ │ 顺序 / 链式   │ ──→ │ 随机访问 O(1) vs   │
   │       栈/队列  │      │ 数组 / 指针   │      │ 插删 O(1)          │
   │       串      │      │              │      │                  │
   ├──────────────┤      ├──────────────┤      ├──────────────────┤
   │ 树形  二叉树   │ ──→ │ 链式 / 顺序   │ ──→ │ 高度 ↔ 查找深度    │
   │       树/森林  │      │ 线索 / 父子   │      │ 递归遍历的模板      │
   │       BST/AVL  │      │ 平衡因子      │      │ O(log n) 怎么保证  │
   │       B/B+     │      │ 多路          │      │ 磁盘 I/O 次数      │
   ├──────────────┤      ├──────────────┤      ├──────────────────┤
   │ 图     有向/无向│ ──→ │ 邻接矩阵/表   │ ──→ │ 稠密 vs 稀疏       │
   │       带权    │      │ 十字/多重     │      │ 遍历 → 四类应用     │
   ├──────────────┤      ├──────────────┤      ├──────────────────┤
   │ 集合   散列表   │ ──→ │ 除留余数+探测 │ ──→ │ ASL / 装填因子      │
   └──────────────┘      └──────────────┘      └──────────────────┘
```

**贯穿全科的五个"母操作"**（后面每一块都是它们的变体，认出它们就省一半力气）：

1. **遍历**（树的递归 / 图的 DFS·BFS）—— 一切"统计型"算法的外壳。
2. **查找**（顺序 / 折半 / 散列 / 树型）—— 一切"定位"问题的核心。
3. **插入与删除**（指针改法 / 数组搬移 / 旋转 / 分裂合并）—— 一切"动态结构"的代价来源。
4. **建**（建树、建堆、建图、建哈夫曼）—— 常考"这个过程走完之后长什么样"。
5. **排序**（比较型 vs 非比较型；内部 vs 外部）—— 独立成章，但本质是"用结构换时间"。

### 2.2 设计层（②）—— 为什么这些结构长这样

| 结构        | 它解决的是谁的痛点                | 代价换来了什么                  |
| --------- | ------------------------ | ------------------------ |
| 链表        | 顺序表插删要搬 O(n) 个元素         | 放弃随机访问，换 O(1) 插删         |
| 栈 / 队列    | 递归与 BFS 需要"记住来路" / "排队"  | 把"回溯"和"层次"变成显式数据结构       |
| 二叉树       | 线性结构查找必须 O(n)            | 用"分支"把查找降到 O(log n)（平衡时） |
| 平衡树 / 红黑树 | 普通 BST 在有序输入下退化成链表       | 用旋转换取"高度被锁在 O(log n)"    |
| B / B+ 树  | 磁盘 I/O 次数由**树高**决定，二叉树太高 | 一个结点塞多个 key，把树高压到 3–4 层  |
| 堆         | 只要"取最值"，不需要全序            | 用完全二叉树的数组表示，O(1) 取顶      |
| 并查集       | 只需回答"是否同集合"，不需枚举成员       | 用父子指针 + 路径压缩，近似 O(1)     |
| 散列表       | 比较型查找下界是 O(log n)        | 放弃"有序"，换平均 O(1)          |
| 图         | 线性/树形表达不了"任意两点可能有边"      | 用两种存储换不同的遍历/算法代价         |

**贯穿全科的三个设计原理**（② 的答题模板，简答题也可能考）：

1. **时间换空间 / 空间换时间**：链表 vs 数组、索引 vs 全扫、线索 vs 递归栈。
2. **用不变量约束形状**：AVL 的平衡因子、红黑树的五条性质、B 树的结点上下界、堆的偏序 ——  
   **全都是"为了让高度可控而人为加的限制"**。看到一种新树，第一问永远是"它用什么不变量控制高度"。
3. **局部性**：数组连续 → 缓存友好；链表指针跳转 → 缓存不友好。  
   408 不直接考，但这是"为什么工程里用 vector 不用 list"的答案（也是 `ds/05-01`…`ds/05-07` 里 CS149 并行 BFS 的底层原因）。

**特殊矩阵压缩：下标公式（本节数值已机器复核，见下）**

设矩阵元素为 `a[i][j]`（**i, j 从 1 开始**），压缩后一维数组为 `B[0..]`（**从 0 开始**）：

| 矩阵类型           | 存哪些元素                      | `B` 的下标 k                     |
| -------------- | -------------------------- | ----------------------------- |
| 对称矩阵（下三角，行优先）  | `i ≥ j` 的部分                | `k = i(i−1)/2 + (j−1)`        |
| 上三角（行优先）       | `i ≤ j` 的部分                | `k = (i−1)(2n−i+2)/2 + (j−i)` |
| 三对角（行优先）       | `abs(i−j) ≤ 1`（主对角线及上下各一条） | `k = 2i + j − 3`              |
| 三对角（行优先，另一种数法） | 同上                         | `k = 2(i−1) + (j−1)`          |

**三对角的两条公式是同一个东西**：`2(i−1)+(j−1) = 2i+j−3`。写哪个都行，别混。

**唯一的硬纪律**：**先把 `a[1][1]` 代进去看等不等于 0**。  
若题目的一维数组从 1 开始编号，则所有 k 加 1。**这道题失分九成出在这里，不在公式本身。**

**机器复核锚点**（n=5，`a[1][1]` 应为 `B[0]`，四条公式全部逐一代入验证通过）：

- 下三角：`a11→0`、`a21→1`、`a22→2`、`a31→3`、`a32→4`、`a33→5`
- 上三角：`a11→0`、`a15→4`、`a22→5`、`a25→8`、`a33→9`、`a55→14`
- 三对角：`a11→0`、`a12→1`、`a21→2`、`a22→3`、`a23→4`、`a32→5`、`a33→6`

任一公式代进去对不上，就是"一维数组起点"搞错了 —— 不是公式错。

**易错**

- 循环队列把"队满"写成 `rear == front`（那是**队空**的条件）。
- 卡特兰数记成 `C(2n,n)`（漏除 `n+1`）。锚点：n=3→5、n=4→14、n=5→42、n=6→132。
- 中缀转后缀时对 `(` 和 `)` 的处理顺序搞反。
- 压缩存储的 `k` 公式差常数（**每次现推 `a[1][1]` 边界，别背**）。
- 队列元素数公式写成 `rear − front`（漏掉 `+M) % M` 的环回）。

**三套约定（必须分清，这是 KMP 单选题的唯一陷阱）**

```
                  下标起点    next[首]     next 值的含义
标准前缀函数 pi     0        pi[0]=0      pi[i] = 最长公共前后缀的「长度」

你的代码 next       0        next[0]=0    next[i] = pi[i]（实测如此，与注释不符）
```

**换算**：教材 `next[j] = pi[j-1] + 1`（j ≥ 2），`next[1] = 0`。  
**验算锚点**：`t = "ababaaababaa"` → `pi = 0 0 1 2 3 1 1 2 3 4 5 6`（本文档已机器复核）。  
你原版 `build()` 给出 `0 0 1 2 3 3 3 4 5 4 5 6` —— **错的**，可作为对照反例。

**⚠️ 快排的退化是真证据，建议保留**

源码 `sort.hpp:128-129`：

```cpp
while (l < r && *vec[r] >= *partition) r--;   // 用 >=
while (l < r && *vec[l] <= *partition) l++;   // 用 <=
```

全等数组时，`r` 一路退到 `l`，划分成 `[1 个][n−1 个]` —— **每层只削掉一个元素**，深度等于 n。  
实测（复刻同一逻辑）：n=10→深度 10、n=100→100、n=1000→1000、n=5000→5000。

> 这就是教材上「快排最坏 O(n²)」的**物理证据**。教材通常说"有序或逆序时退化"，  
> 但**全等元素同样退化**，而且更隐蔽（因为不少人以为"重复元素多会让快排更快"）。  
> **建议不修它**，留作反例；真要修也不难：改用 `<`/`>` 配三路划分（Dutch flag），或随机化枢轴。

**⚠️ 这一块的关键判断：代码优先级 < 表格优先级**

408 排序的采分点**九成在"过程 + 表"上**：一趟之后序列长什么样、复杂度是多少、稳不稳。  
这些**写代码不能帮你记住**。所以：

- **必须动手的三件事**（代码真能帮上）：
  1. **堆排序的自底向上建堆 O(n)** —— 现有的 `HeapSort` 是 O(n log n) 版本，**要重写一版**才算过这个考点。
  2. **快排的划分**（挖坑法的边界最容易错）。仓里这版已有，且带"全等退化"的反例价值。
  3. **外部排序的归并趟数对拍**（算 `⌈log_k m⌉` 容易差一）。
- **不必写代码的**：冒泡/选择/插入/希尔/基数/归并 —— 手算一遍就够。


**易错**

- 希尔排序的**增量序列**不同，结果不同（题目不指定就按题给）。
- 快排"最坏 O(n²)"的条件写成"逆序"（**有序、逆序、全等元素三种都会退化** —— 本质是每次划分极不平衡。  
  全等这一种最隐蔽，实测递归深度 = n，见块9 代码对位）。
