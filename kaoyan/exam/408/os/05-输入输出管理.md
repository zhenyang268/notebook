## 二、正文

### 5.1 I/O 设备与 I/O 端口

**分类**。按信息交换单位，设备分成两类，这个分法直接决定后面用哪种控制方式：

- 块设备：以数据块为单位存取，可寻址（磁盘）。速率高，成块传送，天然适配 DMA。
- 字符设备：以字符为单位，不可寻址，只能顺序读（键盘、打印机）。速率低，天然适配中断。

**为什么需要 I/O 端口**。CPU 没法直接驱动电机和磁头，中间必须有设备控制器负责“翻译”。控制器里对 CPU 可见的那几个寄存器就是 I/O 端口，分数据寄存器（存传送的数据）、状态寄存器（busy/ready/error 位）、控制寄存器（CPU 下命令）。CPU 与设备之间唯一的握手窗口就是这几个端口，所以后面所有控制方式，本质都是“CPU 什么时候去读状态、什么时候去读写数据寄存器”的区别。

端口编址有两种：独立编址用专门的 `in/out` 指令，端口地址空间与内存分开；统一编址（内存映射）把端口当地址单元，用普通访存指令访问，代价是占内存地址空间。

### 5.2 I/O 控制方式的演进

四种方式是同一问题的四次“减负”，减的都是 CPU 的干预次数。

**轮询**：CPU 循环读状态寄存器的 busy 位，忙等。CPU 与设备串行，利用率最低，只在极简单的嵌入式里用。

**中断**：设备就绪后主动发中断，CPU 转中断处理程序搬一个单位的数据。CPU 不必空转，但每传一个字节/字就要被打断一次。

**DMA**：DMA 控制器接管总线，直接在设备与内存之间成块搬运，CPU 只在传送开始（填内存地址、字节数、方向）和传送结束（处理一次中断）时干预。关键点：数据不经过 CPU 寄存器。

**通道**：通道是一台能执行通道程序的专用 I/O 处理机。一条通道指令能控制一组数据块的传送，一次通道程序结束才中断一次。

量化对比：设一块含 $n$ 个字节、一次中断处理开销为 $t$。中断方式 CPU 被干预 $n$ 次、开销 $nt$；DMA 干预 $1$ 次、开销 $t$；通道处理 $m$ 块才干预一次，开销 $t/m$。这就是“CPU 干预频率从每字节降到每块、再降到每组块”。

**例**：磁盘块 $1\text{ KB}$，传输率 $20\text{ MB/s}$，CPU 主频 $1\text{ GHz}$，一次中断开销 $1000$ 个时钟周期。用 DMA 求 CPU 的 I/O 开销占比。

$$T_{\text{传}} = \frac{1024\text{ B}}{20\times10^{6}\text{ B/s}} = 51.2\ \mu s,\qquad T_{\text{中断}} = \frac{1000}{10^{9}\text{ Hz}} = 1\ \mu s$$

$$\text{占比} = \frac{1}{51.2+1} \approx 1.9\%$$

若改用中断方式每字节中断一次：$1024 \times 1\ \mu s = 1024\ \mu s$，已是传输时间的 20 倍，CPU 完全被淹没。这组数字就是选择控制方式的判据。

### 5.3 I/O 软件的四个层次

自顶向下：用户层 I/O 软件 → 设备独立性软件 → 设备驱动程序 → 中断处理程序 → 硬件。

- **用户层 I/O 软件**：库函数（`printf`、`scanf`）把格式化需求变成系统调用；SPOOLing 的用户接口也在这层。
- **设备独立性软件**：做“与具体设备无关”的事——统一命名、逻辑设备名到物理设备名的映射（LUT 逻辑设备表）、缓冲管理、设备分配与回收、差错控制、向用户提供统一的逻辑块大小。
- **设备驱动程序**：把抽象的读写请求翻译成对某个控制器寄存器的具体操作序列，它知道寄存器含义与时序，通常由设备厂商提供。它**不**做缓冲管理、**不**做设备分配、**不**做逻辑名映射。
- **中断处理程序**：保存现场、识别中断源、把数据从设备寄存器取走、唤醒等待进程。

**例（一次 read 的路径）**：用户程序 `read(fd, buf, n)` → 陷入内核，设备独立性软件按 `fd` 查 LUT 得到物理设备与驱动程序入口，检查缓冲区 → 调用驱动程序的读例程，驱动程序向控制寄存器写命令 → 设备工作 → 完成后发中断 → 中断处理程序把数据搬入内存缓冲区并唤醒进程。

### 5.4 I/O 应用程序接口

- 字符设备接口：`get`/`put`，字节流，不可寻址。
- 块设备接口：`read`/`write`/`seek`，以块为单位，可随机寻址。
- 网络设备接口：`socket`、`send`/`recv`，面向连接或无连接。它不属于前两类，因为网络没有“设备”实体，地址是 IP+端口。

阻塞与非阻塞的区别在**调用返回时进程处于什么状态**：阻塞 I/O 发起后进程被挂起进等待队列，I/O 完成才唤醒返回；非阻塞 I/O 立即返回（返回已传字节数或错误码），进程继续跑，通常配轮询或多路复用。

### 5.5 缓冲

缓冲要解决四件事：缓和 CPU 与设备的速度差、减少中断次数、解决数据粒度不匹配（设备按块、进程按字节）、提高 CPU 与设备并行度。

设 $T$ 为设备把一块输入缓冲区的时间，$M$ 为缓冲区数据传送到用户区的时间，$C$ 为 CPU 处理一块的时间。

**单缓冲**：只有一块缓冲区，设备往里写时 CPU 不能从里面取，所以 $T$ 与 $M$ 不能并行。设备输入第 $k+1$ 块的同时，CPU 只能处理第 $k$ 块，即 $T$ 与 $C$ 重叠：

$$T_{\text{单}} = \max(C,\,T) + M$$

**双缓冲**：设备输入第 $k+1$ 块到 buf2 的同时，CPU 可以对 buf1 做“传送 + 处理”，即 $M+C$ 整体与 $T$ 并行：

$$T_{\text{双}} = \max(T,\; C+M)$$

**例**：$T=100\ \mu s$，$M=50\ \mu s$，$C=80\ \mu s$。

$$T_{\text{单}} = \max(80,100)+50 = 150\ \mu s,\qquad T_{\text{双}} = \max(100,\;80+50) = 130\ \mu s$$

单缓冲时瓶颈在设备（$T>C$），双缓冲后瓶颈转成 $C+M=130$，说明再改双缓冲也只能提升到 130，想更快得提高 CPU 处理速度或降低 $M$。

**循环缓冲**：多个缓冲区首尾相接，设 in/out 指针，应付输入输出的突发波动。

**缓冲池**：把缓冲区集中管理，三类队列——空缓冲队列 emq、输入队列 inq、输出队列 outq；四种工作缓冲区——收容输入 hin、提取输入 sin、收容输出 hout、提取输出 sout。进程用 `Getbuf` 从 emq 取一块、按用途挂到 inq 或 outq，用完 `Releasebuf` 归还 emq。

### 5.6 设备分配与 SPOOLing

数据结构是四级链表：SDT（系统设备表，全局一张）→ DCT（设备控制表）→ COCT（控制器控制表）→ CHCT（通道控制表）。

分配三条原则：看**设备类型**（独占 / 共享 / 虚拟）决定分配方式；看**访问权限**（安全性，独占设备要用银行家算法做安全检测）；看**分配算法**（FCFS 或优先级高者优先）。

分配顺序必须是**先设备、再控制器、再通道**，任一级失败就逆序释放已分配的上级资源，否则会因“持有设备等控制器”形成死锁。

**SPOOLing（假脱机）**：磁盘上开输入井、输出井，内存设输入/输出缓冲区，配预输入进程与缓输出进程。以共享打印机为例：进程要打印时，设备独立性软件在输出井申请空闲盘块，把数据写进去，再挂一张打印请求表到打印队列，随即返回；缓输出进程按队列把井中数据真正送打印机。进程不必等打印机打完，独占的打印机被改造成多进程“同时”使用的虚拟设备。

### 5.7 设备驱动程序接口

内核维护驱动程序表，按设备号索引。驱动程序对外只暴露一组标准入口（`open`/`close`/`read`/`write`/`ioctl`），上层用统一形式调用，下层各自实现——这是“设备独立性”能成立的技术前提。

## 三、真题落点

- 2024 #31 选择：键盘中断后数据的存放位置。考的是**中断处理程序这一步**：CPU 响应键盘中断后，在中断服务程序里把控制器数据寄存器中的扫描码读入内存的内核缓冲区，既不留在设备寄存器，也不直接写进用户区。
- 2022 #32 选择：关于驱动程序，不正确的是。考的是**驱动程序在四层 I/O 软件中的位置与职责边界这一步**：它位于设备独立性软件之下、中断处理程序之上，只负责把抽象请求翻译成设备寄存器操作，不承担缓冲管理、设备分配、逻辑设备名到物理设备名的映射。
- 2023 #32 选择：设备分配需考虑的是（Ⅰ 类型 Ⅱ 访问权限）。考的是**设备分配策略这一步**：分配前既按设备类型（独占/共享/虚拟）定分配方式，又检查进程对该设备的访问权限，还要考虑分配算法与分配安全性。

## 四、易错清单

1. 把 $M$（缓冲区→用户区）当成能与 $T$ 完全并行 → 单缓冲里同一块缓冲区不能同时被设备和 CPU 动，$M$ 只能与 $C$ 部分重叠，公式是 $\max(C,T)+M$；只有双缓冲才是 $\max(T,\;C+M)$。
2. 算单缓冲时写成 $T+M+C$ → 那是完全串行的结果，忽略了设备输入与 CPU 处理的重叠，必须取 $\max(C,T)$。
3. 认为 DMA 传数据要经过 CPU 寄存器 → DMA 控制器直接在设备与内存间搬运，CPU 只在传送前后各干预一次，这才是它省 CPU 的原因。
4. 把通道当成“DMA 的别名”或“通道控制表” → 通道是能执行通道程序的 I/O 处理机，一条通道程序可控制多块乃至多台设备，干预频率再降一个量级。
5. 设备分配只分配设备 → 必须设备→控制器→通道逐级分配，失败时逆序释放，否则死锁。
6. 把 SPOOLing 说成“加个内存缓冲区” → SPOOLing 的实质是磁盘上的输入井/输出井加预输入、缓输出两个进程，属于虚拟设备技术，不是缓冲技术。
7. 把逻辑设备名到物理设备名的映射划给驱动程序 → 那是设备独立性软件用 LUT 完成的，驱动程序只管寄存器级操作。
