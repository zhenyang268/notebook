## 二、正文

### 2.1 进程与线程（`408-OS-0201`）

**为什么需要进程。** 程序是存放在磁盘上的静态指令集合，本身不能运行。多道程序并发时，CPU 要在多个执行流之间来回切换，操作系统必须为每个执行流保存“运行到哪了、占着哪些资源”，于是有了进程：**进程 = 程序段 + 数据段 + PCB**，是资源分配的基本单位，也是动态的、有生命周期的。

**PCB 的内容。** 四类：① 进程标识符（PID、用户 ID、父进程 ID）；② 处理机状态——通用寄存器、PC、PSW、栈指针（这正是上下文切换要搬运的东西）；③ 进程调度信息——状态、优先级、等待事件、其他调度参数；④ 进程控制信息——程序与数据的地址、同步通信机制、资源清单、链接指针。**PCB 是进程存在的唯一标志**：系统创建进程的第一步是申请一个空 PCB，撤销进程的最后一步是回收 PCB。

**五态与转换。** 创建、就绪、运行、阻塞、终止。转换规则要背成“谁能单向走，谁必须靠外力”：

- 就绪 → 运行：调度程序选中，**被动**；
- 运行 → 就绪：时间片到或被更高优先级抢占，**被动**；
- 运行 → 阻塞：进程自己请求 I/O 或等待某事件，**主动**；
- 阻塞 → 就绪：等待的事件发生，**必须由外部（中断/其他进程）触发**，进程自己无法完成；
- 运行 → 终止：正常结束或出错。

加入挂起后多出就绪挂起、阻塞挂起：就绪 → 就绪挂起（内存紧张被换出）、阻塞 → 阻塞挂起（换出）、阻塞挂起 → 就绪挂起（等待的事件发生了，但进程还在外存）。

> 最小例子：进程执行 `read(fd, buf, 100)`，需要等磁盘 I/O，从运行态转入阻塞态——这是主动的；I/O 完成后由中断处理程序把它从阻塞态改为就绪态——这是被动的。

**线程。** 进程切换要换页表、刷 TLB、换地址空间，开销大；而且一个进程内部的多个并发活动没必要各自独占一套资源。于是把“资源分配单位”和“调度执行单位”拆开：进程管资源，线程管执行。同进程内的线程**共享**地址空间、全局变量、打开的文件，**各自独有**寄存器组、栈、PC、状态。用户级线程由线程库管理，切换不进内核、快，但一个线程阻塞会让整个进程阻塞，也不能真正并行；内核级线程由内核调度，可并行，切换要陷入内核。多对一、一对一、多对多就是二者的组合。

**上下文切换的开销来源**：保存/恢复寄存器与 PC、切换页表导致 TLB 失效、Cache 与分支预测器冷启动、调度器本身的运行。同一进程内线程切换可省掉页表切换这一大块。

### 2.2 CPU 调度（`408-OS-0202`）

**三级调度。** 高级调度（作业调度，外存→内存，频率最低）；中级调度（内存↔外存，对应“挂起”，目的是提高内存利用率）；低级调度（进程调度，就绪→运行，频率最高，必须高效）。**抢占式**调度在时间片用完、更高优先级进程到达、中断处理结束返回用户态时都可以换人；**非抢占式**只在进程主动放弃 CPU（阻塞或结束）时换人。

**四个指标**，其中完成时刻 $C_i$、到达时刻 $A_i$、服务时间 $S_i$：

$$T_i = C_i - A_i,\quad W_i = T_i - S_i,\quad \text{带权周转}=\frac{T_i}{S_i},\quad R_i=\text{首次运行时刻}-A_i$$

**四个算法与一张表。** 设：

| 进程 | 到达 | 服务 |
|---|---|---|
| P1 | 0 | 7 |
| P2 | 2 | 5 |
| P3 | 4 | 1 |
| P4 | 5 | 4 |

**FCFS**：顺序 P1(0–7)、P2(7–12)、P3(12–13)、P4(13–17)。周转 $7,10,9,12$，平均 $9.5$；等待 $0,5,8,8$，平均 $5.25$。对短作业不利。

**SJF（非抢占）**：0 时刻只有 P1；7 时刻 P2(5)、P3(1)、P4(4) 均到齐，先 P3(7–8)，再 P4(8–12)，最后 P2(12–17)。完成时刻 $7,17,8,12$，周转 $7,15,4,7$，平均 $8.25$；等待 $0,10,3,3$，平均 $4$。非抢占 SJF 中长作业 P2 反而被后来者连续插队，这就是**饥饿**的根源。

**HRRN**：响应比 $R=\dfrac{W+S}{S}$。7 时刻：P2 $(5+5)/5=2$，P3 $(3+1)/1=4$，P4 $(2+4)/4=1.5$ → 取 P3（7–8）；8 时刻：P2 $(6+5)/5=2.2$，P4 $(3+4)/4=1.75$ → 取 P2（8–13）；P4（13–17）。周转 $7,11,4,12$，平均 $8.5$，等待平均 $4.25$。HRRN 用“等待越久响应比越高”把长作业的优先级慢慢抬起来，消除了饥饿，但代价是每次都要算一遍响应比。

**RR（$q=2$）**：队列变化 P1(0–2 剩5) → P2(2–4 剩3) → P3(4–5 完) → P4(5–7 剩2) → P1(7–9 剩3) → P2(9–11 剩1) → P4(11–13 完) → P1(13–15 剩1) → P2(15–16 完) → P1(16–17 完)。完成时刻 $17,16,5,13$，周转 $17,14,1,8$，平均 $10$；等待 $10,9,0,4$，平均 $5.75$；响应时间 $0,2,0,0$，平均 $0.5$。**RR 的平均周转最差，响应时间最好**——这是“公平换吞吐”的典型。$q\to\infty$ 退化为 FCFS，$q\to 0$ 则切换开销压倒一切。

**多级反馈队列**：多个就绪队列，优先级递减、时间片递增；新进程进最高级，用完时间片没完就降一级；只有高优先级队列空时才调度低级的。它不需要预知服务时间，兼顾响应与吞吐，代价是计算复杂、可能饥饿（可用“老化”缓解）。

### 2.3 同步与互斥（`408-OS-0203`）

**临界区四原则**：空闲让进、忙则等待、有限等待（不能饿死）、让权等待（进不去就释放 CPU，别忙等）。

**Peterson 软件方案**（两进程）：

```
flag[i]=true; turn=j;
while (flag[j] && turn==j);   // 等
临界区
flag[i]=false;
```

若两者同时进入，`turn` 只能取一个值，$i$ 与 $j$ 中必有一个的 `while` 条件为假，所以不会同时进；若 $j$ 不在临界区，`flag[j]=false`，$i$ 直接进。`turn` 保证“有限等待”。

**硬件方案 TSL**：`TSL RX, LOCK` 把 `LOCK` 读到 `RX` 并置 1，两步不可分割。用 `while TSL(...)` 实现自旋锁。**自旋锁**不睡眠、忙等，适合多处理机上极短的临界区，单处理机上纯属浪费 CPU；**互斥锁**在拿不到时睡眠、由内核唤醒，切换开销大但长临界区划算。

**信号量**：`P(S): S=S-1; if(S<0) block;` `V(S): S=S+1; if(S<=0) wakeup;`。注意 $S<0$ 时 $|S|$ 就是阻塞队列长度。

**生产者-消费者**：`empty=n, full=0, mutex=1`。生产者 `P(empty); P(mutex); 放; V(mutex); V(full);`，消费者 `P(full); P(mutex); 取; V(mutex); V(empty);`。**资源信号量必须排在互斥信号量之前**：若先 `P(mutex)` 再 `P(empty)`，缓冲区满时生产者抱着锁睡死，消费者进不来，直接死锁。

**条件变量**：`wait(cv)` 释放锁并睡眠，`signal(cv)` 唤醒一个等待者。必须与互斥锁配套，且判断条件要用 `while` 而不是 `if`——被唤醒到真正拿到锁之间条件可能又被别人改回去。

**管程**：把共享数据、操作、条件变量封装在一起，**互斥由编译器保证**（同一时刻只有一个进程在管程内），编程者只需在条件不满足时 `wait`。信号量是“自己加锁”，管程是“语言替你加锁”。

**读者-写者**：`rw_mutex` 保证读写互斥，`mutex` 保护 `count`。读者进入时 `P(mutex); count++; if(count==1) P(rw_mutex); V(mutex);`，最后一个读者离开时 `V(rw_mutex)`。这个版本读者优先，写者可能饿死；加一个写者排队信号量即可改成写者优先。**哲学家**：破坏循环等待——最多允许 4 人同时取筷子（加一个初值为 4 的信号量），或奇偶号哲学家取筷顺序相反。

### 2.4 死锁（`408-OS-0204`）

**四个必要条件**：互斥、不可剥夺、请求并保持、循环等待。四个同时成立才可能死锁，破坏任意一个即可预防。

**一个必须能自己推的不等式**：$n$ 个进程，每个最多需要 2 个同类资源，系统至少给多少才一定不死锁？最坏情况是每个进程都已占 1 个、共占 $n$ 个，全部在等第 2 个。若资源数为 $n$，死锁；若为 $n+1$，多出的那 1 个必被某进程拿到，它拿满 2 个就能运行完并释放 2 个，再把资源顺次传下去。故答案为 $n+1$。推广：每个进程最多需 $k$ 个同类资源，则需 $n(k-1)+1$ 个。

**银行家算法**。系统资源 $A=(10,5,7)$：

| 进程 | Allocation | Max | Need=Max−Alloc |
|---|---|---|---|
| P0 | 0 1 0 | 7 5 3 | 7 4 3 |
| P1 | 2 0 0 | 3 2 2 | 1 2 2 |
| P2 | 3 0 2 | 9 0 2 | 6 0 0 |
| P3 | 2 1 1 | 2 2 2 | 0 1 1 |
| P4 | 0 0 2 | 4 3 3 | 4 3 1 |

## 三、真题落点

- **2021 #24 选择**：考的是进程创建原语中必须完成的最小动作集合——申请并初始化 PCB、分配 PID、置就绪态并入就绪队列；判断依据是"没有 PCB 就没有进程"，而分配 CPU、装入程序段都不是创建时必须完成的。
- **2021 #25 选择**：考的是分时系统实现时间片轮转的两个前提——硬件间隔时钟中断提供"时间片到"的信号，就绪队列按先来先服务排队；缺时钟中断则轮转无法启动。
- **2021 #27 选择**：考的是发生进程调度的判断点——中断处理结束、即将返回用户态时，若已有更高优先级进程就绪或当前进程时间片用完，才置调度标志；在中断处理过程中不立即切换。
- **2021 #31 选择**：考的是"各进程最多需 2 个同类资源、不死锁所需最少资源数"的最坏情况推导：每个进程先占 1 个，共 n 个，再多 1 个即可让某进程凑齐 2 个并归还，故为 $n(2-1)+1=n+1$。
- **2022 #25 选择**：考的是按优先级（数小者高）调度时逐时刻选进程并画执行区间，再由完成时刻反推周转时间与等待时间。
- **2022 #26 选择**：考的是安全性算法的执行细节——令 Work 从 Available 起步，逐个找 Need ≤ Work 的进程，试分配后 Work 加上它的 Allocation，并枚举不同选取次序来数安全序列个数。
- **2022 #28 选择**：考的是"执行态→阻塞态"的因果方向——只有进程主动请求 I/O 或等待某事件才发生，且必须由运行中的进程自身发出，不能被其他进程抢占造成。
- **2023 #27 选择**：考的是"线程执行态→就绪态"的触发条件——时间片用完或被更高优先级线程抢占，线程仍可运行只是失去 CPU；要与"等待 I/O 而转为阻塞态"区分开。

## 四、易错清单

1. 把"分配内存""分配 CPU"当成创建进程必须完成的步骤 → 创建只做 PCB 申请与初始化、置就绪态入队；CPU 是调度阶段才给的，创建时进程还不运行。
2. 认为分时系统靠"程序主动让出"实现轮转 → 轮转的驱动力是间隔时钟中断，先有时钟中断置调度标志，才有时间片切换。
3. 把调度时机写成"中断一发生就切换" → 正确做法是区分中断处理中与中断返回用户态：只有在返回用户态前检查调度标志，才可能真正切换，内核态临界段内不切换。
4. 资源不死锁题直接套"总需求 = 2n" → 用最坏情况法：每进程先占 $k-1$ 个，总数为 $n(k-1)$ 时仍可能死锁，故最少需 $n(k-1)+1$；本题 $k=2$ 得 $n+1$。
5. 优先级调度画甘特图时中途插入就绪进程却仍按原进程跑完 → 每个进程到达/完成时刻都要重新比较优先级，抢占式要在到达点立刻分割执行区间，再逐段累加得完成时刻。
6. 安全性算法里忘了更新 Work → 每接纳一个进程必须执行 $Work \leftarrow Work + Allocation_i$，且该进程的 Need 置为不再考察，否则会重复计入同一进程导致安全序列数偏多。
7. 把"执行态→阻塞态"写成"被抢占"→ 抢占只能导致执行态→就绪态；转入阻塞态必须由运行进程自己发出 I/O 请求或等待事件。
8. 把线程"失去 CPU"一律当作阻塞 → 时间片到、被抢占都是执行态→就绪态，线程仍是可运行状态；只有等待 I/O 或同步条件才是阻塞态。
