## 二、正文

### 7.1 I/O 系统的层次与端口的编址

**为什么需要“层次”这个概念。** CPU 与 I/O 设备的速度差 3～6 个数量级，外设种类又杂（键盘毫秒级、磁盘微秒级、显示器按场刷新）。如果让 CPU 直接跟每台设备的电平打交道，指令系统会被彻底污染。解决办法是分层：CPU 只认一套统一的“命令—状态—数据”约定（I/O 接口），接口再去适配具体设备。这样**指令系统与设备无关**，这是 I/O 系统分层的全部意义。

层次的划分要背清楚：

$$ \text{CPU} \;\leftrightarrow\; \text{总线} \;\leftrightarrow\; \text{I/O 接口} \;\leftrightarrow\; \text{设备控制器} \;\leftrightarrow\; \text{外设} $$

层次越高越靠近软件、越通用；越低越靠近硬件、越专用。I/O 软件又分四层：用户 I/O 软件 → 设备无关的 OS 软件 → 设备驱动程序 → 中断处理程序。**设备驱动程序是唯一与硬件型号绑定的一层**，这是常考的一句话。

**端口的两种编址方式。** 端口（port）是接口里能被 CPU 访问的寄存器，不是存储器。它要占地址空间，占法有两种：

- 统一编址（存储器映射 I/O）：把端口当存储器单元，用普通 `LOAD/STORE` 访问。优点是指令多、寻址方式全，不需专门 I/O 指令；缺点是**占用了主存地址空间**，且无法用指令字长区分“访存”还是“访端口”，译码稍复杂。
- 独立编址（I/O 映射 I/O）：单独一个 I/O 地址空间，用专门的 `IN/OUT` 指令访问。优点是**不占主存空间**、程序界限清楚；缺点是需专门指令，寻址方式少（一般只能直接/寄存器间接）。

**最小例子。** 某机 I/O 端口用独立编址，地址线 8 位。则 I/O 空间为 $2^8 = 256$ 个端口，与主存空间完全独立，主存 64 KB 一个单元也不少。若改成统一编址，这 256 个单元就要从 64 KB 里划走。

### 7.2 外部设备：磁盘的关键计算

磁盘是本章唯一需要动手算的外设，与 `CO-0304` 存储系统互见，这里只保留 I/O 视角。

设磁盘有 $C$ 个柱面、每道 $S$ 个扇区、每扇区 $B$ 字节，转速 $r$（转/分）。则

$$ \text{容量} = C \times S \times B \quad(\text{单记录面}) $$

$$ \text{平均存取时间} = \text{寻道时间} + \frac{1}{2}\cdot\frac{60}{r} + \frac{1}{r}\cdot\frac{1}{S} $$

三项分别是磁头移动到目标道、等待目标扇区转到磁头下（平均半圈）、读一个扇区的传输时间。

**例 7.1** 磁盘转速 7200 r/min，每道 200 个扇区，平均寻道时间 8 ms。求平均存取时间。

一转时间 $=\dfrac{60}{7200}\,\text{s}=8.33\ \text{ms}$。

平均旋转延迟 $=\dfrac{1}{2}\times 8.33=4.17\ \text{ms}$。

传输一个扇区 $=\dfrac{8.33}{200}=0.0417\ \text{ms}$。

$$ T = 8 + 4.17 + 0.042 \approx 12.21\ \text{ms} $$

注意传输时间项用的是**一个扇区**，题目若问“读一个磁道”则整圈 8.33 ms 全算进去，此时平均存取时间 $=8+4.17+8.33$。这是最容易错的一步。

### 7.3 I/O 接口：三个寄存器的分工

**为什么必须有接口。** 三个理由，对应接口的三大功能：(1) 设备是串行的、CPU 是并行的 → 需要**数据格式转换（串并转换）**；(2) 设备电平/时序与总线不符 → 需要**同步与缓冲**；(3) CPU 要能知道设备“忙不忙、错没错” → 需要**状态寄存器**。

接口内部对 CPU 可见的寄存器只有三个：

| 寄存器 | 方向 | 作用 |
|---|---|---|
| 数据寄存器（DBR） | 双向 | 暂存传送的数据，起缓冲与速度匹配 |
| 状态寄存器（STR） | CPU 读 | 每位一位含义：忙/就绪/错误/中断请求 |
| 控制寄存器（CR） | CPU 写 | CPU 下命令：启动、复位、允许中断 |

**判定“是不是 I/O 接口”的标准**：它是否位于系统总线与设备之间、是否含上述三类寄存器、是否承担地址译码与状态上报。像“显示器适配卡”“磁盘控制器”是接口；而**打印机本身的机械部件、键盘的按键开关**不是接口。真题就考这个边界。

**例 7.2** 某接口状态寄存器格式为：D0=忙，D1=就绪，D2=错误，其余保留。CPU 用程序查询方式输出，写出等待逻辑。

只要 D0=1 就继续读状态；D0=0 且 D2=0 才写数据寄存器。逻辑条件：

$$ \text{可写} = \overline{D_0}\cdot\overline{D_2} $$

少判 D2 会导致把数据写进一个已出错的设备而永远等不到就绪。

### 7.4 三种 I/O 方式：流程与开销

**(1) 程序查询方式。** CPU 循环读状态寄存器，直到就绪再传一个数据。整个等待期间 CPU **原地空转**，不能做别的。设查询一次耗 $t_q$，设备准备一个数据需 $T$，则每传一个字 CPU 浪费约 $T$ 时间（要循环 $T/t_q$ 次）。

**(2) 程序中断方式。** CPU 发命令后**继续执行原程序**；设备就绪时发中断请求，CPU 在一条指令结束后响应，保存断点、转入中断服务程序传一个数据，再返回。CPU 只在传送瞬间介入，等待期被省下来了。

关键认识：中断方式下**每传一个数据仍要一次完整的中断响应+服务+返回**，开销是几十条指令；且数据要经 CPU 寄存器中转，**数据通路是“设备→接口→CPU→主存”**。

**(3) DMA 方式。** DMA 控制器接管总线，在设备与主存之间**直接成块传送**，CPU 既不查状态也不搬数据。传送前 CPU 做初始化：给出主存起始地址、传送字数、方向、设备号；传送中以**周期窃取**方式占用总线（每次窃取一个存取周期）；整块传完，DMA 控制器发一次中断，CPU 只做善后。

数据通路是 **“设备→接口→主存”**，不经过 CPU 寄存器，这是与中断方式的根本差异。

三种方式 CPU 开销的对比如下（传送 $N$ 个字）：

$$ \text{查询}: \; N\,(T + t_{\text{传}}), \qquad \text{中断}: \; N\,(T + t_{\text{响应}}), \qquad \text{DMA}: \; T + t_{\text{初始化}} + t_{\text{中断}} $$

注意 DMA 的等待时间 $T$ 只算**一次**（块内并行），中断与查询的时间都与 $N$ 成正比。这是“DMA 适合高速成块设备”的定量理由。

**例 7.3** 设备传输率 2 MB/s，传送 4 KB 数据块。程序查询每字查询耗时 1 μs，中断响应+服务每字 5 μs，DMA 初始化 100 μs、善后中断 10 μs（按字节计）。

块传输时间 $=\dfrac{4\text{ KB}}{2\text{ MB/s}}=\dfrac{4096}{2\times10^6}=2.05\ \text{ms}$。

查询：$4096\times 1\ \mu s=4.10\ \text{ms}$，且全为 CPU 空转。

中断：$4096\times 5\ \mu s=20.5\ \text{ms}$（本例设每字节一次中断，仅作量级演示）。

DMA：$2.05\ \text{ms}$ 传输 + $0.1\ \text{ms}$ 初始化 + $0.01\ \text{ms}$ 中断 $\approx 2.16\ \text{ms}$，CPU 占用约 $0.11\ \text{ms}$。

结论：数据块越大、设备越快，DMA 的 CPU 开销优势越压倒性。

**DMA 与中断的优先级。** DMA 请求必须**高于**中断请求。原因：DMA 服务于高速设备，请求若不被及时响应，数据会在设备缓冲里被覆盖（丢数）；中断只是通知，晚几个周期处理不影响正确性。所以 CPU 在每条指令执行完的采样顺序上，先判 DMA 请求（让出总线），再判中断请求。同时 DMA 控制器占用总线期间，CPU 若访存会被延迟（周期挪用），这是“DMA 让总线、不让 CPU”的准确说法。

### 7.5 三种方式的判据一句话

- 数据量小、设备慢、CPU 空闲多 → 查询；
- 数据量小、设备随机出现、要求及时响应 → 中断；
- 数据量大、成块、高速 → DMA。

**例 7.4** 某机每秒产生 1000 次键盘中断，每次服务 20 μs。则每秒中断开销 $=1000\times20\ \mu s=20\ \text{ms}$，占 CPU 时间 $2\%$。同一台机若用查询方式，CPU 需不停扫描，占用接近 100%。此例说明**中断的收益来自“等待期不用 CPU”**。

## 三、真题落点

- 2021 #20 选择：不属于 I/O 接口的是——考的是 7.3 节“接口的判定边界”，即接口必须位于总线与设备之间并含状态/控制/数据寄存器，而设备本身的机械/开关部件不是接口。
- 2022 #21 选择：关于中断 I/O，不正确的是——考的是 7.4 节中断方式的流程本质，尤其是“数据要经 CPU 中转”“每传一个字都要一次完整中断响应”这两步。
- 2023 #22 选择：关于 I/O 控制方式，错误的是——考的是 7.4 节三种方式的定性对比，落点在 CPU 参与程度与数据通路的差异。
- 2024 #21 选择：中断 I/O 方式——考的是 7.4 节中断方式的响应时机与开销来源，即 CPU 在指令边界响应、等待期不占用 CPU。
- 2024 #22 选择：DMA 的数据通路——考的是 7.4 节“设备→接口→主存”不经 CPU 寄存器这一步，以及 DMA 请求优先于中断请求。

## 四、易错清单

1. 把“接口”与“设备”混为一谈 → 判定时只问两件事：是否夹在系统总线与设备之间、是否有状态/控制/数据寄存器；两者缺一即不是 I/O 接口。
2. 独立编址说成“省地址线” → 正确说法是**不占用主存地址空间**；地址线是两组还是共用取决于具体实现，别混。
3. 平均存取时间漏掉传输时间项 → 三项必写：寻道 + 半圈旋转延迟 + 传输；读一个扇区取 $1/S$ 圈，读满一磁道取整圈。
4. 认为 DMA 传送期间 CPU 完全停机 → 正确的是 CPU 继续执行程序，只在 DMA 窃取总线周期访存时被延迟一小段；CPU 不被“停”。
5. 认为 DMA 整块传送要每字节中断一次 → 正确是整块传完**只发一次中断**，CPU 只做初始化与善后。
6. 把 DMA 与中断的优先级写反 → 记住判据：DMA 晚响应会**丢数据**，中断晚响应只是**延迟处理**，故 DMA 优先。
7. 中断方式下把数据通路写成“设备→主存” → 中断方式必经 CPU 寄存器中转；只有 DMA 才是“设备→主存”直通。
8. 计算 CPU 开销时把 DMA 的等待时间也乘上 $N$ → DMA 的块传输时间与 $N$ 无关地只算一次，与查询/中断的线性项本质不同。
