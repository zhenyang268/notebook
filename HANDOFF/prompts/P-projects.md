# 任务 P1 / P2 · 项目笔记（两件套）

## 背景

`notebook/` 下有 10 个项目：5 个与考纲相关（在 `kaoyan/projects/`），5 个纯工程（在 `projects/`）。

**旧版做错了三处**，必须先说清楚：

| 错误 | 用户原话 | 现在怎么改 |
|---|---|---|
| 三件套里塞了个 `QUICK.md` | 「你的项目 quick **完全没有任何意义**，本质上应该是项目大纲那个文档」 | **删除** |
| `OUTLINE` 和 `DESIGN` 分成两个文件 | 「大纲的文件那里可以额外补充设计文档的内容，**这两个文件二合一**也不会太大」 | **合并成一个 `OUTLINE.md`** |
| 写了代码仓状态 | 「**不用同步我的代码仓状态，你同步的也不对**」 | **完全不写** |

所以每个项目只剩两个文件：`OUTLINE.md` + `NOTES.md`。

## `OUTLINE.md` 的四段（核心产出）

```markdown
# 项目名 · 大纲与设计

## 一、这个项目在做什么
   一句话说清目标，不用术语堆。读者看完知道"要不要做"。

## 二、目标功能设计（重点）
   这是用户特别强调的一段。要求：不只知道"做什么"，还要知道"**怎么做到**"。

   反例（太浅）：6824 = 实现一个 Raft。
   正例（够用）：一个"替换现成系统的某一层"的项目，得先明确边界：
     - 要替换真实协议栈，得先明确边界：应用层通过 socket API 进来，
       底层通过 TUN/TAP 或 UDP 承载出去
     - 因此第一层是 ByteStream（应用看到的字节流）
     - 第二层是重组器（把乱序段拼回来）
     - 第三层是收发器（窗口、重传、超时）
     - 第四层是连接管理（三次握手、四次挥手、状态机）
     - 每一层怎么单独验证：单测喂字节 → 喂乱序段 → 模拟丢包 → 端到端跑

## 三、章节大纲
   | 章 | 内容 | 涉及知识点 | 对应考纲 KP |
   至少 8 行，每行的知识点要具体，不要写"基础概念"

## 四、不做什么（边界）
   明确范围，避免膨胀
```

**篇幅**：2000–3500 字。

## 硬性约束

1. **不写代码仓状态**：不写"已实现到第几章""commit 到哪"。项目笔记讲项目本身。
2. **不写排期**：不写"第几周做"。
3. **章节大纲的知识点必须具体**，"基础概念"这种不算。
4. 双语化：`OUTLINE.md` 后续要做中英对照（另一任务），所以**句子要能按句拆开**，
   不要写成一逗到底的长句。

## 交付检查

```bash
cd notebook
for p in projects/*/ kaoyan/projects/*/; do
  n=$(basename "$p")
  ok=$(grep -c "^## " "$p/OUTLINE.md" 2>/dev/null || echo 0)
  quick=$(ls "$p"/QUICK.md 2>/dev/null | wc -l | tr -d ' ')
  printf "%-12s OUTLINE %s 段  QUICK %s  %s\n" "$n" "$ok" "$quick" \
    "$([ "$quick" = "0" ] && echo ok || echo '应删除')"
done
```

**判据**：每个项目 `OUTLINE.md` 四段齐、无 `QUICK.md`。
