# 子 agent 调度：12 个真实故障与规范

> 全部来自 2026-11-01~02 两天、约 200 次 `bl` 调用。**每条都造成过实际损失**（返工、白烧额度、错误交付）。
> 接手的人先读这份，再读任务 prompt。

## 一、故障清单（现象 → 根因 → 正确做法）

### 1. 前台同步调用把整个会话卡死
- **现象**：`bl text chat --message "<长 prompt>"` 直接跑，5 分钟不返回，会话无法推进，也无法并行。
- **根因**：把"生成任务"当成"函数调用"。
- **正确**：`nohup bash pool.sh dispatch &`，立即返回；用 `state/*.status` 观察进度。

### 2. 用"文件非空"判断成功，被 1 字节骗过
- **现象**：状态显示 `done`，但文件只有 1 字节（一个换行）。44 个"完成"里 7 个是空的。
- **根因**：`[ -s "$out" ]` 对 `\n` 为真。
- **正确**：`sz=$(wc -c < "$out")` 且要求 `sz > 800`，同时检查退出码和错误特征串。

### 3. pump 在"刚派完、进程未起"的空档误判全部完成
- **现象**：日志写"全部完成"，实际 `done=31/36`，剩下 5 个还没开始。
- **根因**：`pending=0 && running=0` 在两个动作之间瞬时成立。
- **正确**：**连续 3 次**观测到空才算结束；且必须有"曾经出现过 running"这个前置条件。

### 4. `TASKS=x nohup bash pool.sh pump &` 环境变量丢失
- **现象**：明明指定了新任务表，pump 仍然跑旧表（80 个任务全被派出，本该只跑 5 个）。
- **根因**：`VAR=x nohup cmd &` 的变量只作用于 nohup 外层，后台子 shell 拿不到。
- **正确**：先 `export TASKS=...`，再 `nohup ... &`；或者在脚本内用绝对路径写死。

### 5. 同一行 `local` 展开未赋值的变量
- **现象**：`pool.sh: line 41: id: unbound variable`，脚本直接退出。
- **根因**：`local id=$1 pf="$STATE/$id.pid"` 在**同一条 local 语句**里，`$id` 尚未赋值。
- **正确**：拆成多条 `local`，一条只赋一个。

### 6. 单块输出超过约 4000 字必然截断或偷懒
- **现象**：给 11 个考点要求各写 400 字，21 块里 13 块只写了 1–4 条就收尾；另有块写到第 2 条就断在半句。
- **根因**：模型在长输出末段质量骤降，不是"能写但不写"。
- **正确**：**按预估输出字数切块，不按输入条数**。
  - 笔记式（120–200 字/条）→ 每块 14 条
  - 讲解式（300–450 字/条）→ 每块 5–6 条
  - 单词表（一行一词）→ 每块 150–250 行

### 7. 命令行 8000 字节上限
- **现象**：`bash: command length (10309 bytes) exceed 8000 bytes`，整条命令不执行。
- **根因**：heredoc 里塞了整个生成脚本。
- **正确**：脚本先 `write_to_file` 落盘，再 `python3 build.py`；长 prompt 用 `--messages-file`（JSON）。

### 8. `git add -A` 把施工目录带进仓
- **现象**：一次误提交 87 个中间文件（`prompts/` `out/` `state/`）。
- **根因**：`.gitignore` 只写了 `.gen/`，新建的 `.gen2/` 没登记。
- **正确**：所有施工目录统一放 `.gen/` 下（已忽略）；提交前先 `git status --short` 核对目录。

### 9. 模型"偷懒"无法用重试解决
- **现象**：同一块连续失败 2 次，第 3 次仍然只写 1 条。
- **根因**：不是网络问题，是块太大。
- **正确**：**连续两次失败就改 prompt**（拆块 / 降字数），不要重试第三次。`pool.sh` 的 `RETRY=2` 就是为此。

### 10. 补丁内容追加到末尾导致章节乱序
- **现象**：补写的考点被拼到文件末尾，DS-06 的内容跑到了 DS-07 后面。
- **根因**：按"文件顺序"拼接，而不是按"考纲顺序"。
- **正确**：把每块解析成 `{考点主键: 内容}`，**按 syllabus 的顺序重排**再输出。

### 11. 覆盖率检查的正则漏掉三字母科目
- **现象**：报告"112 个主键覆盖 112"，实际检查用的正则是 `[A-Z]{2}`，把 `NET` 整个漏掉了 25 条。
- **根因**：写正则时没核对科目缩写长度。
- **正确**：`[A-Z]{2,3}`；且**先打印"应有 N / 实有 M / 缺哪些"**，缺的条目要列出来，不要只给一个数字。

### 12. 拼接完成不等于交付
- **现象**：36 个块全部 `done`，实际覆盖率只有 41%（112 个考点写了 46 个）。
- **根因**：把"进程退出"当成"内容合格"。
- **正确**：交付前必须跑 `verify.py`，覆盖率不到 100% 不算完成。

## 二、规范（照抄即可）

### 任务表

```
tasks.tsv 每行：id <TAB> model <TAB> sysfile [<TAB> messages_file]
```

### 状态机

```
pending → running → done
                 ↘ failed → (重试 ≤2) → pending
                          ↘ quarantine（不再重试，等人工）
```

`state/<id>.status` 是**唯一状态真源**，一行一个词。不要用"文件在不在"推状态。

### 派发器必须满足的六条

1. **幂等**：派发前用 `state/<id>.pid` + `kill -0` 确认无活进程。
2. **限流**：`MAXPAR=3`；无空位立即返回，不排队。
3. **三条件验收**：退出码 0 + 字节数 > 阈值 + 不含 `Error/429/rate limit`。
4. **自动重试**：`failed → pending`，最多 2 次，超过 `quarantine`。
5. **完成判定防抖**：连续 3 次空才退出。
6. **可观测**：`pump.log` 记时间序列，`state/` 可随时 `grep` 统计。

### 块大小速查（deepseek-v4.1-flash-1017 实测）

| 输出形态 | 每块上限 | 依据 |
|---|---|---|
| 笔记（120–200 字/条） | 14 条 | 14 条稳定写完 |
| 讲解（300–450 字/条） | 5–6 条 | 11 条时 62% 的块欠写 |
| 单词表（一行一词） | 150 行 | 250 行时约 20% 块失败 |
| 双语对照（1.5 倍原文） | 原文 3000 字符 | 超过则末段丢句 |

**统一判据**：预估输出 ≤ 4000 字。

### 模型选择

- `deepseek-v4.1-flash-1017`：默认。稳定、快（约 4–5 分钟/块）。
- `qwen3.8-flash`：更慢（8–10 分钟/块），长输出更容易断。**只在需要第二种文风时用**，不要当主力。

### 禁止事项

1. 不用 `git add -A`（先用 `git status` 看清）。
2. 不在会话内前台同步调用 `bl`。
3. 不把"模型说写完了"当完成。
4. 不在同一 prompt 上连续重试超过 2 次。
5. 不在同一次调用里既生成又审校（审校要独立上下文，否则模型给自己打高分）。

## 三、工业界准则 ↔ 本方案

| 准则 | 落地 |
|---|---|
| 幂等性 | 任务 id 唯一 + pid 判活，重置不会重复执行 |
| 可观测性 | `state/` 状态文件 + `pump.log` 时间序列 |
| 背压 | `MAXPAR` 硬上限，无空位立即返回 |
| 断点续跑 | 全部状态落盘，中断后 `dispatch` 即从 pending 继续 |
| 失败隔离 | 重试 2 次进 `quarantine`，不再消耗额度 |
| 单一真源 | `tasks.tsv` 定义任务，`state/` 定义进度，产物只在 `out/` |
| 验收标准 | `verify.py` 覆盖率 + 重复检查，PASS 才算交付 |
| 关注点分离 | 生成与审校用不同 system prompt、不同轮次 |
