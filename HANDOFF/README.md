# 交接说明（2026-11-02）

> 这份目录的唯一用途：让**另一个主 agent**（或几个并行主 agent）能在不看历史对话的前提下，
> 接手做完这套笔记。每个任务都写成**可直接粘贴执行的 prompt**，彼此尽量不依赖。
>
> 目录本身进仓，是交付物的一部分，不是临时文件。

## 一、目标结构（与我上一轮做法不同的地方）

```
notebook/
├── math/                      【不动】用户明确说没问题
├── kaoyan/
│   ├── syllabus/              L0 考纲依据：考点 + 要求档位 + 真题落点
│   ├── quick/                 L1 快速学完（三合一：依据 + 概括 + 口语）
│   │   ├── 408-ds.md  408-co.md  408-os.md  408-net.md   ← 408 必须分四科
│   │   ├── math-hs.md  math-la.md  math-ps.md
│   │   ├── english.md  politics.md
│   │   └── README.md
│   ├── note/                  L2 考点 × 真题复合版（一个考点一文件，按考法归类去重）
│   │                          ※ 真题来源只有 exam/真题/ 的 2016–2024，数一无原题
│   ├── exam/
│   │   ├── 真题/              按年份完整真题（题干 + 思路）
│   │   └── 408/ math1/ …      分章详细讲解（辅导书正文）
│   ├── words/                 L3 单词书（5500+，分组 + 每组短文）
│   └── projects/              每项目两件套：OUTLINE（大纲+设计）+ NOTES（分章详细）
└── projects/                  同上两件套
```

### 用户的复习流程与文件对应（这是最终判据）

| 步 | 做什么 | 文件 |
|---|---|---|
| 1 | 研究考纲：考什么、要求到哪档 | `syllabus/` |
| 2 | 读口语解释版：建立直觉 | `quick/`（概括 + 口语） |
| 3 | **看考点与真题的复合版** | `note/`（一个考点一文件） |
| 4 | 多余时间刷真题库：整套做 | `exam/真题/YYYY.md` |
| 5 | 深挖 | `exam/<科>/<章>.md` |

**判断任何内容该放哪，就回到这张表**：它在第几步用？第 3 步用的进 `note/`，
第 4 步用的进 `exam/真题/`，第 5 步用的进 `exam/<科>/`。

### 三条被明确否掉的做法（不要再犯）

| 错误做法 | 为什么错 | 正确做法 |
|---|---|---|
| `quick/` 写成"按考点逐条详解" | 用户要的是 B 站那种**一口气讲完一门课**，不是教材 | 概括版 + 口语版，按科目（408 分四科） |
| `quick/` 按子科拆成 9 份手册 | 拆成清单就不是"过一遍"了 | 408 分四科（用户明确要求），数三分三科，其余各一份 |
| `projects/QUICK.md` | 用户判定"完全没有任何意义" | **删除**。项目只要 OUTLINE（大纲+设计合一）+ NOTES |

## 三、怎么用这份交接

```bash
# 每个任务一个 prompt 文件，直接粘给主 agent
ls HANDOFF/prompts/

# 派发时按 SCHEDULING.md 的规范跑，不要用前台同步调用
```

**并行度建议**：`MAXPAR=3` 是**单账号总额度**，多开主 agent 不会提速。
正确做法是**只让一个 pump 在跑**，其余 agent 做规划与验收（与 `EXECUTION.md` §3 一致）。

## 四、验收（每个任务都必须过）

1. **覆盖率**：`syllabus` 里的考点在本任务产物中是否都有落点（脚本核对，不靠肉眼）。
2. **篇幅**：字数落在规定区间，超了下限是偷懒，超了上限是注水。
3. **格式**：标题层级、KaTeX 写法、无前言无客套。
4. **不编造**：年份、题号、会议名、数据，没有把握一律不写。

具体脚本见 `TASKS.md` 末尾。
