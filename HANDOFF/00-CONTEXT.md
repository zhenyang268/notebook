# 接手前必读：这是什么、边界在哪

## 一、这是什么

一个**个人学习笔记仓**，2026-11-01 由两个旧仓合并而成，现为单一 git 仓：

```
notebook/
├── math/       LaTeX 数学笔记（141 页 PDF，含四篇跨篇串讲）
├── kaoyan/     考研笔记（408 / 数学一 / 英语一 / 政治）
└── projects/   工程笔记（5 个与考纲无关的项目）
```

remote 沿用原 `11408-notebook`：`gitee` 可用，GitHub 侧**仓未创建**。

## 二、用户是谁、怎么用这套东西

一位考研学生（11408，即 408 + 数学一 + 英语一 + 政治），同时自学工程课程。
他的复习流程是**五步**，这是判断任何内容该放哪的唯一标准：

| 步 | 做什么 | 对应文件 |
|---|---|---|
| 1 | 研究考纲：考什么、要求到哪档 | `kaoyan/syllabus/` |
| 2 | 读口语解释版：建立直觉 | `kaoyan/quick/` |
| 3 | **看考点与真题的复合版** | `kaoyan/note/` |
| 4 | 多余时间刷真题库：整套做 | `kaoyan/exam/真题/` |
| 5 | 深挖 | `kaoyan/exam/<科>/<章>/` |

**他不在这里刷题**，只要「题干 + 做题思路」。所以：

- 不写标准答案（他纸上自己得出）
- 不写判分、错题本、难度星级
- 思路写"第一步做什么"，不写"选 C"

## 三、硬约束（越界就重做）

1. **408 必须分四科**（数据结构 / 组成 / 操作系统 / 网络），不许合并成一份。
2. **quick 是"一口气讲完一科"的口语稿**，不是按考点逐条详解，不是清单速查。
3. **不做项目 `QUICK.md`**（用户明确判定无意义）；项目只有 `OUTLINE.md` + `NOTES.md`。
4. **项目笔记不写代码仓状态**（"我实现到第几章"这类内容一律不要）。
5. **双语化只做 `OUTLINE.md`**（大纲 + 设计），`NOTES.md` 不翻。
6. **不编造真题**：不超过 `exam/真题/` 里实际存在的年份与题号。
7. **`math/` 不动**（用户明确说"这个库没问题"）。

## 四、内容尺度（做什么、不做什么）

| 项 | 做 | 不做 |
|---|---|---|
| 篇幅 | quick 每份 6000–10000 字；exam 每章 2000–4000 字 | 注水凑字数 |
| 公式 | KaTeX，行内 `$...$`，独立 `$$...$$` | `\(...\)`、`\[...\]` |
| 引用真题 | 题干照录 + 思路 + 坑 | 编题号、编图表数据 |
| 术语 | 中文优先，首次出现补英文 | 中英夹杂成习惯 |
| 排版 | 标题层级 `#`→`##`→`###` | 一级标题出现在正文文件里 |

## 五、验收（不是"跑完了"）

每批产物必须过 `HANDOFF/tools/verify.py`：

```bash
python3 HANDOFF/tools/verify.py kaoyan/quick
python3 HANDOFF/tools/verify.py kaoyan/note
```

它检查四件事：文件齐全、字数下限、结构完整（分段/思路条数）、覆盖率（考点是否都有落点）。

**覆盖率不到 100% 不算完成**，且必须列出缺哪些，不许只报数字。

## 六、工具与额度

- 生成用 `bl text chat`，两个模型：`deepseek-v4.1-flash-1017`（主力）、`qwen3.8-flash`（备用，慢一倍）。
- `MAXPAR=3`。**多个主 agent 并行时总额度不要超过 3**，否则撞 429。
- 长 prompt 用 `--messages-file`（JSON），不要走 `--message`（命令行上限 8000 字节）。
- 派发器：`HANDOFF/tools/pool.sh`，用法见 `SCHEDULING.md`。

## 七、提交规矩

- `notebook/` 是单一仓，在此提交，不要在父仓提交。
- 不用 `git add -A`（先 `git status` 看清）。
- 施工目录统一放 `.gen/`（已忽略），不要散落在 `kaoyan/` 里。
- 每次提交说清"改了什么层、覆盖率多少"。
