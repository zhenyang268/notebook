# 子 agent 调用规约（agent pool）

> 来源：2026-11-01~02 两天里用 `bl` 批量生成笔记，连续踩了 9 个坑之后归纳。
> 目标：**长任务可以断、可以续、可以验收**，而不是"跑完看看有没有东西"。

## 一、七条硬规（每条对应一次真实故障）

| # | 规矩 | 故障记录 |
|---|---|---|
| 1 | **状态判定不能只判"文件非空"** | `bl` 失败时输出 1 字节换行，`-s` 判非空 → 误标 done，后续统计全错 |
| 2 | **done 必须三条件同时满足**：退出码 0 + 字节数 > 阈值 + 不含错误特征 | 单看退出码会漏掉"200 里包着 Error"的响应 |
| 3 | **派发必须幂等**：用 pid 文件确认无活进程再派 | 重置状态后 pump 重复派发同一任务，白烧额度 |
| 4 | **完成判定要防抖动**：连续 N 次为空才算结束 | pump 在"刚派完、进程还没起来"的空档误判全部完成并退出 |
| 5 | **单块输出有上限**：按输出长度切块，不按输入条数 | 一次给 15 个考点，模型写到第 2 条就收尾；给 9 个才稳定写完 |
| 6 | **长文本走 `--messages-file`**，不走 `--message` | 命令行长度上限 8000 字节，长 prompt 直接被拒 |
| 7 | **验收用覆盖率脚本，不用"跑完了"** | 36 个块全 done，但实际覆盖只有 41%（112 个考点写了 46 个） |

## 二、工业界准则的对应关系

| 准则 | 在本方案里的落地 |
|---|---|
| **幂等性 (idempotency)** | 任务 id 唯一；`state/<id>.pid` 判活；重置不会重复执行 |
| **可观测性 (observability)** | `state/<id>.status` 是唯一状态真源；`pump.log` 记时间序列 |
| **背压 (backpressure)** | `MAXPAR` 硬上限；无空位立即返回，不排队不阻塞 |
| **断点续跑 (resumability)** | 全部状态落盘；中断后直接 `dispatch` 即从 pending 继续 |
| **失败重试与隔离** | `failed` 自动回 `pending`，超过 `RETRY` 次进 `quarantine` 不再重试 |
| **单一真源 (SSOT)** | `tasks.tsv` 定义任务，`state/` 定义进度，产物只在 `out/` |
| **验收标准 (acceptance)** | `verify.py` 跑覆盖率与重复检查，输出 PASS/FAIL 才算交付 |
| **关注点分离** | 生成（广撒网）与审校（严格标准）用不同 system prompt，不同轮次 |

## 三、标准流程

```bash
# 1. 准备：写 build.py 生成 prompts/ 与 tasks.tsv
python3 build.py

# 2. 首轮：小样本验证形态（1 块），确认格式再批量
./pool.sh dispatch && sleep 240 && ./pool.sh status

# 3. 批量：pump 常驻，自动补位与重试
nohup ./pool.sh pump > /dev/null 2>&1 &

# 4. 验收：覆盖率 + 重复 + 格式
python3 verify.py

# 5. 第二轮：对欠写/注水的块做 critique→rewrite
python3 review.py && ./pool.sh dispatch

# 6. 拼接：只拼 verify 通过的块
python3 assemble.py
```

## 四、块大小经验值（deepseek-v4.1-flash-1017）

| 输出形态 | 每块上限 | 实测 |
|---|---|---|
| 笔记式（每条 120–200 字） | **14 条** | 14 条稳定写完 |
| 讲解式（每条 300–450 字） | **5–6 条** | 11 条时 6/21 块只写 1–4 条就收尾 |
| 结构化表格 | 10 行 | 更多会开始省略行 |

**规律**：输出总字数超过 4000 字，末段质量明显下降或直接截断。
所以切块标准是**预估输出字数 ≤ 4000**，不是条数。

## 五、禁止事项

1. **不要用 `git add -A`**：施工目录（`.gen*/`）会被带进仓，实测一次带进 87 个中间文件。
2. **不要在会话内前台同步调用** `bl`：长任务会阻塞整个会话，且无法并行。
3. **不要把"模型说写完了"当完成**：唯一判据是字节数 + 覆盖率。
4. **不要反复重试同一个 prompt**：连续两次失败就说明块太大或措辞有问题，改 prompt 而不是重试。
5. **不要在同一次调用里既生成又审校**：审校需要独立上下文，否则模型会给自己打高分。
