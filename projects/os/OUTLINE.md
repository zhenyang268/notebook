# os/ · 操作系统与系统 API

> 分组目录：把「在真内核上改对一处（`xv6/`）」「用真实内核的接口（`linux-api/`）」「看两种内核为什么不同（`kernel-compare/`）」「设备层怎么接（`drivers/`）」「边界怎么被跨过（`security/`）」「一台机器怎么被切成多台（`virtualization/`）」放在一起。
> **五个视角 + 一条动手线**，子项目各自两件套，本文只做路由，不复制正文。
> **基准**：实现读 xv6，接口读 Linux。**JOS 已于 2026-11-17 归档**（`.gen/archive/jos-2026-11-17/`），不再作为动手线；`kernel-compare` 里的 JOS 列降为历史附注。

## 一、这个目录是什么

| 子项目 | 站在哪一层 | 回答什么 |
|---|---|---|
| `os/linux-api/` | **用户态接口** | 真实内核给了我什么形状的接口，以及每个症状背后是哪个内核决定：进程/线程、内存（VSS/RSS/PSS、缺页与 OOM）、CPU 使用率、I/O 与 epoll、网络（`ss -i`、TIME_WAIT）、信号与定时器；含「API 背后的六个决定」与 macOS/Windows 差异附录 |
| `os/xv6/` | **内核态实现（动手线）** | 十二块：初始化 / 物理内存 / 地址翻译 / 地址空间 / 陷入 / 进程 / 系统调用 / 调度 / 文件系统 / 驱动 / 网络 / 虚拟化；每块「一份什么→多份什么 + ≤5 条使用面 + 四条线的检查点」，并给 xv6 ↔ Linux 的 API 对照 |
| `os/kernel-compare/` | **横向对比** | 同一格（陷入 / 进程结构 / 地址空间 / 文件 / 设备）在不同约束下为什么长成不同形状；JOS 列只作历史参照 |
| `os/drivers/` | **设备层** | 驱动到底在做什么：找设备 / 配置 / 搬数据 / 处理完成四步；块设备与网卡各走一遍，再对照 Linux 的五层配套（设备模型、DMA API、上下半部、NAPI） |
| `os/security/` | **边界与对抗** | 权限边界怎么被跨过：内存破坏 → 原语 → 控制流劫持 → ROP → 内核提权 → 侧信道；外挂与反作弊作为「同一组原语、不同获取方式」的对照 |
| `os/virtualization/` | **把机器切成多台** | VT-x/EL2 的世界切换、EPT 两跳、I/O 四级台阶（全模拟→virtio→vhost→直通）、KVM `ioctl` 与最小 VMM、QEMU 设备/块/迁移，再对照容器、WSL1/WSL2、gVisor、Firecracker |

一句话定位：**`linux-api` 是你天天用的那一侧，`xv6` 是你在真内核上改对一处的那一侧，`kernel-compare` 解释两者为什么不同，`drivers` 解释硬件怎么被接进来，`security` 解释这些边界里哪一条会被跨过、靠什么跨、被什么挡住，`virtualization` 解释这些边界怎么被复制成好几份、每复制一次要付多少钱。** 面试里最值钱的不是任一层知识点，而是层与层对不上的地方——`top` 显示 380% 到底在说几个核、epoll 边缘触发为什么会丢事件、描述符环的 `tail` 归谁、为什么用户指针不能直接解引用、为什么 NX 迫使攻击者去拼 ROP、为什么一次 `vmexit` 是虚拟化的唯一成本单位。

**入口（本文的读法）**：在「CPU 只给三样材料」这个约束下——特权级与陷入入口、页表项权限、设备 MMIO/DMA——看每个子项目把哪一样用到了哪一层。换的是 API 名、结构名、驱动路径与攻击原语，不换的是同一条从用户调用到寄存器/页表/队列的落点链。

**不换的是什么**：全程不变的是陷入入口（`CS/SS`、`TSS.rsp0`、`syscall/sysret`，或 RISC-V 的 `stvec/sscratch`）、地址转换（`CR3`/`satp` + `PTE` 的 `U/R/W/X`）、系统调用分发（号 → 分发表 → 进程结构）、队列所有权（描述符环的 head/tail 由谁推进）、完成通知（IRQ/EOI 或轮询状态位）和对象生命周期（引用计数、fd 表、inode 状态机）。看到差异先问：它是否改变了「谁推进 head/tail、谁设权限位、陷入时 `pc/sp` 从哪来、号落到哪个分发表」。

**积木**：①`syscall/ecall` 与入口寄存器（`MSR_LSTAR` 或 `stvec`+`sscratch`）；它能独立验证「用户态陷入时返回到哪、现场存在哪」。②`CR3/satp` + `PTE` 的 `U/R/W/X` + 缺页原因；它能独立验证「一次访问被拒是权限还是未映射」。③PCI BAR + MMIO + 描述符环 `head/tail` + `DD`；它能独立验证「收包时 CPU 与 DMA 的写所有权靠谁标记」。

**最小情形**：单核单进程执行一次 `read(fd, buf, 1)`：陷入把用户 `pc/sp` 冻结进 trapframe，内核按 fd 表找到 file，`copyout` 写 `buf`，`sret` 返回。这一情形初等，因为 SMP、TLB shootdown、`epoll` 边缘触发、e1000 多队列、RCU 都不触发。

**两边**：同一份执行现场有两份表示——用户态持有寄存器与 `pc`，内核持有 trapframe 的 31 个槽位加 5 个簿记字段；同一份「能访问的内存」也有两份表示——用户看到段与权限，内核看到页表树。

## 二、为什么这样分组（功能设计）

**取舍一：为什么分成实现与接口两侧，而不合成一份。** 判据不同。`xv6` 的判据是**改对一处且能停住看**（页表项对不对、现场是否精确、引用计数是否平衡），错一次就 panic；`linux-api` 的判据是**用一个命令或一个调用解释真实症状**（380% 是哪几个字段、`ss -i` 里哪个计数在涨）。合成一份会让「实现正确」与「解释正确」互相稀释。

**取舍二：为什么 `xv6` 是动手线，而 Linux 只到 API。** 缺口是「细节虚」，补细节要能停住、能改坏、能立刻看到症状——这只有万行级内核给得起。Linux 的价值在**接口形状**：`clone` 把共享参数化、`mmap` 把映射统一、`epoll` 把通知独立。**实现读 xv6、接口读 Linux**，差异一眼可见。**代价**：不能拿 Linux 的内核结构当「原理」，也不能拿 xv6 的简化当「本来如此」——每处都要标「它选了哪个点」。

**取舍三：为什么 `xv6` 按「块」切，而不按 lab 或 408 章切。** lab 按改动点切（判据是 patch 过测试），408 按考纲切（判据是每章能独立出题）；两者都把「一块资源怎么被复用」打散。块按「一份什么变多份什么 + 一组失效模式」切，粒度可查（`LEARNING.md` §3.1 ②），且四条线（准入/配额/并发/故障）能落成矩阵。**代价**：一个 lab 会横跨两块（cow 落在 B3 与 B5），验收表要按块标，不能按 lab 编号。

**取舍四：为什么 `kernel-compare` 保留 JOS 列。** 它不再有动手价值，但「x86-32 用 TSS 换栈、RISC-V 用 `sscratch`、x86-64 用 `swapgs`」这组对照仍是理解「硬件契约决定代码形状」的最短路径。**代价**：它成了唯一还提 JOS 的地方，引用时必须标「已归档」，否则读者会去找那个项目。

**取舍五：为什么驱动、安全、虚拟化各占一篇。** 驱动是「块怎么从硬件来」，与文件系统的「块之上」判据不同；安全的核心是一条跨边界的因果链（内存错误 → 原语 → 权限跨越），任何单篇都装不下；虚拟化问的是另一个问题——**内核本身也可以是被 VMM 调度的用户态代码**，它把页表、特权级、设备、中断四个概念同时反转一遍，还要解释成本（退出次数）。并进任何一篇都会被那篇的判据压平。

**取舍六：为什么和 408 并行而不另立体系。** 408 考「给场景选算法/选指标」，xv6 练「指到哪一行」。重叠处（分页与缺页、系统调用与中断、文件分配与缓冲、DMA 与中断驱动）互相校验：选择题答对说明概念没歪，断点停住说明细节没虚。**代价**：不重叠的部分（置换算法、磁盘调度、SPOOLing）只有 408 一侧，这里不补也不假装补。

**分组只做路由**：六个子项目各自五段、各自判据；本文只负责顺序、口径与跨项目追问。

## 三、推荐顺序与判据

**先接口 → 实现 → 横向对比 → 设备层 → 安全 → 虚拟化。** 理由不是难度，而是**反馈速度与面试权重**：`linux-api` 每条都能在十分钟内用一个命令验证；`xv6` 每块都要真调通或真停住才有价值；`kernel-compare` 建立在两边都有画面之后；`drivers` 是设备层延伸；`security` 要求你先知道边界在哪；`virtualization` 排最后，因为它把前面四个概念同时反转。

| 阶段 | 内容 | 判据 |
|---|---|---|
| 1（必做） | `linux-api/` 的 CPU、内存、I/O 三块：`top`/`ps` 字段口径、VSS/RSS/PSS、缺页与 OOM、`ss -i` 与 TIME_WAIT | 给一个真实症状，十分钟内定位到具体机制与具体字段 |
| 2（必做） | `linux-api/` 的进程/信号/epoll（水平与边缘触发的差异与丢事件原因） | 能说清「边缘触发必须配非阻塞 + 读到 `EAGAIN`」的因果，不是背结论 |
| 3（建议） | `xv6/` 的前五块：B0 初始化、B1 物理内存、B2 地址翻译、B3 地址空间、B4 陷入 | 能默写 `ecall` 六步的 `pc/sp/satp/stvec/sscratch`；能说清一次写缺页从硬件到返回 |
| 4（加分） | `xv6/` 的 B5–B8：进程、系统调用、调度、文件系统 | 能说清 `fork`/`exec` 的账本（复制/共享/替换）与日志提交点 |
| 5（建议） | `kernel-compare/` 的四格：陷入、进程结构、地址空间、API 形状 | 同一格能说出两种约束下的形状，并解释「换约束哪条结论失效」 |
| 6（看岗位） | `drivers/` 与 `xv6/` 的 B9–B10：块设备、e1000 描述符环、收包路径 | 能画出块读与收包的所有权时间线；能指出 xv6 的一段在 Linux 里被拆成哪几层 |
| 7（建议） | `security/` 的原语框架、ROP 三段式、缓解机制「假设—违反」表 | 任给一个漏洞描述，能说出跨哪条边界、几个原语、被谁挡住 |
| 8（看岗位） | `virtualization/` 的退出成本模型、EPT 两跳、I/O 四级台阶、KVM `ioctl` 骨架 | 能画出 guest 写串口/读 4KB 盘的路径并标出退出次数；说清容器与 VM 的边界由谁强制 |

**一条硬判据**：任何结论都要能落到「一个命令 + 一段输出」「一次断点」或「一条所有权时间线」。落不上去的，是背来的。

## 四、不做什么 · 必要性 · 失效点

### 必要性：删掉会怎样

| 机制 | 删掉会怎样 | 判定 |
|---|---|---|
| 页表项与地址转换 | 进程无法把虚拟地址翻成物理页，隔离与共享同时落空 | 必需 |
| 陷入入口与现场保存 | 系统调用没有跨特权级的现场保存/恢复，返回时寄存器被破坏 | 必需 |
| COW 与引用计数 | 父子写同一页不触发复制，或共享页被提前释放 | 必需（承诺 COW 之后） |
| 用户指针校验 | 内核直接解引用用户指针，缺页与权限边界丢失 | 必需 |
| 描述符环的 `tail` 与 `DD` | 收包路径判不出所有权，描述符被重复写或跳过 | 必需 |
| 日志 | 断电后元数据与数据不一致 | 必需（承诺崩溃一致性之后） |
| 缓冲区缓存 | 正确性不受影响，只是每次读写都落盘 | 选择 |
| TIME_WAIT | 少一条端口复用的归因；xv6 不依赖 TCP 状态机，可后补 | 选择 |

### 失效点：哪条前提一破，结论就变

- **核数**：单核 xv6 → 多核 Linux，`top` 的 380% 必须拆成 per-CPU 字段；xv6 的引用计数表与 `e1000` 寄存器访问要加锁。
- **介质**：PIO 轮询 → MMIO + DMA + 中断，「搬数据」从读寄存器变成写描述符环，`tail` 所有权成为判据。
- **协议版本**：TCP 正常关闭保留 TIME_WAIT → `SO_LINGER` 跳过，端口复用的归因失效。
- **权限位**：`PTE_U` 与用户指针校验缺失 → 内存破坏可直接跨过系统调用边界。
- **内核简化**：xv6 无 lazy、无线程、无 uid、无 socket——把这四点当原理，讲 Linux 必错。

### 不做什么（范围）

**`xv6/` 不写完整操作系统。** 不做日志的 checkpoint 优化、不做 TCP、不做多用户；日志提交与 e1000 收包各只到「能验证一次 / 一次收包」。

**`linux-api/` 不深入内核数据结构。** 只到「API 背后的决定」：`task_struct`/`mm_struct` 可以出现在对照里，不在正文展开；不写内核模块、不改内核。

**不做容器与虚拟化的完整实现。** namespace/cgroup 原理、VM 与容器四条路线、KVM 最小 VMM 在 `virtualization/`；这里不做 runc/CRIU 级实现。

**不移植 Linux。** 跑 Linux 需要的特权级、中断、原子指令是「换项目」级投入。

**不做发行版运维。** 包管理、systemd、发行版差异一律不涉及。

**安全只讲机制。** 不写 shellcode、不给偏移与 payload、不针对商业游戏或反作弊提供绕过；实验限于自己写的程序或公开 CTF。

## 五、面试怎么讲

### 30 秒版本

> 操作系统这块我按「接口 + 实现 + 对比」三层准备：接口这侧我能把一个线上症状（CPU 380%、OOM、连接建立慢）在十分钟内定位到具体机制和字段；实现这侧我在 xv6 上改了页表、陷入、COW、日志和网卡驱动，能停在一次 `ecall` 里说清 31 个寄存器存到 trapframe 的哪个偏移、为什么先切 `satp` 再跳 `usertrap`；对比这侧我能说清同一件事在 xv6 与 Linux 的接口为什么形状不同——`fork` 替调用者定死，`clone` 把共享参数化。再往上是设备层与虚拟化：一次块读的所有权时间线，和一次 `vmexit` 的成本。

### 可能被追问的 8 个点

1. **「`top` 里一个进程 380% 是什么意思？」** → 考点：分母与按核累加。答法：`%CPU` 是单核 100% 的口径，380% 约等于占满 3.8 核；判据是与 `nproc` 比、与 `ps -L` 的单线程分布比。边界：容器里读到可能是宿主核数，先看 `cpu.max`。
2. **「RSS 与 PSS 差在哪？」** → 考点：共享页归属。答法：RSS 把共享页整份计入每个进程，PSS 按共享者均摊；判据 `smaps_rollup` 的 `Pss`。边界：页被换出后 RSS 降，虚拟大小不变。
3. **「minor 与 major 缺页，为什么前者便宜？」** → 考点：缺页的两条来源。答法：minor 内存里已有页（页缓存、COW、已映射未建 PTE），只补表项；major 要读设备。判据 `pgfault`/`pgmajfault`。边界：COW 触发的是 minor，但复制本身有成本。
4. **「epoll 边缘触发为什么必须配非阻塞？」** → 考点：事件语义。答法：只在状态变化时通知一次，没读干净就不再通知，所以必须循环读到 `EAGAIN`；而读 `EAGAIN` 的前提是非阻塞。判据 `strace`。边界：三者缺一就是「连接卡住但 CPU 空闲」。
5. **「COW fork 后父子页表项什么状态？」** → 考点：实现细节。答法：共享同一物理页、双方 PTE 只读并带 COW 标记、计数为 2；写触发 15，复制后改回可写、旧页计数减一。判据：`forktest` 后空闲页数回初值。边界：`vfork` 是不复制路径。
6. **「缺页处理为什么不能随便睡眠？」** → 考点：上下文约束。答法：缺页本身要等 I/O，必须在可睡眠上下文；中断上下文或持自旋锁时访问用户地址是 bug。判据：`BUG: sleeping function called from invalid context`。边界：xv6 的教学模型没有这层严格区分。
7. **「同一件事，xv6 与 Linux 的接口为什么不同？」** → 考点：接口形状由「谁做决定」挤出。答法：`fork` 定死全共享地址空间，`clone` 参数化共享集合；`sbrk` 定死一块连续区，`mmap` 统一文件与匿名映射。差异不是先进与否，是决定权放在哪。
8. **「虚拟化与容器的隔离差在哪？」** → 考点：边界由谁强制。答法：VM 由 CPU 强制（non-root 的 ring0、EPT、IOMMU），容器由内核软件强制（namespace/cgroup），内核共享。所以容器快是因为要做的事少，不安全也是同一句。判据：逃逸要打穿什么。

**别说什么**

- 「我写过操作系统。」追问「调度器怎么处理优先级反转」就崩。说清边界：改过 xv6 的页表、陷入、COW、日志、网卡驱动；没写调度器、没做协议栈。
- 「RSS 就是进程占的内存。」一句话暴露没看过 `smaps`。
- 「epoll 比 select 快。」没有事件复杂度与就绪队列的解释，只是口号。
- 报没测过的数字。没有口径的「提升 X 倍」不如说「我能给出复现路径」。
