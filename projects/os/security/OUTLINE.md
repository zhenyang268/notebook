# security · 内存破坏、ROP 与反作弊对抗

> 本文只讲**机制与判据**：漏洞为什么会成立、缓解机制在提高什么成本、外挂与反作弊各自站在哪一层。
> 不提供可用利用代码、不针对具体商业游戏或具体反作弊产品给出绕过步骤，所有实验限定在**自己写的示例程序或公开 CTF 环境**里。
> 与 `../jos/`、`../kernel-compare/` 共用同一套内核词汇；与 `eng/system-design/` 的分界：那边管业务侧鉴权限流，这边管内存与权限边界。

## 一、它在做什么

把"安全"从一堆名词变成一条**因果链**：一处内存错误 → 一个原语（能读/能写/能跳）→ 一条控制流或数据流 → 一个权限边界被跨过 → 一个缓解机制让成本上升。

这条链上有三个不同层次的战场，本文都要各给一格：

| 层次 | 典型问题 | 谁在防 | 判据形态 |
|---|---|---|---|
| 进程内 | 栈/堆溢出、UAF、类型混淆 | 编译器与 libc（canary、FORTIFY、CFI） | 能不能劫持控制流、需要几个原语 |
| 内核 | 越界写、UAF、引用计数错、`ioctl` 缺校验 | 内核加固（SMEP/SMAP、KPTI、KASLR、LSM） | 能不能从 ring3 到 ring0、需不需要信息泄露 |
| 系统/对抗 | 外挂读写内存、注入、驱动级对抗 | 反作弊（完整性校验、内核驱动、行为分析） | 能不能在不被检测的前提下稳定改状态 |

**为什么"外挂"要和 ROP 放在一起讲**：它们共享同一套底层能力——**任意地址读写、任意函数调用、代码注入**。ROP 是在受限条件下把"已有的代码片段"拼成一次调用；外挂是在有调试权限的条件下把"我的代码"塞进目标进程。**前者是漏洞利用的极限形态，后者是权限滥用的极限形态**，放在同一份文档里才能看清"能力"和"权限"的区别。

**入口（本文的读法）**：在 canary/CFI/SMEP/SMAP/KPTI/LSM/完整性校验已存在的约束下，按“原语→边界→缓解成本”读每一章：进程内看能否用任意读写/函数调用绕过 stack canary、FORTIFY_SOURCE、CFI；内核看能否通过 `ioctl`/`syscall`/引用计数缺陷跨过 ring3→ring0 并触发 SMEP/SMAP、KPTI、KASLR、LSM；系统/对抗看能否用 `ptrace`、`ReadProcessMemory`、`VirtualAlloc`、`CreateRemoteThread`、内核驱动或行为日志稳定注入与改状态。这里换的是具体指令序列（ROP gadgets、JOP/BOP）、页表/寄存器状态（CR3、CS/SS、RSP/RIP）和协议字段（`ioctl` opcode、权限掩码），不是换漏洞名。

**不换的是什么**：全程不变的是特权级与页表边界（CS/SS、CR3/KPTI、SMEP/SMAP）、可执行性边界（NX/`PROT_EXEC`/CFI）、数据完整性与权限判定（stack canary、ELF/模块签名、引用计数、LSM `cred`/`inode` 检查），所以看到差异先问是否新增任意读写、任意函数调用、代码注入原语，是否跨过 ring3→ring0 或进程边界，是否绕过具体检查字段（canary、CFI target、`ioctl` 校验、SMAP/PAN、LSM hook、反作弊完整性哈希）。

**积木**：①`CR3` 与页表项 `P`/`R/W`/`U/S`/`NX` 位给出地址空间与执行权限；它能独立验证一次 `MOV [RAX],RBX` 是否落在可写用户页或只读内核页。②`CS`/`SS` 的 CPL/RPL 与 `EFER.SCE` 给出 ring3/ring0 入口；它能独立验证一次 `SYSCALL` 是否只把 `RIP` 送入 `MSR_LSTAR` 指定的内核入口。③`RSP`、`RET` 与 stack canary/`%fs:0x28` 给出返回地址完整性；它能独立验证 `RET` 前栈槽 canary 是否等于 `%fs:0x28`。④`RIP`、`CALL`/`JMP` 与 CFI target 集合给出间接控制流校验；它能独立验证一次 `CALL [RAX]` 是否只在 `RAX` 位于 CFI 合法目标集合时把 `RAX` 装入 `RIP`。

**最小情形**：单核单线程一次 `ioctl(fd, cmd, arg)` 时，`SYSCALL` 把 `RIP` 送入 `MSR_LSTAR`，`cmd` opcode 选择 `ioctl` 分支，`access_ok` 检查 `arg` 是否位于 `TASK_SIZE` 以下，`copy_from_user` 按 `cmd` 指定长度复制字段，`cred` 的 `uid`/`gid`/`cap_effective` 决定是否允许该 `ioctl`；此时 stack canary、CFI target 集合、CET `SHSTK` 不作用，因为这次操作不依赖被覆盖的 `RET` 或 `CALL [RAX]`，`spin_lock`、`futex_wait`、`per-CPU`、`RCU` 不作用，因为单核单线程不触发 `lock cmpxchg` 争用、`TLB shootdown`、`rcu_read_lock`。

**生成**：累加把一次 `ioctl` 扩为 `ioctl`/`mmap`/`mprotect`/`ptrace` 序列，新增 `cmd` opcode、`arg` 指针、`TASK_SIZE`、`VMA` 的 `vm_flags`、`PROT_EXEC`、`ptrace` 的 `PTRACE_ATTACH` 与 `task_struct` 状态约束；覆盖把单线程用户态扩为 `SYSCALL`/`SYSRET`、`CR3`/`KPTI`、`CS`/`SS`、`SMEP`/`SMAP`、`LSM` 的 `cred`/`inode` 检查，新增 `task_struct`/`nsproxy` 的进程边界约束；最坏情形是任意地址读写、任意函数调用、代码注入同时成立，使 `RIP` 可跳向 `VirtualAlloc` 返回的 `PAGE_EXECUTE` 页、`RSP` 可指向 `ReadProcessMemory` 写入的 gadget、`CR3` 可被内核驱动页表修改绕过 `KPTI`。

**两边**：同一份控制流现场有两种表示：用户态 `RIP`/`RSP` 寄存器，内核栈上的 `struct pt_regs` 中 `ip`/`sp` 字段。持有者也不同：用户线程在 `RET` 前持有 `RIP`/`RSP`，内核在 `SYSCALL` 入口通过 `SWAPGS` 与 `PUSH` 持有 `struct pt_regs`。

## 二、为什么这样做（功能设计）

**取舍一：为什么以"原语"为中心，而不是以"漏洞类型"为中心。** 按漏洞类型讲会变成名词表（栈溢出、堆溢出、格式化字符串、UAF…）；按原语讲才有迁移性：**读原语、写原语、调用原语、跳转原语**——四类原语各自能做什么、拿到几个才能完成一次跨越权限边界的动作。缓解机制的作用也才能被正确描述：它们不是"消灭漏洞"，而是**提高凑齐原语组合的成本**。

**取舍二：为什么必须成对讲"缓解 / 绕过思路"。** 只讲缓解会得到虚假的安全感（"开了 NX 就安全了"）；只讲绕过会变成攻击手册。正确讲法是**抽象的成对结构**：NX 让"跳到栈上执行"失效，于是攻击者转而"拼已有代码"（ROP）；ASLR 让"地址固定"失效，于是需要信息泄露或部分覆盖；CET 让"间接跳转"受限，于是转向数据面攻击。**每一对都在回答同一个问题：上一个机制的假设是什么。**

**取舍三：为什么把外挂写成"技术谱系"而不是教程。** 外挂的技术栈（内存读写、指针扫描、Hook、注入、驱动）与漏洞利用的技术栈高度重叠，讲清谱系就能让两边互相解释；但**写具体手法等于写教程**，所以只到"用了哪一层能力、为什么需要它、防御方怎么观测"。

**取舍四：为什么必须有法律与边界一节。** 这一块的知识天然双用途。文档的立场是：**只在自己拥有或明确授权的系统上做实验**；不针对商业产品提供绕过；不做可分发的作弊工具。这不是免责声明，而是这套知识的正确使用方式——**面试里能讲清机制的人，不需要靠"我做过外挂"来证明能力**。

## 三、章节大纲

**第 1 章 攻击面地图与权限边界。** 用户态 → 内核态 → 硬件/固件三层；数据面与控制面；哪些边界由硬件强制（页表、特权级）、哪些由软件检查（`copy_from_user`、`access_ok`）、哪些靠约定（ABI、ABI 稳定）。**判据：能指出一个具体漏洞跨过了哪条边界、靠的是硬件还是软件漏洞。**

**第 2 章 内存破坏的四种形态。** 栈溢出（覆盖返回地址/保存的寄存器）、堆溢出（破坏相邻块头与元数据）、UAF（释放后仍可读写，指针还在）、整数溢出（长度计算绕过检查）。每种给出"最小成立条件"和"为什么现代分配器让它变难"。**判据：能说清每种形态需要一个什么原语，以及被哪个检查挡住。**

**第 3 章 控制流劫持的三个台阶。** 返回地址（最经典）→ 函数指针（`ops` 结构、回调）→ 虚表指针/vtable 劫持（C++ 对象）。三者难度递增的原因：越靠上越容易被 canary/CFI 覆盖，越靠下越依赖类型混淆。**判据：能说清"为什么虚表劫持需要先拿到一个写原语 + 一个可预测布局"。**

**第 4 章 ROP：用已有代码拼出一次调用。** gadget 的构成（`pop rdi; ret` 之类）、栈布局、`ret2libc`/`ret2plt`/`ret2syscall` 的差别、栈迁移（`leave; ret` 与 `xchg rsp`）、`ret2csu`（用 `__libc_csu_init` 里的通用 gadget 补参数寄存器）、SROP（用 `sigreturn` 一次性设置全部寄存器）。**重点讲清：ROP 之所以成立，是因为调用约定把"参数在寄存器"这件事变成了可编排的拼装。判据：能给出一条"设 rdi → 设 rsi → 调函数"的三段式栈布局，并说明每段为什么需要对齐。**

**第 5 章 缓解机制与它们各自的假设。** NX/DEP、ASLR、PIE、stack canary、RELRO、FORTIFY、CFI/CET（影子栈与 `endbr64`）、堆加固（safe-linking、tcache 校验）、内核侧 SMEP/SMAP/KASLR/KPTI。成对给出"它假设了什么 → 违反假设会发生什么"。**判据：能对任一机制说出"它在抬高哪类原语的成本"，而不是"它防住了溢出"。**

**第 6 章 从用户态到内核。** 内核漏洞的常见入口（`ioctl`、文件系统、网络栈、驱动）、提权的经典骨架（改凭据结构）、以及三个硬件/内核加固如何破坏这条链：SMEP（内核不能执行用户页）、SMAP（内核不能随意读写用户页）、KPTI（页表隔离，缓解 Meltdown）。**判据：能画出"一次内核 UAF → 任意写 → 改凭据"的链条，并指出每一步被哪个机制挡住。**

**第 7 章 侧信道与硬件层面的攻击。** Spectre/Meltdown 的机制级描述（推测执行留下缓存痕迹）、Rowhammer（相邻行翻转）、缓存计时（`Flush+Reload` 的思想）。**只讲机制与后果，不给利用实现**；与 `cpu/cpu-microarchitecture/` 的乱序与缓存章节交叉引用。**判据：能说清"为什么这类攻击不需要软件漏洞"。**

**第 8 章 外挂的技术谱系。** 四层能力：**读**（进程内存读取、指针扫描与指针链、特征码扫描）、**写**（改数值、改结构体）、**调**（注入后调游戏内部函数、Hook 拦截）、**藏**（反调试、完整性对抗、驱动级）。每层给出"它解决了什么问题、留下了什么痕迹"。**判据：能对一个具体需求（如"让角色血量不掉"）说出至少两条技术路线及各自的检测面。**

**第 9 章 反作弊与防御工程。** 用户态完整性（代码段校验、内存扫描）、内核驱动（跨进程访问拦截、句柄过滤、驱动签名与 Secure Boot）、行为与统计（异常命中率、输入分布）、以及 Linux 侧的对应物（`seccomp`、LSM、`eBPF`、只读挂载、namespace）。**判据：能说清"为什么反作弊必须进内核，以及进内核的代价"。**

**第 10 章 判据、实验方法与边界。** `checksec` 看缓解、`readelf -lW` 看 `GNU_STACK`/`GNU_RELRO`、`/proc/pid/maps` 看布局、ASan/Valgrind 与 libFuzzer/AFL 找 bug、在自己写的示例程序上验证"缓解生效/失效"。**以及边界：只做授权实验，不针对商业产品。判据：每个结论都能落到一条命令或一次受控复现。**

## 四、不做什么 · 必要性 · 失效点

### 必要性：删掉会怎样

| 机制 | 删掉会怎样 | 判定 |
|---|---|---|
| canary | 删掉栈哨兵后，栈溢出只需覆盖返回地址即可把写原语升级为跳原语；“劫持控制流必须先泄露 canary”的承诺破。 | 必需 |
| CFI | 删掉间接调用目标校验后，攻击者只要把 gadget 地址写入函数指针即可绕过类型约束；ROP 从“凑齐调用约定”退化为“凑齐跳转地址”，控制流边界承诺破。 | 必需 |
| KPTI | 删掉用户态最小内核页表后，ring3 可用页表项时序侧信道读取内核内存；KASLR 的“基址不可见”前提失效，内核信息泄露不再需要 UAF/越界读。 | 必需 |
| ioctl | 删掉命令号、`access_ok` 和 in/out 长度校验后，字符设备可把用户指针当内核指针解引用；一次系统调用就能把“读一个字段”变成“读任意内核地址”，KASLR 只需一个静态偏移即可定位。 | 必需 |
| CET | 删掉 shadow stack 对 `ret` 的校验后，ROP 可用被污染的 `rsp` 把返回地址指向 gadget；CFI 的函数签名约束不能阻止“合法类型但错误控制流”的跳转。 | 必需 |
| 行为分析 | 删掉对内存读写频率、Hook 安装点和驱动加载序列的观测后，外挂只要保持进程镜像校验一致就能稳定改状态；这是检测成本取舍，不是控制流因果链必需。 | 选择 |

### 失效点：哪条前提一破，结论就变

- CR4.SMEP=0 且页表项 U/S=1 → SMEP/SMAP 的“内核不执行用户页”前提破，攻击者只要用 `ioctl` 把用户页地址传入内核，就能把 shellcode 或伪造 `cred` 结构放进 ring0 执行路径，不再需要内核 gadget。
- CET 未启用且 `rsp` 可被用户控制 → CFI 的“间接跳转目标受签名约束”前提破，ROP 可用栈迁移把 `ret` 目标指向 libc gadget；canary 只能检测返回地址覆盖，不能阻止合法 gadget 链。
- `ioctl` 参数为指针且 `access_ok` 未校验 → “系统调用只能访问用户缓冲区”前提破，一次 `ioctl` 调用可把任意内核地址作为读/写目标，KASLR 只需泄露一个静态符号偏移即可定位内核对象。
- 时钟源为 TSC 且行为分析只比较 `RDTSC` 间隔 → “内存读写频率可区分外挂与正常程序”前提破，外挂可伪造合法延迟，完整性校验仍通过；检测必须改用 HPET、`rdpmc` 或内核时间戳。
- 介质为 DRAM 且驱动允许映射用户物理页 → “进程镜像校验能证明代码未被改”前提破，外挂可用驱动把篡改页直接映射进目标进程，绕过 Hook/注入检测。

### 不做什么（范围）

**不提供可用利用代码与外挂实现。** 不写 shellcode、不给具体偏移与 payload、不针对任何商业游戏或反作弊产品给出绕过步骤。只讲机制、原语与判据。

**不做纯 Web / 业务安全。** SQL 注入、XSS、鉴权越权属于应用层；`eng/system-design/` 已覆盖业务侧取舍，这里只到"输入验证是最后一道"。

**不做密码学。** 不推导算法、不讲协议；只在"为什么不能自己造加密"这一句上出现。

**不做硬件逆向与固件分析。** 侧信道只到机制层，不做具体芯片的测量实验。

**不做"谁的防护更强"排名。** 对抗是成本博弈，没有绝对强弱；说"某方案能防住一切"就是不懂。

**不做法律与合规咨询。** 只写一句立场：只在自己拥有或明确授权的环境里实验。

## 五、面试怎么讲

**30 秒版本**（开场直接说，140–180 字）

> 安全这块我按"原语"来理解，而不是按漏洞名词背。一处内存错误给我的是读、写、调用、跳转四类原语中的若干；ROP 就是在只有"跳转 + 已有代码"的条件下，用 gadget 按调用约定拼出一次函数调用。缓解机制的作用不是消灭漏洞，而是提高凑齐原语组合的成本——NX 迫使你拼代码，ASLR 迫使你泄露地址，CET 迫使你转数据面。同一个框架也能解释外挂：它在有调试权限的前提下，直接拿"任意读写 + 注入调用"这组原语，只是拿原语的方式从漏洞变成了权限滥用。所以我讲这块会说清三件事：跨的是哪条边界、需要几个原语、被哪个机制挡住。

**可能被追问的 8 个点**

1. **「ROP 为什么能绕过 NX？」** → 考点：NX 防的是"执行"，不是"跳转"。
   → 答法：NX 让数据页不可执行，所以"把 shellcode 放栈上再跳过去"失效；但 ROP 不执行新代码，只是**把已有代码里的短片段（以 `ret` 结尾）按顺序串起来**，用的全是可执行段里的指令。所以 NX 抬高的是"注入代码"的成本，不是"控制流劫持"的成本——后者要靠 CFI/CET 之类别的手段。

2. **「一个 `pop rdi; ret` 为什么这么关键？」** → 考点：调用约定与拼装。
   → 答法：x86-64 的第一个整数参数在 `rdi`；没有 gadget 就没法把值放进 `rdi`，也就没法控制函数参数。`pop rdi; ret` 一条指令同时完成"从栈上取值"和"继续走链"两件事，所以它是最基础的拼装件。缺它就要退到 `ret2csu`（借 `__libc_csu_init` 里成对的 `pop rbx/rbp/r12-r15` 与 `call [r12+rbx*8]`）或 SROP。

3. **「ASLR 是不是开了就安全了？」** → 考点：熵与信息泄露。
   → 答法：ASLR 只是把"地址固定"这个假设打破，攻击者改用**信息泄露**（格式化字符串、越界读、未初始化内存）或**部分覆盖**（只改低字节，绕过随机化）。而且熵不足时（32 位、fork 出的子进程共享布局）可以爆破。**判断要看"拿到一个读原语要多久"，不是"ASLR 开没开"。**

4. **「栈 canary 怎么绕过？」** → 考点：检查的边界。
   → 答法：三类路径——泄露 canary（越界读、格式化字符串）、不破坏 canary 的写（跳到 canary 之前的局部变量、改函数指针而非返回地址）、以及不经过该函数的劫持（长跳转、信号处理）。**canary 只保护"函数返回"这一个时刻，且只保护有 canary 的函数**，这是它的假设。

5. **「内核对用户指针为什么要 `copy_from_user`？」** → 考点：边界与并发。
   → 答法：用户指针可能非法、可能跨页、可能指向内核地址，且用户可以在检查后改页表。`copy_from_user` 走异常表与 `access_ok`，缺页时返回未拷贝字节数而不是崩溃；直接解引用等于把内核暴露给用户态。**这是"软件检查"而不是"硬件强制"，所以最容易写错。**

6. **「SMEP/SMAP 挡住了什么？」** → 考点：硬件强制的方向。
   → 答法：SMEP 让内核态不能执行用户页（挡住"ret2usr"：把返回地址指向用户态代码）；SMAP 让内核态不能随意读写用户页（挡住"用用户内存当跳板"）。两者都是**硬件按页表 U/S 位检查**，绕过需要先改页表项（即先有任意写 + 能改到 PTE）。

7. **「外挂为什么很多要进内核？」** → 考点：权限模型。
   → 答法：跨进程读写、隐藏模块、拦截系统调用这些能力在用户态受限（`ptrace` 受 `yama`、`process_vm_readv` 受权限限制、Hook 需要注入），进内核才能绕过这些限制并隐藏痕迹。代价是：驱动要签名、要过 Secure Boot、一旦被识别就是整机封禁级别的对抗——**反作弊必须进内核是同一个道理**。

8. **「你怎么区分'这个漏洞严重'和'这个漏洞能用'？」** → 考点：原语与前提。
   → 答法：看三件事——能不能稳定触发（可靠性）、拿到什么原语（读写/调用）、跨哪条边界（同进程/跨进程/到内核）。一个"能读一个字节"的漏洞可能比"能溢出但无信息泄露"的更危险，因为前者给了 ASLR 破解的入口。**严重性不是 CVSS 分值，是原语组合。**

**别说什么**

- **「我做过外挂。」** 这句话在正经面试里通常是负分：既不证明工程能力，又踩合规红线。要讲就讲防御视角与机制理解。
- **「开了 NX / 开了 ASLR 就安全了。」** 一句话暴露只背过名词；要能说出它假设什么、违反后会发生什么。
- **「ROP 就是栈溢出。」** ROP 是**在没有注入代码的条件下拼装调用**，与溢出只是常见入口关系。
- **给具体产品的绕过步骤。** 无论面试还是笔记，这类内容都不该出现；讲机制、讲检测面，不讲手法。
