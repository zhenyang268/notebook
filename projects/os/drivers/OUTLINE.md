# drivers · 从 JOS 的磁盘与网卡看驱动

> 分组内的设备层：拿 JOS 的两块真实设备（IDE 磁盘、e1000 网卡）把"驱动到底在做什么"讲透，再对照 Linux 的配套机制。
> 内核结构对比在 `../kernel-compare/`，JOS 逐 lab 实现在 `../jos/`，用户态症状在 `../linux-api/`。

## 一、它在做什么

驱动这件事，剥掉平台差异后只剩四个动作：**找到设备、配置设备、搬数据、处理完成**。教学内核与生产内核的差别不在动作种类，而在这四个动作各自要处理多少并发、错误与抽象。

本文用两块设备把这条链路走完：

| 设备 | 交互方式 | 交付什么 | 为什么选它 |
|---|---|---|---|
| IDE 磁盘（PIO） | 端口 I/O + 轮询 | 扇区读写 → 块缓存 → 文件系统 → 用户态 FS 进程 | 没有 DMA 和中断也能工作，**能把"块设备"整条链路用最少的机制串起来** |
| e1000 网卡 | MMIO + DMA + 中断 | 描述符环 → 收发 → ARP/IP/UDP → web server | 把 DMA 与中断这两件事**暴露在必须自己处理的形态**上 |

**交付四样东西**（这才是判据，不是"驱动能跑"）：

1. **一块盘能被按块读写**，且错误（超时、BSY 不落、DRQ 不来）有明确返回值而不是死等。
2. **块之上有一个一致的布局**（superblock / bitmap / inode / 数据），并且"分配—释放—写回"在异常路径上不会留下不可恢复的状态。
3. **一块网卡能收能发**，描述符环的所有权转移清楚（谁写、谁读、什么时候归还），丢包与满环有明确策略。
4. **每条结论都能被观测**：中断计数、环指针、块缓存命中率、抓包结果。

**入口（本文的读法）**：在“同一内核既要能用 ATA 寄存器命令/状态位以 PIO 完成扇区读写，又要能用 e1000 的 TDT/RDT、IMS/IC、描述符环与 DMA 完成收发包”的约束下，本文只解决找到设备、配置设备、搬数据、处理完成四件事，并把它们接到块缓存、superblock/bitmap/inode、文件系统、ARP/IP/UDP 与 web server。换的是传输机制（端口 I/O 轮询 vs MMIO/DMA/中断）、错误路径（超时、BSY/DRQ、丢包、满环）和所有权交接（CPU 写命令、网卡写描述符、驱动归还缓冲区）。

**不换的是什么**：全程不变的是“任一时刻只有一个持有者、每个状态转移都落到 ATA 状态位、描述符 DD/EOP、e1000 IC/IMS、块缓存 dirty 位或返回值，异常必须返回 -EIO/-ENXIO/-ENOBUFS 或回滚 superblock/bitmap/inode 的 dirty 位”，所以看到差异先问：谁写 TX/RX 描述符、谁读 ATA 状态寄存器、哪个字段表示 ERR/DRQ/BSY/DF/TXQE/RXQE/LSC/MDIC/DD/EOP、块缓存与 inode bitmap 的 dirty 位由哪个锁保护、失败时返回明确错误码还是死等。

## 二、为什么这样做（功能设计）

**取舍一：为什么先讲 PIO 再讲 DMA。** 因为 PIO 把"设备寄存器—数据搬运—完成判定"三件事摊开在最小的面上：你写 `0x1F7` 发命令、读状态位等 `DRQ`、用 `insl` 搬 512 字节、再等 `BSY` 落。没有描述符、没有中断、没有并发，错了就是轮询循环写错。**先在这种形态上把"设备是异步的"这件事变成手感，再上 DMA 与中断才有对照物。**

**取舍二：为什么网卡选 e1000 而不是 virtio。** virtio 是"为虚拟化设计的、协议被简化过的"设备，它把大量细节藏在规范里（且宿主替你兜底）；e1000 是真实硬件的行为模型，寄存器、描述符、状态位都得自己碰。**教学价值在于"必须自己处理所有权与可见性"，virtio 会把这两点变模糊。**

**取舍三：为什么必须写 Linux 侧的对照。** 只看 JOS 会得到一个错误印象：驱动就是"读寄存器、搬数据"。Linux 要在同一件事上再加五层：设备模型（谁匹配谁）、DMA API（地址与缓存一致性）、中断上下半部（不能在硬中断里做重活）、块层多队列与页缓存（并发与回写）、NAPI 与 `sk_buff`（收包批处理与内存管理）。**不讲这五层，就答不出"为什么生产驱动这么复杂"。**

**取舍四：不做真实硬件适配。** 不碰 PCIe 枚举细节、不做电源管理、不做热插拔、不做 IOMMU 配置；这些属于平台代码，讲了会把主线冲散。

## 三、章节大纲

**第 1 章 设备的四种"说话方式"。** 端口 I/O（PIO）、内存映射 I/O（MMIO）、中断、DMA。四者的组合决定驱动形状：PIO+轮询最简、MMIO+DMA+中断才是现代设备。**判据：能说出一块设备用哪几种方式交互、缺哪一种会带来什么后果。**

**第 2 章 JOS 磁盘（一）：ATA PIO 读扇区。** 端口表（`0x1F0`–`0x1F7`）、命令（`0x20` 读 / `0x30` 写）、状态位（`BSY/DRDY/DRQ/ERR`）、LBA28 的寄存器拼法、400ns 延迟的来由、`insl` 批量搬运。**判据：能解释"为什么必须等 BSY 落、再等 DRQ 起"，以及"为什么读一次状态要重复四次"。**

**第 3 章 JOS 磁盘（二）：块缓存与磁盘布局。** 扇区（512 B）与块（4 KB）的关系；`bcache` 的哈希表 + LRU + 引用计数；`bread/bget/brelse` 的所有权；superblock / bitmap / inode 区 / 数据区的布局；直接块 + 单级间接的容量上限。**判据：能画出一次 `read` 从 inode 到块号到缓冲区到用户空间的完整路径，并说出每一步谁持有引用。**

**第 4 章 JOS 文件服务与 `spawn`。** 为什么把文件系统做成用户态进程；`FSREQ_*` 请求集；页映射如何让客户端直接看到文件内容；`spawn` 如何读 ELF、映射段、搭初始栈。**判据：能说清"一次文件读比内核内路径多了哪些步骤、换到了什么"。**

**第 5 章 JOS e1000（一）：MMIO 与描述符环。** 寄存器组（控制、发送环基址/长度/头尾、接收环、中断掩码）；发送/接收描述符的字段与 16 字节对齐；环的"生产者/消费者"所有权；`DD` 状态位的语义。**判据：能画出"填描述符 → 敲门铃（写 tail）→ 设备取走 → 置 DD"的时间线，并指出每一步的可见性要求。**

**第 6 章 JOS e1000（二）：中断与收包。** 中断掩码与状态寄存器、中断服务程序要做什么与**不能**做什么、收包路径（取描述符 → 交给上层 → 归还缓冲 → 移动 tail）、满环与丢包策略。**判据：能解释"为什么接收缓冲要在处理完才能归还"，以及"ring 满时丢包发生在哪一端"。**

**第 7 章 Linux 侧的配套：同一件事的五层加成。** 块层（`bio`、请求队列、`blk-mq`、页缓存与回写）；设备模型（总线/设备/驱动、`probe`、sysfs）；DMA API（映射、一致性与 IOMMU）；中断上下半部（硬中断只做最少事，`softirq`/`workqueue`/线程化中断）；网络（`net_device`、`ndo_start_xmit`、NAPI、`sk_buff`）。**判据：能指出 JOS 的某段代码在 Linux 里被拆成了哪几层、每层解决什么问题。**

**第 8 章 判据与调试：怎么证明驱动是对的。** 环回、抓包、中断计数、超时与坏块注入、块缓存一致性检查、性能口径（`iostat`、`ethtool -S`）。**判据：每条都给出"观察到 X 就说明驱动哪一步错了"。**

## 四、不做什么 · 必要性 · 失效点

### 必要性：删掉会怎样

| 机制 | 删掉会怎样 | 判定 |
|---|---|---|
| `0x1F7` / `DRQ` / `BSY` / `insl` | 删掉 PIO 命令与状态轮询后，IDE 读命令不等 `DRQ` 就 `insl` 512 字节，缓冲区拿到未就绪扇区；`BSY` 不落时没有超时返回值，交付一“错误有明确返回值而不是死等”破。 | 必需 |
| `superblock` / `bitmap` / `inode` | 删掉块上布局与分配—释放—写回检查后，`bitmap` 与 `inode` 在超时或掉电路径可分叉，后续分配重复块或释放已用块，交付二“一致布局且异常路径可恢复”破。 | 必需 |
| 描述符环所有权转移 / 环指针 | 删掉 TX/RX 描述符所有权与环指针观测后，CPU 与 e1000 可同时写同一描述符，满环与丢包没有归还策略，交付三“能收能发且所有权清楚”破。 | 必需 |
| 中断计数 / 块缓存命中率 / 抓包结果 | 删掉观测点后，无法区分 NIC 没中断、驱动没归还描述符、文件系统没写回，交付四“每条结论能被观测”破。 | 必需 |
| DMA API / 中断上下半部 / 块层多队列与页缓存 / NAPI 与 `sk_buff` | 删掉 Linux 侧对照后，JOS 四交付仍可成立，但“为什么生产驱动这么复杂”破：无法说明 DMA API 要处理地址与缓存一致性、中断上下半部要把重活移出硬中断、块层多队列与页缓存要处理并发回写、NAPI 与 `sk_buff` 要批处理收包。 | 必需 |
| virtio / PCIe 枚举 / 电源管理 / 热插拔 / IOMMU 配置 | 删掉真实硬件细节与平台适配后，QEMU 固定 MMIO/端口映射下仍能完成 IDE/e1000 主线；但换成 virtio 会把描述符所有权与缓存可见性交给宿主，真实平台会因枚举不到设备、复位后寄存器默认值不可信、热插拔事件丢失、IOMMU 拦截 DMA 地址而失效。 | 选择 |

### 失效点：哪条前提一破，结论就变

- 单核 QEMU 且 IDE 控制器独占访问 → 多核同时调用 PIO 路径时，`0x1F7`/`0x1F0`/`0x1F1` 命令序列被交错，`BSY`/`DRQ` 状态位可能属于另一条命令，超时返回值变成假超时或假完成。
- 介质是 512 字节可写磁盘且扇区对齐 → 介质换成 4Kn 4096 字节扇区或只读光盘时，`insl` 搬 512 字节、`superblock`/`bitmap`/`inode` 固定偏移、写回策略都失效，块缓存命中率统计不再对应文件系统块。
- e1000 寄存器为 82545/I210 兼容且中断由本地 APIC 投递 → 换成 virtio-net 或新 PCIe NIC 时，TX/RX 描述符所有权、`RCTL`/`TCTL`、中断向量与 NAPI/`sk_buff` 批处理路径

### 不做什么（范围）

**不做真实硬件的适配与移植。** 不涉及 PCIe 配置空间枚举、ACPI、电源管理、热插拔、SR-IOV。

**不做完整网络协议栈。** 只到 ARP/IP/UDP 够跑一个 web server 的程度；TCP 的可靠性机制不在本文（那属于传输层，见 `../linux-api/` 第 11–14 章）。

**不做文件系统的高级特性。** 不做日志、不做崩溃一致性、不做配额与快照——JOS 的文件系统本来就没有；xv6 的日志在 `../kernel-compare/` 第 8 章讲。

**不做性能调优。** 只给口径（命中率、中断数、环满次数），不给"提升几倍"。

**不写 Linux 驱动代码。** 只讲它的分层与约束；写一个真实字符设备驱动属于另一条线。

## 五、面试怎么讲

**30 秒版本**（开场直接说，130–180 字）

> 驱动我按"找到设备、配置、搬数据、处理完成"四步讲。手上走过两块真实设备：一块 IDE 盘，用 PIO 加轮询把扇区读写、块缓存、inode 布局到用户态文件服务整条链串起来；一块 e1000 网卡，用 MMIO 加描述符环加中断做收发，所有权转移和环满丢包都得自己处理。再往上是 Linux 的分层：块层与页缓存、设备模型与 probe、DMA API、中断上下半部、NAPI 与 sk_buff——我能说清 JOS 的那段代码在 Linux 里被拆成了哪几层、每层为什么存在。

**可能被追问的 8 个点**

1. **「为什么 ATA 读扇区前要读四次状态寄存器？」** → 考点：设备响应延迟。
   → 答法：那是 400ns 的等待技巧——老 ATA 没有"就绪中断"，读备用状态寄存器四次大约耗掉 400ns，用来代替 `udelay` 且不依赖定时器。**这不是玄学，是"设备比 CPU 慢"的最小证据。**
2. **「PIO 和 DMA 的本质区别是什么？」** → 考点：谁搬数据。
   → 答法：PIO 是 CPU 用 `in/out` 一条条搬，占 CPU；DMA 是设备直接读写内存，CPU 只填描述符并等完成。代价是**一致性**：DMA 看到的数据要先刷缓存，设备写的数据要先失效缓存，这就是 Linux 的 DMA API 存在的原因。
3. **「描述符环的所有权怎么划分？」** → 考点：并发与可见性。
   → 答法：发送侧由驱动写描述符并移动 `tail`（门铃），设备取走后置 `DD` 并把 `head` 前移；接收侧相反，驱动先把缓冲交给设备（移动 `tail`），设备填好置 `DD`，驱动处理后归还并再次移动 `tail`。**谁移动游标，谁就拥有那一段。**
4. **「中断处理里为什么不能做重活？」** → 考点：原子上下文。
   → 答法：硬中断里通常关着本地中断、不能睡眠、不能等锁太久，做重活会拉高延迟、丢中断、拖垮系统。所以 Linux 分上半部（确认设备、取状态、唤醒下半部）与下半部（`softirq`/`workqueue`/线程化中断），JOS 则干脆在中断里做完整处理——因为它是教学系统，没有延迟预算。
5. **「环满了怎么处理？」** → 考点：背压策略。
   → 答法：发送侧返回"忙"让上层重试或排队；接收侧只能丢，并且要把丢弃计数暴露出来（Linux 的 `ethtool -S` 里的 drop 计数）。**丢包不是 bug，没有计数才是 bug。**
6. **「用户态文件系统（JOS）比内核内（xv6）多付了什么？」** → 考点：路径长度。
   → 答法：一次读要两次上下文切换、一次 IPC 打包、一次页映射操作；换来的是崩溃隔离与"文件系统逻辑不污染内核"。Linux 用 FUSE 保留同一取舍，代价同样是延迟。
7. **「Linux 的 `probe` 是在什么时候被调的？」** → 考点：设备模型。
   → 答法：总线发现设备后创建设备对象，按 ID 表匹配驱动，匹配成功调 `probe`；驱动在 `probe` 里做资源申请（BAR、DMA、IRQ）与注册。**"谁先谁后"由总线模型决定，不是由模块加载顺序决定。**
8. **「怎么证明你的驱动没有丢数据？」** → 考点：判据意识。
   → 答法：分层验证——环回（自发自收）验通路、抓包验内容与顺序、中断计数验完成通知、注入超时/坏块验错误路径、块缓存一致性检查验"读回等于写入"。**没有注入测试的驱动，只在 happy path 上是对的。**

**别说什么**

- **「驱动就是读写寄存器。」** 漏掉所有权、可见性与错误路径，等于没说。
- **「DMA 就是比 PIO 快。」** 没提一致性维护代价（缓存刷新、地址映射、IOMMU）。
- **「中断里干活最简单。」** 在真实系统里这是延迟与丢包的直接来源；要能说出为什么分上下半部。
- **报没测过的吞吐。** 没有块大小、队列深度、缓存状态的口径，任何 IOPS/带宽数字都不成立。
