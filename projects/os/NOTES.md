# os/ · 路径手册

> 编排，不是教材：规定「先读哪一块、配哪个命令验证、用什么判据收尾」。
> 基准：**实现读 xv6，接口读 Linux**。JOS 已归档（2026-11-17），不再进入路径。

## 0 怎么用

- 选路径：读 §2。

## 1 同一件事的两侧

| 机制 | `linux-api/` 看到的 | `xv6/` 落在哪一块 | 面试常问的方向 |
|---|---|---|---|
| 地址空间 | VSS/RSS/PSS、`/proc/pid/maps`、缺页计数 | B2 地址翻译 / B3 地址空间 | 「虚拟地址到物理地址怎么走」→ 两侧都要答 |
| 缺页 | minor/major、OOM killer、`vmstat` | B3 的 COW 钩子 + B4 的陷入 | 「COW 的 PTE 状态」只有实现侧答得出 |
| 进程与线程 | `ps -L`、`clone` 参数、`/proc/pid/task` | B5 进程（xv6 无线程） | 「PCB 里到底有什么」 |
| 调度 | `nice`/cfs 权重、`%CPU` | B7 调度 | 「为什么我的程序被抢占」 |
| 陷入与信号 | `signal`、`sigaction`、`strace` | B4 陷入 / B6 系统调用（xv6 无信号） | 「系统调用怎么进内核」 |
| I/O 与阻塞 | epoll、非阻塞、`EAGAIN` | B8 文件 + B9 驱动（xv6 无 epoll） | 「边缘触发为什么丢事件」 |
| 内存压力 | `cgroup` 限额、swap、OOM 评分 | B1 物理内存（无回收策略） | 「为什么 OOM 杀的是它」 |
| 硬件契约 | 只能看到「能用什么系统调用」 | B0/B2/B4 | `kernel-compare/`：**同一格两种答案** |
| 设备 | `iostat`/`ethtool -S` 的计数 | B9 驱动 / B10 网络 | 「一次块读/收包的所有权时间线」 |
| 边界 | 权限、`ptrace_scope`、`seccomp` | B2 的 `PTE_U` + B6 的参数校验 | `security/`：**跨的是哪条边界、硬件还是软件** |
| 机器边界 | 容器里 `nproc`/`top` 的数字、`%steal` | B11 虚拟化（xv6 无实现） | 「一次退出要不要发生、发生几次」 |

**一条口径铁律**：说「内存占用」必须带口径（VSS / RSS / PSS / 匿名 / 文件页），说「CPU 占用」必须带分母（单核 100% 还是整机）。这两条最容易被追问打穿。

**第二条口径**：说「某个机制更简单/更快」之前，先说是**在什么约束下**——教学内核赢在可验证性，生产内核赢在兼容与扩展。

## 2 推荐顺序

### 第一段：用户态症状（必做）

读 `linux-api` 的 CPU、内存、I/O 三块，每块配一个命令：

```bash
top -H -p $$                       # 线程级 CPU：%CPU 的分母是单核
ps -o pid,vsz,rss,cmd -p $$        # VSS/RSS 的差
cat /proc/$$/smaps_rollup          # PSS 与 Shared_Clean / Private_Dirty
grep -E 'pgfault|pgmajfault' /proc/vmstat
ss -tan state time-wait | wc -l    # TIME_WAIT 的真实数量
ss -ti | head -5                   # 重传与 RTT 字段
```

**判据**：给一个症状（内存涨但 RSS 不涨、连接偶发超时但 CPU 不高），十分钟内指到机制 + 字段。

### 第二段：进程与 I/O 语义（必做）

读 `linux-api` 的进程/信号/epoll。

**判据**：讲清「边缘触发 + 非阻塞 + 循环读到 `EAGAIN`」为什么缺一不可；能用 `strace` 指出事件丢失发生在哪一次调用。

### 第三段：块 B0–B4（建议）

读 `xv6` 的初始化、物理内存、地址翻译、地址空间、陷入。

**判据**：能默写 `ecall` 六步的 `pc/sp/satp/stvec/sscratch`；能画出一次写缺页从硬件到返回；能说清「页表结构归翻译设施、页表项里的物理地址归分配」。

### 第四段：块 B5–B8（加分）

读进程、系统调用、调度、文件系统。

**判据**：能说清 `fork`/`exec` 的账本（复制什么、共享什么、替换什么），以及日志的提交点为什么是第二次 `write_head`。

### 第五段：横向对比（建议）

读 `kernel-compare/`，按「一格两答」复盘：陷入、进程结构、地址空间、API 形状（JOS 列只作历史附注）。

**判据**：任选一格，能说出**硬件契约给了什么 → 两种内核怎么用 → 换约束会怎样**；能举一个「把一家的做法搬到另一家就错」的例子（把 xv6 的 `sleep/wakeup` 搬到多核、把 Linux 的 `clone` 语义套到 `fork`）。

### 第六段：设备层（看岗位）

读 `drivers/` 与 `xv6` 的 B9–B10：先 PIO（建立「设备是异步的」手感），再 MMIO + DMA + 中断。

**判据**：能画出两条所有权时间线（块读、收包），每步写清「谁移动游标、谁持有引用」；能指出 `e1000_recv` 在 Linux 里被拆成上半部 + NAPI poll 两段。

### 第七段：边界与对抗（建议）

读 `security/`，按「原语」复盘：内存破坏给什么原语 → 能拼成什么 → 被哪个缓解挡住。

**判据**：任给一个漏洞描述，能说出跨哪条边界、需要几个原语、被哪个机制迫使多走一步。另需一句话说清 ROP 与外挂的共同点：都依赖任意读写与调用，区别只在**原语是漏洞给的还是权限给的**。

> 纪律：实验只用自己写的程序或公开 CTF 环境；不针对商业游戏/反作弊做绕过。

### 第八段：虚拟化（看岗位）

读 `virtualization/`：先建「退出 = 成本单位」模型，再用最小 VMM 证明「VM 就是个用户态进程」，最后用对照表把容器与 WSL 放回同一谱系。

**判据**：能画出「guest 写一次串口 / 读一次 4KB 盘」两条路径并标注退出次数、谁在处理、内存拷几次；能说清容器与 VM 的边界分别由谁强制。

## 3 常见误配

| 误配 | 后果 | 正确做法 |
|---|---|---|
| 一上来读 xv6 源码 | 没有用户态症状做锚，读完全忘 | 先用 `linux-api` 建立症状→机制索引 |
| 把 xv6 当「完整 OS」讲 | 被问线程/权限/TCP 就露馅 | 明确口径：教学内核，无 lazy/线程/uid/socket |
| 把 xv6 的简化当原理 | 「页表就是三级」「驱动就是轮询 DD 位」 | 讲原理用必须/可以/不做，讲实现标选点 |
| 背 `top` 字段不背分母 | 380% 的解释直接错 | 记住单核口径与 `nproc`/cgroup |
| 只讲 epoll 快不讲语义 | 追问丢事件就崩 | 水平/边缘 + 非阻塞 + `EAGAIN` 一起讲 |
| 混淆 VSS/RSS/PSS | 内存结论全错 | 三个都带口径说 |
| 说「容器是轻量级虚拟机」 | 后面所有隔离/性能追问都会答错 | 按「边界由谁强制」讲 |

## 4 跨项目追问

1. **「你说缺页很贵，贵在哪一步？」** → 区分 minor（补 PTE）与 major（读设备），给量级关系而不是绝对数。
2. **「页表遍历为什么要走 TLB？」** → 交界题：主战场在 `cpu/cpu-microarchitecture/`，这里只答「地址翻译本身也是一次访存」。
3. **「你的程序为什么被 OOM 杀了而不是别人？」** → `oom_score`、内存占用、cgroup 限额三者一起说。
4. **「信号处理函数里为什么不能随便调 `printf`？」** → 可重入与 async-signal-safe；延伸到「为什么 `malloc` 不是」。
5. **「容器里的 `nproc` 为什么不准？」** → cgroup 配额与 CPU 亲和性的区别；展开在 `virtualization/`。
6. **「同一段代码在裸机、VM、容器里跑，慢的顺序为什么不一定一致？」** → 三段各自收费不同：裸机纯硬件；VM 收「退出税」（fork/小 I/O 最痛）；容器收「overlay 与共用内核」的税（首次写、元数据密集最痛）。没有「谁一定快」，只有「这个负载在收谁的税」。
7. **「xv6 与 Linux 的 `fork` 语义一样吗？」** → 名字一样、决定权不同：`fork` 全共享地址空间（COW），`clone` 把共享集合参数化；进程与线程的差别在 Linux 是参数，在 xv6 是「没有」。

## 5 一句话收口

**用户态那侧决定你能不能在十分钟内定位线上问题，内核态那侧决定你能不能解释它为什么发生。** 两侧都讲得出来，才算懂操作系统。
