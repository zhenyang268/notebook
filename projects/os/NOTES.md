# os/ · 路径手册

> 编排，不是教材：规定「先读哪一块、配哪个命令验证、用什么判据收尾」。

## 0 怎么用

- 选路径：读 §2（推荐顺序）。
- 查对应：§1 的「同一件事的两侧」表。
- 准备追问：§4 的跨项目问题。
- 避坑：§3 的误配。

## 1 同一件事的两侧

| 机制 | `os/linux-api/` 看到的 | `os/jos/` 要实现/理解的 | 面试常问的方向 |
|---|---|---|---|
| 地址空间 | VSS/RSS/PSS、`/proc/pid/maps`、缺页计数 | 页目录/页表项、物理页分配、映射建立 | "虚拟地址到物理地址怎么走"→ 两侧都要答 |
| 缺页 | minor/major、OOM killer、`vmstat` | 页错误处理入口、COW、按需分配 | "COW 的 PTE 状态"只有实现侧答得出 |
| 进程与线程 | `ps -L`、`clone` 参数、`/proc/pid/task` | 用户环境（Env）结构、上下文切换、`fork` 实现 | "PCB 里到底有什么" |
| 调度 | `nice`/`cfs` 权重、`%CPU` | 就绪队列、时间片、抢占点 | "为什么我的程序被抢占" |
| 陷入与信号 | `signal`、`sigaction`、`strace` | 中断/异常入口、trapframe、`iret` | "系统调用怎么进内核" |
| I/O 与阻塞 | epoll、非阻塞、`EAGAIN` | 等待队列、睡眠与唤醒 | "边缘触发为什么丢事件" |
| 内存压力 | `cgroup` 限额、swap、OOM 评分 | 页回收（教学内核里通常简化） | "为什么 OOM 杀的是它" |
| 硬件契约（新增） | 只能看到"能用什么系统调用" | 陷入指令、换栈方式、页表寄存器 | `kernel-compare/` 第 2–3 章：**同一格的三家答案** |
| 设备（新增） | `iostat`/`ethtool -S` 的计数 | ATA 状态位、描述符环所有权 | `drivers/` 第 2–6 章：**一次块读/收包的所有权时间线** |
| 边界（新增） | 权限、`ptrace_scope`、`seccomp` | `access_ok`/`copy_from_user`、页表 U/S 位 | `security/` 第 1、5 章：**跨的是哪条边界、硬件还是软件** |

**一条口径铁律**：说"内存占用"必须带口径（VSS / RSS / PSS / 匿名 / 文件页），说"CPU 占用"必须带分母（单核 100% 还是整机）。这两条是最容易被追问打穿的地方。

**第二条口径**：说"某个机制更简单/更快"之前，先说是**在什么约束下**——教学内核赢在可验证性，生产内核赢在兼容与扩展；脱离约束的比较都是空话（这是 `kernel-compare/` 全篇的立场）。

## 2 推荐顺序

### 第一段：用户态症状（必做）

读 `linux-api` 的 CPU、内存、I/O 三块，每块配一个命令练习：

```bash
top -H -p $$                       # 线程级 CPU：%CPU 的分母是单核
ps -o pid,vsz,rss,cmd -p $$        # VSS/RSS 的差
cat /proc/$$/smaps_rollup          # PSS 与 Shared_Clean / Private_Dirty
grep -E 'pgfault|pgmajfault' /proc/vmstat
ss -tan state time-wait | wc -l    # TIME_WAIT 的真实数量
ss -ti | head -5                   # 重传与 RTT 字段
```

**判据**：给一个症状（例如"进程内存涨但 RSS 不涨"、"连接偶发超时但 CPU 不高"），十分钟内指到具体机制 + 具体字段。

### 第二段：进程与 I/O 语义（必做）

读 `linux-api` 的进程/信号/epoll 部分。

**判据**：能讲清「边缘触发 + 非阻塞 + 循环读到 EAGAIN」这三件事为什么缺一不可；能用 `strace` 指出事件丢失发生在哪一次系统调用。

### 第三段：内核侧三块（建议）

读 `jos` 的页表、陷入、COW。

**判据**：能画出一次缺页的完整路径（硬件缺页 → 保存现场 → 分发 → 处理 → 恢复），并指出 `jos` 在教学模型里省掉了什么（例如页回收、反向映射的完整实现）。

### 第四段：调度、IPC、fork/exec、文件系统（加分）

**判据**：能说清一次 `fork` + `exec` 的资源账本：哪些被复制、哪些被替换、哪些被继承（fd、信号处理、环境变量）。

### 第五段：横向对比（建议）

读 `kernel-compare/`，按"一格三答"的方式复盘：陷入路径、进程结构体、地址空间、系统调用 API。

**判据**：任选一格，能说出**硬件契约给了什么 → 三家各自怎么用 → 换约束会怎样**；能举一个"把一家的做法直接搬到另一家就会错"的例子（例如把 JOS 的显式页映射搬到 Linux、把 xv6 的 `sleep/wakeup` 搬到多核）。

### 第六段：设备层（看岗位）

读 `drivers/`：先 PIO（IDE 盘）建立"设备是异步的"手感，再 MMIO + DMA + 中断（e1000）。

**判据**：能画出两条所有权时间线（块读、收包），每一步写清"谁移动游标、谁持有引用"；能指出 JOS 的 `e1000_recv` 在 Linux 里被拆成上半部 + NAPI poll 两段，以及为什么。

### 第七段：边界与对抗（建议）

读 `security/`，按"原语"复盘：内存破坏给什么原语 → 能拼成什么 → 被哪个缓解机制抬高成本。

**判据**：任给一个漏洞描述，能说出三件事——**跨哪条边界**（同进程 / 跨进程 / 到内核）、**需要几个原语**（读/写/调用/跳转）、**被哪个机制挡住或迫使多走一步**（NX→ROP、ASLR→泄露、CET→转数据面）。另需能一句话说清"ROP 与外挂的共同点"：都依赖任意读写与调用能力，区别只在**原语是漏洞给的还是权限给的**。

> 纪律：这一段的实验只用自己写的程序或公开 CTF 环境；不针对商业游戏/反作弊做绕过，不产出可分发的工具。

## 3 常见误配

| 误配 | 后果 | 正确做法 |
|---|---|---|
| 一上来读 `jos` 源码 | 没有用户态症状做锚，读完全忘 | 先用 `linux-api` 建立症状→机制的索引 |
| 把 `jos` 当"完整 OS"讲 | 被问文件系统/驱动就露馅 | 明确口径：教学内核，做到用户进程为止 |
| 背 `top` 字段不背分母 | 380% 的解释直接错 | 记住 `%CPU` 单核口径与 `nproc`/cgroup 限制 |
| 只讲 epoll 快不讲语义 | 追问丢事件就崩 | 水平/边缘 + 非阻塞 + EAGAIN 三件套一起讲 |
| 混淆 VSS/RSS/PSS | 内存结论全错 | 三个都带口径说，且知道 `smaps_rollup` 在哪看 |

## 4 跨项目追问

1. **「你说缺页很贵，贵在哪一步？」** → 要区分 minor（补 PTE）与 major（读设备），并给出量级关系而不是绝对数。
2. **「页表遍历为什么要走 TLB，TLB 和 cache 什么关系？」** → 交界题：主战场在 `cpu/cpu-microarchitecture/` 第 8 章，这里只需答"地址翻译本身也是一次访存"。
3. **「你的用户态程序为什么被 OOM 杀了而不是别人？」** → `oom_score` 与内存占用、cgroup 限额三者一起说；不要只说"内存不够"。
4. **「信号处理函数里为什么不能随便调 `printf`？」** → 可重入与异步信号安全；延伸到"为什么 `malloc` 不是 async-signal-safe"。
5. **「容器里的 `nproc` 为什么不准？」** → cgroup 配额与 CPU 亲和性的区别；这是"用户态看到的数字与内核实际约束不一致"的典型。

## 5 一句话收口

**用户态那侧决定你能不能在十分钟内定位线上问题，内核态那侧决定你能不能解释它为什么发生。** 两侧都讲得出来，才算懂操作系统。
