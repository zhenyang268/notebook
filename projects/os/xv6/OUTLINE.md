# xv6 · 五个 lab 的功能视图（OS 动手底座）

> 只做 xv6-riscv 的五个对症 lab：**pgtbl / traps / cow / fs / net**。
> 不造自己的内核，不做 xv6 扩展，不追「完成 MIT 课程」。
> 定位：**面试 OS 追问的底座 + 408 协同**，不是简历主项目（主项目仍是 benchmark / graphics / raft）。
> 决策真源：`learning-benchmark/notes/00-knowledge-map.md` §7.1（2026-11-16 收口）。
> 路由：`../OUTLINE.md`；三内核横向对照 `../kernel-compare/`；驱动机理 `../drivers/`；逐章细节 `NOTES.md`。

## 一、它在做什么

输入是一份约一万行、能在 QEMU 上从 `_entry` 自举到 shell 的 xv6-riscv 源码，加一条 `make qemu-gdb` 的调试通道；输出**不是**一个新内核，而是三样东西：

1. **五个能让机制显形的补丁**——每个 lab 只改两三个函数，改坏立刻有症状（panic、断言失败、ping 不通）。
2. **一张进程能力地图**——地址空间分段 + 每段权限 + 每段的访问行为（写会怎样、访问新的会怎样）。
3. **一组固定断点**——`vmprint` / `backtrace` / `b usertrap` / `b cowfault` / `b commit` / `b e1000_recv`，停在哪里、看哪个变量，都写死。

验收不看「做完了哪几个 lab」，看五类可观察行为：

| lab | 可观察行为（判据） |
|---|---|
| pgtbl | `vmprint` 能打出 init 进程的完整页表并读懂每一段；被读/写过的页能被 `pgaccess` 报出来；共享给用户的那一页在页表里**只读**，写它触发缺页 |
| traps | 任意系统调用里 `backtrace` 能打出 3–5 层返回地址；`sigalarm` 每 N 个 tick 进一次 handler，handler 返回后 `a0` 与原值一致 |
| cow | `forktest` 跑完不 panic；反复写 COW 页之后空闲页数回到初值（无泄漏） |
| fs | 单文件写到 ~64MB 量级并能读回；写大文件途中杀 QEMU，重启后文件长度是旧值或新值，**不是半截** |
| net | 宿主机能 ping 通 guest；能画出一次收包的 `RDT` 推进与 buffer 替换顺序 |

一句话：把「我的进程能访问哪段内存、什么权限、写一下会发生什么、访问一段新的会发生什么」从源码注释落到**能跑、能看、能指**的行为上。

**入口（本文的读法）**：在「CPU 只给三样保护材料」这个约束下——页表项权限、特权级与陷入入口、设备 MMIO/DMA——看 xv6 用最小代码把每一件落到哪一行。换的是被补的机制（映射 / 陷入 / COW / 日志 / 驱动），不换的是每次都问的三个问题：**谁能访问、谁在什么时候改、改完怎么看见**。

**不换的是什么**：五个 lab 共用同一批硬件契约，没有哪个 lab 引入第四类材料——地址翻译只用 `satp` + Sv39 页表项；陷入只用 `stvec` / `sscratch` / `sepc` / `scause`；文件系统只用到 virtio 磁盘的块读写；网卡只用到 e1000 的寄存器和描述符环。**所以读每一章该问的是「这次改的是哪条权限、哪个游标」，而不是「这章又讲了什么新东西」。**

**积木**：①`PTE_V/R/W/X/U` 这几位——它能独立验证「用户读一段只读页成功、写同一页触发 `scause=15`」；②`stvec → uservec`、`sscratch → trapframe`、`sepc` / `scause`——它能独立验证「U 态一条 `ecall` 之后 `sp` 还是用户栈，而内核已经知道该跳到哪、现场存在哪」；③描述符环的 `tail` 与 `DD` 完成位——它能独立验证「`e1000_transmit` 必须等 `DD` 才能复用描述符，否则 DMA 会写进一个还没发完的 buffer」。

**最小情形**：单核、单进程、一次 `write(1, "x", 1)`：U 态执行 `ecall` → `uservec` 把 31 个寄存器存进 `trapframe`、切内核页表与内核栈 → `usertrap` 认出 `scause=8`、`epc += 4` → `syscall` 按 `a7` 查表进 `sys_write` → `usertrapret` → `sret` 回到 U 态下一条指令。这一情形初等，因为 COW 缺页、日志提交、网卡中断、多核 `wakeup` 都不触发。

**两边**：同一份「执行现场」有两份表示——U 态持有 31 个通用寄存器与 `pc`；内核持有 `trapframe` 里的 31 个槽位，加 `kernel_satp` / `kernel_sp` / `kernel_trap` / `epc` / `kernel_hartid` 五个簿记字段（合计 288 字节）。同一段「能访问的内存」也有两份表示——用户看到的是段与权限（能力地图），内核看到的是三段页表（用户段、直接映射、顶端两页）。

## 二、为什么这样做（功能设计）

**取舍一：为什么是 xv6，不是自写内核或 rCore。** JOS 已经从零写过一遍，剩下的缺口不是「没造过」，而是**细节虚**：页表怎么逐级走、陷入现场到底存在哪、COW 的引用计数在哪减、日志什么时候算提交。这些只有在一个「能跑、能被 gdb 停住、能改坏再修好」的内核上才补得实。xv6-riscv 约一万行，五个 lab 各对应一处机制，改坏立刻有症状。从零造（rCore 或自写）要先把引导、驱动、文件系统全铺一遍才轮到你真想补的那一处，付出十倍代码量换同一批概念。**代价**：要接受 xv6 的约定——trapframe 字段顺序、`kalloc` 的 freelist、日志的块格式——这些不是「标准答案」，只是「一个能跑的最小答案」，讲的时候必须自己说清这一点。

**取舍二：为什么只五个 lab。** 缺口是具体的：页表细节、陷入路径、COW 落地、文件系统、网卡驱动。五个 lab 一一对上，多一个都不加。调度、锁、IPC、多核这些**能讲清概念但不动手**——408 与 `kernel-compare/` 里有对照，面试最多追问一句「xv6 的 `sleep/wakeup` 为什么要求持锁」，答得出来就够。**代价**：被问「你自己写过调度器吗」，答案是「没有，只读过 xv6 的 round-robin 与 `sleep/wakeup`」。这条边界要自己先说，不能等对方问出来。

**取舍三：为什么功能视图优先，结构层按需下钻。** 每个机制先回答三件事：**它让我能干什么、为什么非它不可、我怎么看见它在起作用**。结构（PTE 位怎么排、三级页表怎么走、物理帧从哪来）只在解释「为什么这次访问会/不会触发缺页」时才展开。理由不是结构不重要，而是结构先讲，学到的就是背位图；从行为出发，结构是**被问题叫出来的**。**代价**：第一次讲 pgtbl 时说不出 `PTE_G` / `PTE_D` 这种冷位，被追问就得现场下钻——所以每章留一张「下钻表」，写清哪个问题该翻到哪一位、哪一行。

**取舍四：为什么用 gdb 当状态查看器，不画全系统并发时间线。** 单进程学机制不需要并发时间线，需要的是**随时能把当前状态打出来**：`vmprint` 是页表的静态快照，`backtrace` 是调用链的静态快照，`b usertrap` + `info registers` 是陷入瞬间的静态快照。三样合起来等价于 Linux 侧的 `/proc/PID/maps` + `pmap` + `strace`，但能停在任何一条指令上。**代价**：看不到竞态——引用计数漏减、日志并发提交错，静态快照可能都是对的；这类错只能靠「跑 `forktest` 若干轮 + 数空闲页」暴露。

**取舍五：为什么只用官方 lab 骨架。** 骨架已经把「该改哪里」缩到两三个函数，判据由 lab 自带测试给出。自己加扩展（fuzzer、性能计数器、优先级调度）已否决：不补缺口，只增加维护面。**代价**：lab 测试通过不等于理解对了——`forktest` 过只说明没立刻崩，说明不了引用计数没漏。所以每章都配一条**比 lab 测试更狠的检查**：数空闲页、读 `log.lh.n`、盯 `RDT`。

**取舍六：为什么 `jos/` 与 `kernel-compare/` 都保留，不合并进本文。** 三者判据不同：`jos/` 是「从零造」的完整因果链，回答「每一步为什么必须存在」；`xv6/` 是「在真内核上改对一处」，回答「改这三行，行为怎么变」；`kernel-compare/` 是「同一格三家答案」，回答「换约束会长成什么样」。合并会把三种判据压成一种。**代价**：同一机制在三处各有一段描述，可能口径漂移——所以**机制正文只在 `kernel-compare/` 定义一次**，本文只写「在 xv6 里落到哪个函数、怎么验证」，不重写因果。

**取舍七：为什么和 408 并行，不另立一套体系。** 408 考「给你一个场景选哪个算法/哪个指标」，xv6 练「指到哪一行代码」。重叠处——分页与缺页、系统调用与中断、文件分配与缓冲、DMA 与中断驱动——正好互相校验：选择题答对说明概念没歪，断点停住说明细节没虚。**代价**：不重叠的部分（页面置换算法、磁盘调度、SPOOLing）只有 408 一侧，xv6 不补，也不假装补。

**取舍八：为什么只放静态 ASCII 图，不做交互动画。** 动画能建立直觉，但不能回答「这一刻 `satp` 是什么」。需要交互演示（COW 两进程逐页分裂、缺页时序）时落到 `learning-web`；本文只放静态图与判据，且图必须能和代码对上——对不上的图是装饰，不是文档。

## 三、章节大纲

0. **环境与三个固定动作** — 工具链、`make qemu-gdb`、`CPUS=1` 与默认多核的区别、`vmprint` / `backtrace` / 断点三件套。判据：能从 `_entry` 一路跑到 shell，`b usertrap` 能停住每一次系统调用。
1. **能力地图** — 先定义「功能视图」与「结构视图」的分界，再画 init 的段 + 权限 + 访问行为；三种快照（`vmprint` / `pmap` / `/proc/PID/maps`）各自回答什么。判据：不看源码能画出地图，并指出哪一段「写一下会触发缺页」。
2. **pgtbl** — `walk` / `mappages` / `kvmmap` / `proc_pagetable`；三段地址空间怎么被划出来；三个 lab 任务各自补哪条功能（只读共享页、结构快照、访问位）。判据：`vmprint` 能读；能解释某次访问为什么失败；写共享页触发缺页。
3. **traps** — `ecall` 到 `sret` 的六步，每步的 `pc` / `sp` / `satp` / `stvec` / `sscratch`；trapframe 288 字节的布局；`backtrace` 的栈帧规则；`sigalarm` 为什么要整份保存 trapframe。判据：能单步走完并说出每步的值，不看代码。
4. **cow** — 引用计数表、`uvmcopy` 的双向只读、`scause=15` 的写缺页、`cowfault` 的分配—拷贝—重映射；三个必错点。判据：写 COW 页后父子物理页不同、空闲页数回初值。
5. **fs** — `bio` 缓存、`log` 事务、`inode` 与目录三层；提交点是第二次 `write_head`；日志吸收；大文件的三级索引；符号链接的环检测。判据：写大文件中途杀 QEMU，重启后长度不半截。
6. **net** — MMIO 寄存器与 16 项描述符环；`DD` 位与所有权；`e1000_transmit` / `e1000_recv` 的推进顺序；环满为什么返回错误而不是等。判据：ping 通，并能画出收包的 `RDT` 与 buffer 替换顺序。
7. **收口** — 五个 lab → 面试追问 → 408 章节的三列映射；与 JOS / Linux 的一格三答；一份「能讲的三句话」清单与断点速查。判据：任给一个 408 OS 考点，能指到 xv6 的哪个函数、哪次断点。

> 顺序理由：0–1 是「先建坐标系」（没有地图，后面五个 lab 就是五段孤立代码）；2–4 是「同一段地址空间的三种行为」（能访问 / 陷入 / 写时分裂），必须连起来看；5–6 换到「持久化与设备」，此时页表和陷入已经是已知条件；7 才做收口。
> 排期不在本文：目录级阶段与优先级只在 `projects/PLAN.md`（当前口径：OS 整块留初试后）。

## 四、不做什么 · 必要性 · 失效点

### 必要性：删掉会怎样

| 机制 | 删掉会怎样 | 判定 |
|---|---|---|
| 页表项的 `U` 位 | 用户能读内核页，隔离承诺直接破 | 必需 |
| trampoline 在用户页表里同址映射 | 换 `satp` 的下一条指令地址在新页表里无效，陷入即崩 | 必需 |
| `trapframe` | 返回时寄存器与返回地址丢失，进程无法继续 | 必需 |
| COW 引用计数 | 共享页被提前释放，随机 panic，且与「哪次 fork」无关，极难定位 | 必需（承诺 COW 之后） |
| 日志 | 断电后元数据与数据不一致，文件系统自相矛盾 | 必需（承诺崩溃一致性之后） |
| 描述符 `DD` 位 | 复用未发完的描述符，DMA 写坏一个已交出的 buffer | 必需 |
| 缓冲区缓存 | 正确性不受影响，只是每次读写都落盘 | 选择 |
| 符号链接 | 只是接口便利，不改变存储语义 | 选择 |

最后两行是这张表的用处：它把「必做」和「可换」分开。**强制集会随承诺变**——不承诺崩溃一致性，日志就可以不要；不承诺并发写，引用计数也可以省。

### 失效点：哪条前提一破，结论就变

- **单核 → 多核**（xv6 默认 `CPUS=3`）：引用计数表必须加锁；`e1000` 的寄存器访问必须持锁；`sleep/wakeup` 的「持锁才能睡」从良好习惯变成正确性前提。单核下「看不出错」的实现，多核下会偶发。
- **Sv39 → Sv48**：`walk` 的层数、`MAXVA`、页表项的索引位数全变；「三级」这句话失效。
- **trapframe 字段顺序变**：`trampoline.S` 里的偏移量是硬编码的，改一个字段就是随机崩——不是「可能出错」，是「一定错」。
- **磁盘换成 virtio-blk 的现代队列**：`bio` 的「一次一个块、同步等待」前提消失，`bread` 要变成异步提交 + 完成回调。
- **网卡换成 virtio-net**：描述符环从「单环 + `DD` 位」变成「avail / used 双环 + 通知」，e1000 的所有权经验不能直接搬。
- **加上 KPTI 一类加固**：用户页表不再包含内核映射，trampoline 从「省事」变成「唯一可用的跳板」；`usertrapret` 的路径也要多一次页表切换。

### 不做什么（范围）

- **不做 xv6 扩展**：fuzzer、FS 崩溃测试、性能计数器、优先级调度——已否决，不补缺口只增维护面。
- **不写调度器与协议栈**：调度只到「读懂 `scheduler` / `sleep` / `wakeup`」；网络只到驱动与 `net_rx` 的一跳，不做 TCP。
- **不移植 Linux、不做发行版运维**：那是另一条线。
- **不报性能数字**：没有基准就没有倍数；只说「这次多了几次内存访问 / 几次中断」，不说「快了多少」。
- **不背讲义**：每个结论必须能落到一次断点、一段输出或一次 lab 判据。落不上去的，就是背来的。
- **不把 lab 补丁当作品**：讲的时候要说清「改了哪三行、为什么必须这样」，而不是「我完成了五个 lab」。

## 五、面试怎么讲

### 30 秒版本

> 操作系统这块我用 xv6 补细节，只做了五个对症 lab：页表、陷入、COW、文件系统、网卡驱动。我不是在造内核，是在一个能跑的最小内核上把机制改对一处，然后用 gdb 把它停住看现场——比如一次 `ecall` 之后，我能逐条说清 `uservec` 把 31 个寄存器存到 trapframe 的哪个偏移、为什么必须先切 `satp` 再跳 `usertrap`、返回时 `stvec` 和 `sscratch` 各是什么。判据是可观察行为：`vmprint` 打得出一张页表、`backtrace` 打得出调用链、ping 通、写完大文件断电重启数据不半截。

### 可能被追问的 8 个点

**1.「`ecall` 之后为什么不能直接用内核栈？」**
→ 考点：RISC-V 陷入不换栈，谁负责换。
→ 答法：`ecall` 只把返回地址放进 `sepc`、原因放进 `scause`，`sp` 还是用户栈。所以 xv6 把 `stvec` 指向 `trampoline` 里的 `uservec`，`sscratch` 里预先存着 `TRAPFRAME`；`uservec` 第一条 `csrrw a0, sscratch, a0` 用一条指令同时拿到 trapframe 地址、把用户 `a0` 暂存走，然后才从 trapframe 里取 `kernel_sp` 换栈。
→ 边界：trampoline 必须在用户页表里映射在**同一个虚拟地址**（`MAXVA-PGSIZE`），否则 `csrw satp` 之后下一条指令就取不到——这就是它叫 trampoline 的原因。

**2.「trapframe 里 288 字节都是什么？」**
→ 考点：现场到底保存了什么，哪些不是寄存器。
→ 答法：前 40 字节是 5 个内核簿记字段（`kernel_satp` / `kernel_sp` / `kernel_trap` / `epc` / `kernel_hartid`），后面 248 字节是 31 个通用寄存器（`x0` 不用存）。`epc` 是「回到用户态从哪条指令继续」，`a7` 是系统调用号，`a0` 是返回值。
→ 边界：字段顺序由 `proc.h` 定，`trampoline.S` 里的偏移是硬编码；改顺序一定崩，不是概率问题。

**3.「一次写缺页从硬件到返回，经过哪些点？」**
→ 考点：能不能把「硬件—入口—分发—处理—恢复」串成一条线。
→ 答法：写一个 `PTE_W=0` 的页 → CPU 报 page fault，`scause=15`，出错地址在 `stval` → `uservec` 存现场、切内核 → `usertrap` 看到 15 就调 COW 处理 → 分配新页、拷贝、把 PTE 改成可写、`kfree` 旧页 → `usertrapret` 恢复现场、`sret` 重执行那条写指令。若是 13（读缺页），COW 不该处理，因为读不需要分裂。
→ 边界：COW 只对「本来就合法、只是被改成只读」的页成立；对未映射地址的写缺页必须杀进程，不能也去分配一页。

**4.「COW 的引用计数放在哪，为什么在那减？」**
→ 考点：单点释放原则。
→ 答法：按页号索引一张计数表，`kalloc` 置 1、`kfree` 减 1、减到 0 才真正回收。放在 `kfree` 而不是 `uvmunmap`，因为释放路径不止一条（`uvmunmap`、`uvmcopy` 失败回滚、`cowfault` 换页），只要有一条忘了减就是泄漏或提前释放；收敛到一个函数就只有一处要验。
→ 边界：计数表本身要锁；多核下不加锁先崩的是计数，不是页。

**5.「文件系统的日志什么时候算提交？」**
→ 考点：崩溃一致性的提交点在哪。
→ 答法：事务把修改写进日志块（`write_log`），再写日志头记录块号（`write_head`），然后装回原位（`install_trans`），最后把日志头清零（第二次 `write_head`）。**真正的提交点是第二次写头**：此前崩，重启看到 `n=0`，什么都不做；装回过程中崩，重启看到 `n≠0`，重放一遍（幂等）；清零之后崩，就是已提交。
→ 边界：`begin_op` 必须预留日志空间，否则写到一半发现日志满，事务没法原子收尾。

**6.「e1000 收包时 `RDT` 谁推进，为什么顺序不能反？」**
→ 考点：描述符环的所有权。
→ 答法：`RDT` 由软件（内核）推进，指向「最后一个已处理的描述符」。处理一个包：取 `RDT+1` 那项 → 确认 `DD` → 把 buffer 交给协议层 → 给这个槽换一个新 buffer → 清状态 → 才把 `RDT` 推到这一项。顺序反了（先推 `RDT`），网卡会把下一包 DMA 进一个已经交出去的 buffer。
→ 边界：环满时 `transmit` 返回错误而不是等待——网卡驱动在中断上下文里，不能睡。

**7.「`vmprint` 打出来的东西怎么读？」**
→ 考点：结构快照与功能视图的对应。
→ 答法：每一级 512 项，输出只列非零项；`..` 的层数就是级数。第一段是用户的代码/数据/栈（有 `U` 位），第二段是内核直接映射（`U=0`，所以用户碰它必 fault），顶端两项是 trampoline 与 trapframe（同样 `U=0`，但必须存在）。看到某个地址没有对应项，就是「没映射」——访问它必 fault。
→ 边界：`vmprint` 只显示页表，不显示权限；权限要 `p/x *pte` 或看 `PTE_U/W/X` 才有。

**8.「xv6 的 `sleep/wakeup` 为什么要求调用者持锁？」**
→ 考点：lost wakeup。
→ 答法：`sleep(chan, lk)` 会先拿 `lk` 检查条件、再把自己挂到 `chan` 上、再 `sched()` 让出 CPU，中间释放 `lk`。如果调用者不持锁，「检查条件」和「挂到 chan 上」之间就有一个窗口，`wakeup` 可能正好落在这个窗口里，然后睡眠者永远等下去。持锁把这个窗口关掉——不是靠关中断，因为 `sched` 会切上下文。
→ 边界：这条在单核也一样成立（唤醒可能来自中断），不要以为只有多核才要管。
