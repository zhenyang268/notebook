## 一、它在做什么

输入是一份约一万行、能在 QEMU 上从 `_entry` 跑到 shell 的 xv6-riscv，加一条 `make qemu-gdb`；输出**不是**一个新内核，而是三样东西：

1. **十二块的功能视图**——每块一句话说清「把一份什么变成多份什么」，接口只到 5 条。
2. **一张 4×12 的线矩阵**——准入／配额／并发／故障四条线在各块的检查点。
3. **一张 xv6 ↔ Linux 的 API 对照表**——同一件事两种形状，差异来自「内核替谁做了决定」。

验收不看「做完几个 lab」，看每块六项齐不齐（职责／使用面／实现面／依赖／判据／失效点），以及判据是否可观测：

| lab | 覆盖的块 | 可观察判据 |
|---|---|---|
| pgtbl | B2 B3 | `vmprint` 能读；写只读共享页触发缺页；`pgaccess` 两次结果不同 |
| traps | B4 B6 | 能默写 `ecall→sret` 六步；`backtrace` 出 3–5 层；`sigalarm` 后 `a0` 原值 |
| cow | B3 B5 | `forktest` 跑完且空闲页数回初值；`cowfault` 里旧 PTE 的 `W`/COW 位正确 |
| fs | B8 | 写大文件途中杀 QEMU，重启后长度不半截；`write_head` 命中两次 |
| net | B9 B10 | ping 通；`RDT`/`RDH` 差一格；环满返回 -1 |

一句话：把「这块把一份什么变成了多份什么、接口是哪五条、边界由谁检查、换约束哪条失效」落到能跑、能停、能指的行为上。

## 二、为什么这样做（功能设计）

**取舍一：为什么以 xv6 为实现、以 Linux 为接口基准。** xv6 给的是「能停住看的现场」：一万行、五个 lab、每个机制两三个函数。Linux 给的是「生产形状」：同一件事在接口上被拆得更多（`clone` 把共享参数化、`mmap` 把文件映射并进来、`epoll` 把就绪通知独立出来）。**实现读 xv6，接口读 Linux**，两者对照才看得出「哪些是机制必需，哪些是历史选择」。**代价**：xv6 的简化不能当原理（无 lazy、无线程、无 uid），每处都要标「它选了哪个点」。

**取舍二：为什么按块切，不按 lab 也不按 408 章。** lab 按改动点切，判据是 patch 过测试；408 按考纲切，判据是每章能独立出题。两种切法都把「一块资源怎么被复用」打散。块按「一份什么变多份什么 + 一组失效模式」切，粒度判据可查（`LEARNING.md` §3.1 ②）。**代价**：一个 lab 会横跨两块（cow 落在 B3 与 B5），所以验收表要按块标注，不能按 lab 编号。

**取舍三：为什么只到使用面，实现面压到六个名词。** 虚拟内存、进程的实现面各自能列二十项，但对外只有 4–5 条能力。正文只写使用面，实现面写成下钻清单，每个名词必须能答「删掉它会怎样」。**代价**：第一次被追问 `PTE_G`/`PG_A` 这类冷位，要现场下钻——所以每块留了下钻指针。

**取舍四：为什么 jos 归档而不是留着当对照。** 它解决的是「从零造一遍的完整因果链」，而当前缺口是「细节虚」。两者判据不同，留着会诱导按「实现步骤」讲。三家对照的历史价值保留在 `../kernel-compare/`（JOS 列降为附注）。**代价**：`../kernel-compare/` 的 JOS 列从此只作历史参照，引用时要标「已归档」。

**取舍五：为什么用 gdb 当状态查看器。** 单块机制不需要并发时间线，需要随时能把当前状态打出来：`vmprint`（页表快照）、`backtrace`（调用链快照）、`b usertrap` + `info registers`（陷入瞬间快照）。**代价**：看不到竞态——引用计数漏减、日志并发提交错，静态快照可能都对；这类错只能靠「跑 `forktest` 多轮 + 数空闲页」暴露。

**取舍六：为什么只放静态 ASCII 图。** 动画能建直觉，但回答不了「这一刻 `satp` 是什么」。需要交互演示（COW 逐页分裂、缺页时序）落到 `learning-web`；本文只放能与代码对上的静态图。

## 三、块清单、依赖与矩阵

### 3.1 十二块（按「一份什么 → 多份什么」命名）

| # | 块 | 一份什么 → 多份什么 | 使用面（≤5） | 依赖 |
|---|---|---|---|---|
| B0 | 初始化与运行底座 | 一块裸板 → 能跑 C 的环境 | 无接口；产出三保证：能切特权级／有栈／能输出 | — |
| B1 | 物理内存 | 一段 RAM → 可反复分配的页 | `alloc`／`free`／页大小固定 | B0 |
| B2 | 地址翻译 | 一段虚拟地址 → 任意物理页 + 权限 | `map`／`unmap`／`walk`／同一 `pa` 可多次映射 | B1 |
| B3 | 地址空间 | 一堆映射 → 能长能缩能复制的对象 | `grow`／`shrink`／`copy`／`free_all` | B2 |
| B4 | 陷入与返回 | 一条执行流 → 可冻结可恢复的现场 | trapframe／不可改的入口／`return` | B1,B2 |
| B5 | 进程 | 流 + 地址空间 + 资源 → 可管理的单位 | `create`／`fork`／`exec`／`exit`／`wait` | B3,B4 |
| B6 | 系统调用 | 任意用户请求 → 一个受检的窄入口 | `syscall(n,args)`／返回值约定／参数校验 | B4,B5 |
| B7 | 调度 | 一条 CPU 时间线 → 多份时间片 | `yield`／`sleep`／`wakeup` | B5,B4 |
| B8 | 文件系统 | 一块盘 → 多个命名对象 + 断电不坏 | `open/close`／`read/write`／`mkdir`／重启还在 | B6,B1,B9 |
| B9 | 设备与驱动 | 寄存器 + 中断 + DMA → 提交/完成 | `submit`／完成通知／`irq_ack` | B1,B4 |
| B10 | 网络 | 一块网卡 → 多个端点 | `send/recv`／`bind`／（可靠+有序） | B9,B6 |
| B11 | 虚拟化 | 一台机 → 多台能跑内核的环境 | `vm_create`／`vcpu_run`／MMIO 陷入 | 全部 |

**块粒度判据**：一块 = 一种复用方式 + 一组失效模式。B1/B2/B3 拆三块，是因为三者的失效模式不同（分配重复／翻译错／边界越界）；B4 独立，是因为进程**借**它，借的东西不能同时是借者的字段。

### 3.2 依赖是 DAG，不是章节顺序

```text
B0 → B1 → B2 → B3 ──→ B5 ──→ B7
        └→ B4 ──────→ B6 ──→ B8 ←─ B9 ← B1
                        └───→ B10 ←─ B9
B11 ← 全部（它把每块的假设反转一遍）
```

施工顺序 B1 先于 B2（页表要用页来存），讲解顺序可以先讲 B2 再回看 B1——B2 的接口里有一句「我需要页来存表」，那就是一次按需借。

### 3.3 每块六项（正文按这个填，`NOTES.md` 逐块展开）

**B0 初始化与运行底座**
- 职责：把复位后的 CPU 带到「能执行 C、能输出一个字符」的状态。
- 使用面：无对外接口；产出三保证——能切特权级、有一个可用栈、有一个输出通道。
- 实现面（≤6）：链接脚本／入口汇编／BSS 清零／栈设置／UART MMIO／`sret` 前的特权级字段。删掉 BSS 清零 → 全局变量随机；删掉栈设置 → 第一次函数调用就崩。
- 依赖：无。被依赖：全部。
- 判据：能打印第一行；`b _entry` 能看到 `pc/sp`。
- 失效点：x86 叫保护模式，RISC-V 是从 M 落到 S——职责相同，实现整体替换。

**B1 物理内存**
- 职责：一段连续 RAM → 可反复分配回收的页。
- 使用面：`alloc()`／`free(p)`／页大小固定 4K。
- 实现面：freelist／位图／buddy／引用计数（`kfree` 减到 0 才回收）。删掉引用计数 → COW 页被提前释放。
- 依赖：B0。被依赖：B2、B5（内核栈）、B9。
- 判据：若干轮 alloc/free 后空闲页数回初值；两次 `alloc` 不返回同一页。
- 失效点：多核不加锁 → 同一页发两次；空闲表未初始化 → 拿到 0 页。

**B2 地址翻译**
- 职责：一段虚拟地址 → 任意物理页，并带 `U/R/W/X`。
- 使用面：`map(va,pa,perm)`／`unmap(va)`／`walk(va)`／同一 `pa` 可挂进多张表。
- 实现面：三级索引／PTE 位布局／TLB 刷新／重复映射检测。删掉 TLB 刷新 → 旧翻译还在；删掉重复映射检测 → 静默覆盖。
- 依赖：B1。被依赖：B3、B4。
- 判据：映射后可读写；`unmap` 后访问 fault；同一 `pa` 两处映射，改一处另一处可见。
- 失效点：**页表结构 ≠ 进程**——结构归这里，页表项里的物理地址归 B1，进程只到「我拿到哪张、能读写哪些」。

**B3 地址空间**
- 职责：把很多次映射合成一个能长、能缩、能复制、能整体替换的对象。
- 使用面：`grow(n)`／`shrink(n)`／`copy()`／`free_all()`。
- 实现面：段布局／栈方向／guard page／COW 钩子／按需分配（xv6 无 lazy）。删掉 guard page → 栈溢出静默写坏堆。
- 依赖：B2。被依赖：B5、`exec`。
- 判据：`grow` 后可写；越界 fault；`copy` 后两边独立写。
- 失效点：先改边界后分配 → 能访问但没内存；`copy` 只改子不改父 → 写穿。

**B4 陷入与返回**
- 职责：执行流能在任意指令边界被冻结、交给别的代码、原样恢复。
- 使用面：trapframe（现场）／用户不可改的入口（`stvec`+`sscratch`）／`return`。
- 实现面：入口汇编／换栈／`sscratch` 暂存／trapframe 布局／嵌套与中断开关。删掉不可改入口 → 提权；删掉换栈 → 返回地址可篡改。
- 依赖：B1、B2。被依赖：B5、B6、B7、B9。
- 判据：`ecall` 后能回来；一个寄存器不漏；内核里再陷入不毁现场。
- 失效点：trapframe 字段顺序一改，`trampoline.S` 的偏移全错——不是概率问题。

**B5 进程**
- 职责：流 + 地址空间 + 打开的资源 → 可创建、暂停、调度、复制、销毁的单位。
- 使用面：`create`／`fork`／`exec`／`exit`／`wait`。
- 实现面：`struct proc` 字段取舍／pid／父子／zombie／上下文切换保存哪些寄存器。删掉 zombie 设计 → 退出码无处交付。
- 依赖：B3、B4。被依赖：B6、B7、B8（fd 表）。
- 判据：`fork` 后两边独立写；`exec` 后 pid 不变、地址空间换掉；`exit` 后父能拿到码。
- 失效点：复制漏 fd 表 → 资源泄漏；不回收 → zombie 堆积。

**B6 系统调用**
- 职责：任意用户请求 → 一个受检的窄入口。
- 使用面：`syscall(number,args)`／返回值约定／用户指针校验。
- 实现面：分发表／号约定／`copyin/copyout`／错误码。删掉参数校验 → 内核按用户指针解引用。
- 依赖：B4、B5。被依赖：B8、B10。
- 判据：非法指针返回错误而不是崩内核；未知号返回 -1。
- 失效点：xv6 只到「内核态 vs 用户态」，没有 uid/属主——权限链从这里开始断。

**B7 调度**
- 职责：一条 CPU 时间线 → 多个执行流各占一段。
- 使用面：`yield`／`sleep(chan)`／`wakeup(chan)`。
- 实现面：runqueue／时间片／优先级／抢占点／上下文切换。删掉「持锁才能睡」→ lost wakeup。
- 依赖：B5、B4。被依赖：无（但所有块假设会被切走）。
- 判据：两个死循环交替；`sleep` 后不被选中直到 `wakeup`。
- 失效点：在持锁时睡 → 死锁；`wakeup` 不持同一把锁 → 丢唤醒。

**B8 文件系统**
- 职责：一块盘 → 多个有名字、能增长、断电不坏的对象。
- 使用面：`open/close`／`read/write(offset)`／`mkdir/link`／「写成功的，重启后还在」。
- 实现面：inode／目录／块映射／缓冲／日志／位图。删掉日志 → 断电半截；删掉缓冲 → 每次读写都落盘。
- 依赖：B6、B1、B9。被依赖：B5 的 fd 表、`exec` 读 ELF。
- 判据：写-断电-重启数据不坏；`write_head` 两次，第二次参数 0。
- 失效点：`begin_op` 不预留日志空间 → 写到一半无法原子收尾。

**B9 设备与驱动**
- 职责：寄存器 + 中断 + DMA → 「提交一个请求、稍后拿到完成」。
- 使用面：`submit(buf)`／完成通知／`irq_ack`。
- 实现面：MMIO／PIO vs DMA／描述符环／中断上下半部。删掉 `DD` 检查 → 复用未发完的描述符。
- 依赖：B1、B4。被依赖：B8（磁盘）、B10（网卡）。
- 判据：读一个块内容正确；连续提交不丢；环满返回错误。
- 失效点：不 ack 中断 → 中断风暴；提前推进游标 → DMA 写坏 buffer。

**B10 网络**
- 职责：一串帧 → 有地址、有端口、能重传的字节流。
- 使用面：`send/recv`／`bind`／（若做 TCP）可靠 + 有序。
- 实现面：ARP/IP/UDP/TCP／校验和／重传／拥塞。删掉重传 → 丢包即数据丢失。
- 依赖：B9、B6。被依赖：无。
- 判据：ping 通；丢包后能重传（若做 TCP）。
- 失效点：只做 UDP 就宣称「网络通了」→ 一被问重传就空。

**B11 虚拟化**
- 职责：一台物理机 → 多个能跑内核的隔离环境。
- 使用面：`vm_create`／`vcpu_run`／MMIO 与 I/O 的陷入模拟。
- 实现面：VT-x/EL2 世界切换／EPT 两跳／设备四级台阶／vCPU 调度。删掉 EPT → 每次访存都要影子页表。
- 依赖：全部。被依赖：无。
- 判据：guest 能启动；一次 I/O 的退出次数能数清；**反向复用**——逐条引用 B0/B2/B4/B9 的检查点，说出「缺了它 guest 哪一步先崩」（终点块没有后续块可复用，判据 1 按反向计）。
- 失效点：把容器当轻量 VM → 边界由谁强制说不清。

### 3.4 四条线 × 十二块（线不单独成章）

| 块 | 准入（能不能） | 配额（多少） | 并发一致性 | 故障恢复 |
|---|---|---|---|---|
| B0 | 特权级切换 | — | — | 入口前的状态假设 |
| B1 | — | 空闲页上限 | freelist 锁 | 分配失败返回空 |
| B2 | `U/R/W/X` | — | TLB 失效 | 非法访问 fault |
| B3 | 段权限 | 地址空间上限 | COW 引用计数 | 越界杀进程 |
| B4 | 入口与现场不可改 | — | 嵌套／中断开关 | 现场完整性 |
| B5 | 地址空间与 fd 隔离 | CPU 时间、fd 上限 | 状态机加锁 | zombie 与回收 |
| B6 | 参数校验、号表 | — | 重入 | 返回错误而非 panic |
| B7 | — | 时间片、优先级 | 队列锁、lost wakeup | 死锁（不做） |
| B8 | 属主／root（xv6 空） | 磁盘配额 | 事务、日志 | 崩溃恢复 |
| B9 | — | 环深度 | 自旋锁、完成位 | 超时／重试 |
| B10 | 端口绑定 | 缓冲区 | 协议状态机 | 重传 |

### 3.5 xv6 ↔ Linux：同一件事的两种接口形状

| 能力 | xv6 | Linux | 差异来自哪 |
|---|---|---|---|
| 创建进程 | `fork()` | `fork` / `clone(flags,…)` | Linux 把「共享什么」参数化，于是线程与进程同一套 |
| 执行 | `exec(path, argv)` | `execve` + `FD_CLOEXEC` | Linux 把「exec 后关哪些 fd」做成标志位 |
| 等待 | `wait(status)` | `waitpid(pid, status, opt)` | 选择性等待与作业控制 |
| 内存 | `sbrk(n)` | `brk` + `mmap` | Linux 把「文件映射 / 匿名映射」统一进一个入口 |
| 读文件 | `read(fd, buf, n)` | `read` + `pread` + `io_uring` | 偏移是隐式的（共享 file）还是显式的 |
| 目录 | `mkdir` / `link` / `unlink` | 同 + `renameat` | 原子重命名是 POSIX 的硬需求 |
| 事件等待 | 无（阻塞读） | `select` / `poll` / `epoll` | 需要「一个线程等多路」时，阻塞语义不够用 |
| 信号 | 无（`kill` 只用于退出） | `sigaction` | 异步通知独立成一套机制 |
| 用户与权限 | 无 | uid/gid/root + 文件模式位 | xv6 的权限链到「内核态」为止 |
| 网络 | 无（lab 的 UDP 收发） | `socket` / `bind` / `connect` | 端点抽象与协议族选择 |

这张表的用法：**差异不是「谁更先进」，是「内核替谁做了决定」**。`clone` 把决定交给调用者，`fork` 替调用者定死；`mmap` 把决定交给调用者，`sbrk` 定死「只能增长一块连续区」。

## 四、不做什么 · 必要性 · 失效点

### 必要性：删掉会怎样

| 机制 | 删掉会怎样 | 判定 |
|---|---|---|
| PTE 的 `U` 位 | 用户能读内核页，隔离承诺破 | 必需 |
| trampoline 同址映射 | 换 `satp` 后取指地址失效，陷入即崩 | 必需 |
| trapframe | 返回时寄存器与返回地址丢失 | 必需 |
| 引用计数 | COW 共享页被提前释放，随机 panic | 必需（承诺 COW 之后） |
| 日志 | 断电后元数据与数据不一致 | 必需（承诺崩溃一致性之后） |
| 描述符 `DD` 位 | 复用未发完的描述符，DMA 写坏 buffer | 必需 |
| 缓冲区缓存 | 正确性不受影响，只是每次读写都落盘 | 选择 |
| 符号链接 | 只是接口便利 | 选择 |

### 失效点：哪条前提一破，结论就变

- **单核 → 多核**（xv6 默认 `CPUS=3`）：引用计数表要加锁；`e1000` 寄存器访问要持锁；`sleep` 的「持锁才能睡」从习惯变正确性前提。
- **Sv39 → Sv48**：`walk` 层数、`MAXVA`、索引位数全变；「三级」这句话失效。
- **trapframe 字段顺序变**：`trampoline.S` 偏移硬编码，改一个字段一定崩。
- **网卡换 virtio-net**：单环 + `DD` 位变成 avail/used 双环 + 通知，所有权经验不能直接搬。
- **加 KPTI**：用户页表不再含内核映射，trampoline 从「省事」变「唯一可用跳板」。
- **xv6 的简化当原理**：无 lazy、无线程、无 uid、无 socket——每处都要标「它选了哪个点」（§2.5 选点判据）。

### 不做什么（范围）

- 不做 xv6 扩展（fuzzer、崩溃测试、性能计数器、优先级调度）——已否决。
- 不写调度器与协议栈：调度只到「读懂 `scheduler`/`sleep`/`wakeup`」；网络只到驱动与一跳，不做 TCP。
- **不深入 Linux 内核数据结构**：只引 API 形状，`task_struct`/`mm_struct` 出现在对照里，不在正文展开。
- 不移植 Linux、不做发行版运维。
- 不报未测数字：只说「多了几次访存／几次中断」，不说「快了几倍」。
- 不把 lab 补丁当作品：要说清「改了哪三行、为什么必须这样」。

## 五、面试怎么讲

### 30 秒版本

> 操作系统这块我按「块」准备，不按章节。一个块就是把一份资源变成多份，接口就那么几条：页表那块给我的是「一张表 + 四类权限 + 共享」，地址空间那块给我的是「能长能缩能复制」，进程那块给我的是「fork/exec/exit/wait」。我用 xv6 做实现——因为它能停住看现场：一次 `ecall` 之后 `uservec` 把 31 个寄存器存到 trapframe 的哪个偏移、为什么先切 `satp` 再跳 `usertrap`、返回时 `stvec` 和 `sscratch` 各是什么，我都能说出来；接口形状对照 Linux——`clone` 把共享参数化、`mmap` 把映射统一，差异不是先进与否，是内核替谁做了决定。

### 可能被追问的 8 个点

> 总纲先答：「研究进程要不要先学完整内存管理？」→ 不要。页表结构归翻译设施，页表项里的物理地址归分配，进程只要「拿到哪张、能读写哪些、sbrk/fork/exec 时怎么变」。

**1.「`ecall` 之后为什么不能直接用内核栈？」**
→ 考点：RISC-V 陷入不换栈，谁负责换。
→ 答法：`ecall` 只把 `pc→sepc`、原因 `→scause`、`pc→stvec`；`sp` 还是用户栈。所以 `stvec` 指 `uservec`，`sscratch` 里预存 `TRAPFRAME`，第一条 `csrrw a0, sscratch, a0` 一条指令拿到 trapframe 并把用户 `a0` 暂存走。
→ 边界：trampoline 必须在用户页表同址映射，否则 `csrw satp` 后下一条指令取不到。

**2.「trapframe 288 字节都是什么？」**
→ 考点：现场到底存了什么。
→ 答法：前 40 字节是 5 个簿记字段（`kernel_satp/kernel_sp/kernel_trap/epc/kernel_hartid`），后面 248 字节是 31 个通用寄存器（`x0` 不存）；`a0` 在 112、`a7` 在 168。
→ 边界：字段顺序由 `proc.h` 定，`trampoline.S` 偏移硬编码，改了一定崩。

**3.「一次写缺页从硬件到返回？」**
→ 考点：硬件—入口—分发—处理—恢复。
→ 答法：写 `PTE_W=0` 的页 → `scause=15`、出错地址在 `stval` → `uservec` 存现场切内核 → `usertrap` 调 COW → 分配、拷贝、改可写、减旧页计数 → `sret` 重执行。
→ 边界：`scause=13`（读）不该走 COW，否则读非法地址会被静默分配。

**4.「COW 的引用计数放在哪，为什么在那减？」**
→ 考点：单点释放。
→ 答法：按页号索引一张计数表，`kalloc` 置 1、`kfree` 减 1、到 0 才真回收。放 `kfree` 而不是 `uvmunmap`，因为释放路径不止一条，收敛到一处只有一处要验。
→ 边界：计数表要锁；多核下先崩的是计数不是页。

**5.「日志什么时候算提交？」**
→ 考点：提交点。
→ 答法：`write_log` → `write_head`（`n≠0`）→ `install_trans` → `write_head`（`n=0`）。**提交点是第二次写头**：此前崩=旧内容；装回中崩=重放（幂等）；之后崩=已提交。
→ 边界：`begin_op` 要预留日志空间，否则写到一半无法原子收尾。

**6.「e1000 收包时 `RDT` 谁推进，为什么顺序不能反？」**
→ 考点：描述符环所有权。
→ 答法：`RDT` 由软件推进，指向最后一个已处理项。顺序是「取 `RDT+1` → 确认 `DD` → 交协议层 → 换新 buffer → 清状态 → 推进 `RDT`」。反过来，网卡会 DMA 进一个已交出去的 buffer。
→ 边界：环满返回错误而不是等——持自旋锁不能睡。

**7.「同一个能力，xv6 与 Linux 的接口为什么不同？」**
→ 考点：接口形状是被「谁做决定」挤出来的。
→ 答法：`fork` 替调用者定死「全共享地址空间」，`clone` 把共享集合参数化，于是线程与进程同一套；`sbrk` 定死「只能长一块连续区」，`mmap` 把文件映射与匿名映射统一。差异不是先进，是决定权放在哪。
→ 边界：别把 xv6 的简化当原理（无 lazy、无线程、无 uid）。

**8.「xv6 的 `sleep/wakeup` 为什么要求持锁？」**
→ 考点：lost wakeup。
→ 答法：`sleep(chan, lk)` 要先持锁检查条件、挂到 `chan`、再 `sched`，中间放锁。不持锁，「检查」与「挂上」之间有窗口，`wakeup` 落进窗口就永远等。持锁关掉这个窗口——不是靠关中断，因为 `sched` 会切上下文。
→ 边界：单核也成立（唤醒可能来自中断）。
