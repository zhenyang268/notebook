# projects/ — 工程线（**服务面试**）

**唯一位置**：所有项目都在这里，`kaoyan/projects/` 已于 2026-11-02 并入。
工程线与考试线**单向隔离**：`kaoyan/` 只管考纲内的东西，`projects/` 只管「面试能讲什么」。
工程线可以**单向引用**考点的 KP 号（`408-XX-NNNN`，只写编号与考点名），但**绝不复制** `exam/` 的正文、真题原题与分数线——
反方向没有引用：`kaoyan/` 里不出现任何项目名。

## 一句话定位

> 这一层不是教程，是**面试弹药库**：每个项目都要能回答「你做了什么、难在哪、怎么解决的、怎么验证」。

课程项目与能力方法论共用同一套文档结构，`OUTLINE.md` 的第五节固定是 `## 五、面试怎么讲`：
30 秒版本 + 6–8 个追问点（问法 → 考点 → 怎么答）+ 别说什么。

## 两件套（+ 一个例外）

| 文件 | 回答什么 | 篇幅 |
|---|---|---|
| `OUTLINE.md` | **在做什么 / 为什么这样做（功能设计）/ 章节大纲 / 不做什么 / 面试怎么讲** | 2–6 千字（实测 2.4–6.2 千，分组总纲更长） |
| `NOTES.md` | **分章详细**：每章「要解决的问题 / 机制 / 最小例子 / 面试高频问法」 | 1.5–4 万字（分组手册 0.2 万字级，单列大项目 3 万字以上） |

| `cpu/compiler/MINI-COMPILER.md` | 例外：自研小而全编译器的路线与判据 | 5000+ 字 |

**已废除**：`QUICK.md`（一小时上手）、`DESIGN.md`（内容已并入 OUTLINE §二）。旧文件在 `../.gen/archive/`。

## 一、操作系统：`os/` 分组（1 + 5）

| 子项目 | 一句话 | 面试主打 |
|---|---|---|
| `os/linux-api/` | **16 章 + 附录**：APUE 口径的 API + 每章配套 shell 命令 + 内核原理，重心在 CPU / 内存 / 网络 | `top` 380% 怎么判、VSS/RSS/PSS、缺页与 OOM、`ss -i` 看重传、epoll 边缘触发、TIME_WAIT 与端口耗尽 |
| `os/jos/` | 从引导写到用户进程的操作系统内核（10 章） | 页表与地址转换、陷入内核、COW、调度、用户态文件服务 |
| `os/kernel-compare/` | JOS / xv6 / Linux **为什么完全不同**：CPU 架构给了什么材料 → 内核形状 → API 形状（10 章） | 陷入路径三家用什么指令、`trampoline` 为什么存在、`clone` 的资源划分、API 对照表与「不能互换」的论证 |
| `os/drivers/` | 驱动在做什么：JOS 的 IDE 盘（PIO）与 e1000 网卡（MMIO+DMA+中断）+ Linux 的五层配套（8 章） | 状态位顺序、块缓存引用计数、描述符环所有权、环满丢包、设备模型与 DMA API、中断上下半部、NAPI |
| `os/security/` | **边界与对抗**：内存破坏 → 原语（读/写/调用/跳转）→ 控制流劫持 → ROP → 内核提权 → 侧信道；外挂与反作弊作为"同一组原语、不同获取方式"的对照（10 章） | 原语框架、ROP 三段式栈布局、缓解机制的"假设—违反"表、`copy_from_user` 与 SMEP/SMAP/KPTI、外挂四层能力与检测面、为什么反作弊要进内核 |

> 五层是同一台机器：`linux-api` 是你天天用的那一侧，`jos` 是你自己造的那一侧，`kernel-compare` 解释两者为什么不同，`drivers` 解释硬件怎么被接进来，`security` 解释这些边界里哪一条会被跨过。**顺序：用户态（十分钟可验证）→ 内核态（要真调通 lab）→ 横向对比 → 设备层 → 安全（要先知道边界在哪）。**
>
> `security/` 只讲机制与判据：不给可用利用代码、不针对商业游戏/反作弊提供绕过步骤，实验限定在自己写的程序或公开 CTF 环境。

## 二、体系结构与编译器：`cpu/` 分组（1 + 4）

`cpu/` 是**分组目录**（2026-11-03 起）：它自己也有两件套——`OUTLINE.md` 讲四条线怎么串成一条叙事，`NOTES.md` 是路径手册（**60 分版 / 80 分版**两条路线 + 章节↔步骤映射 + 跨线追问）。四个子项目各自仍是独立两件套。

| 子项目 | 一句话 | 面试主打 |
|---|---|---|
| `cpu/asm-link-arch/` | x86-64 与 ARM64 对照 + 链接装载全链路 | 调用约定、栈帧、ELF 与重定位、PLT/GOT、PIE/ASLR |
| `cpu/cpu-microarchitecture/` | **读核**：五级流水线到乱序的因果链 + 性能归因 | 冒险与转发、分支预测、ROB 与重命名、乱序访存、roofline |
| `cpu/riscv-core/` | **造核**：RV32I 单周期 → 流水线 → 乱序，配 difftest 与 STA | 立即数与译码、转发与停顿、BHT/BTB、ROB 与重命名、LSQ 消歧、时序与面积取舍 |
| `cpu/compiler/` | 直接讲 LLVM：IR、Pass、后端、ABI；**第 11 章**讲 GPU 与 DSL（Triton/TVM/XLA/MLIR） | SSA 与 phi、Pass 怎么写、寄存器分配、什么时候不该用 LLVM、GPU 编译器分层与选型 |

> 顺序不是并列的：**读得懂**（`asm-link-arch`）→ **说得清**（`cpu-microarchitecture`）→ **做得出来**（`riscv-core`）→ **编得动**（`compiler`）。路径与判据见 `cpu/NOTES.md`。

## 共同约定

1. **不写进度流水，但允许就绪度快照**：不写「这周做到第几章」「commit 到哪」这类**会过期**的记录。
   允许在 `NOTES.md` 里留一张**带日期的就绪度快照**（哪些 lab 有真实产出、哪些还是官方骨架），
   因为排期要依据它（见 `PLAN.md`）；快照必须标「截至 YYYY-MM-DD」，且只写仓库里能查到的事实。
2. **`OUTLINE.md` 五段固定**，第五节必须是 `## 五、面试怎么讲`，口径是**模板**不是「我已完成」的总结。
3. **`NOTES.md` 每章四段**：要解决的问题 / 机制 / 最小例子 / 面试高频问法。
4. **不编造数字**：没有实测就写「用什么口径测、测出什么量级」。
5. **排期只在 `PLAN.md`**：单个项目的 `OUTLINE.md` / `NOTES.md` 里不写「第几周读哪章」；
   目录级的阶段、路线与优先级一律写在 **`PLAN.md`**（本目录唯一的规划文件）。
6. **分组只做路由**：`cpu/` 这类分组目录自身有两件套（总纲 + 路径手册），但**不复制**子项目正文；子项目的判据各自独立。
