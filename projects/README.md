## 两件套结构（2026-11-02 起）

每个项目一个目录，固定两个文件，**读的顺序就是它们的顺序**：

| 文件 | 回答什么 | 什么时候读 | 篇幅 |
|---|---|---|---|
| `OUTLINE.md` | **大纲 + 设计合一**：在做什么 / 为什么这样做（功能设计）/ 章节大纲 / 不做什么 | 决定"要不要做、怎么做" | 2000–3500 字 |
| `NOTES.md` | **详细记录**：分章详细、踩坑、实测数字 | 做的时候查、做完了复盘 | 1–8 万字 |

`OUTLINE.bi.md` 是 `OUTLINE.md` 的英文版（只翻大纲，`NOTES` 不翻）。

**判据**：`OUTLINE` 读完要能回答「这个项目到底在做什么、为什么这样做」；
`NOTES` 是仓库不是教程。

## 共同约定

1. **`OUTLINE.md` 四段固定**：在做什么 / 为什么这样做（功能设计，写清关键决策怎么落地）/ 章节大纲 / 不做什么。
2. **不写代码仓状态**：不写「我实现到第几章」「commit 到哪」，一个字都不许出现。
3. **`NOTES.md` 不重写教程**，只记"我做了什么、卡在哪、怎么解决的、实测数字"。
4. **不写排期**（"第几周做"不算项目内容）。
