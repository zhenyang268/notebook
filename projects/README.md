# projects/ — 工程线（**服务面试**）

**唯一位置**：2026-11-02 起，所有项目都在这里，`kaoyan/projects/` 已并入。
工程线与考试线物理分开：`kaoyan/` 只管考纲内的东西，`projects/` 只管「面试能讲什么」。

## 一句话定位

> 这一层不是教程，是**面试弹药库**：每个项目都要能回答「你做了什么、难在哪、怎么解决的、怎么验证」。

所以每份文档的第五节都是固定的 `## 五、面试怎么讲`：30 秒版本 + 6–8 个追问点（问法 → 考点 → 我怎么答）+ 别说什么。

## 两件套

| 文件 | 回答什么 | 篇幅 |
|---|---|---|
| `OUTLINE.md` | **在做什么 / 为什么这样做（功能设计）/ 章节大纲 / 不做什么 / 面试怎么讲** | 2400–3400 字 |
| `NOTES.md` | **分章详细**：每章「要解决的问题 / 机制 / 最小例子 / 面试高频问法」 | 1–3 万字 |
| `OUTLINE.bi.md` | `OUTLINE.md` 的英文版（可选，成对出现） | 同上 |

**已废除**：`QUICK.md`（一小时上手）、`DESIGN.md`（第三代文件，内容已并入 OUTLINE §二）。
旧文件归档在 `../.gen/archive/`，不要再生。

## 共同约定

1. **不写代码仓状态**：不写「我实现到第几章」「commit 到哪」，一个字都不许出现。
2. **`OUTLINE.md` 五段固定**，第五节必须是 `## 五、面试怎么讲`。
3. **`NOTES.md` 不重写教程**：每章四段（要解决的问题 / 机制 / 最小例子 / 面试高频问法）。
4. **不编造数字**：没有实测就写「用什么口径测、测出什么量级」。
5. **不写排期**。
