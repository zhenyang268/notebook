## 三件套结构（2026-11-01 起）

每个项目一个目录，固定三个文件，**读的顺序就是它们的顺序**：

| 文件 | 回答什么 | 什么时候读 | 篇幅 |
|---|---|---|---|
| `OUTLINE.md` | **项目大纲**：目标、里程碑、验收标准、时间预算与取舍 | 决定"要不要做、做多少" | 40–80 行 |
| `QUICK.md` | **一小时上手**：最小可跑路径 + 三个核心难点 + 卡住怎么办 | 开始动手的第一小时 | 50–100 行 |
| `NOTES.md` | **详细记录**：完整实验过程、代码、踩坑 | 做的时候查、做完了复盘 | 200–2000 行 |

**判据**：`OUTLINE` 读完要能决定做不做；`QUICK` 读完要能开始敲；`NOTES` 是仓库不是教程。

## 共同约定

1. **`OUTLINE.md` 必须有「时间预算与取舍」一节**，明确写"最小闭环是哪几个里程碑"。没有取舍的大纲等于没有大纲。
2. **`QUICK.md` 必须有「一小时做什么」+「卡住怎么办」两节**。前者给行动，后者给排障。
3. **`NOTES.md` 不重写教程**，只记"我做了什么、卡在哪、怎么解决的、实测数字"。
4. **不写排期**（"第几周做"不算项目内容）。
