# projects/ — 工程线（**服务面试**）

**唯一位置**：2026-11-02 起，所有项目都在这里，`kaoyan/projects/` 已并入。
工程线与考试线物理分开：`kaoyan/` 只管考纲内的东西，`projects/` 只管「面试能讲什么」。

## 一句话定位

> 这一层不是教程，是**面试弹药库**：每个项目都要能回答「你做了什么、难在哪、怎么解决的、怎么验证」。

所以每份文档的第五节都是固定的 `## 五、面试怎么讲`：30 秒版本 + 6–8 个追问点（问法 → 考点 → 我怎么答）+ 别说什么。

## 两件套

| 文件 | 回答什么 | 篇幅 |
|---|---|---|
| `OUTLINE.md` | **在做什么 / 为什么这样做（功能设计）/ 章节大纲 / 不做什么 / 面试怎么讲** | 2400–3400 字（方法论类 2600–3400） |
| `NOTES.md` | **分章详细**：每章「要解决的问题 / 机制 / 最小例子 / 面试高频问法」 | 1–3 万字 |
| `OUTLINE.bi.md` | `OUTLINE.md` 的英文版（可选，成对出现） | 同上 |

**已废除**：`QUICK.md`（一小时上手）、`DESIGN.md`（第三代文件，内容已并入 OUTLINE §二）。
旧文件归档在 `../.gen/archive/`，不要再生。

## 二、能力方法论（7 个）

这七个不是课程作业，是**面试能力的骨架**：把一项能力拆成可练、可考、可答的章。

| 目录 | 一句话 | 章 | 面试主打 |
|---|---|---|---|
| `perf-engineering/` | 从 benchmark 到火焰图的完整性能方法论 | 8 | 指标口径、benchmark 自欺、on/off-CPU 火焰图、Amdahl |
| `testing/` | UT→集成→契约→冒烟→CI 门禁 | 9 | 测试金字塔、替身取舍、覆盖率骗局、flaky 治理 |
| `database/` | 索引、事务、MVCC、日志恢复 + **一致性四层串讲** | 12 | B+ 树分裂、隔离级别、版本链、四层可见性对照 |
| `debug-toolchain/` | 从 core dump 到 TSan 的定位链路 | 8 | ASan 原理、TSan 报告读法、strace、最小复现 |
| `system-design/` | 量级估算 → 缓存 → 限流 → MQ → 分库分表 → 秒杀 | 8 | 容量估算、缓存三坑、超卖与削峰、熔断隔离 |
| `latent-issues/` | 平常碰不到、面试专挑的工程陷阱 | 12 | **惊群**、伪共享、ABA、优先级反转、队头阻塞、TIME_WAIT、fd 耗尽、Nagle 与延迟 ACK、EINTR |
| `algorithm-interview/` | 按题型的算法题库（8 类题型 × 8–10 题） | 8 | 题型识别、关键一步、边界与常见错法 |

**`latent-issues` 是什么**：惊群效应、伪共享、ABA、优先级反转、活锁、队头阻塞、TIME_WAIT 耗尽、
fd 耗尽、内存碎片、Nagle 与延迟 ACK 打架、EINTR 与 fork 后的锁状态——这些不写业务代码就遇不到，
但面试官问「你遇到过最难的 bug」时，答得出这些的人立刻和背八股的分开。

## 共同约定

1. **不写代码仓状态**：不写「我实现到第几章」「commit 到哪」，一个字都不许出现。
2. **`OUTLINE.md` 五段固定**，第五节必须是 `## 五、面试怎么讲`。
3. **`NOTES.md` 不重写教程**：每章四段（要解决的问题 / 机制 / 最小例子 / 面试高频问法）。
4. **不编造数字**：没有实测就写「用什么口径测、测出什么量级」。
5. **不写排期**。
