> 这份文件是**编排**，不是教材：它规定「先读哪一章、再动手哪一步、用什么判据收尾」。

## 1 四条线的公共词汇（口径统一）

| 词 | 在 `asm-link-arch` 里 | 在 `cpu-microarchitecture` 里 | 在 `riscv-core` 里 | 在 `compiler` 里 |
|---|---|---|---|---|
| ISA | 指令编码、寻址方式、调用约定的寄存器分工 | **契约**：可见状态怎么变，不承诺周期数 | RV32I 的 40 条指令与五种立即数格式 | 目标 triple、可用指令集特性 |
| ABI | 参数/返回值寄存器、栈对齐、callee-save 边界 | 与流水线无关，但决定 `sret` 类操作的访存形态 | 决定你自己核的调用约定（教学核可自定义，但要写清） | 后端 lowering 与 `sret/byval` 属性 |
| 关键路径 | 不涉及 | 决定主频上限的那条组合逻辑链 | STA 报出来的起点→终点路径 | 指令选择的延迟模型（`llvm-mca`） |
| CPI / IPC | 不涉及 | 主指标，必须与 miss 指标一起看 | 结构改动后的实测值 | 指令数一端的贡献（向量化、展开） |
| 内存层次 | 段/节在文件里的布局 | AMAT、VIPT、MSHR、TLB 覆盖范围 | 你实现的 I/D cache 的位划分与策略 | 分块、预取提示、向量化后的访存形态 |
| 抽象层次 | 源码 → 汇编 → 目标文件 → 装载 | ISA → 微架构 | RTL → 网表 → 布局（到综合为止） | 高层 IR → 低层 IR → 机器码 |
| 判据形态 | 一条命令 + 一段输出 | 一条「观察到 X 则我错」的断言 | difftest 零分歧 + STA slack | pass 是否触发 + IR diff + 运行时指标 |

**一条跨线铁律**：任何性能结论都要能落到「指令数 × CPI × 周期时间」这三项的哪一项上。落不上去的结论，说明你还没归因。

## 3 60 分版：逐项清单

目标：**被追问三层仍站得住**。四项，按顺序做，不要跳。

### 3.1 读 `asm-link-arch` 第 4/5/6/10 章

**产出**：一个你自己写的最小 C 程序，`-O2` 编译后能讲清每个函数的序言、参数落在哪几个寄存器、栈为什么减了那个数。

```bash
cc -O2 -S -o - t.c | head -40      # 看序言与寄存器
cc -O2 -o t t.c && objdump -d t | sed -n '/<main>:/,+25p'
readelf -sW t | grep -i main       # 符号表：binding/type/section
```

**判据**：能回答「这个函数为什么没有 `sub rsp`」（叶函数 + 红区）、「第 7 个整数参数在哪」（栈上，从右往左压）。

### 3.2 读 `cpu-microarchitecture` 第 1–4 章 + 第 9 章

**产出**：一页纸的因果链——ISA 与实现的分离 → 单周期浪费 → 五级流水线 → 三类冒险 → 预测与冲刷 → 归因。

**判据**：8 分钟不看稿讲完；每个结论后面能补一句判据（"如果 `perf` 显示 front-end bound 占比高，则我的结论错"）。

### 3.3 做 `riscv-core` S0–S3

**产出**：一个能跑通 riscv-tests 的五级流水线核，带转发与 load-use 停顿。

**判据**：`rv32ui-p-*` 全过；`lw` + `add` 数出 1 拍停顿；分支冲刷后寄存器状态与顺序模型一致。

### 3.4 读 `compiler` 第 3/5 章 + OUTLINE 全文

**产出**：能读懂一段 `-O2` 的 IR，指出循环、phi、`sret`。

```bash
clang -O2 -S -emit-llvm -o - t.c | sed -n '/define/,/^}/p' | head -30
```

**判据**：能答「`-O0` 的 IR 为什么全是 `alloca`」「`getelementptr` 为什么不访存」。

## 4 80 分版：60 分之上的增量

目标：**手里有能展示的东西**。三样：一张四数表、一条曲线、一份 STA 报告。

### 4.1 读 `cpu-microarchitecture` 第 5–8、10 章

**产出**：能把「ROB 满 vs 保留站满」「保守消歧 vs 投机消歧」「VIPT 与别名」三组对比各讲 90 秒。

**判据**：每组都能给出「在什么观测结果下我的判断会错」。

### 4.2 做 `riscv-core` S4–S8

**产出**：IBHT/BTB → I/D cache → difftest → 乱序 → LSQ。

**判据（缺一不可）**：

- 与 Spike 逐提交零分歧（S6）；
- 人为注入的故障被抓到（S6）；
- 扫 `ROB_DEPTH` 得到 IPC 饱和曲线（S7）；
- `memcpy`/链表/随机访存三个 microbench 的 IPC 变化可归因（S8）。

### 4.3 做 `riscv-core` S9

**产出**：Yosys 综合 + OpenSTA 在 sky130 上的一条关键路径 + 一次取舍实验。

**判据**：四数表填满；能指出「当前 fmax 卡在哪一级的哪条路径」；改完之后四个数都变，且净收益有结论。

### 4.4 读 `asm-link-arch` 第 7/8/9 章

**产出**：解释一次真实的动态绑定与一次 PIE 下的地址计算。

**判据**：能用 `LD_DEBUG=bindings` 的输出对上 PLT/GOT 的解析流程。

### 4.5 读 `compiler` 第 6/7/9/11 章

**产出**：能判「这段循环为什么没被向量化」；能说清 Triton/TVM/XLA 的分层差异与选型判据。

**判据**：能画出「高层表示 → 中层 dialect/IR → GPU 后端」这条下降链，并指出每一层的典型变换（融合、tiling、线程映射、流水线化）。

## 5 常见误配

| 误配 | 后果 | 正确做法 |
|---|---|---|
| 先做乱序，顺序流水线还没干净 | bug 无法归因，改了也不确定对不对 | 先 S1–S3，用 difftest 立基线 |
| 只读 `cpu-microarchitecture` 不动手 | 讲得出结构，一问「你测过吗」就退 | 至少做到 S3，最好到 S6 |
| 先装整套 PDK 再写代码 | 工具链成了项目本身 | S0 只装 Verilator + GCC + Spike；PDK 留到 S9 |
| 把 `compiler` 当主线深挖 | 与目标岗位错配（除非投编译器岗） | 60 分只读 IR/SSA；80 分再加管线与 GPU 一章 |
| 把 `asm-link-arch` 当纯基础课跳过 | 读核时看不懂反汇编，无法验证编译器生成了什么 | 第 4/5/6 章必须在造核之前 |
| 用 `IPC 提升` 单独报收益 | 违反「指令数 × CPI」的分项前提 | 四项一起报：IPC、指令数、面积、fmax |
| 把 Triton/TVM 当"会用就行" | 被问分层与代价就露馅 | 记住一句话：它们在替你决定线程映射与调度，代价是控制力 |

## 6 跨线追问（单份文档答不完整的）

1. **「你这个 pass 让循环快了，那在流水线上发生了什么？」** → 要同时有 IR 侧（指令数、访存形态）与体系结构侧（IPC、miss）的证据。答法：先给指令数变化，再给 IPC/MPKI 变化，最后说清值来自哪一层。
2. **「你的核 IPC 高，是不是因为 ABI 简单？」** → ABI 影响的是 spill/reload 与参数搬运，进而影响访存压力。答法：把 ABI 选择当成结构参数讲——寄存器传参多，spill 少，但寄存器堆端口压力大。
3. **「为什么 XLA 能做整图融合，LLVM 做不了？」** → 层次不同：XLA 在**图**层（算子级），LLVM 在**指令**层；融合是把多个算子合成一个 kernel，属于调度空间的操作，指令层没有这个自由度。
4. **「Triton 的 `num_stages` 在编译器里对应什么？」** → 软件流水线（software pipelining）：把循环不同迭代的 load 提前，用多级 staging 隐藏显存延迟。在 RTL 世界里这叫"流水级间提前取数"，是同一种权衡。
5. **「你说 cache 友好，具体到哪一层？」** → 必须落到 AMAT 三项之一（命中时间/缺失率/缺失代价）或具体结构（组相联、MSHR、预取器）；说"局部性好"不算答案。
6. **「你这些数字怎么复现？」** → 每条给命令：`perf stat` 事件名、riscv-tests 用例名、Yosys/OpenSTA 的脚本与 liberty、`opt -print-changed` 的 pass 名。

## 7 一句话收口

**60 分靠"讲得清 + 动手过一次"，80 分靠"有数字 + 能取舍"。** 四条线的顺序不是并列的：读得懂（`asm-link-arch`）→ 说得清（`cpu-microarchitecture`）→ 做得出来（`riscv-core`）→ 编得动（`compiler`），而最后一条会反过来改变你对前三条的判断——因为它决定"进来的是什么指令"。
