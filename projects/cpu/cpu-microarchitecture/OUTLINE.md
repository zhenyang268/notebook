> 本文只做**读核与归因**：把「慢」定位到某一层、某一结构。
> **造核**（RTL、difftest、综合与时序）不在这里，见 `riscv-core/`；两个方向共享词汇，但不互相复制正文。

## 一、它解决什么问题

它解决的首先是两类问题：**性能归因错误**，以及**只会背名词、不能推演**。

场景一：一个数据规模在 $10^8$ 量级的遍历和聚合内核，计算逻辑没动，只把指针跳转改成连续数组访问、把数据相关分支改成无分支选择，端到端耗时从秒级的高位掉到秒级的低位，差出两三倍很常见。如果只会说“cache 友好”，就答不出这两三倍具体差在哪一层：是 L1 命中率、分支误预测，还是 TLB 缺页。有微架构口径的人先看每千条指令的 miss 数、误预测率、IPC 变化，再决定改哪里。

场景二：面试里的“这段循环为什么没被向量化”“为什么 8 核只跑出 2 核的吞吐”“为什么加了 `-O3` 反而慢”。这类问题共同要求把 ISA 层看得见的东西（指令条数、浮点宽度、访存顺序）和实现层的约束（发射宽度、乱序窗口、load/store 队列深度、带宽）分开谈。答不出来的人通常是给出一个 IPC 就结束了，或者把“慢”归给“这颗 CPU 不行”。

数量级的感觉必须有：L1 命中几个周期，L2 十几到二十几个周期，DRAM 上百周期；一次分支误预测在深流水核上是十几个到二十几个周期的量级。具体数字按实现而定，但**数量级之间的比例关系**决定了优化该落在哪一层——这正是这门能力唯一能给出的东西：把“慢”定位到某一级、某一个结构。

**入口（本文的读法）**：在 `CPUID` 暴露的 ISA 扩展、`CR0/CR4` 控制位、`PTE/TLB` 映射与 `MESI` 状态不变的前提下，把流水线、分支预测、`SIMD`、缓存、TLB、一致性与 DRAM 的耗时差异，读成 `perf_event_open` 的 `instructions`/`cycles`/`cache-misses`/`branch-misses`/`TLB-misses`/`stalled-cycles-backend`。这些计数器分别对应 `ROB/RS/LSU/IQ` 深度、`BTB/BHT` 误预测、`SIMD` 端口、`LSQ` 满、cache line 迁移与 DRAM row-buffer 冲突——定位就是把 `cycles` 归到其中一条。
换的是把源码改写直接映射到 `BTB/BHT` 误预测、`ROB` 回收、`LSQ` 满、`SIMD` 端口、cache line 迁移和 `DRAM row-buffer` 冲突的归因链。

**不换的是什么**：全程不变的是 ISA 指令语义、`RFLAGS` 条件码、`CR3/PTE` 页表结构、`MESI` cache-line 状态、`lock cmpxchg` 的原子语义和 `syscall/sysret` 边界，所以看到耗时差异时先问 `perf_event_open` 的 `instructions` 与 `cycles` 是否同比例变化、`cache-misses`/`branch-misses`/`TLB-misses`/`stalled-cycles-backend` 是否同向变化，再问 ROB/RS/LSU 是否出现 `load/store queue full`、`memory order buffer full`、`prefetcher miss` 或 `DRAM bank/row-buffer conflict`。

## 二、为什么这样做（方法论设计）

四个取舍：

**（1）有口径才算数 vs 看起来专业但无法证伪。** 有口径的表述是：“`perf stat` 里 `cycles` 与 `instructions` 的比值下降，同时 `cache-misses` 与 `branch-misses` 的每千指令数上升，所以瓶颈从后端算力转到了访存。” 无法证伪的表述是：“这个核乱序窗口大，所以快”“加个预取就好了”“超标量嘛，肯定并行”。前者的判据能被别人复现和反驳，后者只能靠语气。分界线是：**能不能写出一条“如果观察到 X，则我的结论就错”的判据**。

**（2）指标怎么定。** 主指标只留三个：$IPC = instructions/cycles$（以及它的倒数 $CPI$）、每千条指令的 miss 数（cache、TLB、分支误预测各自一套，即 MPKI 口径）、以及实测带宽与实测算力。辅助公式只用两条：平均访存时间 $AMAT = t_{hit} + m \times t_{miss}$，和 roofline 的 $P = \min(\pi \cdot I,\ \beta)$，其中 $I$ 是算术强度（FLOP/Byte）、$\pi$ 是峰值算力、$\beta$ 是可持续带宽。所有结论最终要能落到“$I$ 在平衡点的哪一侧”。

**（3）边界怎么划。** 只在稳态、单线程为主、热数据可复现的条件下讨论。冷启动、I/O 与锁竞争主导、以及被测程序本身方差大于优化幅度的情况，一律先排除再谈微架构。

**（4）这套方法什么时候失效。** 一是测量本身有代价：PMU 事件数超过硬件计数器个数时会被多路复用，得到的是按比例缩放的估计值，短程序上不可信；二是程序运行时间太短，流水线填充、cache 预热、页表冷启动占主导；三是编译器已经吃掉了手写优化的空间，你测到的差异来自内联和重排而不是微架构；四是在真实多租户环境里，SMT 邻居和内存带宽争用让单线程口径失效。

**常见错误做法及其代价。** 只看 IPC 不看指令数——向量化或展开后指令数暴涨，IPC 掉了但程序更快，按 IPC 归因会得出反向结论。只盯 cache miss 不看 TLB——大页没开时，四级页表遍历的开销可以记在一个完全不相干的指标上，改了半天循环分块没效果。盲目展开循环——I-cache 与 ROB 压力上升，前端受限反而更重。单次 `wall clock` 计时、无重复无方差——把噪声当成收益，后续所有推理都建在假的基线上。

整套大纲的组织原则是**因果链**：每一章只回答“上一章留下的那个瓶颈，用什么结构解决，又引入了什么新瓶颈”。这样学完不是一个名词表，而是一条能从“顺序语义”推到“现代乱序多核”的路。

## 三、章节大纲

**从指令集到微架构：ISA 与实现的分离**——讲清哪些是指令集契约（可见的架构寄存器、内存模型、异常精度），哪些是实现的自由度（流水深度、发射宽度、缓冲大小）。它解决的是“把性能绑死在某一代实现上”的问题，为后面所有章节划定“哪些能改、哪些不能改”。能回答：同一条指令序列为什么可以在不同微架构上跑出数量级不同的时间，而结果必须一致？

**五级流水线：取指、译码、执行、访存、写回**——讲每一级的职责、级间寄存器、以及“每级延迟要拉平”这个硬约束。它解决上一章留下的问题：ISA 语义是顺序的，但逐条串行执行的 CPI 上限被最慢一级的关键路径钉死，流水化把吞吐从 $1/t_{inst}$ 提到约 $1/t_{stage}$。能回答：为什么流水级数越深频率越高，但单条指令延迟并没有变短？

**流水线冒险：结构冒险、数据冒险、控制冒险，转发与停顿**——讲三类冒险的判定条件、转发路径能救哪些、哪些必须停。它解决上一章新引入的瓶颈：重叠执行让相邻指令互相踩资源、踩寄存器、踩取指流，$CPI = 1 + \text{每指令停顿拍数}$ 里的加数就是它。能回答：load 后面紧跟一条用它的指令，为什么通常无法靠转发完全消除停顿？

**分支预测：静态与动态、BTB、TAGE、误预测的代价**——讲 BTB 提供目标、方向预测器提供走向，两级自适应到 TAGE 的演进（多长度全局历史 + 带偏置的选择逻辑）。它解决上一章的控制冒险：不预测就只能等分支解析，取指带宽被浪费。能回答：误预测的代价为什么约等于“流水深度 × 前端重填宽度”，以及 TAGE 在什么模式的分支上反而会输？

**乱序执行：重排序缓冲、保留站、寄存器重命名**——讲重命名消除 WAW/WAR 假依赖、保留站在操作数就绪时唤醒、ROB 保证顺序提交与精确异常。它解决上一章之后仍存在的瓶颈：转发再强也救不了长延迟操作（miss 的 load、除法），顺序流水线只能原地等待，而乱序允许后续无关指令填满这些空拍。能回答：ROB 满了和保留站满了，表现出的停顿有什么不同？

**乱序访存：load/store 队列、内存消歧、store-to-load forwarding**——讲访存为什么不能像算术那样自由重排、消歧的保守与激进两端、以及转发失败的情形（部分重叠、跨对齐边界）。它解决上一章的瓶颈：如果访存严格按序，乱序窗口会被队头的 load/store 卡住，前面所有的重命名收益都被吞掉。能回答：一次“假依赖”是怎么让两条毫不相干的访存串行化的？

**超标量与 SMT：发射宽度、超标量的极限、超线程共享了什么**——讲发射宽度受限于取指带宽、寄存器堆端口、功能单元数量与 ROB 出队宽度，以及 SMT 共享执行单元、L1、BTB，私有架构寄存器与重命名空间。它解决上一章的瓶颈：单条指令流的指令级并行有限，窗口再大也找不到独立指令可发。能回答：超线程在什么负载上有收益、在什么负载上只增加争用？

**存储层次与 TLB：多级 cache、预取、页表遍历的隐藏开销**——讲多级 cache 的包含/非包含关系、预取器的触发与副作用、TLB 覆盖范围 $= \text{条目数} \times \text{页大小}$ 与页表遍历的串行延迟。它解决上一章的瓶颈：发射宽度上去了，但取指和数据供给跟不上，宽发射变成空转。能回答：为什么开大页有时比改循环分块更有效，以及预取在什么访问模式下会污染 cache？

**性能计数器与 roofline：怎么判断是算力受限还是带宽受限**——讲 `perf stat`/`perf record` 的基本事件、Top-down 的四分类（retiring、bad speculation、front-end bound、back-end bound）、以及 roofline 的平衡点判读。它解决上一章的瓶颈：知道了有哪些层次，但没有测量就没法归因，优化变成试错。能回答：给你一段慢代码，你在十分钟内怎么定出瓶颈类别？

**现代核的横向对照：大小核、向量单元、多发射与能效**——讲公开可验证的结构差异：大核宽而深、小核窄而浅、向量单元宽度与频率-电压曲线的取舍。它解决上一章的瓶颈：单核指标不能跨核直接比较，同一个瓶颈在不同功耗与面积约束下的解法不同。能回答：同功耗下比较两颗核，应该看哪几个量，为什么不能只比单核 IPC？

## 四、不做什么 · 必要性 · 失效点

### 必要性：删掉会怎样

| 机制 | 删掉会怎样 | 判定 |
|---|---|---|
| `perf stat` 的 `cycles` 与 `instructions` 比值 | “瓶颈从后端算力转到访存”的承诺破：只剩“乱序窗口大所以快”“超标量肯定并行”这类不可证伪语气。 | 必需 |
| MPKI 口径（`cache-misses`、`TLB`、`branch-misses`） | 把 L1 命中率、分支误预测、TLB 缺页混成一个“cache 友好”，优化落点会错层。 | 必需 |
| `AMAT = t_hit + m × t_miss` | L2 十几到二十几个周期与 DRAM 上百周期无法折算成周期代价，无法判断 miss 是否主导端到端耗时。 | 必需 |
| roofline `P = min(π·I, β)` | 无法判断算术强度 `I` 在平衡点哪一侧，会把 `load/store` 队列饱和或 `β` 受限误判成算力不足。 | 必需 |
| 大页 | 四级页表遍历开销可被记到不相干指标上，“改循环分块有效”的承诺破；但保留大页会引入 `madvise(MADV_HUGEPAGE)`、页表更新与内存碎片代价，属选择。 | 选择 |

### 失效点：哪条前提一破，结论就变

- 被测线程数=1、工作集已热且 `perf stat` 重复计数方差小于优化幅度 → 冷启动或高方差时，`TLB` 缺页、`I-cache` 填充与页表遍历占主导，`MPKI` 与 `IPC` 不再指示稳态后端瓶颈。
- PMU 事件数 ≤ 硬件计数器个数 → 多路复用使 `cache-misses`、`branch-misses` 成为按比例缩放估计，短程序上的 `AMAT` 与 `roofline` 平衡点判断失效。
- SMT=关闭或邻居负载=0、介质=本地 DRAM → 8 核吞吐可能受内存控制器队列饱和、L3 slice 争用或 `load/store` 队列深度限制，单线程 `β` 口径失效。
- 时钟源=TSC invariant 且 `RDTSC` 可用 → DVFS、虚拟化时钟源或 `RDTSC` 禁用使 `cycles/instructions` 与 `wall clock` 不可比，`IPC` 下降可能来自时钟源而非微架构。
- 权限位/系统调用=`madvise(MADV_HUGEPAGE)` 成功且页表层级=4-level → 5-level paging、禁用 `transparent_hugepage_enabled` 或 `MADV_HUGEPAGE` 失败时，`TLB` 覆盖与页表遍历开销改变，循环分块收益需重算。

### 不做什么（范围）

不写 408 考点式的计算题：流水线加速比公式、cache 组相联的地址位划分手算，只在必要处引用定义，不作为主线。不写 RTL 与门级时序：不展开 Verilog 实现、工艺角、时钟树，这些属于数字设计层。想看 RTL 怎么写、怎么用 difftest 证明正确、怎么在开源 PDK 上出关键路径与面积，去 `riscv-core/`——那里才是「造核」；这里只保证你在看到一份 STA 报告或一份 Top-down 分解时，知道它在说什么。不给未公开的微架构参数：某代产品的 ROB 项数、保留站大小、各操作的精确延迟与 miss 惩罚周期，一律写“按实现而定”，只讲公开可验证的结构。不写编译器后端的完整调优流程（自动向量化报告怎么读、循环变换全流程），那属于编译器层，这里只到“为什么这段没被向量化”的判断为止。不写 OS 调度、虚拟化与大页策略的完整设计，只在 TLB 章节讲清开销来源。不写 GPU/SIMT 微架构，仅在 roofline 对照时提一句。不写具体业务系统的调优复盘，本文只负责骨架，不负责案例。

## 五、面试怎么讲

**30 秒版本（约 170 字）**

我能把“这段代码为什么慢”拆成可测量的归因：先用 `perf` 看 IPC、每千条指令的 cache/TLB miss 与分支误预测率，把问题归到前端受限、错误投机、后端算力或访存受限中的一类；再用 roofline 判断是算力还是带宽顶到了天花板。解释时能落到具体结构——转发与停顿、BTB/TAGE 的误预测代价、ROB 与保留站决定的乱序窗口、load/store 队列与内存消歧、发射宽度与 SMT 共享的资源、多级 cache 与页表遍历的开销。结论都以计数器口径给出，不用“这个核比较宽”这类说法。

**可能被追问的 8 个点**

1. **问法**：“五级流水线里 load 后面紧跟用它的指令，要停几拍？”→ **考点**：数据冒险与转发路径是否存在。→ **答法**：先给判据——若存在 MEM→EX 转发，load 的数据在 MEM 末尾才可用，所以至少 1 拍；无转发路径则退化为 2 拍。明确说“按实现而定”，只给结构推理，不报绝对周期数。
2. **问法**：“TAGE 比两级自适应好在哪里？”→ **考点**：是否理解预测器的历史长度问题。→ **答法**：TAGE 用多条不同长度的全局历史分别预测，再由带偏置的选择逻辑挑一个；长历史覆盖相关分支，短历史兜住噪声，因此对难以预测的模式更稳。判据看每千指令误预测数（MPKI）与误预测率，不看“准不准”的形容词。
3. **问法**：“寄存器重命名到底解决了什么？”→ **考点**：真假依赖之分。→ **答法**：消除 WAW/WAR 假依赖，把架构寄存器映射到物理寄存器堆；真依赖 RAW 仍要靠保留站唤醒。顺序提交由 ROB 保证，这样才能在乱序执行下仍保持精确异常。
4. **问法**：“ROB 满了会怎么样？”→ **考点**：会不会区分停顿位置。→ **答法**：前端停止派遣，执行单元可能空闲；在 Top-down 里表现为后端资源受限而非算力受限。判据是 `cycles` 上升但功能单元利用率不升。
5. **问法**：“load 能不能越过前面的 store？”→ **考点**：内存消歧的保守性。→ **答法**：地址未知时必须保守，可能产生假依赖导致串行化；现代核用地址预测器加投机执行，猜错就回滚重放。转发失败常见于部分重叠和跨对齐边界。
6. **问法**：“超线程共享了什么？”→ **考点**：哪些是私有、哪些是共享。→ **答法**：私有架构寄存器与重命名空间，共享执行单元、L1、BTB、L2 与带宽。是否有收益看 IPC 提升幅度与 cache 争用指标，不预设结论。
7. **问法**：“怎么用 roofline 判断瓶颈？”→ **考点**：算术强度与平衡点。→ **答法**：算 $I = \text{FLOP}/\text{Byte}$，与机器平衡点 $\pi/\beta$ 比较；$I$ 小于平衡点落在斜线上就是带宽受限。判据是实测吞吐是否贴着那条斜线，工具用 `perf` 的带宽事件或 likwid 一类，具体事件名按平台而定。
8. **问法**：“大核和小核怎么公平比较？”→ **考点**：约束不同不能只比 IPC。→ **答法**：取等功耗或等面积区间，同时看单线程 IPC、频率-电压曲线与能效；只比单核 IPC 会把功耗预算当成免费的。

**别说什么**

- 别说“这颗核的 ROB 有 XX 项 / miss 惩罚是 XX 周期”——未公开参数说出口就露馅，正确说法是“按实现而定，但量级关系是这样”。
- 别说“加个预取就好了”“开个 `-O3` 就快了”——没有 miss 率、带宽、指令数证据的因果断言，追问一句就站不住。
- 别说“IPC 高所以更快”——不区分指令数和工作量，向量化之后这句话会直接反例。
