# 自己实现一个小而全的编译器

> 这份文件回答一个问题：从零到「能编译一个真语言子集、产出可执行文件」，按什么顺序做、每一步的判据是什么。
> LLVM 走的是「复用成熟后端」，这里走的是「自己造一遍」，两条路的目的不同：前者学工程，后者学原理。

## 词法分析

**要做的事**：把字符流切成 token 流，每个 token 至少含 `(kind, lexeme, literal, span)`。手写的核心是一个「跳过 trivia → 取最长匹配」的循环；生成器路线是把每条 token 的正则编译成 NFA 再确定化为 DFA。关键字不单独建规则，先按标识符规则扫完整个 word 再查关键字表。span 从第一天就要维护行列号，否则后面所有报错都定位不准。

**最小可跑判据**：喂一段含数字、字符串、注释、多字符运算符的源码，能打印 `(kind, lexeme, line:col)` 序列，且 token 数量与手工清点一致；对「未闭合字符串、非法字符、`1abc` 这类坏字面量」三种输入，能报出准确位置而不是崩溃或死循环。

**最常见的坑**：用逐条正则「先匹配到的赢」而不是最长匹配，`>=` 被切成 `>` `=`；回溯式实现导致退化成 $O(n^2)$；先把 `if` 当关键字匹配，`ifx` 被切成 `if` `x`；字符串扫描里同时处理转义和行号计数，行号在续行处错位。

```rust
fn next_token(&mut self) -> Token {
    self.skip_trivia();                  // 空白 + // 与 /* */，同时推进 line/col
    let start = self.pos();
    let Some(c) = self.bump() else { return Token::new(EOF, start) };
    match c {
        c if c.is_ascii_digit() => self.number(start),
        c if is_ident_start(c) => self.ident(start),   // 扫完整个 word 再查关键字表
        '"' => self.string(start),
        _ => self.operator(start),        // 先试三字符、再两字符、最后一字符
    }
}
```

## 语法分析

**要做的事**：把 token 流变成 AST。三条路线各有适用面：递归下降（每个非终结符一个函数，手写编译器里语句层最常用）、Pratt / 运算符优先级（只负责表达式，按 binding power 循环，天然处理优先级和结合性）、生成器（给文法让工具生成表驱动分析器，省事但错误恢复和位置信息往往要额外接）。常见组合是「语句用递归下降 + 表达式用 Pratt」。

**最小可跑判据**：`1 + 2 * 3 - 4 / 2` 解析出的树形正确（`-` 左结合、`*` 比 `+` 紧）；能解析 `if / while / 函数定义 / 调用 / 赋值`；遇到缺右括号这类错误能给出「期望 X、得到 Y、在 line:col」，并靠 panic-mode 跳到 `;` 或 `}` 继续，一次编译报出多个语法错。

**最常见的坑**：把左递归文法直译成递归函数（`expr := expr '+' term`）导致栈溢出，必须先改写成循环 + 后缀；一元负号和二元的优先级混在一起，`-a*b` 和 `a*-b` 树形错；`a - b - c` 解析成右结合；没有错误恢复，第一个错就 panic，用户每次只能看到一个错。

```rust
fn parse_bp(&mut self, min_bp: u8) -> Expr {
    let mut lhs = self.parse_prefix();          // 字面量 / 标识符 / '(' expr ')' / 一元运算
    loop {
        let op = self.peek_op();
        let (l_bp, r_bp) = binding_power(op);   // 左结合 (l, l+1)；右结合 (l, l-1)
        if l_bp < min_bp { break; }
        self.bump();
        let rhs = self.parse_bp(r_bp);
        lhs = Expr::Binary { op, lhs: Box::new(lhs), rhs: Box::new(rhs) };
    }
    lhs
}
```

## AST 设计

**要做的事**：定节点类型。两个决策点：语句与表达式是否统一成一个 `Expr`（统一了后面 lowering 简单，分离了类型检查清晰）；节点用和类型（enum）还是继承/接口。每个节点必须带 `Span`（起止，不只是起点），并建议统一包一层 `Node<T> { id, span, kind }`——`id` 在符号表、类型表、错误信息里当键用，没有它后面所有分析都要靠指针地址做键。AST 保持纯数据，遍历用模式匹配或 visitor，语义信息不往节点里塞。

**最小可跑判据**：写一个 printer 把 AST 打回近似原文（或 sexp 形式），对 5 个样例「parse → print → 再 parse」，两次 AST 结构相同；再写一个 span 校验，断言每个节点的 span 包含所有子节点的 span。

**最常见的坑**：到处裸用 `Box<Expr>`，等想加类型标注/唯一 id 时无处可放，只能大改；把词法 token 直接挂在 AST 节点上（改写后就失效）；span 只存起始 offset，报错时画不出下划线；一开始就照搬某个后端 IR 的形状设计 AST，前端写起来别扭且丢信息。

```rust
struct Node<T> { id: NodeId, span: Span, kind: T }

enum Expr {
    Int(i64), Var(Symbol),
    Unary(UnOp, Box<Expr>),
    Binary(BinOp, Box<Expr>, Box<Expr>),
    Call(Box<Expr>, Vec<Expr>),
}
enum Stmt {
    Expr(Expr), Let(Symbol, Option<Expr>),
    If(Expr, Block, Option<Block>), While(Expr, Block), Return(Option<Expr>),
}
```

## 语义分析

**要做的事**：名字解析 + 类型检查，顺带产出 lowering 要用的元信息（函数签名、变量是否可变、变量最终归属哪个作用域）。符号表用作用域栈：进 block push 一层 map，出 block 整层 pop；同名遮蔽靠栈序自然生效。函数体检查走两趟——先收集所有顶层声明建立签名，再检查函数体，这样互递归和前向引用不用特殊处理。类型检查对每个节点算一个类型，错误时返回一个「错误类型」占位。

**最小可跑判据**：能报出「未定义变量 / 同作用域重复定义 / 条件不是 bool / 调用参数个数或类型不匹配」，每条都带 span；一个含两层嵌套作用域、内层遮蔽外层同名变量、两个互递归函数的 20 行程序全部通过，并输出「每个标识符 use → 它绑定的声明」的映射，人工核对全部正确。

**最常见的坑**：单趟边解析边查，函数互递归直接报未定义；pop 时逐个删名字而不是整层丢弃，遮蔽关系恢复不回去；类型检查塞进 parser；错误类型不吸收，一个错引出一串连锁报错（要吸收，但错误计数保留）。

## IR 设计

**要做的事**：定指令集与基本块结构。三地址码的门槛是「每条指令至多一个算子、结果落进新的临时量」：`t1 = a + b`、`if t1 goto L1`、`call f, 2`、`return t1`。SSA 在此之上要求每个变量只被定义一次，控制流汇合处用 phi 显式选择来源：`$x_3 = \phi(x_1 \text{ from } B_1,\; x_2 \text{ from } B_2)$`。**为什么要有 phi**：`if c { x = 1 } else { x = 2 }` 之后 `x` 有两个定义，既要保持「单赋值」又要表达「汇合后 x 是哪一个」——phi 把「按控制流来源选择」变成一个显式指令，于是 def-use 链变成纯图结构，常量传播、死代码消除、寄存器分配都不必再做数据流交集。

**最小可跑判据**：指令集十几条就够，写一个 IR printer；手写一段含 if/while 的三地址码能打印成基本块列表；SSA 侧再写一个校验器：每个变量恰好一个定义点，且每个使用都被该定义支配（支配树用简单迭代算即可），对随机构造的几个 CFG 跑通。

**最常见的坑**：三地址码里直接嵌 AST 子树，等于没降；循环头的 phi 忘了回边那一路（循环变量必须有来自 backedge 的入参）；把 phi 当普通指令去调度或复制，忽略「phi 参数与前驱块按顺序一一对应」；临时量不做编号规范，printer 打出来根本看不出数据流。

## 从 AST 降到 IR

**要做的事**：每个 AST 节点一个 `lower_*` 函数，上下文里维护「当前基本块」和「临时量计数器」。表达式类返回一个 `Value`（常量或临时量）；语句类负责建块、连边、终结。控制流用 backpatch 回填跳转目标，`break/continue` 各维护一个待回填列表。短路求值 `&&`/`||` 必须降成控制流而不是算术。变量先统一 alloca + load/store，之后再做 mem2reg 提升成 SSA 值——比前端直接建 SSA 好写，因为循环处的 phi 交给提升阶段统一插。

**最小可跑判据**：一个含 `if/else`、`while`、函数调用、局部变量的 10 行程序能降到 IR 并打印；CFG 校验通过：每条边的两端块存在、每个块恰好一条终结指令、无不可达块（或明确列出）；用一个小解释器直接跑 IR，结果与手算一致。

**最常见的坑**：表达式里带副作用（赋值、调用）时求值顺序不固定，同一程序两次跑结果不同——必须写死「先左后右」；短路求值按算术降，`f() && g()` 里 `g()` 被无条件调用；`if` 没有 else 时不补空块，后面插 phi 时前驱数对不上；backpatch 列表漏了嵌套循环里的 `break`；离开作用域不清临时量映射，同名变量串味。

```rust
fn lower_expr(&mut self, e: &Expr) -> Value {
    match &e.kind {
        Expr::Int(n) => Value::Const(*n),
        Expr::Var(s) => self.emit_load(s),            // 当前实现：alloca + load
        Expr::Binary(op, l, r) => {
            let a = self.lower_expr(l);               // 先左后右，顺序固定
            let b = self.lower_expr(r);
            let t = self.new_temp();
            self.emit(Instr::Bin(*op, t, a, b));
            Value::Temp(t)
        }
        Expr::Call(f, args) => { /* 逐个 lower args，emit Call，返回新临时量 */ }
        _ => unreachable!(),
    }
}
```

## 里程碑

| 阶段 | 产出 | 判据 |
| --- | --- | --- |
| M0 骨架 | 驱动（读文件 → 各阶段 → 报错汇总）、span 类型、错误类型 | 空管线能跑通并打印一行统计，退出码正确 |
| M1 词法 | `Token` 定义 + 扫描器 + token dump | 样例 token 数与人工清点一致；3 类坏输入报出位置 |
| M2 表达式 | Pratt 解析器 | `1+2*3-4/2` 树形正确；缺右括号有恢复 |
| M3 语句与函数 | 递归下降语句层 + 函数定义/调用 | if/while/return/调用全部能解析成 AST |
| M4 AST 定型 | `Node<T>{id,span,kind}` + printer | parse→print→parse AST 相同；span 包含性校验通过 |
| M5 名字解析 | 作用域栈符号表 | 未定义/重复定义报错；use→decl 映射人工核对正确 |
| M6 类型检查 | 类型表 + 错误类型吸收 | bool 条件、参数匹配能报错；20 行样例零误报 |
| M7 IR 定义 | 指令集 + 基本块 + printer | 手写 IR 能打印成块列表 |
| M8 Lowering | `lower_*` + backpatch | 10 行程序降到 IR，CFG 边与终结指令校验通过 |

M1–M4 是「能看见」的阶段，每个都能独立交付；M5 之后每一步都依赖 AST 上的 `id` 与 `span`，所以 M4 不要图省事跳过。到 M9 为止，前端全链路闭环，后面接 SSA 构造、优化和后端才有稳定的输入。

## 后端流水线的整体形状

```text
AST → IR(虚拟寄存器) → [CFG + 支配树] → [常量折叠/传播/DCE] → 指令选择
    → 寄存器分配 → 栈帧布局 → 汇编文本 → as/cc → 可执行文件
```

顺序不是随意的：CFG 是所有数据流分析的地基，所以它在优化之前；指令选择假设虚拟寄存器无限多，寄存器分配才去处理物理寄存器的稀缺性；栈帧大小要等寄存器分配 spill 完才能定。可以跳过的是优化（第一版完全可以不做），不能跳过的是指令选择、栈帧、汇编输出。

## 常量折叠与死代码消除

**要做的事**：在基本块内做常量传播与折叠（`3*4+1` → `13`），再用「结果未被使用且无副作用」判定删掉整条指令；配合不可达块删除。关键是副作用判定要显式建模：可能 trap 的除法、可能抛异常的调用、volatile 读写都不算纯。

**最小可跑判据**：IR dump 里 `t1 = 3 * 4` 已经消失、直接出现常量 13；一个「赋值后从未被读」的局部变量在 IR 里查不到；且打开/关闭该 pass 时所有已有测试输出一致（语义不变是唯一验收标准）。

**最常见的坑**：用宿主语言的 `int` 直接算折叠，溢出行为和目标语言不一致（`INT_MIN / -1`、有符号左移、负数取模）；把 `x/0` 折成常量而不是保留 trap 语义；DCE 只统计「被赋值次数」而不是真正算活跃性，删掉循环里的值。

## 控制流图与支配树

**要做的事**：把 IR 切基本块（leader = 函数入口 / 跳转目标 / 跳转后一条），连 succ/pred 边；迭代求每个块的支配集合，再求直接支配者 idom 组成支配树。循环识别、SSA 构造、稀疏条件常量传播全都建在支配树上。

**最小可跑判据**：对一个带 `if/else` 与 `while` 的函数打印支配集合，`if` 汇合点的 dom 恰好是 `{entry}`，循环头 dom 循环体；不可达块能被标出来。

**最常见的坑**：只连显式跳转边，漏掉异常边和「不可返回调用」之后的块，支配关系整体错位；用块的下标顺序当拓扑序，逆后序迭代才能快速收敛；支配集合用 list 而不是 bitset，块一多就不可用。

## 寄存器分配：线性扫描 vs 图着色

**要做的事**：先算每个虚拟寄存器（或 SSA 值）的活跃区间，把区间不重叠的映射到同一物理寄存器，冲突的溢出到栈槽。图着色是「建冲突图 → 简化/合并/选择 → 溢出重写 → 重跑」的循环；线性扫描是「按起点排序 + 维护 active 列表」的单趟贪心。

```text
sort intervals by start
active = []                          // 按 end 有序
for i in intervals:
    for a in active where a.end < i.start:  free(a.reg); remove(a)
    if len(active) == K:             // K 个可用物理寄存器
        s = active 中 end 最大者
        if s.end > i.end: spill(i); continue
        else: spill(s); free(s.reg)
    i.reg = 空闲 reg 或新栈槽
    active.insert(i)
```

**最小可跑判据**：3 个同时活跃的变量能正确分配；把可用寄存器数人为压到 1，程序仍跑出正确结果（证明 spill 路径通）。

**最常见的坑**：忘记调用约定里 caller-saved 寄存器在 `call` 前后是被破坏的，跨调用的值必须重新活跃；溢出代码本身需要寄存器，必须预留 scratch；x86 这类两地址指令 `add dst, src` 破坏性写，会人为拉长活跃区间；活跃区间里的空洞（中间不活跃）线性扫描利用不到，图着色却可以——这是两者质量差的主要来源。

面试问「为什么很多 JIT 用线性扫描」：实现量小、单趟、编译速度快、结果「够好」；图着色质量更好但要反复重写。具体快多少、好多少按实现而定，不要背数字。

## 指令选择

**要做的事**：把 IR 的树/DAG 用目标指令模式覆盖（tree covering），自底向上匹配，每个节点选一条「根指令 + 子节点待覆盖」的规则；常见优化是把 load 折进寻址模式。

```text
ADD(MUL(a, b), c)        →  t = a * b ; t = t + c
ADD(LOAD(base, off), c)  →  add c, [base+off]     // 寻址模式吸收 load
```

**最小可跑判据**：`a*b+c` 选出乘、加两条指令；每个 IR 节点都能匹配到规则，匹配不到时**报编译错误**而不是静默输出错误代码。

**最常见的坑**：覆盖表不全又没断言，最后生成空指令或垃圾；忽略立即数位宽与是否为合法编码（超出范围必须走常量池或 `movabs`）；按树而非 DAG 选择，公共子表达式被重复选择——这不是 bug，要么接受，要么交给 CSE。

## 栈帧与调用约定

**要做的事**：定下帧布局（返回地址、保存的 callee-saved、spill 槽、局部变量、对齐填充），生成 prologue/epilogue；落实参数放在哪几个寄存器、超出部分怎么放栈、返回值在哪、varargs 的额外约定。

**最小可跑判据**：`fib(n)` 递归版本结果正确；5 个参数的函数调用结果正确（强制走栈传参路径）；对栈对齐有断言或测试（x86-64 SysV 在 `call` 时要求 16 字节对齐）。

**最常见的坑**：栈对齐差 8 字节，任何用到 SSE 对齐的 libc 函数直接崩；参数寄存器用完不回落到栈；忘了保存 callee-saved，调用者的变量被踩，表现为「加了条 printf 就好了」；varargs 调用没设向量寄存器计数。

## 汇编与链接

**要做的事**：输出汇编文本（`.globl`、标签、`.section`），交给系统汇编器/链接器（`as`/`ld`，或直接 `cc file.s`），符号和重定位交给工具链，自己不碰 ELF 编码。

**最小可跑判据**：`./yourc hello.lang > hello.s && cc hello.s -o hello && ./hello` 打印正确内容；能调用 `puts`/`printf`/`malloc` 这些 libc 符号。

**最常见的坑**：默认 `cc` 产出 PIE，绝对寻址的代码直接段错误（用 RIP 相对或 `-no-pie` 先跑通）；自己手写目标文件/ELF 编码，工作量翻十倍且不产生任何教学收益；漏 `.note.GNU-stack` 引出一堆可执行栈警告。

## 调试信息与错误报告

**要做的事**：前端错误带 `file:line:col` 加源码行和 `^` 指示；IR 指令携带源位置，后端可选地发 `.loc` 指示符生成 DWARF 行表，让 gdb 能按源码行单步。

**最小可跑判据**：类型错误输出 `t.lang:7:13: expected int, found string` 加一行源码和指针；错误恢复后一次编译能报出多个错误而不是遇错即停。

**最常见的坑**：只有 token 位置、AST 节点没位置，报错指到上一行末尾；把错误恢复做成「跳过到下一个分号」，结果一个错误引发十几条级联报错（需要抑制后续派生错误）；调试信息和优化叠加后行号漂移（先不优化再谈）。

## 测试策略

**要做的事**：三层——pass 级单元测试（优化前后 IR 快照对比）；语料回归（`tests/*.lang` + 期望 stdout + 期望退出码）；差分测试（同一程序分别用你的编译器和一个参考实现跑，比结果）。语言够强时自举是最强收敛信号，但它是里程碑末尾的事，不是起点。

**最小可跑判据**：`run_tests.sh` 遍历用例、比对输出、有失败就非零退出，能在 CI 里跑；错误用例也有期望的报错文本。

**最常见的坑**：只测正确程序不测错误程序（错误信息也是可观测行为）；只比退出码不比 stdout；随机差分测试造出未定义行为的程序，把误报当 bug 追一天（生成器必须约束在良定义子集）。

## 「最小而全」里程碑清单

| 阶段 | 产出 | 判据 |
|---|---|---|
| 0 端到端骨架 | `return 42` → 汇编 → `cc` → 可执行 | `./a.out; echo $?` 输出 42 |
| 1 表达式与变量 | 算术、局部变量、`puts` 调用 | 打印字符串与整数结果正确 |
| 2 控制流 | `if/while`、比较、短路求值 | 循环求和、素数筛出正确结果 |
| 3 函数与调用约定 | 多参数、递归、返回值 | 递归 fib(20) 与迭代版一致 |
| 4 指令选择补全 | 覆盖表 + 立即数合法化 + 断言 | 无 "no pattern" 且全语料通过 |
| 5 朴素分配 | 所有虚拟寄存器一律走栈槽 | 全语料通过（作为分配器的对照组） |
| 6 寄存器分配 | 线性扫描 + spill | 压到 K=1 仍正确；压测函数不崩 |
| 7 CFG 与优化 | 支配树、常量折叠、DCE | 优化开关切换后输出一致 |
| 8 错误报告 | 位置 + 源码片段 + 多错恢复 | 错误用例逐条匹配期望文本 |
| 9 测试体系 | 回归脚本 + 差分测试 | CI 绿；新增用例只需丢文件 |

顺序上的两个判断：**先把「全 spill 到栈」跑通再上寄存器分配**，能把「分配器错」和「栈帧错」两类 bug 分开；**优化放在第 7 位**，因为它不改变可观测行为，可以在有完整回归网之后再引入——反过来做，你会分不清是新优化错了还是后端本来就错。
