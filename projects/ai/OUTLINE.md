## 一、它解决什么问题

这项能力拦住的是两类事：**面试里算不出来**，和**工程里估错了量级**。

**场景一（面试）**：面试官问「Transformer 一层有多少参数」「224×224 的图直接接 1024 维全连接层要多少参数」。这类题没有推导，只有口径。答不上来不是数学差，是从没把「模型 = 参数化函数」这件事落到可数的量上。比如 $224\times224\times3\times1024\approx1.54\times10^{8}$，一个 FC 层就是 1.5 亿参数；同样输出的 $3\times3$ 卷积（$3\to1024$ 通道）只有 $3\times3\times3\times1024+1024\approx2.8\times10^{4}$。差三个数量级——这个对比能一句话讲清「归纳偏置换参数效率」。

**场景二（工程）**：上线前估显存，只数了参数量，漏了激活值与自回归解码的 KV cache。一个 $d$ 维、$L$ 层的解码器，每 token 的 KV cache 是 $2\times L\times d$ 个元素（×2 是 K 和 V），乘上 batch 与上下文长度再乘 dtype 字节数——按实现而定，但量级必须能当场写出来。漏算这一项直接从「够用」变成 OOM，而这类事故在形状层面**完全不报错**：`reshape` 把 batch 维和序列维混掉，张量形状合法、数值全错、静默训完。

还有一个高频静默错误：`transpose` 之后直接 `view`，要么抛 stride 不连续，要么被 `reshape` 悄悄拷贝 —— 正确性和显存都中招。

**入口（本文的读法）**：在「参数量、显存、算力」都能从字段里查到的前提下（`total_memory`、`numel`、`itemsize`、`TensorImpl.sizes()`、`past_key_values` 的形状、`memory_allocated()`），把「面试能不能算」和「上线会不会 OOM」合并成同一张账：权重、激活、KV cache、梯度、优化器状态各占多少字节。换的是具体架构，不换的是「形状 → 参数量 → 显存 → 能不能跑」这条估算链。

**不换的是什么**：全程不变的是 `state_dict` 的 key→`TensorImpl.sizes()/strides()/dtype`、`input_ids/attention_mask` 的 `torch.Size`、`past_key_values` 的 `[batch, heads, seq_len, head_dim]`、`requires_grad` 与 AdamW `state` 的 `numel`、`cudaMalloc` 返回的 allocator bytes；看到差异先问这五项是否同口径，再查 `transpose().view()` 是否触发 `contiguous` 拷贝或 `reshape` 是否改变 `storage_offset`。

## 二、为什么这样做（方法论设计）

**有口径才算数的**：参数量 $N=\sum_p \mathrm{numel}(p)$，逐层可数、可复现；FLOPs/MACs，但**必须声明口径**——batch 是否为 1、序列长度取多少、是否含 bias 与激活、MACs 算 1 次还是 2 次。同一份代码用 `fvcore` 的 `FlopCountAnalysis` 和用论文口径能差 2 倍，不是谁错，是口径不同。感受野 $r_l=r_{l-1}+(k_l-1)\prod_{i<l}s_i$、输出尺寸 $\lfloor (I+2P-D(k-1)-1)/S\rfloor+1$、注意力复杂度 $O(n^2d)$——这些是**闭式可算**的，算完能被人当场复核。

**看起来专业但无法证伪的**：「注意力更符合人类直觉」「深度带来层次化表征」「这个结构更鲁棒」。这些话没有判据，说了等于没说。可替换的证伪口径是：**等变性**（CNN 对平移等变、自注意力对 token 置换等变，所以必须加位置编码）、**复杂度阶**（$n$ 翻倍，注意力类结构代价 ×4，卷积类近似 ×2）、**参数效率**（同感受野下的参数比）。

**指标怎么定、边界怎么划**：本文只做**前向推理口径**。选型看三个数：$N$、MACs、峰值显存，加一个延迟约束。边界是单样本（或固定 batch）单次前向，不做训练吞吐。

**这套方法会失效的地方**，要主动说：① 稀疏化/剪枝之后 FLOPs 与实际时延脱钩；② depthwise 卷积 FLOPs 很低但算术强度低，受内存带宽限制，实测不一定更快；③ MoE 的总参数量与激活参数量是两个数，混用就没有可比性；④ 动态形状、变长序列下，静态 FLOPs 只是上界。

**常见错误做法及其代价**（不是「不推荐」，是有账）：

- **用「层数深」当能力代理**：同参数量下宽度和 token 数的分配对结果影响更大，用深度做指标会系统性选到更慢的结构，代价是同等效果多花一档延迟预算。
- **用参数量代替计算量**：大词表 embedding 参数占比很高但不参与主干计算；卷积参数少而 FLOPs 高（FLOPs ≈ 参数量 × 输出位置数）。代价是显存和时延估算错一个数量级——这正是场景二那类事故。
- **只看 FLOPs 不看访存**：结论是「A 比 B 快」，实测反过来，方案评审直接失去可信度。
- **抄架构不看归纳偏置**：在小数据图像任务上把 CNN 换成 ViT，丢掉平移等变先验，同参数量下更差——而且不是调参能救的。
- **数学陷入推导**：把「够用」做成「重建线性代数」，读者记住的是证明过程，忘了 $QK^\top$ 是在算相似度。

数学的取舍就一条：**只讲到量纲和形状能自洽为止**，不推公式。

## 三、章节大纲

**第 1 章 最小数学集：向量与矩阵、内积与投影、范数、随机变量与期望**
形状约定与矩阵乘即批量内积；内积=投影=未归一化余弦相似度（注意力打分的来源）；$L_1/L_2/L_\infty$ 各自衡量的「大小」；期望即加权平均。
→ 能答：$q^\top k$ 到底在算什么？为什么除以 $\sqrt{d_k}$？——内积是相似度，独立性假设下各维方差为 1 时点积方差为 $d$，缩放把量纲拉回 $O(1)$。

**第 2 章 张量与形状：广播规则、batch 维、reshape 与 transpose 的代价**
广播从右对齐、长度为 1 的维扩张；batch 作为首维的约定与例外；`reshape` 需连续内存、`transpose` 只改 stride 不搬数据、`contiguous` 才真拷贝。
→ 能答：`transpose` 之后 `view` 为什么报错？代价是什么？（$O(n)$ 内存搬运，`reshape` 会静默拷贝）

**第 3 章 从线性回归到感知机：模型就是一个参数化的函数**
$y=f_\theta(x)$；线性模型是仿射变换；感知机=仿射+阶跃；单层只能划超平面，XOR 不可分。
→ 能答：为什么单层感知机解决不了 XOR？几何上如何解释？

**第 4 章 全连接网络：层的堆叠、激活函数、为什么必须有非线性**
一层是 $Wx+b$，参数 $d_{in}d_{out}+d_{out}$；两层线性复合仍是线性（$W_2W_1$ 可合并）；ReLU/GELU/SiLU 的形状与计算代价差异。
→ 能答：去掉所有激活函数，10 层 MLP 等价于什么？（一层线性变换）

**第 5 章 卷积网络：卷积就是加权和、感受野、padding/stride/dilation、池化**
互相关定义与权值共享带来的参数下降；输出尺寸公式；感受野递推；dilation 扩感受野不增参数；池化的下采样收益与平移不变性代价。
→ 能答：3 层 $3\times3$、stride=1 的感受野多大？（7）两个 $3\times3$ 代替一个 $5\times5$ 的收益与代价？（感受野同为 5，参数 18 vs 25，多一次非线性；代价是两次算子启动、访存更多）

**第 6 章 序列模型：RNN 的链式依赖、LSTM 的门控到底解决了什么**
$h_t=f(W_hh_{t-1}+W_xx_t)$；沿时间展开、依赖路径长度 $O(T)$、时间步不可并行；LSTM 以 cell state 作加法主干，门控是逐元素乘的软开关，把信号传播路径从纯连乘改为主干加法。
→ 能答：LSTM 相比 RNN 到底解决了什么？为什么它仍被 Transformer 取代？（路径长度改善，但 $O(T)$ 串行性没变）

**第 7 章 注意力与 Transformer：QKV、多头、位置编码、残差与归一化的位置**
$\mathrm{softmax}(QK^\top/\sqrt{d_k})V$ 的逐步形状；$O(n^2d)$；多头是拆维并行再投影；位置编码（正弦/可学习/RoPE 的相对位置性质）；Post-LN 与 Pre-LN 的放置与数值稳定性差异；残差提供恒等短路。
→ 能答：为什么必须加位置编码？（自注意力对置换等变）一个 block 多少参数？（注意力 $4d^2$ + MLP $8d^2$ ≈ $12d^2$，按实现而定）

**第 8 章 架构选型：参数量与计算量估算、归纳偏置、什么时候不该用 Transformer**
$N$ 与 MACs 的估算模板；CNN 的局部性/平移等变 vs Transformer 的全局感受野/置换等变+位置编码；数据量、序列长度、延迟预算三条判据。
→ 能答：1 万张图、边缘端 10ms 预算，选 CNN 还是 ViT？给出判据而不是结论。

## 四、不做什么 · 必要性 · 失效点

### 必要性：删掉会怎样

| 机制 | 删掉会怎样 | 判定 |
|---|---|---|
| KV cache 字节项 `2*L*d*batch*seq_len*dtype_bytes` | 删掉后峰值显存只数 `sum_p numel(p)*dtype_bytes`，长上下文时 `cudaMalloc`/allocator 触发 `CUDA out of memory`，形状检查不会报错。 | 必需 |
| `reshape`/`view` 的 stride 连续性检查 | 删掉后 `transpose` 产生的非连续 stride 被 `view` 抛 `RuntimeError: view size is not compatible...` 或被 `reshape` 静默拷贝，batch/seq 维混叠导致数值全错。 | 必需 |
| MACs 口径声明（`batch`、`seq_len`、bias、MAC=1/2） | 删掉后 `fvcore.FlopCountAnalysis` 与论文口径混用，同一 `QK^T`/`FFN` 图差 2 倍无法复核，选型表里的 `MACs` 列失去可比口径。 | 必需 |
| 等变性/位置编码判据 | 删掉后无法把位置编码必要性写成 token 排列前后 `QK^T` 矩阵是否变化的检查项，只剩口头判断。 | 选择 |
| MoE 激活参数量 | 删掉后只报总 `numel(p)`，不报 `top-k` 路由后的激活参数量，`FlopCountAnalysis` 与 all-to-all 通信量混用，参数效率不可比。 | 必需 |

### 失效点：哪条前提一破，结论就变

- `dtype_bytes=2` 且 `batch*seq_len` 固定 → 改 `int8/fp8` 后 KV cache 字节项 `2*L*d*batch*seq_len*dtype_bytes` 变，OOM 边界移到量化 scale/zero-point 与 cache 布局边界。
- `transpose` 后 `tensor.is_contiguous()==True` → 若 stride 非连续，`view` 抛 `RuntimeError` 或 `reshape` 触发拷贝，静态 `MACs` 不变但 allocator 峰值显存和 kernel 时延估算失效。
- 注意力 kernel 稠密计算 `QK^T` 且 `seq_len=n` 固定 → 若 `causal mask` 或 `varlen` 动态形状使有效计算量下降，`O(n^2d)` 静态 MACs 变上界，`MACs` 排序表变。
- depthwise 卷积算术强度高于 GPU DRAM roofline 拐点 → 若低于拐点，`MACs` 低但 `ld.global`/`st.global` 带宽成为瓶颈，实测时延不随 FLOPs 下降。
- MoE 路由 `top-k` 与容量系数固定 → 若 `top-k` 改变，总 `numel(p)` 不变但激活参数量、`FlopCountAnalysis` 和 all-to-all 通信量改变，参数效率结论变。

### 不做什么（范围）

- **不写任何训练内容**：损失函数推导、优化器、学习率调度、正则化、数据增强、分布式训练、调参经验、反向传播的梯度公式——全部不写。本文只描述「结构长什么样、为什么这样设计、参数量与计算量怎么算」。
- **不写 408 考点**：Cache、流水线、进程调度、内存管理属于计算机组成/操作系统层。
- **不写具体语言语法与框架手册**：Python 语法、PyTorch API 逐条罗列、autograd 机制细节。
- **不做 SOTA 复现与排行榜对比**：不承诺任何精度数字。
- **不写部署与推理优化**：量化、蒸馏、TensorRT/ONNX 转换属于推理工程层。
- **不推导公式**：数学只到量纲与形状自洽为止。

## 五、面试怎么讲

**30 秒版本（约 150 字）**

我能把一个网络结构拆成三件事讲清楚：形状怎么流、参数怎么数、代价怎么估。拿到任何一个结构，我能写出每层的输入输出尺寸、算出参数量 $\sum\mathrm{numel}(p)$ 和 MACs，并说明这个口径的边界——batch 多大、序列多长、含不含 bias。选型时我用三条判据：数据量够不够喂全局注意力、序列长度下 $O(n^2d)$ 是否可接受、延迟预算是否允许丢掉卷积的局部性先验。我不做训练侧的判断。

**可能被追问的 6–8 个点**

1. **「Transformer 一层多少参数？」** → 考点：结构参数化。答：注意力四个投影 $4d^2$，MLP 若隐层 $4d$ 则 $8d^2$，合计约 $12d^2$；词表 embedding 单独算，是否与输出层共享权重按实现而定。
2. **「注意力的计算复杂度？」** → 考点：复杂度阶。答：全序列前向 $O(n^2d)$，$n$ 翻倍代价 ×4；自回归增量解码每步 $O(nd)$，但 KV cache 显存随层数×$d$×token 数线性增长，字节数按 dtype 而定。
3. **「为什么除以 $\sqrt{d_k}$？」** → 考点：内积的方差。答：各维独立、方差为 1 时点积方差是 $d_k$，标准差 $\sqrt{d_k}$；不缩放会让 softmax 进入饱和区、输出近似 one-hot，缩放是量纲归一，不是调参。
4. **「两个 $3\times3$ 换一个 $5\times5$，值不值？」** → 考点：感受野与参数。答：感受野同为 5；参数 18 vs 25；非线性从 1 次变 2 次。但算子启动次数翻倍、访存更碎，实测时延是否更优按实现而定，不能只看 FLOPs。
5. **「LSTM 的门控解决了什么？」** → 考点：路径长度。答：cell state 是加法主干，门控是逐元素乘的软开关，可学习地决定保留比例，信号传播不再纯靠矩阵连乘；但时间步仍串行，这是被 Transformer 取代的主因。
6. **「`transpose` 后 `view` 报错怎么办？」** → 考点：stride。答：`transpose` 只换 stride 不搬数据，内存不连续；`.contiguous()` 会做 $O(n)$ 拷贝；改用 `reshape` 会静默拷贝，形状对了但性能账要记上。
7. **「为什么 Transformer 需要位置编码？」** → 考点：等变性。答：自注意力对 token 置换等变，不加位置编码时打乱输入顺序输出只是同步打乱；正弦编码固定、可学习编码受最大长度限制、RoPE 把相对位置编进内积。
8. **「什么时候不该用 Transformer？」** → 考点：归纳偏置与判据。答：小数据 + 强局部性（图像、短序列）、边缘端严格延迟、超长序列下 $n^2$ 爆炸。回答要给判据——数据规模、$n$、延迟预算——而不是给结论。

**别说什么**

- 「Transformer 一定比 CNN 强 / 注意力更符合直觉」——不可证伪，且当场会被要求给判据。
- 「参数量大就强」——直接把计算量、数据量、延迟三个约束全忽略，是选型事故的标准开场。
- 「FLOPs 大概是 X」而不说口径（batch、序列长度、是否含 bias）——一追问就露馅。
- 「我全部实现过、实测提升 N 倍」——未经证实的断言，说了反而丢掉可信度；换成「我按这个口径算过 $N$ 和 MACs，边界是这样」更稳。
