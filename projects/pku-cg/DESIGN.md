# 北大图形学 · 渲染与游戏 · 设计文档

> 本文是该项目的设计说明，不是教程。
> 大纲见 `OUTLINE.md`，一小时上手见 `QUICK.md`，详细记录见 `NOTES.md`。

## 一、定位与边界

pku-cg 是从零实现的离线渲染器，为北大图形学课程作业产出可对比的图像。它解决的问题：三维场景经 MVP 变换、光栅化、着色、阴影得到一帧；另一条光追路径用 BVH 加速求交，产出硬阴影参考图。它不解决：实时帧率与 GPU 管线、全局光照与路径追踪、完整模型格式与资产管线。与相邻项目分工：数学库提供 Vec/Mat 与求交原语，本项目负责把它们组织成流水线并保证图像正确；并行化项目把像素循环改成多线程，本项目只暴露按 tile 划分的接口。

## 二、整体架构

模块：`math`（Vec2/3/4、Mat4、Ray、AABB，纯头文件）；`scene`（相机、mesh、材质、光源与解析）；`raster`（顶点处理、三角形装配、光栅化、深度缓冲）；`shade`（Blinn-Phong 与纹理采样）；`raytrace`（求交原语、BVH、阴影射线）；`image`（帧缓冲、sRGB、PNG）；`app`（命令行与后端选择）；`tests`。

调用方向：`app` → `scene` → {`raster` | `raytrace`} → `shade` → `image`。两个后端互不调用，共享 `math` 与 `shade`；`shade` 只读 `scene` 的数据结构，不反向依赖后端，因此两路图像的差异只来自可见性判定，便于交叉验证。

## 三、技术选型与理由

C++17：需要显式内存布局与零成本抽象撑起深度缓冲和 BVH 数组；Python 太慢，Rust 的借用检查会让后期共享场景数据的并行改造代价偏高。

自写 Vec/Mat 而非 Eigen：作业核心是推导 MVP 与齐次除法，Eigen 会把行/列主序与变换语义封掉；自写才能在测试里逐元素断言矩阵。代价是无 SIMD，可接受。

不用 OpenGL/Vulkan：那等于免费拿到光栅化与深度测试，恰是本节要考的部分。

stb_image_write：单头文件写 PNG，便于肉眼比对与 diff；自写要处理 zlib，收益为零；OpenCV 依赖过重。

CMake + CTest：CTest 直接挂图像回归脚本；Bazel 在课程环境配置成本高。Catch2 v3：SECTION 与浮点容差断言够用，自研框架的失败信息组织要额外花时间。

自定义文本场景格式而非 glTF：解析器三十行内写完，glTF 的节点层级与 PBR 材质超出本项目边界。

## 四、数据流

命令：`app --scene spheres.scene --backend raytrace --size 512x512 --out out.png`。

输入：场景文件（相机、图元、材质、光源）解析为 `Scene`。

光栅路径：逐顶点算 $\text{clip}=P\,V\,M\,v$，透视除法得 NDC，视口变换得屏幕坐标，装配成 `Triangle`，写入 `Framebuffer{color[], depth[]}`，用重心坐标插值 UV 与法线，`shade` 逐片元求色。

光追路径：由 `Scene` 建 `BVH{nodes[], primIdx[]}`，主射线得 `HitRecord{t, n, uv, matIdx}`，阴影射线再遍历一次判遮挡。

关键结构：`Mat4`（列主序）、`Triangle{v[3], n[3], uv[3], matIdx}`、`Framebuffer{w, h, color, depth}`、`BVHNode{AABB box; int start, count, left, right}`。

输出：帧缓冲经 sRGB 编码写 PNG，另存一张深度可视化图用于调试。

## 六、验收判据

- 变换：MVP 合成与逐步相乘逐元素误差 $<10^{-6}$；10 个随机顶点的 NDC 坐标误差 $<10^{-5}$。
- 光栅化：16/16 单元测试通过（覆盖判定、top-left 规则、退化三角形、屏幕外裁剪）；交叠三角形在 1000 个随机采样像素上遮挡判定 100% 正确。
- 纹理：倾斜 60° 平面上，透视校正插值与解析 UV 偏差超 5% 的像素占比 $<0.1\%$。
- 阴影：1024$^{2}$ shadow map 加斜率 bias 后自阴影 acne 像素占比 $<1\%$；与光追硬阴影比对，非边界像素一致率 $\ge98\%$。
- 求交：20/20 单元测试通过，与高精度数值解相比根误差 $<10^{-6}$。
- BVH：512×512 下与暴力求交差异像素数为 0；10k 三角形场景单线程加速比 $\ge5\times$；SAH 比中位数分割的遍历节点数少 $\ge30\%$；构建时间 $<2$ s。
- 性能：640×480、10k 三角形，光栅化单帧 $<100$ ms（`-O2`，单线程）。
- 工程：ASan 与 UBSan 零报告，valgrind 无泄漏。

## 七、风险与已知坑

矩阵约定：主序与乘法顺序不一致会让 MVP 整体错却"看着在动"，先用已知点锁定结果。

近平面：相机后方顶点 $w<0$，透视除法后三角形翻转爆炸，必须做近平面或 $w$ 裁剪。

透视校正漏掉 $1/w$ 会出现游泳式扭曲。

深度精度：near/far 比值过大导致 z-fighting，取 0.1 与 100，别用 $10^{-4}$。

阴影 bias 太小出 acne、太大出 peter-p
