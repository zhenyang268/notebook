## 一、它在做什么

这个项目把 Python 岗面试里最常追问的四块内容（对象模型、迭代协议、并发、内存）做成一套能当众演示的知识。输入是一张问题清单：每条都是面试中真实出现的“为什么”，比如“为什么默认参数不能写 `[]`”“`for` 循环到底调了什么”“既然有 GIL，为什么还要加锁”。这些口语化问题会先被改写成可验证的假设：一句预测，加一个能推翻它的最小实验。输出是两类成对产物：每个假设配一个几十行、只用标准库的独立脚本，以及一张结论卡，包含结论句、成立边界、反例、常见错误答法和 30 秒口述版。验收不看读了多少材料，而看三件事：随机抽一张结论卡，能在本机跑脚本复现结论；能说清这条结论在哪个版本、实现或平台上不成立；能在三分钟内把它讲成面试官愿意点头的答案。

**入口（本文的读法）**：在 CPython 版本与标准库可固定的约束下，把 12 章都读成一次可复现的断言，每条结论落到 `sys.implementation.name`、`id` 变化、`sys.getrefcount`、`gc` 代数、`__slots__` 布局这类可核对字段上。换的只是语言特性的载体（对象模型 / 容器 / GIL / 协程 / GC）。不换的是「预测 → 最小 `assert` → 结论字段」这条证据链。

**不换的是什么**：全程不变的是同一套可执行判据：每章都绑定至少一个 `assert`、一个 `sys.version`/`sys.implementation.name`/`platform.system` 成立边界和一个 `pyproject.toml`/`build-system.requires` 依赖边界，所以看到差异先问这三项是否改变，再定位到解释器版本、实现、平台、并发运行时、GC、类型标注或打包依赖层，而不是先改 `assert` 结论。

**积木**：① CPython `PyObject` 头里的 `ob_refcnt` 字段与 `Py_INCREF`/`Py_DECREF` 宏：它能独立验证 `del` 后 `sys.getrefcount` 是否归零并调用 `tp_dealloc`；② CPython `type` 对象里的 `tp_iter`/`tp_iternext` 协议槽与 `StopIteration` 异常对象：它能独立验证 `for` 是否只读取这两个槽并在异常时退出循环；③ OS `epoll_create`/`epoll_wait` 系统调用与 `epoll_event.events` 字段：它能独立验证 asyncio 是否把 `await` 挂到内核 `epoll` 文件描述符而不是 `sched_yield` 系统调用。

**最小情形**：单核单线程里执行一次 `a = []; a.append(1); del a`，只触发 `PyList_Append`、`ob_refcnt` 减一和 `tp_dealloc`；此时 `epoll_wait`、`fork`、`gc.collect` 的循环引用扫描不起作用。

**生成**：累加 12 章的断言到 `sys.version`、`sys.implementation.name`、`platform.system` 字段和 `pyproject.toml`/`build-system.requires` 边界；覆盖 `__slots__` 布局、`dict` 哈希表、`gc` 代数、`asyncio.Task` 状态机、`multiprocessing` 的 `fork`/`spawn` 页表差异；最坏情形 `gc.collect()` 在自引用容器、`__del__` 异常、`StopIteration` 在协程帧里的传播、`fork` 后继承的 `epoll` 文件描述符上同时发生。

**两边**：同一份 Python 对象状态的用户态表示是 `PyObject` 头里的 `ob_type`、`ob_refcnt` 与 `tp_dictoffset` 指向的 `__dict__`，内核态表示是进程页表里的虚拟地址映射和 `mmap` 堆页；持有者分别是 CPython 解释器用 `Py_INCREF`/`Py_DECREF` 持有引用计数，操作系统用 `brk`/`mmap` 与缺页中断持有页表项。

## 二、为什么这样做（功能设计）

四块内容不是并列的清单，而是有依赖的一条主线：对象模型是底层基础，可变性决定容器、默认参数、切片的行为；迭代协议把对象模型接到控制流上，`for`、解包、生成器、`async for` 是同一套协议的不同变体；并发与内存是代价问题，GIL 决定线程能做什么，引用计数决定对象什么时候消失。章节顺序由这条主线决定，不从“哪个话题热门”出发。

**替换掉的是“教程 + 背诵”这条二手知识链。** 它真正要替换的，是“一句话结论”和“一段能跑的标准库脚本”之间的绑定关系，这不在编辑器或笔记软件里；卡片上没有可执行片段，就不算成立。这里要自己实现一套最小的断言层：每张卡必须带预测（我预期输出是什么）、反例（什么情况下不成立）、复现方式；三样齐全，才允许进卡片库。这样一来，“我记得是这样”在流程上就被排除了。

**数据形态与不可靠性。** 输入是口语化问题，不是结构化需求：主语常常缺失，现象和结论混在一起（“生成器省内存”——省的是哪一块？常驻集还是峰值？）。不可靠性有四个来源。版本：3.8 到 3.12 之间，dict 顺序保证、asyncio 接口、报错信息都变过。实现：引用计数与 GIL 是 CPython 的实现细节，不是语言规范，换 PyPy 结论就不同。平台：`multiprocessing` 默认启动方式在 Linux 与 macOS/Windows 上不同，`fork` 和 `spawn` 能跑出相反结论。测量噪声：任何带时间的结论，单次都不可信。压制手段是固定的：脚本头部锁定版本与实现，卡片写明适用边界；时间类用 `timeit` 多轮取中位数并报离散度，不报单次；内存类把 `tracemalloc`（分配）和 `sys.getsizeof`（对象头）分开测，不用 RSS 冒充；GC 类用 `gc.get_referrers`、`getrefcount` 交叉验证，不靠打印猜；并发类必须配一个“去掉并发也成立”的对照组，否则不承认加速，也不承认竞态。

**为什么不用更简单的做法。** 最省事的是背八股，代价是记忆一旦与真实行为冲突就无法自证，面试官往下追一层就露底；而且八股记的是结论不是条件，一问“什么时候不成立”立刻失效。第二种省事是只读官方文档，代价是文档写规范和 API，不写实现：GIL 的切换间隔、引用计数的即时回收、闭包的晚绑定、生成器 `close` 时抛什么，都属于实现行为，只有实际运行才会暴露。第三种是做成刷题，代价是覆盖面被题库绑架，追问就断。所以选“最小实验 + 结论卡”：成本是要自己设计对照实验，收益是每条结论自带边界，被追问时能修正说法，而不会直接答不上来。

## 三、章节大纲

1. **对象模型与可变性**：`id`、`type`、值三元组，名字绑定与引用，可变与不可变的真正分界，小整数与字符串驻留，默认参数陷阱，`==` 与 `is`，`__eq__` 与 `__hash__` 的契约。做完能预测一次赋值后 `id` 是否变化，能解释“元组里放列表算不算可变”。
2. **容器**：`list` 的连续数组取向与 `dict`、`set` 的哈希表取向，字典保序的来源，哈希冲突与自定义 `__hash__`，成员测试的复杂度，按操作组合选容器。做完能针对给定读写比例选出容器并说清复杂度理由。
3. **切片与推导式**：切片返回新对象、负索引与步长、切片赋值、推导式的作用域（Py3 不外泄）、嵌套推导的求值顺序、生成器表达式的惰性。做完能预判一段代码的分配次数与求值时机，能指出推导式里藏副作用的写法。
4. **迭代器与生成器**：`iter`、`__iter__`、`__next__` 与 `StopIteration`，可迭代与迭代器的区别，生成器的暂停与恢复，`send`、`throw`、`close`，`yield from`，生成器只能跑一次。做完能手写一个符合协议的类，并把 `for` 完整展开成 `while` 加 `next`。
5. **装饰器与闭包**：闭包捕获变量而非值，循环里的晚绑定，`nonlocal`，`functools.wraps` 保元信息，带参装饰器的三层结构，类装饰器，多个装饰器的叠加顺序。做完能写出带参且保留签名的装饰器，能预测循环中创建的一批函数的输出。
6. **上下文管理器与 with**：`__enter__` 与 `__exit__` 的返回值如何决定是否吞异常，异常路径下的调用顺序，`contextlib.contextmanager` 的生成器写法，`ExitStack`，多资源退出顺序。做完能写出异常安全且可复用的资源管理，并说清为什么 `try/finally` 在组合场景下不够。
7. **GIL 与多线程**：GIL 是什么、为什么存在、切换间隔，CPU 密集与 IO 密集的分野，竞态与锁的粒度，哪些内置结构本身线程安全，free-threading 版本的现状。做完能跑出“多线程不加速 CPU 任务、加速 IO 任务”的对照，能指出一段代码哪里必须加锁。
8. **多进程与并发选型**：`fork`、`spawn`、`forkserver` 的差异与踩坑，进程间通信（`Queue`、`Pipe`、共享内存），序列化开销，进程池，线程、进程、协程的选型表。做完能按任务画像（CPU 占比、IO 类型、数据量）选型，并说出被否决方案的代价。
9. **asyncio 与事件循环**：协程与生成器的血缘，事件循环如何调度，`await` 的确切语义，`Task` 与 `Future`，`gather` 与取消、超时，同步阻塞调用如何拖垮整个循环，`async with` 与 `async for`。做完能写出不阻塞循环的并发任务，能解释在协程里调 `time.sleep` 的后果。
10. **内存管理与垃圾回收**：引用计数的即时回收，循环引用与分代 GC 的三代与阈值，`gc` 模块接口，`__del__` 与 `weakref`，泄漏的常见形态（无界缓存、闭包持有、全局注册表）。做完能构造循环引用并用 `gc` 观察到回收，能用 `tracemalloc` 定位一处持续增长。
11. **类型标注**：标注是运行期元数据而非约束，`Optional`、`Union`、`TypeVar`、`Generic`、`Protocol` 的用法，`Protocol` 的结构化子类型与 ABC 的差异，mypy、pyright 的检查口径，`from __future__ import annotations`。做完能给一段动态代码补齐标注并通过严格模式检查。
12. **打包与工程化**：模块与包、`__init__` 与导入机制、相对导入的坑、`pyproject.toml`、虚拟环境与依赖锁定、最小可安装包、测试与 CI 的基本形态。做完能把一堆脚本变成可安装、可导入、别人能复现的包。

## 四、不做什么 · 必要性 · 失效点

### 必要性：删掉会怎样

| 机制 | 删掉会怎样 | 判定 |
|---|---|---|
| 引用计数 | `del obj` 后资源立即释放的承诺破，`with` 之外的文件句柄、socket 只能等 GC；`__del__` 时机从确定性变成不确定 | 必需 |
| 分代 GC 的循环检测 | 自引用容器永久泄漏：`a.append(a)` 的引用计数永远不为 0，`tracemalloc` 会看到持续增长 | 必需 |
| `__iter__`/`__next__` + `StopIteration` 约定 | `for` 无法判终止，`yield` 的暂停/恢复失去载体，生成器与迭代器协议整体失效 | 必需 |
| 事件循环的单线程调度 | `await` 的「协程体不会并发执行」语义破，两个 `Task` 会在同一段同步代码里交错，竞态重新出现 | 必需 |
| 哈希表（`dict`/`set`） | 成员测试与去重从均摊 O(1) 退化为 O(n) 或 O(n log n)，且自定义 `__hash__`/`__eq__` 的契约无处安放 | 选择 |
| 小整数与字符串驻留 | `is` 的结果不再稳定，同一数值可能有两个身份；改为一律用 `==` 也能写对，只是丢掉一处性能 | 选择 |
| GIL | CPU 密集任务可以真并行（free-threading），代价是 `list.append` 这类操作不再免费原子，内置结构的线程安全承诺要重新论证 | 选择 |

### 失效点：哪条前提一破，结论就变

- **CPython → PyPy**：引用计数不存在，`del` 后立即回收的结论失效；`weakref` 回调时机不同。
- **CPython 3.6 之前**：`dict` 不保序，靠插入序的结论失效。
- **free-threading 版本（3.13t）**：GIL 消失，`list.append` 需要显式锁，第 7 章的线程安全清单要重写。
- **`fork` 之后**：父子进程各有一份引用计数，父进程的 `del` 不影响子进程持有的对象。
- **`sys.setswitchinterval` 被调大**：竞态窗口变窄，同一段代码可能"偶发不复现"，不能据此判定无竞态。

### 不做什么（范围）

不做 CPython 源码级剖析：深度到“足以解释观察到的行为”为止，不逐行读解释器主循环。不覆盖第三方生态（Web 框架、ORM、数据栈），它们不在这四块焦点上。不做性能调优工程：只做能解释差异的测量，不追求把某段代码压到极限。不追求版本全覆盖：以一个固定版本为主，差异只在边界处标注，不维护版本矩阵。不产出“最佳实践清单”式结论集：没有条件的结论一律不收。

实现自由度留在这几处：脚本用纯函数还是类组织、结论卡用 Markdown 还是结构化数据、断言用 `assert` 还是 pytest、是否再配一个按关键词检索卡片的小命令，都可以自行决定，不影响验收。

常见的跑偏有五种：把项目做成笔记摘抄，卡片全是转述而没有可执行片段；把结论写成绝对真理，边界一栏空着；用 `time.time()` 测微秒级操作，测出来全是噪声；用“我记得是这样”代替复现，遇到分歧不跑脚本；追新语法和新特性，忘了口径是面试常问的那一层，讲得深却答不上基础题。

## 五、面试怎么讲

**30 秒版本**

> 这个项目要解决的是把 Python 数据模型、迭代协议、并发、内存四条线串成一条能讲清的链：可变对象怎么影响哈希与别名、迭代协议怎么统一 for 与推导式、GIL 怎么决定线程/进程/协程的取舍、引用计数加分代 GC 在哪种循环引用下失效。卡点是容易停在“会用”——能写 async 函数，却说不清一次阻塞调用为什么卡死整个事件循环。验证口径：每个结论配一段最小可运行代码加一个反例，用 pytest 钉住。

**可能被追问的 8 个点**

1. **他问：list 为什么不能当 dict 的 key，tuple 就一定行吗？**
   考点：`__hash__`/`__eq__` 契约，以及“哈希值在对象生命周期内必须不变”。
   答法：dict 查找先比 hash 再用 `==` 确认。`list` 有 `__eq__` 但 `__hash__` 被置为 `None`，所以直接 `TypeError: unhashable type`。`tuple` 可哈希的前提是每个元素都可哈希——`([1], 2)` 一样报错。自定义类只要定义了 `__eq__`，`__hash__` 会自动变 `None`，要么显式写 `__hash__`，要么用 `@dataclass(frozen=True)`。再补一句一致性：`a == b` 必须推出 `hash(a) == hash(b)`，否则对象在 dict 里“明明放进去却查不到”。
   顺带能接住 `is` 和 `==`：`is` 比 `id()`，`==` 走 `__eq__`；`-5..256` 小整数缓存和短字符串驻留是 CPython 实现细节，`a = 257; b = 257` 在同一 code block 里因常量折叠可能为 True，换个模块就不成立，不能当语言保证讲；判空一律 `is None`。

2. **他问：for 循环背后到底调了什么？生成器为什么只能遍历一次？**
   考点：迭代协议的三段式，以及“可迭代对象”和“迭代器”的区别。
   答法：`iter(obj)` 先找 `__iter__`，没有才回退到 `__getitem__` 的序列协议；`__iter__` 返回的对象必须有 `__next__`，用 `StopIteration` 表示结束，`for` 只吞这一个异常。生成器函数调用后返回 generator，它同时实现 `__iter__` 和 `__next__`，`__iter__` 返回 `self`——迭代器“遍历一次就耗尽”的根源就在这。补充：生成器里的 `return x` 会把 x 放进 `StopIteration.value`，`yield from` 会把它带出来并透传 `send`/`throw`；耗尽后再 `next()` 仍然是 `StopIteration`，不会复活。

3. **他问：生成器的 send/throw/close 分别对应什么场景？**
   考点：挂起点的控制权语义，这题答得出说明真用过协程。
   答法：第一次必须 `next()` 或 `send(None)` 预热到第一个 yield，否则 `TypeError`。`close()` 在挂起点抛 `GeneratorExit`，此时生成器若再 `yield` 就是 `RuntimeError: generator ignored GeneratorExit`，所以清理写在 `finally` 里。`contextlib.contextmanager` 就是靠这套：yield 之前的代码是 `__enter__`，异常在 yield 处抛回生成器内部，`finally` 保证清理——如果 `__exit__` 返回真值，异常被吞掉。

4. **他问：写个带参数的装饰器；为什么必须加 functools.wraps？**
   考点：闭包捕获的是 cell 不是值。
   答法：三层结构 `deco(arg) → wrapper(fn) → inner(*a, **kw)`。`wraps` 复制 `__module__`/`__name__`/`__qualname__`/`__doc__`/`__dict__` 并设 `__wrapped__`，不加的话 `inspect.signature` 拿到的是 `*a, **kw`，`lru_cache` 的 key、文档生成、调试栈全歪。闭包晚绑定：`__closure__` 里存的是 cell 对象，循环里 `lambda: i` 全部指向同一个 cell，最后一个值赢；修法用默认参数 `lambda i=i:` 或 `functools.partial`。改外层变量用 `nonlocal`，`global` 是模块级，两者别混。

5. **他问：GIL 到底锁什么？多线程什么时候真的有用？**
   考点：区分“并发”与“并行”，以及知道自己在说什么版本的 CPython。
   答法：GIL 保证同一时刻只有一个线程执行字节码，锁的是解释器状态而不是你的数据，所以 `x += 1` 仍然要加锁。切换粒度看 `sys.getswitchinterval()`，默认 0.005 秒，且要走到检查点才可能让出。`time.sleep`、socket IO、以及 numpy 这类在 C 层放锁的大运算会释放 GIL，所以 IO 密集多线程有收益；CPU 密集只能 `multiprocessing` / `ProcessPoolExecutor`，因为进程各有各的解释器。3.13 起有 free-threaded 的可选构建，但不能默认线上就是这个。

6. **他问：await 一个协程发生了什么？为什么一次 time.sleep 会卡死整个服务？**
   考点：事件循环的调度模型，而不是 API 记忆。
   答法：协程对象创建时不执行任何东西，没被 await 还会在 GC 时报 `RuntimeWarning: never awaited`。`await` 把控制权交回事件循环，循环用 selector（Linux 上是 epoll）等 fd 就绪，就绪后再 `send(None)` 恢复协程。`time.sleep` 是阻塞系统调用，不让出控制权，整个 loop 线程停住，所有 task 一起卡——所以要么 `asyncio.sleep`，要么 `await asyncio.to_thread(f)` 丢进默认 executor。再补两个坑：`asyncio.gather` 传协程会被包成 Task，官方文档明确要求自己保存 Task 引用，否则可能中途被 GC；CPU 密集丢线程池也救不了，因为还是 GIL。

7. **他问：引用计数什么时候不够用？分代 GC 是怎么触发的？**
   考点：知道 CPython 的两套机制各自负责什么。
   答法：引用计数管不了循环引用——互相引用的两个对象计数永远 ≥1。GC 按代回收，`gc.get_threshold()` 默认 `(700, 10, 10)`：第 0 代净分配减净释放到 700 触发一轮，0 代回收 10 次晋升到 1 代，依此类推，越老的对象扫得越少。`sys.getrefcount(x)` 返回的值比真实计数多 1，因为传参本身是临时引用。`__del__` 从 PEP 442（3.4）起可以被 GC 处理，但在里面复活对象仍有坑。实用手段：`weakref` 打破循环或做缓存、`tracemalloc` 对比两次快照定位泄漏，注意 `sys.getsizeof` 只算容器本身、不含元素。

8. **他问：类型标注在运行时有用吗？Protocol 和 ABC 差在哪？**
   考点：分清“静态检查”和“运行时行为”。
   答法：标注默认不产生运行时开销，`list[int]` 只是对象，真正检查靠 mypy/pyright。`from __future__ import annotations` 把标注变成字符串，前向引用不用加引号、启动更快，但要运行时拿到类型得走 `typing.get_type_hints()`。`Protocol` 是结构化子类型——不继承也能匹配，`runtime_checkable` 的 `isinstance` 只查方法名存不存在，不查签名，这点必须说清楚，否则等于宣称做了运行时校验。`TypeVar` 用于泛型约束，`Optional[X]` 就是 `X | None`。

**别说什么**

- **别说“asyncio 就是更快”“多线程就是并行”。** 这是把库名当原理。面试官只要追问一句“那 time.sleep 呢”，就暴露出没读 GIL 和事件循环的语义。
- **别说“跑通了所以是对的”。** 说“我验证过了”却拿不出反例，一问边界（空输入、生成器耗尽、`__exit__` 返回 None、跨模块的 257）就塌。验证口径要落到具体代码和 `pytest` 用例上。
- **别报没测过的数字。** “性能提升 3 倍”“内存降一半”没有测量工具（`timeit`、`tracemalloc`）、样本量和场景说明，就是负资产；宁可说“用这个口径可以测”，也不要编一个数。
- **别把 CPython 实现细节说成语言保证。** 小整数缓存、字符串驻留、dict 的 compact 布局、GIL 本身，都是实现层面的事，说成“Python 规定”会被当成背书式学习。
