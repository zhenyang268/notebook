## 一、它在做什么

这个项目把 CSAPP 前九章里五块最容易被「背过去」的机制——整数与浮点的位级表示、汇编层面的过程调用与栈帧、Cache 的映射与替换、链接器的符号解析与重定位、进程/线程的并发控制——各做成一个**必须与参考实现逐项对齐**的实现任务。

输入很小：每个实验只允许改一个 C 文件。输出是可以被机器判定的行为差异：位运算函数的返回值、Cache 模拟器给出的 hit/miss/eviction 三个计数、作业控制下进程的状态迁移、分配器的利用率与吞吐、自建链接器产出的可执行文件、并发服务器在压力下的正确性与无线程竞态。

验收不看「能跑起来」，只看三件事：结果与参考实现**逐项相等**（不是命中率接近、不是吞吐差不多）、静态检查无告警、在边界与随机输入下不崩。这个项目真正训练的是「把一个模糊的机制描述，压缩成一组能通过的断言」。

**入口（本文的读法）**：在「每个实验只改一个 C 文件、结果必须与参考实现逐项相等、`-Werror` 无告警」的约束下，把八章的验收对象从「退出码 0」换成可比对的断言：IEEE-754 位模式、`%rsp` 栈帧、cache hit/miss 计数、ELF 重定位条目、堆元数据、同步不变量。换的是观测点，不换的是「逐项相等」这条口径。

**不换的是什么**：全程不变的是补码溢出与 IEEE-754 位级语义、x86-64 调用约定与栈帧布局、Cache 映射/替换策略、ELF 符号绑定/重定位格式、POSIX 信号与进程状态机、`malloc`/`free` 的堆块元数据与对齐不变量、`pthread` 互斥/条件变量的同步语义，因此看到差异时先问它落在位掩码/返回值、`%rsp`/`%rbp`/callee-saved 寄存器、set/line 状态与 eviction、符号绑定与 `.rela` 条目、`sigmask`/进程状态、header/footer/bin 链、锁顺序与条件谓词中的哪一层。

**积木**：①C 语言与 x86-64 提供 `~`、`&`、`^`、`|`、`<<`、`>>` 运算符与补码 `int` 位宽。它能独立验证 `bitAnd`/`logicalShift` 的位掩码与 `Tmin` 取负。②x86-64 提供 `%rsp`、`%rbp`、`%rax`、`%rbx`、`%r12`–`%r15` 与 `push`、`pop`、`call`、`ret`、`leave` 指令。它能独立验证 `prologue` 后 `%rsp` 偏移、`epilogue` 前 `%rbp` 链、返回地址与 callee-saved 寄存器是否恢复。③IEEE-754 binary64 提供 `sign`、`exponent`、`fraction` 位字段、非规格数隐含位、round-to-even 与 `cvtsi2sd`、`cvttsd2si`、`ucomisd` 指令。它能独立验证 `floatScale2`、`floatFloat2Int`、`floatNeg` 的 64 位模式、`ucomisd` 的 `ZF`/`CF`/`PF` 标志、`cvttsd2si` 的向零截断与溢出标志。④ELF64、虚拟内存、POSIX 与 pthread 提供 `Shdr`、`Phdr`、`.symtab`、`.rela.text`、`STB_GLOBAL`、`R_X86_64_PC32`、`R_X86_64_64`、`PT_LOAD`、`PTE`、`mm_struct->pgd`、`fork`、`execve`、`setpgid`、`waitpid`、`sigprocmask`、`pthread_mutex_lock`、`pthread_cond_wait`、`futex` 与内核 `task_struct`、`sigpending`、`sigmask`。它能独立验证 `STB_GLOBAL` 符号绑定、`.rela.text` 重定位条目、`PTE` 物理帧号、`sigprocmask` 阻塞窗口、`waitpid` 返回的 `WIFEXITED`/`WEXITSTATUS`、`pthread_mutex_lock` 的 `cmpxchg` 地址、`pthread_cond_wait` 谓词检查。

**最小情形**：单核单线程执行一次 `bitAnd` 的 `and` 指令、一次 `floatScale2` 的 `xmm0` 位模式、一次 `call`/`ret` 的 `%rsp` 栈帧、一次 `access` 的 set/line 命中、一次 `mmap` 的 `PT_LOAD`、一次 `fork`/`execve`/`waitpid` 的 `task_struct` 状态、一次 `mm_malloc` 的 header/footer 写入、一次 `pthread_mutex_lock` 的 `cmpxchg`；此时 `lock cmpxchg`、`SIGCHLD` 合并、同一 set 内 `LRU` 替换、`.rela.text` 符号解析、空闲 bin 链分裂、条件变量虚假唤醒不起作用。

**生成**：累加从单次 `and`/`cvtsi2sd`/`call`/`access`/`mmap`/`fork`/`mm_malloc`/`pthread_mutex_lock` 扩展到随机输入序列、多 `set/line` 状态、多 `.rela.text` 条目、多 `task_struct`、多 heap block、多 `pthread_cond_wait` 唤醒，新增 `hit/miss/eviction` 顺序、`STB_GLOBAL` 符号解析、`sigpending` 合并、header/footer/bin 链、`pthread_mutex_lock` 获取顺序与 `pthread_cond_wait` 条件谓词的约束。覆盖 `Tmin`、`0x0000000000000001` 非规格数、`%rbx`/`%r12` callee-saved、`hit/miss/eviction` 计数、`R_X86_64_PC32` 符号解析、`sigpending`/`sigmask`、header/footer/bin 链、`pthread_mutex_lock` 获取顺序与 `pthread_cond_wait` 条件谓词。最坏情形是多核 `lock cmpxchg` 竞争、`SIGCHLD` 风暴、同一 set 内 `LRU` 连续驱逐、`.rela.text` 符号冲突与重定位溢出、堆外部碎片使 `mm_malloc` 失败、条件变量虚假唤醒使 `pthread_cond_wait` 谓词检查重复。

**两边**：同一份状态可表示为用户进程页表中的虚拟地址 `0x400000` 与内核 `mm_struct->pgd` 指向的页表项 `PTE` 中的物理帧号。持有者分别是用户进程页表与内核 `mm_struct->pgd`，对应 `mmap`/`execve` 映射与 `switch_to` 切换的 `task_struct->thread` 现场。

## 二、为什么这样做（功能设计）

核心思路是**逐个替换掉现成组件**，而且替换点都选在「抽象边界」上——正是教材用一句话带过、你从没亲手实现过的那一层。

**用位运算重建算术与浮点（替换编译器的算术指令）。** 接口在函数签名这一层：`bitAnd`、`logicalShift`、`floatScale2`、`floatFloat2Int` 之类，约束是被测文件里只能出现 `~ & ^ | << >>` 和有限常数，不能有循环、条件、函数调用、强转。这意味着补码的模运算语义、算术右移与逻辑右移的区别、IEEE 754 的三段拆分、round-to-even、非规格化数隐含位为 0、NaN 的比较、浮点转整数的向零截断与溢出，全都得自己补上。不可靠性来自边界值：`Tmin` 取负还是自己、`-0.0` 与 `0.0`、舍入进位把阶码顶上去一格。压它的机制是两层——静态检查器把语言能力削到只剩位运算（不给你偷懒的语法），大规模随机向量则跟参考实现逐位对拍。为什么不直接写 `a & b`：那正是要拆掉的抽象；为什么不用 Python 写：Python 的整数没有位宽，溢出和非规格化根本不存在，等于把要学的东西绕过去。

**用软件模拟 Cache（替换硬件里的缓存控制器）。** 接口落在「内存访问流」这一层：输入是 trace 里的 `L/S/M addr,size` 序列，输出是三个计数。要自己实现的约定包括：地址按 s/E/b 拆成标记、组号、块内偏移，LRU 的替换顺序，写命中与写缺失的策略（写回还是写直达、是否写分配），以及 `M` 要算一次 load 加一次 store。不可靠性来自 trace 是黑盒、地址空间远大于缓存，而**同组内的替换顺序会决定后面所有命中**——一个策略错误会放大成几百个计数差。所以验收方式是逐项相等，不是命中率接近；差 1 就说明替换或 `M` 的语义错了。更简单的做法（只用大数组按地址下标存取）等于假设全相联且容量无限，冲突缺失这一整个概念就消失了。

**用用户态代码重建一个 shell（替换 bash 的进程管理）。** 接口在系统调用层：`fork` / `execve` / `setpgid` / `waitpid` / `kill` / `sigprocmask` / `tcsetpgrp`。要自己定的约定：前台进程组与终端的归属、`SIGINT`/`SIGTSTP` 只发给前台进程组、Ctrl-Z 后作业进入 stopped 状态、`jobs`/`fg`/`bg` 的状态机、以及**谁负责回收**。不可靠性来自异步：`SIGCHLD` 可能在任意两条指令之间到达，与 `waitpid` 形成竞态——子进程在父进程进入阻塞之前就退出，信号被合并、丢失，作业表就漏项。压它的机制是信号屏蔽：`fork` 前阻塞 `SIGCHLD`，等父进程把 pid 写进作业表之后再解除，用 `sigprocmask` 手工构造临界区，而不是靠 `sleep` 撞运气。更简单的做法是直接 `system()` 或让子进程不换进程组——前者丢掉作业控制，后者会让 Ctrl-C 把 shell 自己一起杀掉。

**用自己写的分配器替换 glibc 的 malloc。** 接口只有 `mm_malloc` / `mm_free` / `mm_realloc` 三个函数，加一块由 `memlib` 提供的模拟堆（一段定长数组 + 一个 `brk` 指针），完全不碰真实内核的 `brk`/`mmap`。要自己实现的约定：对齐粒度、块头里塞大小与分配位、空闲块合并的时机、`realloc` 的原地扩展与搬移、分离空闲链表的大小类划分。不可靠性来自**碎片化是长期累积的**：每一次操作都合法，序列拉长之后大块请求开始失败；而堆破坏表现为延迟崩溃，崩的地方离出错的地方很远。压它的机制是双指标加一个检查器：利用率不允许靠浪费对齐来刷，吞吐不允许靠不合并来刷，两边互相牵制；再写一个 `mm_checkheap`，在操作后遍历整堆，验证块边界、空闲链表一致性、无重叠——把「看不见的破坏」变成当场断言。更简单的做法是包一层系统 malloc 或用定长块池：前者彻底跳过碎片化，后者在混合尺寸下利用率会掉到三成以下。

**自己走通一次链接（替换 ld 的部分职责）。** 输入是若干可重定位目标文件和静态库，输出是可执行文件。约定要自己实现：ELF 头与节头表、符号表里 global/weak/local 的绑定、符号解析规则（强符号唯一、弱符号让位、未定义最后才报错）、静态库「按需拉取且顺序敏感」、重定位条目里加数与 PC 相对地址的计算。不可靠性来自目标文件的形状不统一和库顺序带来的不确定性。压它的机制是与参考链接器的输出逐节比对，并让诊断信息与 ld 对齐。更简单的做法是直接让 gcc 去链——那第七章就只剩名词了。

## 三、章节大纲

1. **位与整数**——补码的模运算、移位语义、溢出判定、用位运算实现加减乘除与比较。做完能验证：在不用算术运算符的前提下，所有整数用例与参考实现逐位相等。
2. **浮点**——IEEE 754 三段拆分、规格化/非规格化/特殊值、round-to-even、整数与浮点的双向转换。做完能验证：`floatScale`、`floatFloat2Int` 在边界（`Tmin`、`-0.0`、`Inf`、`NaN`）上与硬件结果一致。
3. **汇编与过程调用**——寄存器用途与调用约定、栈帧布局、控制流的还原（跳转表、循环）、返回地址与缓冲区溢出的原理。做完能验证：给定一段无反汇编的机器码，能逐函数讲出参数在哪、局部变量在哪、返回值在哪。
4. **存储层次与 Cache**——局部性、地址拆分、直接映射/组相联/全相联、LRU 与写策略、分块转置。做完能验证：自建模拟器输出的三个计数与参考逐项相等；分块转置的缺失数随块长呈现预期的 U 形。
5. **链接**——ELF 结构、符号解析、重定位、静态库与共享库的差别。做完能验证：自建链接器对给定目标文件集合产出的可执行文件能正确运行，且符号冲突的报错与参考一致。
6. **进程与信号**——进程创建与替换、进程组、作业控制、信号语义与阻塞、竞态的产生与消除。做完能验证：作业控制在 Ctrl-C / Ctrl-Z / `fg` / `bg` 的各种交错下状态正确，且不留下僵尸进程。
7. **堆管理**——块布局与对齐、隐式/显式空闲链表、分离适配、合并与 `realloc`、堆检查器。做完能验证：利用率与吞吐双指标同时达标，且每次操作后堆检查器无告警。
8. **并发**——线程与共享状态、互斥量与信号量、生产者—消费者、预线程化服务器、用竞态检测工具定位数据竞争。做完能验证：压力下结果正确、无死锁、检测工具报告干净。

## 四、不做什么 · 必要性 · 失效点

### 必要性：删掉会怎样

| 机制 | 删掉会怎样 | 判定 |
|---|---|---|
| 静态检查器（只允许 `~`、`&`、`^`、\|、`<<`、`>>` 与有限常数） | `bitAnd`、`logicalShift`、`floatScale2`、`floatFloat2Int` 可用 `if`、循环、强转绕过，补码 `Tmin` 取负、算术右移/逻辑右移、IEEE 754 非规格化隐含位 0、round-to-even、NaN 比较、向零截断溢出的逐项相等承诺破 | 必需 |
| `s/E/b` 地址拆分、`LRU`、`M` 一次 load 一次 store | Cache 模拟器 hit/miss/eviction 三个计数不再逐项相等；同组替换顺序错误会放大成几百个计数差，写回/写直达/写分配策略错会让 `M` 的 eviction 差 1 | 必需 |
| `sigprocmask` 阻塞 `SIGCHLD` 的 `fork`/`execve`/`setpgid`/`waitpid` 临界区 | 子进程在父进程写入作业表前退出时 `SIGCHLD` 被合并/丢失，`jobs`/`fg`/`bg` 状态机漏项，`SIGINT`/`SIGTSTP` 可能发给错误进程组或 shell | 必需 |
| `mm_checkheap` 遍历块头/空闲链表一致性 | `mm_malloc`/`mm_free`/`mm_realloc` 造成的块边界重叠、空闲链表断裂只在后续 `brk` 访问时延迟崩溃，操作后无法当场断言 | 必需 |
| 分离空闲链表的大小类划分 | 单一空闲链表仍可维持 `mm_malloc`/`mm_free`/`mm_realloc` 不崩，但混合尺寸序列下大块请求因外部碎片失败，利用率与吞吐互相牵制的双指标变松 | 选择 |

### 失效点：哪条前提一破，结论就变

- `x86-64 SysV ABI 下 `call` 压返回地址、`ret` 弹栈，`%rsp`/`%rbp` 栈帧链不变 → 汇编过程调用与栈帧的逐指令对齐成立；若启用 shadow stack 或 CFI 把返回路径改成异常表，`ret` 地址和 `%rbp` 链断言变。
- `Linux 的 `SIGCHLD` 在 `sigprocmask` 屏蔽期间只记一次、`waitpid(-1,...,WNOHANG)` 对未退出子进程返回 0 → shell 作业表临界区成立；若内核实时排队 `SIGCHLD` 或 `tcsetpgrp` 权限位改变前台组，`Ctrl-Z` 后 stopped 状态和 `jobs`/`fg`/`bg` 迁移变。
- `memlib` 的模拟堆用定长数组 + `brk` 指针且块头按 16 字节对齐 → `mm_checkheap` 能验证块边界/空闲链表一致性；若把 `brk` 换成 `mmap` 多段非连续页，块头遍历会跨页断裂，堆破坏从延迟崩溃变成 `mm_checkheap` 当场断言失效。
- ELF `STB_GLOBAL`/`STB_WEAK` 绑定与 `R_X86_64_PC32` 加数规则、静态库归档

### 不做什么（范围）

不做内核态的东西：不写系统调用、不写页表硬件、不实现真实的虚拟内存换页，`memlib` 是纯用户态模拟。

不追求满分性能：分配器的吞吐不刷到参考值的极限，够达标即止；性能调优的通用方法论（profiling 驱动的迭代）不在范围内。

不写攻击载荷：缓冲区溢出只读到原理层——栈帧、返回地址、栈随机化与不可执行栈的作用，不实际构造 getshell 的字符串。

不做网络与协议：代理服务器、HTTP 解析属于另一个项目；这里的并发停在「多线程正确性」这一层。

不教语言：不教 C 语法、不教 Makefile 写法、不教 gdb 基本命令，这些是前置。

不写测试框架本身：判分器、trace 回放器、参考实现视为给定，被测文件不得依赖任何测试头文件、不得读 trace、不得按输入特判——这条是硬边界，越界即视为未完成。

实现自由度在于：分配器用隐式还是显式链表、分离适配分几类、Cache 模拟器的数据结构、shell 的作业表组织方式，都可以自选，只要对外行为对齐。常见跑偏是「先优化再定指标」——先把结构写漂亮，再去凑利用率，最后发现碎片化来自最初的对齐选择，只能推倒重来。

## 五、面试怎么讲

### 30 秒版本

面试开场可以这样说：

> 「这个项目把 CSAPP 前九章里五块最容易被背过去的机制——位级表示、Cache 映射、链接、进程与信号、堆分配——各做成一个必须与参考实现逐项对齐的任务。要解决的不是『能跑』，而是把模糊的机制描述压成一组能通过的断言。卡点在边界和异步：`Tmin` 取负、`-0.0`、`SIGCHLD` 与 `waitpid` 的竞态、碎片化长期累积。验证口径是逐项相等：位运算逐位对拍，Cache 三个计数差 1 就算错，作业状态在各种交错下正确且无僵尸，分配器双指标加堆检查器。」

### 可能被追问的 7 个点

**1. 他问：位运算实验为什么不直接写 `a & b`，为什么不用 Python？**
真实考点：你懂不懂「限制语言能力」本身就是在逼出原理，不是会不会写。
怎么答：被测文件只允许 `~ & ^ | << >>` 和有限常数，禁循环、条件、调用、强转；`bitAnd` 要写成 `~(~x | ~y)`。Python 的整数没有位宽，溢出和非规格化根本不存在，等于把要学的东西绕过去。边界上：`logicalShift` 在 n=0 时不能算 `x >> 32`，C 里移位量不小于位宽是未定义行为，要单独分支；`isLessOrEqual` 不能直接取 `x - y` 的符号位，溢出会翻号，要先用 `x ^ y` 分同号/异号两支再取符号。

**2. 他问：`floatFloat2Int` 的边界怎么处理？**
真实考点：IEEE 754 拆分和向零截断，不是「调个强转」。
怎么答：拆符号位、8 位阶码、23 位尾数；规格化数隐含位 1，非规格化数隐含位 0；`NaN` 和 `Inf` 返回 `0x80000000`；阶码 `>= 31` 返回溢出值，`< 0` 返回 0；`-0.0` 返回 0。舍入看 guard 和 sticky 两位做 round-to-even。`floatScale2` 要单独处理阶码全 1 的特殊值，以及非规格化时左移尾数。

**3. 他问：Cache 模拟器里 `M` 怎么算？为什么差 1 就算错？**
真实考点：写策略和替换语义，不是命中率高低。
怎么答：`M addr,size` 是一次 load 加一次 store；写命中要看写回还是写直达、是否写分配。LRU 用组内时间戳，命中更新时间戳，缺失替换时间戳最小的那一路。同一组内的替换顺序会决定后面所有命中，一个策略错误会放大成几百个计数差，所以验收是逐项相等，不是「接近」。

**4. 他问：shell 里 `SIGCHLD` 和 `waitpid` 的竞态怎么消？**
真实考点：异步信号与临界区，不是「会不会 fork」。
怎么答：子进程可能在父进程进入 `waitpid` 阻塞之前就退出，`SIGCHLD` 被合并或丢失，作业表就漏项。做法是 `fork` 前用 `sigprocmask` 阻塞 `SIGCHLD`，父进程把 pid 写进作业表后再解除；等待用 `sigsuspend`，不是 `sleep` 撞运气。前台进程组用 `tcsetpgrp` 交给子进程，子进程 `setpgid` 换组，否则 Ctrl-C 会把 shell 自己一起杀掉；`SIGINT`/`SIGTSTP` 只发给前台进程组。

**5. 他问：分配器怎么防止「跑通但实现错了」？**
真实考点：碎片化和堆破坏都是延迟暴露的。
怎么答：堆破坏崩的地方离出错的地方很远，所以写 `mm_checkheap`，每次操作后遍历整堆，验证块边界、空闲链表一致性、无重叠。利用率和吞吐互相牵制：靠浪费对齐刷利用率、靠不合并刷吞吐，都会被另一指标打回。对齐粒度、合并时机、`realloc` 原地扩展还是搬移，是最初就要定的，不能先写漂亮再凑指标。

**6. 他问：链接器的符号解析规则是什么？**
真实考点：强/弱/未定义符号和静态库顺序。
怎么答：强符号唯一，重复定义报错；强弱并存取强；全是弱取一个；未定义最后才报错。静态库按需拉取且顺序敏感，后面的库不会回头解析前面已经解析完的未定义。重定位里 PC 相对是 `S + A - P`，绝对地址是 `S + A`；ELF 符号表 `st_info` 的高 4 位 bind 字段区分 local/global/weak。

**7. 他问：并发服务器怎么证明没有竞态？**
真实考点：正确性口径和工具，不是「跑起来没崩」。
怎么答：压力下结果正确、无死锁、竞态检测工具报告干净。预线程化服务器要讲清共享队列的互斥量和条件变量、生产者—消费者模型、`accept` 返回值的处理。不能说「跑了几次没崩」，那是没测过，不是没竞态。

### 别说什么

- **别说「跑通了就是对的」。** 这个项目的验收口径是逐项相等：Cache 三个计数差 1 就是替换或 `M` 的语义错，分配器延迟崩溃说明堆破坏早就发生了。把「能跑」当「实现对了」会直接露怯。
- **别把现成组件当原理讲。** 「我用 gcc 链的」「我调了 `system()`」「我用 Python 写的位运算」——这三句等于承认替换点没做，面试官会立刻追问到答不上来。
- **别报没按口径测过的数字。** 命中率、吞吐、提升倍数，没测过就不要说；要说效果，就说「用什么口径能验证」，而不是给一个没来源的数。
- **别说「我全部实现了」「全绿」。** 可以说「我按这个口径验证到哪一步、哪块边界还没覆盖」，把完成度讲成可核对的进度，而不是一句结论。
