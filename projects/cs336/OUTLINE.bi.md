## 1. What it does

This project does something very concrete: build the complete pipeline of a decoder-only language model, from raw text all the way to a small model that can answer according to instructions, without calling ready-made components such as `transformers`, `tokenizers`, or `tiktoken` in between. The input is plain-text corpora: short stories or general text for pretraining, instruction-answer pairs and preference pairs for alignment; the output includes three things: a byte-level BPE tokenizer trained by ourselves (vocabulary and merge rules), a Transformer checkpoint (including config and training logs), and an inference script that can load the checkpoint and perform token-by-token generation. Acceptance does not look at "how big the model is", but at four things: the tokenizer is reversible for any UTF-8 text, and the token id sequence on fixed samples matches the reference implementation; the model forward satisfies the shape contract, and short-sequence logits are equivalent with cache off and cache on; the pretraining loss steadily decreases, and generated short sentences are grammatical; after SFT/DPO, the preference win rate on a held-out instruction set has a measurable improvement over the base model. The scale is kept trainable on a single GPU; the goal is "complete pipeline, trustworthy numerics", not leaderboard chasing.

## 2. Why do it this way (functional design)

**1. Tokenizer: replace `tiktoken`/`tokenizers`, with the interface at the "text ↔ id" layer.** Implement byte-level BPE ourselves: first split text into pre-tokenization chunks according to a GPT-2-style regex, then convert each chunk to UTF-8 bytes and map them to visible characters with byte-to-unicode, count adjacent pairs, merge by frequency, and fix merge rules by rank; when encoding, apply merges from small rank to large, and fall back to bytes for unseen characters. The replacement point is not in the training script, but at the function boundary of `encode/decode` and `train_bpe`: upper layers only see `list[int]`, not Rust or cache. Unreliability mainly comes from Unicode normalization, regex splitting on whitespace/punctuation, special token boundaries, and tied frequencies during merging; countermeasures are byte fallback to ensure any string is encodable, deterministic tie-break for merge ordering, special tokens split first before BPE, and per-id comparison against the reference plus round-trip validation on a fixed corpus. A simpler approach is to install `tiktoken` directly, at the cost that the merge loop, cache, and byte mapping are all hidden, leaving no handle later when debugging "why is the id different for the same word".

**2. Model: replace `nn.Transformer`/`nn.MultiheadAttention`, with the interface at `forward(tokens, kv_cache=None) -> logits`.** Internally write QKV projection, multi-head reshape, `QK^T/√d`, causal mask, softmax, and output projection; the structure uses pre-norm RMSNorm, RoPE, SwiGLU, residual connections, and tied embedding; overall it is a modern Llama-style decoder, not the 2017 original. The shape contract is fixed: input `(B,T)` integers, output `(B,T,V)`; each layer cache is a K/V list of `(B, n_head, T, head_dim)`. Why not use libraries: libraries hide whether the mask is added before or after softmax, whether the scale is divided, and how the cache position offset is handled—these three places are exactly where language models most easily go wrong. The cost is that self-written attention is slower and more coarse in memory, so only leave room at the interface layer for "replaceable with fused attention later", and do not pursue throughput in the first version.

**3. Data: compress text into a flat token stream, not sample by sample.** Pretraining data is first encoded into an `int32` `tokens.bin`; during training, use memmap to randomly take `(B,T)` windows, and labels are the input shifted right by one; only in the SFT stage are chat templates and loss masks introduced, computing loss only on the assistant segment. Unreliability comes from duplicate text, document boundaries, and special tokens: use an EOD token to split documents, deduplicate, and sample with a fixed random seed to suppress it. A simpler approach is to pad each sample separately, at the cost of wasting a lot of compute, and if padding positions are forgotten in the mask, it directly teaches the model to generate padding tokens.

**4. Training: use warmup + cosine, gradient clipping, and AdamW to turn "can train" into "can train stably".** Language models have large early gradients; a constant learning rate easily diverges in the first few hundred steps; warmup reduces the update magnitude, cosine fine-tunes later; clipping handles occasional spikes. Numerically use fp32 as the baseline, with bf16 only as a throughput option, and do not touch fp16 loss scaling, avoiding numerical issues interfering in the teaching phase. A simpler approach is "Adam + fixed lr", at the cost of more time tuning and not being reusable across scales.

**5. Alignment: after SFT connect DPO, do not touch PPO/GRPO.** SFT uses instruction-answer pairs for next-token, but only computes loss on the answer segment; DPO uses preference pairs, freezes a reference model, and directly optimizes "the implicit reward difference of chosen relative to rejected". The interface is at the "chat template + loss function" layer: the model itself is unchanged; what changes is data organization and loss. Why not RLHF: the reward model + sampling + PPO pipeline is too long, and sampling variance masks implementation errors; DPO is a static classification-style objective, easy to reproduce. The cost is that DPO is sensitive to beta, length bias, and data quality, so acceptance must use win rate on held-out prompts, not training-set loss.

**6. Inference: KV cache is a first-class module, not an after-the-fact optimization.** Generation is split into prefill and decode: prefill consumes the full prompt to build the cache, decode feeds only one new token per step and appends historical K/V. Sampling supports temperature, top-k, and top-p. A simpler approach is to recompute the full sequence every step, at the cost of quadratic slowdown as generation length grows; the cost of the cache is more state, so semantics must be fixed with "short-sequence cache output consistent with no-cache output".

## 3. Chapter outline

1. **Engineering foundation and numerical contract**: config dataclass, random seed, logging, shape assertions, device management. Knowledge points: reproducibility, tensor shapes, config-code separation. After completion can verify: loss of two forwards under the same seed is identical, and input/output shapes of all modules conform to the contract.
2. **Byte-level BPE tokenizer**: UTF-8 bytes, byte-to-unicode, GPT-2 regex pre-tokenization, pair counting and merging, special token. Knowledge points: BPE training algorithm, rank encoding, reversibility. After completion can verify: encode/decode round-trip for any UTF-8 text; token ids on a fixed corpus match the reference implementation id by id.
3. **Data pipeline and training samples**: token bin to disk, memmap, random windows, document boundary EOD, SFT loss mask. Knowledge points: flat token stream, sampling, padding and mask. After completion can verify: batch shape correct; cross-document samples do not concatenate different documents into one sentence; SFT backpropagates gradients only on the answer segment.
4. **Transformer skeleton**: Embedding, Block stacking, pre-norm residual, LM Head, initialization. Knowledge points: residual stream, parameter sharing, deep initialization. After completion can verify: forward output `(B,T,V)`; small batch overfits to near-zero loss; parameter count matches config.
5. **Attention and positional encoding**: QKV, multi-head reshape, `QK^T/√d`, causal mask, softmax, RoPE, KV cache interface. Knowledge points: scaled dot-product attention, causality, rotary positional encoding, cache increment. After completion can verify: changing future tokens does not affect past logits; logits of short-sequence cache and no-cache match within numerical error.
6. **Modern components and training stability**: RMSNorm, SwiGLU, weight tying, AdamW, warmup+cosine, gradient clipping, bf16 comparison. Knowledge points: normalization placement, activation functions, optimizer hyperparameters, mixed precision. After completion can verify: training for several thousand steps produces no NaN; loss curve has no sustained divergence; turning off warmup shows early spikes.
7. **Small-scale pretraining and evaluation**: TinyStories-level data, cross-entropy/perplexity, generation samples, sampling strategy. Knowledge points: next-token objective, evaluation set split, generation quality judgment. After completion can verify: model can generate grammatical short sentences; held-out set perplexity decreases with training; temperature/top-p changes output diversity.
8. **Inference optimization and generation boundaries**: prefill/decode, KV cache management, top-k/top-p, batching boundaries. Knowledge points: autoregressive decoding, cache lifecycle, sampling. After completion can verify: with cache enabled, generation speed is clearly higher than step-by-step recomputation; output is reproducible under fixed prompt and seed.
9. **Alignment: SFT and DPO**: chat template, SFT loss mask, preference pair construction, reference model freezing, DPO loss, beta. Knowledge points: instruction tuning, preference optimization, implicit reward. After completion can verify: after SFT the model can answer according to the template; after DPO the win rate on held-out preference pairs improves over the SFT base, and no obvious length stacking or repetition appears.

## 4. What not to do

Boundaries are clear:

- Do not do distributed training, DDP/ZeRO, or multi-GPU communication; running on a single GPU is a prerequisite.
- Do not hand-write CUDA/FlashAttention kernels; attention is first assembled with PyTorch operators, and replacing it with a fused implementation later is allowed, but it is not an acceptance item.
- Do not do full RLHF: do not train a reward model, do not write PPO/GRPO; the alignment ceiling is SFT + DPO.
- Do not pursue SOTA perplexity or large-scale data cleaning; do not do the full Common Crawl pipeline; data is mainly small public corpora.
- Do not do production-level serving: dynamic batching, quantization, speculative decoding, and beam search are not required; sampling up to top-p is enough.
- Implementation freedom: number of layers, width, number of heads, vocab size, whether to use weight tying, and whether to use bf16 can all be adjusted according to compute; but four things cannot change: reversibility of `encode/decode`, shape contract of `forward`, cache equivalence, and loss computed only on the target segment.
- Common deviations: using `transformers` tokenizer or model to "save effort"; forgetting to shift labels right by one; adding the mask after softmax; forgetting to divide by `√d`; KV cache position restarting from 0; DPO reference model not frozen; on the training prompt
