# algo/ · 路径手册

## 0 怎么用

- 练题型：§1 的题型表，按"关键一步"复盘，不要按题目顺序刷。
- 补实现：§2 的四个基础结构 + 树删除专项。
- 用工具：§3 的 sanitizer 流程。
- 准备追问：§4；避坑：§5。

## 1 八类题型：关键一步与边界

| 题型 | 关键一步 | 必须说清的边界 | 常见错法 |
|---|---|---|---|
| 数组与双指针 | 把"区间语义"钉死（闭/半开） | 空数组、单元素、全相同值 | 收缩条件与初始区间不匹配；窗口内状态回滚漏项 |
| 字符串 | 明确"子串 vs 子序列" | 空串、单字符、大小写/Unicode | 假设比较是 $O(1)$；用滑窗解子序列题 |
| 链表 | 先画指针图再写码 | 头结点、尾结点、单节点、环 | 断链顺序错；哑结点用了但返回没走哑结点 |
| 栈队列与堆 | 找出"单调性"或"优先级" | 重复元素、堆中元素被删除（延迟删除） | 单调栈弹出条件写反；top-k 用了全排序 |
| 树与图 | 定遍历序与访问标记时机 | 空树、单节点、重复边、有环 | BFS 出队才标记导致重复入队；拓扑排序没判环 |
| 二分与排序 | 区间闭合 + 单调性证明 | 目标在首/尾、目标不存在、全相同 | 循环条件与收缩方式不匹配（死循环/漏解） |
| 动态规划 | 状态定义 + 遍历顺序 | 空输入、单元素、负数、溢出 | 一维压缩后顺序错；初始化漏"不可能状态" |
| 回溯与贪心 | 搜索树剪枝 / 交换论证 | 重复元素去重、剪枝是否改变正确性 | 贪心无证明；回溯剪枝剪掉了合法解 |

**复盘方式**：每题只回答三句话——不变量是什么、上界是多少、哪三个输入会把它打挂。写不出第三句的，说明还没真懂。

## 2 实现侧：四个基础结构 + 树删除

**四个结构**（不看库手写，各自带边界用例）：

| 结构 | 必须处理的边界 | 判据 |
|---|---|---|
| 动态数组 | 扩容时机、缩容、迭代器失效 | 连续 push 到扩容点，观察容量与拷贝次数 |
| 哈希表 | 冲突（链地址/开放寻址）、负载因子、删除标记 | 构造碰撞输入，测最坏插入 |
| 二叉堆 | 上浮/下沉边界、`heapify` 与逐个插入的复杂度差 | 用随机数据对拍暴力排序 |
| 并查集 | 路径压缩 + 按秩合并、孤立点 | 随机合并/查询对拍暴力连通性 |

**树删除专项**（`algo/algorithm/` 的核心）：

```cpp
// BST 删除：三种 children 组合
// 0 个孩子：直接摘除
// 1 个孩子：孩子顶替
// 2 个孩子：找后继（右子树最小）替换值，再删除后继
```

**判据**：能画出"删除黑色节点后黑高不一致"的最小例子，并说清红黑树 fixup 为什么必须按兄弟颜色与其子节点颜色分情况；用自己写的不变量检查（每个节点左右黑高相等）在随机操作后自检。

## 3 工具：把"偶发崩溃"变成"最小复现"

```bash
clang++ -g -O1 -fsanitize=address,undefined t.cpp -o t && ./t
valgrind --leak-check=full --track-origins=yes ./t
```

**流程**（四步，缺一不可）：

1. **稳定复现**：固定随机种子、固定输入；
2. **缩小输入**：二分删数据 / 二分删操作序列；
3. **定位**：ASan 报告的"读/写越界 + 分配点 + 释放点"三处栈；
4. **归因**：写清"少写哪一行/多写哪一行会错"，而不是"改了就好了"。

**判据**：能交出一份四步记录，别人按它能在自己机器上复现同一个崩溃。

## 4 跨项目追问

1. **「为什么快排对已排序输入会退化？」** → 引出 pivot 选择与递归深度，再接到"最坏情况与期望复杂度的区别"。
2. **「B+ 树为什么适合做索引？」** → 与 `database/` 的索引章节交界：扇出高 → 树高小 → 磁盘 I/O 次数少。
3. **「哈希表在什么情况下比红黑树差？」** → 最坏情况、有序遍历需求、内存局部性；这也是 `cpp-basics` 里 `unordered_map` vs `map` 的判据。
4. **「你的结构在高并发下还成立吗？」** → 无锁化、伪共享（`eng/latent-issues`）、内存序（`langs/cpp-basics`）。
5. **「为什么用摊还分析而不是最坏情况？」** → 动态数组扩容、并查集路径压缩；要说清摊还的前提（操作序列而非单次）。

## 5 常见误配

| 误配 | 后果 | 正确做法 |
|---|---|---|
| 按题目顺序刷，不按题型复盘 | 见过很多题但讲不出关键一步 | 按题型归类，每题只记三句话 |
| 只写不验 | 边界错法在面试现场才暴露 | 每题准备三个打挂输入 |
| 遇到 bug 就重写 | 没有归因，下一次还错 | 走"复现→缩小→定位→归因"四步 |
| 把 `algorithm/` 当题库 | 它是实现体检，不是题解 | 题库在 `algorithm-interview/` |
| 报刷题量 | 过程指标冒充能力 | 换成"这类题的边界清单" |

## 6 一句话收口

**算法的分水岭不在"写出来"，而在"为什么对、多快、哪里会错"这三句能不能立刻说出口。**
