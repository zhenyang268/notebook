## 第 1 章 实验台

**要解决的问题**：把「复杂度」从背下来的结论换成自己数出来的量。墙钟时间在小 n 上被常数项淹没、在大 n 上被缓存与编译器优化改变斜率、换机器就全变；只有**机器无关的计数**能把实测值和理论式对上。这一章要解决的问题是：让计数**绕不过去**，而不是"顺手加个计数器"。

**机制**：把计数器嵌到**最底层原语**，而不是包在算法外面。

```c
#define LT(a, b)   (++cmp_cnt, (a) < (b))          // 元素比较
#define RELAX(u,v,w) (++relax_cnt, relax_impl(u,v,w)) // 图松弛
#define ENTER()    (++call_cnt)                     // 递归入口
```

三件事同时成立才算实验台可用：

1. **贯穿**：算法里不允许直接写 `a[i] < a[j]`，一律走 `LT`。漏一处，整条曲线就系统性偏低。
2. **确定性**：同一个种子、同样的输入，两次运行的计数必须完全一致；否则差异是噪声不是算法。
3. **可对拍**：自带暴力 oracle（n ≤ 10 时全排列/子集枚举/记忆化搜索），随机小实例上千组比对。

**最小例子**：六种输入形态 × 八个规模点，输出一张计数表。

| 形态 | 出现退化的典型算法 |
|---|---|
| 随机 | —（基准） |
| 已排序 / 逆序 | 固定取首元素 pivot 的快排 → 划分 1:(n−1) |
| 全相同 | 二路划分（用 `>=`）→ 深度 = n；三路划分 → 线性 |
| 几乎有序 | 插入排序反而最优，快排仍退化 |
| 少量不同值 | 基数计数、三路快排占优 |

判据：**只跑随机数据等于没测**——退化形态才是考点。

**面试高频问法**：

1. **「你怎么保证计数没漏？」** → 考点：计数层是否真的贯穿全部比较路径。答法：所有比较走同一个宏，`grep '<'` 检查裸比较；再跑一个反向用例——结果非平凡但计数为 0，说明有路径绕过了原语；最后用递归调用次数对账（归并的递归树节点数接近 $2n-1$）。
2. **「为什么不直接计时？」** → 考点：知不知道墙钟时间为什么不可用。答法：小 n 常数项淹没信号、大 n 缓存与优化改变斜率、换机器全变。计时不是不做，而是用来**交叉验证**——计数斜率是 2、时间斜率只有 1.2，说明顺序访问对缓存友好，这是能讲出来的观察，但主判据不能是时间。
3. **「怎么保证实验可复现？」** → 考点：随机源与输入管理。答法：固定种子、输入生成与算法彻底分离、每个规模点跑多次取中位数并记分布；单点数字支撑不了任何结论。

## 第 2 章 渐进度量

**要解决的问题**：从离散的计数点反推阶，并解释偏差。直接把两个数相除得到"几倍"没有意义，需要能区分 Θ/Ο/Ω，能说出"斜率 2.3 不是 2"的原因。

**机制**：

- **双对数最小二乘**：对 $\log T$ 与 $\log n$ 做线性拟合，斜率就是阶的估计；$n$ 的跨度至少两个数量级，否则低阶项主导。
- **偏差的方向是诊断信息**：斜率随 $n$ 增大单调趋近理论值 → 低阶项（$n\log n$ 里的那个 $n$ 不可忽略）；反过来越跑越大 → 实现有问题或计数漏了。
- **摊还**：动态数组扩容是 $O(n)$ 但摊还 $O(1)$；并查集路径压缩的摊还界接近常数。摊还的前提是**操作序列**，不是单次操作。

**最小例子**：三种排序的斜率应当分别落在 2（冒泡/插入最坏）、1.1–1.3（快排/归并的 $n\log n$ 在本机规模下的表观斜率）、1（计数排序）。

**面试高频问法**：

1. **「拟合出 2.3 不是 2，怎么解释？」** → 考点：会不会归因而不是硬凑。答法：三个来源——低阶项、常数项、拟合跨度不够；判据是**趋势**：单调趋近则可解释，越跑越大则是 bug 或漏计数。
2. **「Θ、Ο、Ω 各自回答什么问题？」** → 考点：是否只是会背符号。答法：Ο 是上界（"不会更慢"）、Ω 是下界（"不可能更快"）、Θ 是紧确界（两边夹）。工程上说"这个算法是 $O(n\log n)$"时通常想说的是 Θ，这是要主动澄清的地方。
3. **「摊还分析什么时候不适用？」** → 考点：前提条件。答法：摊还依赖操作序列的分布；单次最坏仍是 $O(n)$，实时性要求高的场景必须按最坏算。

## 第 3 章 分治

**要解决的问题**：把"递归树"从图变成可数的量。分治的代价由三件事决定：子问题规模怎么缩、合并代价多少、递归深度多深（深度决定栈空间，深了会爆栈）。

**机制**：

- **主定理**给出 $T(n) = aT(n/b) + f(n)$ 的三个分支，但工程上更常用的是**直接数递归树节点**：节点数 = 调用次数，每层的工作量相加。
- **划分不变式**：快排的 `partition` 必须保证"左侧 ≤ pivot、右侧 ≥ pivot、pivot 归位"，循环不变式写对了，边界（全等、已排序、双元素）才不会漏。
- **二分是分治的退化形态**：只有一支递归，但边界（闭/半开区间、`lo = mid + 1` 还是 `mid`）最容易错。

**最小例子**：归并排序的递归调用次数接近 $2n-1$（递归树节点数），与递归树推导一致；比较次数是 $O(n\log n)$，两者不要混。快排固定取首元素时，已排序输入每次划分 1:(n−1)，深度 = n。

**面试高频问法**：

1. **「快排什么时候退化，怎么缓解？」** → 考点：能不能落到具体实现。答法：固定 pivot + 已排序/逆序 → $\Theta(n^2)$；全等 + 二路划分（`>=`）→ 同样退化。缓解是随机 pivot、三数取中、三路划分、尾递归消除，四者针对的问题不同，要分开说。
2. **「归并和快排怎么选？」** → 考点：稳定性与内存的权衡。答法：归并稳定、$O(n)$ 额外空间、适合链表与外排序；快排原地、平均快、不稳定。工程上 `std::sort` 是内省排序（快排 + 堆排兜底 + 小数组插入）。
3. **「二分怎么写才不漏？」** → 考点：区间语义的闭合性。答法：先定区间是闭 `[lo,hi]` 还是半开 `[lo,hi)`，循环条件与收缩方式必须与之一致；用三个用例验（目标在首、在尾、不存在）。

## 第 4 章 贪心

**要解决的问题**：贪心最容易"看起来对"。例题能过、随机数据能过，但存在反例。这一章要解决的问题是：**用可证伪的手段代替"我觉得对"**。

**机制**：

- **对拍只能否证，不能证明**：$n \le 10$ 时用暴力求真正最优，上千组随机实例比对；不一致就 dump 实例。它的价值是"一个下午否掉一个错误假设"。
- **证明只能靠交换论证**：取最优解里第一个与贪心选择不同的元素，交换后不劣，归纳。写不出这一步，就说明贪心选择性质没被验证。
- **拟阵**是"贪心一定对"的结构性判据（独立集 + 交换性），点到为止即可。

**最小例子**：硬币找零，面值 $\{1,3,4\}$、目标 6：贪心给 $4+1+1$（3 枚），最优是 $3+3$（2 枚）。这个反例一句话就能打破"贪心总是对"。

**面试高频问法**：

1. **「你怎么知道你的贪心是对的？」** → 考点：是否清楚对拍的界限。答法：对拍只能否证；最终要留一份完整交换论证。边界：拟阵类问题（区间调度、Huffman）有结构性证明，非拟阵类只能逐个分析。
2. **「Huffman 为什么是最优前缀码？」** → 考点：交换论证的具体形状。答法：最低频的两个字符在某个最优树里一定是兄弟且最深（交换不增代价），合并后问题规模减一，归纳。
3. **「最小延迟调度为什么按截止时间排？」** → 考点：交换论证。答法：任意最优解中若存在逆序（$d_i > d_j$ 而 $i$ 在前），交换两者不增最大延迟，反复交换得到按 $d$ 排序的解。

## 第 5 章 动态规划

**要解决的问题**：DP 的两类错误——**状态漏维**（少记了影响未来的信息）与**填表顺序错**（依赖还没算完就用了）。只跑样例无法区分这两者。

**机制**：

- **双写对拍**：同一递推写两遍——自顶向下记忆化（状态就是函数参数，天然不会漏维）与自底向上填表（必须显式让依赖先算完）。两遍逐点比对，能区分"转移写错"和"顺序/边界写错"，因为两类错误表现不同。
- **顺序从依赖推出来，不背**：0-1 背包压成一维后容量必须**倒序**（正序会用到本轮已更新的值，等于变成完全背包）；矩阵链乘按区间长度从小到大，因为 $m[i][j]$ 依赖更短区间。
- **无后效性**：状态封装所有影响未来的信息，历史不影响后续最优值。

**最小例子**：0-1 背包一维写法

```c
for (int i = 0; i < n; ++i)
    for (int c = C; c >= w[i]; --c)      // 倒序：保证每件物品只用一次
        dp[c] = max(dp[c], dp[c - w[i]] + v[i]);
```

把 `c` 改成正序，同一份代码就变成"完全背包"——这就是"顺序是语义的一部分"的最小证据。

**面试高频问法**：

1. **「DP 怎么验证？」** → 考点：能否区分错误类型。答法：记忆化与填表逐点一致；再与 $n\le10$ 的暴力 oracle 一致。不一致时看表现：整片错 → 转移错；只在某些规模错 → 顺序或边界错。
2. **「一维压缩后为什么必须倒序？」** → 考点：依赖的是本轮还是上一轮。答法：0-1 背包依赖上一轮状态，倒序保证 `dp[c-w]` 还没被本轮更新；正序就会重复使用同一物品。
3. **「状态怎么定？漏维会怎样？」** → 考点：无后效性。答法：状态要封装所有影响未来的信息（例如"剩余次数""是否已用某操作"）；漏维的典型症状是记忆化与填表结果不一致，或对小规模正确、对大规模错。

## 第 6 章 图的表示与遍历

**要解决的问题**：同一张图，存储方式决定复杂度；同一段遍历，访问标记的时机决定正确性。这两点是图题最主要的失分来源。

**机制**：

- **两种存储的代价**：邻接矩阵 $O(V^2)$ 空间、$O(1)$ 判边；邻接表 $O(V+E)$ 空间、判边 $O(\deg)$。稠密图与稀疏图的取舍不是风格问题。
- **访问标记的时机**：BFS 必须在**入队**时标记，否则同一节点会多次入队（网格图上队列会膨胀）；只有在"允许重复扩展且按距离更新"的场景才在出队时判断。
- **拓扑排序两版**：Kahn（入度队列）判环靠"出队数 != 顶点数"；DFS 版判环靠回边（灰色节点）。两版序列可以不同，但都必须通过"所有边方向一致"的检查。

**最小例子**：含环图上 Kahn 会提前停（出队数 < V），DFS 版会遇到灰色后继——两种判环方式都要能写出来。

**面试高频问法**：

1. **「访问标记放入队还是出队？」** → 考点：去重时机。答法：入队标记；出队标记会导致重复入队、队列膨胀，在网格图与多路径图上尤其明显。
2. **「拓扑排序怎么判环？」** → 考点：两套判据。答法：Kahn 看出队数是否等于顶点数；DFS 看是否有回边（指向栈中节点）。
3. **「邻接矩阵和邻接表怎么选？」** → 考辨：规模与密度。答法：$E \ll V^2$ 用表；需要频繁判边或 $V$ 很小用矩阵；Floyd 必须矩阵。

## 第 7 章 带权图

**要解决的问题**：三个具体的边界——INF 相加溢出、负权让 Dijkstra 失效、负环无法求最短路。这三个都不是"理论上的例外"，而是写代码时必然撞到的东西。

**机制**：

- **INF 取值**：用 `0x3f3f3f3f3f3f3f3fLL`，两条 INF 相加仍远小于 `LLONG_MAX`；直接写 `LLONG_MAX` 相加是 UB。稳妥做法是松弛前 `if (d[u] == INF) continue;`。
- **Dijkstra 的正确性前提**：已出堆的节点距离不会再被松弛。有负权时这条不成立，所以它给的是错答案，而不是"慢一点"。
- **负环检测**：Bellman-Ford 跑到第 $n$ 轮仍能松弛，说明存在负环；从该点沿前驱走 $n$ 步必落在环上。
- **MST 的判据**：Prim 与 Kruskal 的**权和必须相同**，但**边集可以不同**——写清楚这一点，否则会把自己的正确结果误判成 bug。

**最小例子**：边 $1\to2$ 权 2、$1\to3$ 权 5、$3\to2$ 权 $-4$。真值 $d(2)=1$；Dijkstra 先弹出 2 并定死 2，之后不再更新，给出 2。这就是"正确性依赖"而不是"实现 bug"的最小证据。

**面试高频问法**：

1. **「Dijkstra 和 Bellman-Ford 结果必须一样吗？」** → 考点：松弛语义与前提。答法：正权图上距离数组必须逐点相同（路径可能不唯一）；负权时**必须不同**，并且要能指出是哪条边导致的。
2. **「负环怎么检测，为什么要跑 n 轮？」** → 考点：迭代次数的含义。答法：第 $k$ 轮保证最多 $k$ 条边的最短路已知，$n-1$ 轮后应全部收敛；第 $n$ 轮还能松弛就存在负环。
3. **「Prim 和 Kruskal 的 MST 边集一定相同吗？」** → 考点：是否会误判。答法：不一定，权和相同即可；等权边多时边集分歧很常见。

## 第 8 章 策略选择复盘

**要解决的问题**：同一个问题能用四种策略解，但它们在不同规模下的可用性完全不同。这一章要回答的是"什么时候该放弃精确解"。

**机制**：选一个能承受四种写法的问题（建议带权区间选择），把暴力、分治、DP、贪心四条曲线画在同一张图上。判据是**边界点**：哪条曲线在什么规模下超出可接受代价。

**最小例子**：带权区间选择——暴力是指数级、分治与 DP 是 $O(n\log n)$、贪心只在无权情形正确。把"贪心为什么在带权时失效"讲成一个具体反例，比讲一百句"贪心不保证最优"有效。

**面试高频问法**：

1. **「同一个问题，你怎么决定用哪种策略？」** → 考点：能否按约束选型。答法：看是否有最优子结构（DP）、是否能交换论证（贪心）、是否能合并子问题（分治）、规模是否小到可枚举（暴力）；再按上界落在哪个规模段决定。
2. **「贪心失效的判据是什么？」** → 考点：结构性判据。答法：找不到交换论证的交换步骤、或存在"局部最优解把后续更优结构破坏掉"的反例，就是失效。

| A6 | KMP 失配用 `j = next[j]` 而不是 `next[j-1]` | 特定串（如 `AAB`）死循环 | 前缀表语义与下标约定不一致 | `408-DS-0204` 串与 KMP 的 next 数组定义 |
| A7 | 并查集 `unite` 缺同根守卫 | 重复 `unite` 后 size/weight 翻倍 | 同一集合被合并到自己 | `408-DS-0406` 并查集与按秩合并 |
| A8 | 哈夫曼内部结点成员未初始化 | 潜在未定义行为（换编译器/内存填充才暴露） | 构造函数未初始化指针 | `408-DS-0405` 哈夫曼树与 WPL |
| A9 | 头文件不自包含（缺 `<vector>`/`<cassert>`） | 单独实例化模板就编译失败 | 模板体在实例化时才检查，平时测不出来 | 工程类：模板实例化检查 |

**用法纪律**：反例的价值不在"我修过"，而在**能说清触发条件与判据**。每讲一条，必须给出"怎么复现"和"修完用什么验证"——否则只是故事。

## 附录 B 可复查的数值

以下数字都是实算/实测得到的，面试时可直接报；换口径（页大小、块大小、阶数）后要重算。

| 项 | 结果 | 算法 |
|---|---|---|
| $m=100$ 的三层 B+ 树最多关键字 | 999999 | $99\times(1+100+10000)$ |
| 高度上界 $h \le \log_{\lceil m/2\rceil}\frac{n+1}{2}+1$ | $m=3,n=100$ → 6.66；$m=100,n=999999$ → 4.35 | 代入实算 |
| 1 GB / 4 KB 的总块数 | 262144 | $2^{30}/2^{12}$ |
| 置换-选择平均段长倍数 | 内存 100→1.98×；1000→1.82×；2000→1.67× | 独立实现 + 随机数据实测 |
| 9 段、$k=3$ 的归并趟数与代价 | 补 0 虚段；哈夫曼 223，平衡归并 242（省约 7.9%） | 逐次合并验算 |
| 虚段数公式 | $(k-1)-(n-1)\bmod(k-1)$ | $n=2..11$、$k=3/4$ 穷举一致 |
| B+ 树 4 KB 块的分支因子 | 内部（8 B key + 8 B 指针）→ 255 个 key；叶子（+100 B 数据）→ 37 条记录 | 按块大小实算 |
| 1 亿记录、分支因子 510 的树高 | 3 层 | 实算 |

**一条经验**：置换-选择那个"看起来对但没生效"的 bug（内存限制没真正生效，全部数据挤进一段）只能靠实测发现——和附录 A 的不变量检查是同一个道理：**没有独立判据的实现，等于没有验证**。
