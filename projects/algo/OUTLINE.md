# algo/ · 算法能力

> 分组目录：把「实现得对不对」和「现场解得出来吗」放在一起。两个子项目各自两件套，本文只做路由。

## 一、这个目录是什么

| 子项目 | 回答什么 | 判据 |
|---|---|---|
| `algo/algorithm/` | **代码基座体检**：B+ 树/红黑树删除崩溃、边界条件、ASan 定位记录 | 能复现崩溃、定位到具体分支，并说清"少写哪一行会错" |
| `algo/algorithm-interview/` | **题型题库**：8 类题型 × 8–10 题，每题给「关键一步 + 边界 + 常见错法」 | 五分钟内识别题型、给出可证明的解法、列出边界清单 |

八类题型：数组与双指针、字符串、链表、栈队列与堆、树与图、二分与排序、动态规划、回溯与贪心。

**一句话定位**：`algorithm/` 管**代码能不能扛住边界**（实现正确性 + 工具定位），`algorithm-interview/` 管**现场能不能快速收敛**（题型识别 + 证明 + 边界）。两者共同的敌人不是"不会写"，而是**边界与证明**：树删除少处理一种children 组合、二分少一个等号、DP 少一维状态——都是同一类错误。

**入口（本文的读法）**：在限时现场、代码可执行、错误可复现的约束下，algo 把每个子项目按“数据结构不变量 + 边界分支 + 可证明关键一步 + 工具定位记录”来读，algorithm/ 对应 B+ 树/红黑树删除的 children 组合、空/单元素/重复/越界分支、ASan 栈帧与最小复现输入，algorithm-interview/ 对应 8 类题型的题型识别、循环不变量/区间闭合性/堆序/状态转移、边界清单与常见错法。换的是题面、语言、状态表示和面试追问。不换的是用边界与证明收敛问题。

**不换的是什么**：全程不变的是数据结构不变量（父子指针、区间闭合性、堆序、访问标记、状态转移合法性）、边界集合（空/单元素/重复/越界/删除后 children 组合/等号与开闭区间）、证明依据（循环不变量、数学归纳、反证、交换论证）和定位手段（ASan 报告栈帧、断言、最小复现输入）；看到差异先问这四样是否同构，而不是问“写法是否不同”。

## 二、为什么这样分组（功能设计）

**取舍一：为什么合在一起而不是各自单列。** 两个目录名字几乎一样，分开放在顶层时读者要在两处之间跳；但它们服务的场景确实不同——一个是"我的实现有 bug，怎么定位"，一个是"面试官出了一道题，怎么开口"。放在一起能把关系说清：**题库给你题型骨架，基座体检给你实现细节与工具手感**。面试里最强的一句往往是"这个结构我实现过，删除时那两种 children 组合最容易错，我用 ASan 复现过"。

**取舍二：为什么不并入 `cpu/` 或 `eng/`。** 算法既不涉及硬件执行（`cpu/`），也不是流程方法（`eng/`）；它有独立判据（正确性证明 + 复杂度上界 + 边界清单），放别处会被稀释。

**取舍三：为什么不把 `discrete-math/` 拉进来。** 离散数学是"结论落到代码里长什么样"的数学基础，服务多个方向（图论服务算法、布尔服务电路）；拉进 `algo/` 会把它窄化成"算法前置课"，反而削弱它。它留在顶层。

**分组只做路由**：两个子项目仍各自五段。

## 三、推荐顺序与判据

面试权重：题库是主战场，基座体检是加分项。

| 阶段 | 内容 | 判据 | 成本 |
|---|---|---|---|
| 1（必做） | `algorithm-interview/` 八类题型，每类 3–5 题 | 五分钟内说出题型、关键一步、复杂度上界、三条边界 | 大（持续） |
| 2（必做） | 手写四个基础结构：动态数组、哈希表、堆、并查集 | 能不看库写出并通过自己的边界用例（空、单元素、扩容、删除） | 中 |
| 3（建议） | `algorithm/` 的树删除与 ASan 记录 | 能说清 BST/红黑树删除的三种 children 组合与各自的 fixup 路径 | 中 |
| 4（加分） | 用工具定位一个自己写的 bug（ASan/UBSan/valgrind） | 能给出"最小复现 + 定位结论 + 修复"，而不是"改了几行就好了" | 小 |

**一条硬判据**：每道题/每个结构都要能回答三件事——**为什么对（不变量）、多快（上界）、哪里会错（边界清单）**。缺一件就只是"写出来了"。

## 四、不做什么 · 必要性 · 失效点

### 必要性：删掉会怎样

| 机制 | 删掉会怎样 | 判定 |
|---|---|---|
| `B+ 树/红黑树删除崩溃` | `algorithm/` 的“能复现崩溃、定位到具体分支”承诺破；删除时少处理一种 `children` 组合不再被样例捕获，`node->children[i]` 的越界读/UAF 只在随机运行时暴露。 | 必需 |
| `ASan 定位记录` | 删掉后，`heap-buffer-overflow` / `use-after-free` 只能靠 `gdb bt` 猜调用栈，无法给出“少写哪一行会错”的具体分支。 | 必需 |
| `关键一步 + 边界 + 常见错法` | `algorithm-interview/` 退化为题号列表；五分钟内无法从“栈队列与堆”落到 `pop()` 前判空或堆顶 `sift-down` 边界。 | 必需 |
| `二分少一个等号` | 删掉后，`while (left <= right)` 与 `mid` 更新边界失去对照，`[left, right]` 闭区间不收敛的错误不能写成可检查清单。 | 必需 |
| `分组只做路由` | 删掉后，`algorithm/` 与 `algorithm-interview/` 仍各自五段，但 `children` 组合错误 ↔ 题型边界映射丢失；面试表达无法把实现细节接到 `边界清单`。 | 选择 |

### 失效点：哪条前提一破，结论就变

- `-fsanitize=address` 与 `ASAN_OPTIONS=halt_on_error=1` → 若缺失，`algorithm/` 无法稳定停在 `node->children[i]` 越界读/UAF 行，定位记录只能转入 `gdb bt` 或 core dump。
- B+ 树页大小固定为 `4096` 且 `min_degree = 2` → 若页大小或最小度数改变，`children` 组合的分裂/合并边界清单需重算，“少处理一种 children 组合”不再是同一错误。
- 红黑树删除保留 `NIL` 哨兵且 `color` 位用于 `red/black` 判定 → 若去掉哨兵，`parent/sibling` case 表从 8 类变 12 类，ASan 复现的崩溃分支与“少写哪一行会错”的结论变。
- 二分查找采用闭区间 `[left, right]` 且循环条件 `while (left <= right)` → 若改成半开 `[left, right)`，`left = mid + 1` / `right = mid` 的等号与收敛条件变，“少一个等号”不再是通用边界错法。
- DP 使用显式二维表 `dp[i][j]` 且转移读取 `dp[i-1][j]`、`dp[i][j-1]` → 若改成滚动数组 `dp[j]`，边界清单从“少一维状态”变成“更新顺序/覆盖旧值”，证明与边界检查项变。

### 不做什么（范围）

**不做题海。** 目标是题型识别与证明，不是刷题量；同一题型 3–5 题足够覆盖变体。

**不做竞赛算法。** 网络流、后缀自动机、复杂数论只在 `discrete-math/` 里作为结论出现，不作为算法面试内容。

**不做 STL/标准库复刻。** 手写结构的目的是理解边界，不是替代标准库；写完不用，也不追求性能。

**不做算法课教材。** 复杂度分析的基本功不重讲，只讲"这道题的关键一步在哪、边界在哪"。

**不写进度与刷题计数。** 「刷到第几题」是仓状态，不是能力。

## 五、面试怎么讲

**30 秒版本**（开场直接说，110–160 字）

> 算法这块我按两条线准备：一条是题型——八类常见题型我都能在五分钟内识别出骨架、给出可证明的解法并列出边界；另一条是实现的坑——常见结构我手写过，知道树删除的哪种 children 组合最容易漏、二分哪个等号会导致死循环，也能用 ASan/valgrind 把这类问题定位成最小复现。所以我不靠"刷过多少题"自证，而是靠"为什么对、多快、哪里会错"这三件事。

**可能被追问的 7 个点**

1. **「二分怎么写才不漏？」** → 考点：区间语义的闭合性。
   → 答法：先定区间是闭 `[lo,hi]` 还是半开 `[lo,hi)`，再定循环条件与收缩方式，两者必须匹配；`lo = mid + 1` / `hi = mid - 1` 对应闭区间，`hi = mid` 对应半开。判据：三种典型用例（目标在首、在尾、不存在）各跑一次。边界：`mid = lo + (hi - lo)/2` 防溢出，虽然在 64 位下几乎不会发生。

2. **「DP 的状态怎么定，为什么它无后效性？」** → 考点：状态定义与转移的充分性。
   → 答法：状态必须**封装所有影响未来的信息**；无后效性指"给定当前状态，历史不影响后续最优值"。判据：能说出"如果状态少记一维会漏掉哪类情况"。边界：一维压缩后遍历顺序必须保证依赖项是更新过的（背包倒序、区间 DP 正序）。

3. **「快排最坏 O(n²)，怎么避免？」** → 考点：随机化与工程权衡。
   → 答法：随机选 pivot 或三数取中把期望拉回 $O(n\log n)$；工程上对小数组切插入排序、对重复元素多的用三路划分。判据：构造已排序输入对比随机化前后。边界：最坏情况仍然存在，只是概率极低；`std::sort` 用内省排序兜底。

4. **「红黑树删除为什么要分四种情况？」** → 考点：实现细节而非结论。
   → 答法：删除黑色节点会破坏"黑高相等"，fixup 要按兄弟节点的颜色与其子节点颜色分情况（红兄弟、黑兄弟带红侄、黑兄弟带黑侄），核心手段是旋转 + 重新着色。判据：能画出"删除后黑高不一致"的最小例子；用 ASan/自检断言验证不变量。边界：很多人只记得"要旋转"，讲不出为什么必须按兄弟颜色分。

5. **「哈希表扩容为什么可能退化？」** → 考点：摊还与最坏情况。
   → 答法：扩容是 $O(n)$ 但摊还到每次插入是 $O(1)$；退化发生在哈希函数差或负载因子过高，冲突链变长。工程手段：开放寻址 + 好哈希（如乘常数取高位）、负载因子阈值、必要时转红黑树（如 Java 的 HashMap）。判据：构造碰撞输入测最坏插入耗时。

6. **「BFS 的访问标记该放在入队还是出队？」** → 考点：去重时机与状态重复。
   → 答法：入队时标记，否则同一节点会被多次入队（尤其网格图），队列膨胀；只有在"允许重复扩展且需要按距离更新"的场景才在出队时判断。判据：构造一个多路径到达同一节点的图，看队列长度的差异。

7. **「贪心为什么局部最优能到全局？」** → 考点：证明手段。
   → 答法：靠**交换论证**（把最优解的前缀替换成贪心选择而不变差）或**不变量**（每一步保持某个性质）。判据：能说出一个贪心失效的反例（如零钱面额 1/3/4 的找零），并指出反例破坏了哪条性质。

**别说什么**

- **「这题我刷过。」** 追问"为什么对"就停住；要讲关键一步与证明。
- **「复杂度是 O(n²)。」** 不说清 n 是什么（点数？边数？字符数？）等于没说。
- **「用哈希表就 O(1)。」** 不提最坏情况与哈希函数质量，是典型的不完整回答。
- **报刷题数量。** 那是过程指标，不是能力证明；换成"这类题我能给出边界清单"。
