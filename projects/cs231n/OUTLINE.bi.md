## 1. What It Is Doing

This project does one thing: hand-write the entire image-classification pipeline from start to finish using NumPy, without relying on any automatic differentiation in between. **Input** is a tensor of CIFAR-10 color images with shape $(N,3,32,32)$, pixels are integers from 0–255, paired with a class label from 0–9. **Output** is two things: a freely composable set of layers (linear layer, ReLU, SVM and Softmax loss, convolution, max pooling, batch normalization, Dropout), each with handwritten forward and backward passes; and a classifier trained with these layers, together with its training curves, confusion matrix, and misclassified-example visualization. The starting point is a parameter-free baseline like kNN; the endpoint is a small convolutional network with test accuracy in the 55%–65% range—not chasing records, only seeking to explain clearly why at every step.

**Acceptance** has three hard lines. First, every handwritten backpropagation must match central-difference numerical gradients, with relative error below $10^{-7}$; if any layer fails, do not proceed. Second, shrink the training set to 50 images, and the model must be able to overfit to 100% training accuracy—failure to do so indicates a bug in the implementation, not insufficient model capacity. Third, on the full dataset, the convolutional network must clearly exceed the linear softmax baseline, and this improvement must be decomposable and attributable: how much convolution contributes, how much batch normalization contributes, how much data augmentation contributes.

## 2. Why Do It This Way (Functional Design)

**Replace autograd with the cache convention.** The ready-made component that the entire project replaces is automatic differentiation. The interface is set at the layer level: `forward(x, params)` returns the output and a `cache`, `backward(dout, cache)` returns the gradient with respect to the input and the gradient with respect to the parameters. `cache` is the only information channel—this turns the chain rule from a mathematical proposition into an engineering constraint: if you forget to store some intermediate quantity during the forward pass, the backward pass simply cannot be written. What autograd did for you as a convenience now all has to be implemented yourself: parameter initialization, train/inference dual-mode switches, accumulation of moving statistics, gradients of regularization terms, optimizer state. The cost is that an incorrectly written gradient will not raise an error; it will only make training slower or converge to a worse point, so an independent judge is necessary.

**Numerical gradients are the only judge.** Use central differences $(f(x+h)-f(x-h))/2h$, with $h$ on the order of $10^{-5}$, throughout in float64; relative error uses $|a-n|/\max(|a|+|n|,10^{-8})$. Do not use forward differences (truncation error is $O(h)$, precision insufficient), and do not check in float32 (rounding error directly drowns the signal). Know two types of false alarms in advance: ReLU has unequal left and right derivatives near the kink, and in BatchNorm when the variance is close to zero the denominator amplifies error—when encountering these, first change the input sample or increase $h$, do not rush to change the code.

**Data shape and three types of unreliability.** Images are 4-D tensors of shape $(N,C,H,W)$, labels are 1-D integers. Unreliability comes from three places. Numerical level: directly computing $\exp$ in softmax will overflow, so the maximum must be subtracted first (log-sum-exp stabilization); cross-entropy will encounter $\log 0$; the variance of batch normalization may be zero. Shape level: if `reshape` and `transpose` are reversed, no error is raised; it just silently becomes slower or worse, and mixing $(N,C,H,W)$ with $(N,H,W,C)$ is the most common bug—the countermeasure is to hard-code the input/output shapes in the comments of every function and explicitly assert them in tests. Randomness level: initialization scale, shuffle, Dropout mask, and batch sampling can all make the conclusions of two experiments disagree; the countermeasure is to fix the seed, use a single configuration file, and change only one variable in A/B comparisons.

**Why convolution must go through im2col.** A naive six-fold loop in Python takes tens of seconds per training step, making hyperparameter comparison impossible, which amounts to giving up experiments on all the later training techniques. `im2col` flattens each receptive field into a row, producing a matrix of shape $(N H_{out}W_{out},\,C k_h k_w)$, and a single matrix multiplication with the weights $(F,\,C k_h k_w)$ directly calls into BLAS. Its cost is that memory is amplified by a factor of $k_h k_w$ (3×3 means nine times), controlled by chunking the batch. The pitfall in the backward pass is in `col2im`: adjacent windows overlap on the input, so gradients must be accumulated rather than overwritten, using `np.add.at` or reshape followed by summing over dimensions; a mistake manifests as the gradient check being slightly off—just stuck at the threshold edge.

**Behavior split between training and inference.** This is the real core of the training-techniques chapter, and also the place where autograd will not remind you. Batch normalization uses the current batch's mean and variance during training, and moving averages during inference, and this pair of statistics are buffers, not parameters—they do not enter gradients, are not updated by the optimizer, and are only accumulated in the forward pass according to momentum. Dropout is the same: only the inverted version is correct; during training divide by $(1-p)$, and during inference do nothing. If written as "multiply by $p$ during training, do not multiply during inference", accuracy drops by a few points, but no error is raised, making it extremely hard to debug.

**Training techniques are the other half of the workload.** With the same network architecture, a tenfold difference in learning rate yields a twenty-point difference in results. Therefore optimizers (SGD, Momentum, Adam), learning-rate decay, He initialization (the $2/\text{fan\_in}$ corresponding to ReLU), and regularization-strength sweeps must all be experimented with as independent variables, rather than copying a set of default values.

**Why not use a simpler approach.** Using PyTorch directly, one line of autograd and it is done, but you would not know what should be stored in `cache`, and when encountering custom operators or gradients that do not flow you would have no idea where to start; the cost is that we deliberately give up autograd and GPU, and training time is measured in hours rather than minutes. Using only kNN and linear classifiers, you cannot see the benefits of batch normalization and Dropout—a linear model saturates at around forty points on CIFAR-10. Switching to MNIST, 99% accuracy would mask all implementation details. Skipping gradient checks and judging correctness by "the loss is decreasing" is the most expensive shortcut: misaligned gradients can often still make the loss decrease slowly, only converging to a worse point.

## 3. Chapter Outline

**Chapter 1 · Data and kNN Baseline.** Load CIFAR-10, split training/validation, visualize samples. The three distance implementations of kNN form a three-step progression: double loop, single loop, fully vectorized (using $\|a-b\|^2=\|a\|^2+\|b\|^2-2a\cdot b$ to turn the distance matrix into a single matrix multiplication). Knowledge points: broadcasting, memory layout, vectorized thinking. Upon completion you can verify: the three versions produce element-wise identical output, while their runtimes differ by two orders of magnitude.

**Chapter 2 · Linear Classifiers.** SVM hinge loss and softmax cross-entropy; the two have the same scoring function but different losses; derive the gradients of both by hand and see clearly why the structure $\hat y - y$ appears in both (one is sparse with respect to wrong classes, the other dense with respect to wrong classes). Knowledge points: multiclass SVM, cross-entropy, log-sum-exp stabilization, regularization term. Upon completion you can verify: analytical gradients match numerical gradients; the two models' validation-set accuracies and error types can be compared.

**Chapter 3 · Backpropagation and Gradient Checking.** The chain rule from the computational-graph perspective, multiplying local gradients by upstream gradients; write a generic `grad_check` that parametrically accepts any function and inputs. Knowledge points: Jacobian, vectorized backward, central differences, relative error. Upon completion you can verify: a hand-derived matrix expression exactly matches the gradients output by the program.

**Chapter 4 · Layering and a Two-Layer Network.** Split "a lump of forward" into a layer composition of Linear + ReLU + Softmax, and write the Solver training loop, parameter updates, and learning-rate decay. Knowledge points: modular interface, separation of parameters and hyperparameters, criterion for overfitting a small sample. Upon completion you can verify: train to 100% accuracy on 50 samples.
