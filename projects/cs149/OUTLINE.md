# CS149 · 并行计算 — 项目大纲

> **性质**：工程兴趣线，**无考纲对位**。价值在"把 Amdahl、缓存一致性、SIMD 从名词变成实测"。
> **总时长**：25–35 小时 ｜ **详细**：`NOTES.md`

---

## 0 一句话

**用实测加速比，把"并行"从口号变成数字。**

## 1 目标：做完之后必须能回答

1. 8 核上跑出 **6 倍加速**，需要串行比例低于多少？（Amdahl 反推）
2. 为什么**伪共享**会让多线程比单线程还慢？怎么测出来？
3. SIMD 的**向量化宽度**受什么限制？为什么 `if` 会打断向量化？
4. **弱扩展 vs 强扩展**的差别，为什么 GPU 上更关心弱扩展？

## 2 里程碑

| 里程碑 | 内容 | 验收 | 估时 |
|---|---|---|---|
| **A1 性能分析** | 用计时器分析串行瓶颈 | 给出"条件 + 数字 + 基线"的报告 | 4h |
| **A2 SIMD** | 手写 AVX2/NEON 向量化 | 相比标量**≥ 2.5×** | 6h |
| **A3 多线程** | OpenMP / `std::thread` 并行 | 8 核**≥ 5×**（Amdahl 验证） | 6h |
| **A3 伪共享** | 复现并修复 | 修复后**≥ 2×**（相对未修复） | 3h |
| **A4 CUDA/GPU** | 一个 kernel（可选） | 相比 CPU **≥ 10×** | 8h |

**A1 + A3 是核心**。A2 看硬件（Apple Silicon 用 NEON，x86 用 AVX2）。

## 3 验收标准

- **必须带基线**：任何加速比都要写"相对什么、在什么机器、什么规模"。
- **必须多次取中位数**：单次计时不算数（抖动可达 30%）。
- **绑核**：多线程测试要 `taskset`/`thread affinity`，否则数据不可信。

## 4 时间预算与取舍

```
最小闭环：A1（4h）+ A3 多线程（6h）+ 伪共享（3h）= 13h
```
**不做**：完整 A4（需要 GPU）、CUDA 优化到极致（收益递减）。
