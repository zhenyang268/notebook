## 2 最小可跑（50 分钟）

### 2.1 实验一：Amdahl（25 分钟）

```c
// 串行版本
double serial(int n) {
    double s = 0;
    for (int i = 0; i < n; i++) s += f(i);
    return s;
}

// 并行版本（OpenMP）
double parallel(int n) {
    double s = 0;
    #pragma omp parallel for reduction(+:s)
    for (int i = 0; i < n; i++) s += f(i);
    return s;
}
```
**测法**：`n = 10^8`，串行跑 3 次取中位数；并行用 `OMP_NUM_THREADS=1,2,4,8` 各跑 3 次。

**预期**：8 线程**拿不到 8 倍**，因为存在：
- 启动/销毁线程的开销
- 循环外的串行部分
- 内存带宽成为瓶颈（核多了但带宽不变）

**反推串行比例**：若实测加速 $S$、核数 $p$，则
$$S = \frac{1}{(1-f) + f/p}\ \Longrightarrow\ f = \frac{p(S-1)}{S(p-1)}$$
（$f$ = 可并行比例）

### 2.2 实验二：伪共享（25 分钟）

```c
// 坏版本：两个计数器在同一缓存行
struct { long a; long b; } bad;

// 好版本：各占一行（64 字节对齐）
struct { long a; char pad[56]; long b; char pad2[56]; } good;
```

两个线程各加各的计数器，跑 10^8 次：
```
bad  : 慢 3–10 倍（两个核反复争抢同一缓存行）
good : 接近线性加速
```

**这就是"伪共享"**：逻辑上无共享，物理上共享缓存行。

---

## 3 三个核心难点

### 3.1 计时必须取中位数

第一次跑有冷缓存，最后一次可能有频率降。**跑 5 次，取中位数**，不要用单次。

### 3.2 绑核

Linux：`taskset -c 0-7 ./prog`；macOS 没有直接等价物，用 Instruments 看线程分布。
**不绑核的数据不可信**（调度器可能把两个线程放同一核）。

### 3.3 内存带宽上限

8 核做**纯计算**能到 7 倍；做**流式访存**可能只有 2–3 倍，因为带宽是共享的。
**这就是"弱扩展 vs 强扩展"的根源**。

## 4 卡住怎么办

| 现象 | 原因 | 修法 |
|---|---|---|
| 并行比串行慢 | 线程创建开销 > 计算量 | 增大 `n` |
| 加速比 = 8.0 整 | 编译器把循环优化掉了 | 加 `volatile` 或用结果 |
| 数据抖动大 | 没绑核 / 没取中位数 | 绑核 + 5 次取中 |
