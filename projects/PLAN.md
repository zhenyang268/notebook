## 3 初试后的支线（2026-11 重排：测开 / 仿真优先，考研协同次之）

**旧口径作废**：本节原先写「三条互斥支线（系统 / 基础架构 / 图形）按目标岗位选一条」。
现在目标岗位已收窄为**测开 + 仿真**（`docs/career/roles.md` 头部），
三条支线不再是互斥并列关系，而是**一条主攻 + 一条协同 + 若干对照**。
判据仍看 `docs/career/roles.md` §1（CAE / 测开 的 60/80 检查点）与 §3（岗位要求 ↔ 本仓载体）。

### A. 测开 + 仿真核心（主攻，站点里的置顶路线）

站内对应路线 id = `testing-sim`（`learning-web` 工程线首页「按目标选路线」第一条）。
顺序与理由（**站内能学的部分**）：

| 顺序 | 单元 | 为什么在这一位 | 岗位对应 |
|---|---|---|---|
| 1 | `langs/cpp-basics/`（LG01.1） | 测试代码与故障注入脚本都写在 C++ 里；生命周期说不清就分不清「测试错」还是「被测代码错」 | 通用底座 |
| 2 | `csapp/`（CS01.1） | 浮点位级 / 存储布局 / 控制流是追数值错误根因的唯一三层 | 测开岗「能判断数值正确性」 |
| 3 | `eng/debug-toolchain/`（EG02.1） | TSan/ASan 报告能读到具体行，才谈得上质量保障 | `S-E1`（并发正确性 + TSan），测开最核心证据 |
| 4 | `eng/testing/`（EG01.1） | 把手工证据沉成可回归断言 + flaky 治理 | 测开岗日常 |
| 5 | `raft/cpp/`（DF01.1） | 真故障注入（分区 / 延迟 / 杀节点）是差异化证据 | `S-E9`，测开岗的稀缺项 |
| 6 | `cs149/`（PA01.1） | 同机基线 + 扩展曲线 + roofline 归因 = 性能基线能力 | 测开岗「性能回归」 |

**这条路线补不上的三块**（站内无单元，只记缺口，不虚构完成度）：

| 缺口 | 现状 | 依据 |
|---|---|---|
| `learning-benchmark/` 代码闭环 | 设计已闭合（10 次提交 / 7 份文档），**代码零** | `docs/career/roles.md` §3、`interview.md` §4.2 |
| 1D FEM 链路 | 变分 → 弱形式 → Gauss–Legendre → 稀疏系统 → CG，**本仓零行代码**（`grid`/`sparse`/`assemble`/`cg` 均不存在） | `roles.md` §1.1 检查点 1、§3 |
| 商业仿真软件经验 | ANSYS / Abaqus / Fluent **全无**；网格无关性 / 时间步无关性 / 理论对标三问答不出 | `roles.md` §1.1b、§3 |

> 这三块补不上，「仿真」只到「自己写求解器 + 数值验证」，不到「商业软件 + 工程规范」。
> 面试官分得清（`roles.md` §1.1b 末尾）。缺口进 `NOW.md` 决定做不做，本页不排期。

### B. 考研冲高协同（与 A 并行，考研期唯一允许的整块投入）

站内对应路线 id = `kaoyan-sync`。优先做与 408 / 数一**具体条目**重叠的单元，
让同一份时间既出面试证据也出复习进度（**只记重叠关系，不承诺分数**）：

| 单元 | 与 408 / 数一的具体重叠 |
|---|---|
| `csapp/`（CS01.1） | 数据的表示与运算、存储层次、指令系统与异常控制流 |

| `database/`（DB01.1） | B+ 树索引、文件与磁盘管理、事务与日志 |
| `os/xv6/`（SO02.1） | 进程与线程、内存管理（页表/换页）、系统调用 |

`algo/discrete/`（DX01.1）只作**数据结构基础**（组合与图结构建模），不作为初试主线。

## 4 优先级判据（五条，冲突时按此排序）

> 2026-11 追加第 1 条：目标岗位收窄后，「对不对岗」是唯一的一级判据，
> 其余四条只在同档位内部排序。口径见 `docs/career/roles.md`。

1. **对不对岗**：目标岗位 = 测开 + 仿真。站点里每个单元标「求职：必须 / 高增益 / 可选」，
   `必须` 先做（`langs/cpp-basics`、`csapp`、`eng/debug-toolchain`、`eng/testing`、`raft/go-lab`）。
2. **与 408 的重叠度**：`os/xv6`、`database`、`csapp` 的内存/链接/存储部分与考纲重叠，
   重叠越多越优先；考研期只有这一类整块投入（`csapp`、`algo/*`、`database`、`os/xv6`、`os/linux-api`）。
3. **面试复现率**：近三个月面经里出现过的问法优先（`cs149/NOTES.md` §14 那张对照表是样本）。
4. **已有就绪度**：仓里已有真实产出的（`csapp/bomb`）优先——同样的时间能把"做过"变成"讲得清"。
   `raft` 的旧课lab 材料已归档（`../.gen/archive/6824-2026-11-17/`），就绪度只作历史参照；新口径按 `raft/go-lab` 的 lab 判据重算。
5. **可验证产出**：能给出"跑起来 + 一个数字"的优先于只能读懂的。

## 6 不做什么

- **不新增项目**：单元数已经超过能讲完的量，加一个就稀释一个。
  **唯一例外（2026-11-12，用户明确要求）**：`os/virtualization/`（QEMU/KVM + 容器 + WSL）。它补的是原 36 个单元里唯一空缺的"机器边界"视角，不是又一个并列方向；补完之后回到"不新增"。
- **不为了"简历好看"重写已完成的东西**：审查（`raft` 的定位）收益高于续写，写第二遍不会让答案更好。
- **不写排期到单项目文件**：见 `README.md` §共同约定 5。
- **不做与岗位无关的实验**：主攻 + 协同两条线不是形式主义，是时间约束。
  按新口径，**图形 / AI（C2）与基础架构剩余项（C1）只作对照阅读**，不占整块时间。
- **不把缺口写成单元**：`learning-benchmark` 代码闭环、1D FEM 链路、商业仿真软件三块，
  站内没有对应单元 —— 只在本页 §3A 记文字缺口，不虚构支线步骤、不标完成度。
