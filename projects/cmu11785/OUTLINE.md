## 一、它在做什么

这个项目要做的，是把深度学习里最常用的零件亲手造一遍，再用这些零件拼出一个能跑的语音识别系统。

输入是固定来源、规格统一的数据：语音波形先经 fbank 特征化，变成 `(batch, 帧数, 40)` 的定长张量；标签是一串远短于帧数的音素序列。输出有两个：一个是自建的层库加自建的反向传播机制（不依赖 `torch.nn`）；另一个是用它训练出的模型，对每条语音输出一条音素串。

验收分三层。**第一层是正确性**：每个手写层都要通过数值梯度检验，与中心差分的相对误差在 1e-6 量级。**第二层是组件指标**：分类任务达到准确率门槛，序列任务达到 WER 门槛。**第三层是可复现**：一条命令从原始特征跑到评测报告，同一配置两次运行结果一致，并附一份能指出主要混淆对的错误分析。任何一层不过，后面都不算数。

## 二、为什么这样做（功能设计）

**把 `torch.nn` 换成自己的层，接口开在用户态的张量 API 上。** 不碰内核，也不用写 CUDA；替换发生在 Python 层，`nn.Linear` 被一个持有权重、暴露前向与反向的普通对象顶替。要自己实现的约定有四条：层对象必须登记自己的参数，并能枚举它们；反向要么手写链式法则，要么接入自建的自动微分引擎；参数初始化必须显式写出来（Xavier/He），否则深层网络第一轮就死；张量形状要写成注释，并与代码保持一致。

为什么不直接用框架？因为直接调 `nn.Linear` 两行就完事，而 `dW = X.T @ dout` 里那个转置到底转到哪里去，正是这个项目全部价值所在。代价必须承认：纯 Python 层比高度优化的库慢一到两个数量级，所以手写版本只在梯度检验和小数据上跑，训练阶段切回 PyTorch。这个切换点要提前想清楚，不然会在不该优化性能的地方耗掉大量时间。

**从手写反向走到自动微分，是被复杂度逼出来的。** 手工为每个算子推公式，层数一多就会失控：改一个算子要重推三条链。第二步因此是把握公式这件事抽象成机制——张量记录自己的梯度和“谁生了我”，算子提供前向与反向，前向建图、反向沿拓扑序逆序回传。有三个坑必须在机制层面一次解决，否则后面每个模型都得重踩：广播过的张量梯度形状对不上，要在反向里对广播维度求和归约；同一节点被多个下游使用，梯度必须累加而非覆盖，这是计算图是 DAG 而不是树的直接后果；反向模式只能从标量出发。

**数据的不可靠性来自两处：长度不齐，和标签不对齐。** 特征侧每句帧数不同，做法是 pad 到批内最长并同时记录真实长度向量。所有后续计算——softmax、归一化、CTC——都必须读取这个长度向量，否则 pad 帧会静默污染损失和梯度：损失继续下降，指标却不涨，这种错误极难定位。标签侧更棘手：一句两百帧的语音只给八个音素，中间哪帧对哪个音素完全未知。CTC 的办法是把所有可能对齐（含重复与 blank）边缘化掉，用动态规划在前向-后向格子上求和。blank 的存在正是为了让“同一音素连续出现”和“静音过渡”能被表达，否则两个相邻的 a 无法区分是一个 a 还是两个。数值上必须用 log-sum-exp，直接连乘概率在两百帧上会下溢成零。为什么不用更简单的做法？把语音切成帧级标签做普通分类，等于把对齐这件事当成了已知输入，而它恰恰是我们要省掉的成本；用固定长度输出的 seq2seq，等于假设输出长度已知，而它正是未知量。

**归一化的统计维度必须与不变量对齐。** 序列的统计量沿时间轴不稳定，padding 又让批统计量随批内最长句漂移，所以 BatchNorm 在 RNN 里难用；LayerNorm 在特征维上归一，与时间长度解耦，因此成为序列模型与 Transformer 的选择。这里不是为了统一风格，而是维度选错就等于把噪声注入梯度。

**评测与错误分析不是收尾工作。** 解码输出是字符串，用编辑距离算 PER/WER，再统计哪些音素总被混淆。没有这一层，调参就是盲调：WER 涨了两个点，你说不清是特征、模型还是解码宽度的问题。

## 三、章节大纲

1. **形状契约与数据管线**——配置快照、fbank 的口径（窗长、帧移、归一化）、变长批处理与长度向量。知识点：分帧与频谱特征、padding 与 mask、可复现性。验证：任意 batch 进去，特征形状与长度向量自洽；同一配置两次运行的第一批数据逐位相同。
2. **MLP：手写前向与反向**——线性层、ReLU、softmax 交叉熵的前向与解析梯度。知识点：链式法则、交叉熵对 logits 的梯度、softmax 的数值稳定写法、初始化。验证：过梯度检验；在小数据上能过拟合到接近 100%，能过拟合说明反向没写错。
3. **迷你自动微分引擎**——张量与算子抽象、计算图、反向拓扑排序、广播归约、梯度累加。知识点：反向模式微分、DAG、原地操作的风险。验证：同一组算子的梯度，手写版、引擎版、参考实现对得上。
4. **卷积、池化与正则**——卷积的两种实现（显式循环与 im2col）、池化的反向路由、BatchNorm 与 Dropout 的训练与推理差异。知识点：感受野、参数共享带来的梯度求和、滑动统计量。验证：卷积反向过梯度检验；图像分类子集上达到目标准确率。
5. **序列模型与 BPTT**——RNN/LSTM/GRU 前向、沿时间反向、梯度裁剪、变长序列打包。知识点：BPTT 连乘项、梯度消失从雅可比连乘看、门控如何提供短路径。验证：梯度检验通过；玩具任务（复制、累加）学得会；能把梯度范数随时间的衰减画出来。
6. **CTC**——前向-后向格子、log-sum-exp、blank 插入规则、贪心与 beam 解码。知识点：对隐对齐做边缘化、动态规划、数值下溢、beam 剪枝。验证：小词表上 WER 达标；自己算的 loss 与参考实现差在 1e-5 内；退化输入（全 blank）下解码行为可解释。
7. **注意力与 Transformer**——缩放点积注意力、多头、位置编码、残差与 LayerNorm、两类 mask（padding 与因果）。知识点：注意力为何需要位置编码、缩放因子的方差论证、LayerNorm 与 BatchNorm 的取舍。验证：注意力权重行和为 1、被 mask 位置权重为 0；小规模任务上指标达到门槛。
8. **端到端装配与评测**——把编码器、解码器、训练循环、检查点、评测脚本接起来，做混淆对分析。知识点：学习率调度、早停、错误分析的方法论。验证：一条命令从原始特征跑到 WER 报告且可复现；错误分析能指出前三类混淆。

## 四、不做什么

**课程不要求的**：分布式训练、混合精度、CUDA 算子、推理部署与量化。这些是系统工程，与“看清梯度”的目标正交，做它们不会让任何一章变扎实。

**不做大规模预训练与论文复现**。算力和时间都不允许，而且那是另一条线的事，与本项目共享的只有名词。

**不追求榜单排名**。私有评测的分数受数据划分与集成技巧影响很大，本项目只把公开指标当作“做对了没有”的判据，到线即止。

**不自己写 STFT 和滤波器组**。特征口径必须与课程一致，自行实现只会引入窗函数与归一化的偏差，掩盖真正要学的部分。

**不要求用纯手写复现完整 Transformer**。第 7 章允许切回框架的自动微分，手写范围到“能写清注意力反向的形状为什么是这样”为止。

**实现自由度**（没有唯一答案，选一个并写清理由）：卷积用 im2col 还是显式循环；优化器用动量 SGD 还是 Adam；beam 宽度；层 API 的命名与参数注册方式；是否给引擎加禁用梯度的开关。

**常见跑偏**：跳过梯度检验直接训练，损失不降时无法区分“公式错了”和“超参不对”——梯度检验是唯一能在小规模上把这两者分开的手段；mask 只加在损失上，忘了加进 softmax 与归一化，pad 帧静默污染梯度；在 CTC 之前先 softmax 再取 log，把 log-sum-exp 的稳定性白白丢掉；把 blank 当成普通类别做帧级分类，绕过了对齐问题，也就绕过了这一章的全部内容；在 RNN 里照搬 BatchNorm，然后花两天调 batch size；抄一份参考实现跑通就收工，没有把形状和梯度变成自己能复述的东西——下一章会立刻卡住。
