## 1. What It Does

What this project does is build the most commonly used components in deep learning by hand, then use these components to assemble a working speech recognition system.

The input is data from a fixed source with uniform specifications: speech waveforms first undergo fbank feature extraction and become a fixed-length tensor `(batch, 帧数, 40)`; the labels are a phoneme sequence much shorter than the number of frames. There are two outputs: one is a self-built layer library plus a self-built backpropagation mechanism (not relying on `torch.nn`); the other is a model trained with it, which outputs a phoneme string for each utterance.

Acceptance is in three tiers. **The first tier is correctness**: every handwritten layer must pass numerical gradient checks, with relative error against central differences on the order of 1e-6. **The second tier is component metrics**: the classification task reaches the accuracy threshold, and the sequence task reaches the WER threshold. **The third tier is reproducibility**: one command runs from raw features to the evaluation report, two runs with the same configuration produce identical results, and an error analysis that identifies the main confusion pairs is attached. If any tier fails, the later ones do not count.

## 2. Why Do It This Way (Functional Design)

**Replace `torch.nn` with your own layers, with the interface exposed on a user-space tensor API.** Do not touch the kernel, and do not write CUDA; the replacement happens at the Python level, where `nn.Linear` is replaced by an ordinary object that holds weights and exposes forward and backward. There are four conventions you must implement yourself: a layer object must register its own parameters and be able to enumerate them; backward must either hand-write the chain rule or plug into the self-built automatic differentiation engine; parameter initialization must be written explicitly (Xavier/He), otherwise a deep network dies in the first round; tensor shapes must be written as comments and kept consistent with the code.

Why not just use the framework directly? Because calling `nn.Linear` is two lines and done, while exactly where the transpose in `dW = X.T @ dout` actually goes is the entire value of this project. The cost must be acknowledged: pure Python layers are one to two orders of magnitude slower than highly optimized libraries, so the handwritten version only runs on gradient checks and small data, and training switches back to PyTorch. This switch point must be thought through in advance, otherwise you will spend a lot of time in places where you should not be optimizing performance.

**Moving from handwritten backward to automatic differentiation was forced by complexity.** Manually deriving formulas for every operator gets out of control once there are many layers: changing one operator requires re-deriving three chains. The second step is therefore to abstract the act of deriving formulas into a mechanism—tensors record their own gradients and “who generated me”; operators provide forward and backward; forward builds the graph, and backward propagates in reverse topological order.
